# 0.0.12：Structured Verification Evidence（结构化验证证据）

勘察结论：wire 的 `tool_execution_start/end` 事件已带 sessionId/runId/args/result/isError，Swift 侧可直接组装证据账本；bash 退出码从 `isError` + "Command exited with code N" 文本诚实推导（无结构化字段时标"未知"）。**Host 与协议零改动。**

## 数据层（Swift）

1. `VerificationModels.swift`：`VerificationEvidenceRecord` {recordId=`sessionId:runId:toolCallId`、command、exitStatus（ok / failure(code?) / unknown）、startedAt/endedAt/durationMs、cwd、model(provider/id)、gitRevision?（异步补全，可缺席）、toolCallId、runId、sessionId}；`VerificationEvidenceStore`（`~/Library/Application Support/D Code/verification-evidence-v1.json`，版本校验 + 5000 条上限 + 失败熔断，仿 SessionChangeStore 范式）。
2. AppModel：`handleSessionEvent` 的 `tool_execution_start`（bash）记在飞起点（toolCallId→command+startedAt）；`tool_execution_end` 落账（退出码推导：!isError→ok；isError→正则 `Command exited with code (\d+)`，无匹配→unknown）；后台 Task 用既有 git 直跑补 `rev-parse HEAD`（按 cwd 缓存 5 分钟，缺席不阻塞）。0.0.12 只记 bash 命令；其他工具的"执行事实"仍由 0.0.4 变更账本承担。
3. 覆盖范围：展示时按 runId 联结会话变更账本（该 Run 的已确认文件列表），不另行采集。

## UI（WorkInspector 会话作用域）

1. `SessionInspectorView` 新增"运行证据"区：本会话证据倒序列表——命令（等宽截断）、退出徽标（✓ 绿 / ✗ 红+退出码 / ？未知）、耗时、完成时间、revision 短 SHA；行可展开看完整命令、revision 全值、环境（模型 / cwd）与该 Run 的已确认变更文件。
2. 底部诚实声明："证据只来自真实工具运行的转发事实；Agent 的'已验证'文案不构成证据；本视图不是发布门禁"。

## 文档与版本

- ADR 0021《验证证据身份》：证据 = Host 转发的真实工具执行事实（命令 / 退出推导 / 时间 / 环境）+ 异步补全的 revision（可缺席）；与变更账本双轨；反目标（仅凭文案、自动发布）显式排除。
- PRD 0013；路由表、版本演进 0.0.12 行与决策门禁、CHANGELOG；版本常量两端升 0.0.12。

## 验证

- 单测：退出码推导（成功 / 带 code 文本 / 无 code 的 isError）。
- Fake-host 集成：emit `tool_execution_start/end`（bash）→ 记录持久化、时长正确、runId 关联；非 bash 工具不入账。
- 渲染冒烟：证据列表（含失败徽标与展开态）。
