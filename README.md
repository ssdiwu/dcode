# D Code

D Code 的重新设计工作区。目标是在 macOS 上成为能够持续承接开发、沟通与项目工作的智能体开发环境。

## 已确认的起点

- 旧版实现已经封档；新设计从空工作目录开始。旧代码、需求、布局和对象关系只作历史参考，重新采用时须说明理由并确认适用性。
- UI／UX 以 ZCode 为主要参考，研究完整工作流程、信息层级和共享组件。
- 后端技术基石为 Pi SDK `1.0.0`，目标是融合虚拟模型与基于 Pi Durable 的持久化运行和恢复能力。当前目录尚无应用实现、Pi 依赖或应用运行入口，组合接入仍需验证；能力依据见 [Pi 1.0.0 核对记录](doc/Pi-1.0.0-虚拟模型与运行恢复.md)。
- 任务依附工作界面运行，暂停或关闭后保存状态，重新打开后能够接续；当前不做关闭界面后继续后台执行。已确认边界见 [任务暂停与恢复](spec/任务暂停与恢复.md)，具体交互和实现仍需完善。
- 产品主干采用工作空间 → 任务 → 会话；首条完整路径为开发任务。对象与导航规则见 [工作台信息架构](spec/工作台信息架构.md)，页面设计与验收依据见 [开发任务路径](spec/开发任务路径.md)。
- 不同任务可以并行推进；首版协作成员采用 D Code 内部会话，具体范围与待对齐项见 [会话协作方向](spec/工作台信息架构.md#会话协作方向)。这项方向尚未实现或验收。
- Kimi 的四分支 UI／UX 共识已回流：冷启动与草稿态见 [对应规格](spec/冷启动与草稿态.md)，字号、主题、品牌及组件来源方案见 [DESIGN.md](DESIGN.md)。第二轮部分场景已有独立模拟验证记录，会话内列表／协作图示意的阅读方式已获认可；新增功能、完整视觉矩阵与真实 Pi 尚未完成产品运行或集成验收。
- 客户端技术栈已确定为 Electron + React + Tailwind v4；第二轮采用单时间线与按需右侧检查器，重开后等待用户显式恢复执行。首版中英双语共同设计、实现和验证，包含语言切换，不延后英文排版。
- 2026-10-04 补充确认：右侧任务信息面板可持续展开或隐藏，汇总成果、协作与来源，协作信息可在列表与只读图之间切换；首版用量展示兼顾任务用量及可靠可读的账户信息。对应要求见 [开发任务路径](spec/开发任务路径.md) 与 [用量与账户额度](spec/用量与账户额度.md)，当前尚未接通真实执行和账户数据。
- 工程采用“先建立自动架构检查，再开发首批产品功能”的顺序。最小模块约定与检查入口已建立，作为产品代码的必过检查；具体职责和覆盖边界见 [架构约定](doc/架构约定.md)。独立 UI 工作树已有未接 Pi 的客户端模拟原型，尚未集成到本目录。
- 先重新设计 `AGENTS.md`、`DESIGN.md` 与 `GLOSSARY.md`，再依据确认结果开展实现。

## 工程准备与检查入口

当前工具运行环境：Node.js 22 或更新版本、npm；依赖由 package-lock.json 固定。首次使用运行 `npm ci --ignore-scripts`。以下命令均从本工作树根目录运行：

| 用途 | 命令 | 当前状态 |
|---|---|---|
| 架构检查完整门槛 | `npm run verify:architecture` | 检查器正反样例 + 当前源码检查 |
| 只检查当前源码 | `npm run architecture:check` | 依据 architecture-policy.json，只读运行 |
| 验证检查器 | `npm run architecture:test` | 使用隔离样例，临时文件运行后清理 |

2026-10-03 准备验证：主工作树的 28 个正反样例通过；独立 UI 工作树重新安装锁定依赖后同样通过完整门槛。两侧当时产品源码均为 0。

本目录没有产品源码，源码数量为 0 的通过不表示客户端已验收。应用启动、构建和类型检查入口已在 Kimi 独立工作树建立，不能在本目录使用它们，也不能使用旧封档命令。
