# D Code 0.0.35 现有功能与安全加固产品需求

状态：507 于 2026-09-28 认可先收口现有功能和安全边界、再在 `0.0.36` 增加协作展示与工作流能力的版本拆分。本文件是 `0.0.35` 的需求与验收基准；2026-09-29 已在未提交主工作区实施主要安全、恢复与部分键盘／界面修复并完成分层自动回归，尚未形成可分发候选或完成 507 人工验收。条件项和完整窗口路径仍按下方验证记录核对。`0.0.34` 的源码标签、现有候选与未完成的人工验收继续分别记录，不由本版追认。

## 问题与目标

现有工作台已经能处理 Task、Session、成员、附件、文件和候选构建，但少数已观察到的输入、阅读和恢复路径会让用户误触、误读或难以继续；部分安全边界没有按 D Code 的凭据和最小权限原则收紧。在这些基础上叠加新的“＋”菜单、Goal、文件搜索或任务内工作流，会扩大排查范围并使验收难以归因。

本版让现有能力在正常使用、失败和重启后保持可解释：Agent 命令拿不到 Host 私有凭据，主窗口权限和生产网络边界明确，错误不会回显凭据；已有任务和文件操作遇到并发或窗口变化时不会静默丢失工作，键盘用户能够完成与鼠标相同的关键路径。修复以现有对象和协议为准，不建立新 Task、Workflow 或能力体系。

## 需求

### 运行与安全边界

1. Agent 可调用的 bash 及其辅助进程只接收完成项目命令所需的非保密环境变量。Host 私有模型凭据、认证令牌和其他继承自启动环境的秘密不得仅因 Agent 获得 bash 工具而进入其命令环境、输出、持久会话或日志；模型连接继续使用既有保密管道。
2. 主窗口会话对浏览器权限请求与权限检查默认拒绝；产品确需使用的权限须按明确的功能和来源单独开放。隔离 HTML 预览继续使用自己的独立会话，关闭预览或换文件不继承前一次许可。生产客户端的内容安全策略不保留开发热更新的本机 WebSocket 通配规则，开发预览仍能正常连接。
3. Host 协议错误、运行事件与 stderr 诊断向外给出稳定错误码和可行动说明，错误正文、details 与异常栈均不得回显已知凭据或可识别的凭据形状；脱敏不得把失败伪装成成功。
4. 一等项目文档的路径和其他来源元数据进入 D Code System Prompt 时保持数据边界。文件名中的引号、尖括号或换行不能伪造文档标签、工具说明或更高优先级指令；提交原文、来源路径与摘要仍可核对。

### 生命周期与恢复

5. 同一时刻只能有一项 D Code 源码检查或候选构建；两个并发启动请求中只有一个能取得执行权，另一个得到明确的已有任务状态。停止、失败或 Host 中断后，不留下界面已空闲而实际仍在运行、无法归属的维护子进程。
6. 搜索 worker 意外退出时，无论退出码是否为零，在途搜索都在有界时间内得到失败结果；再次搜索可以启动新 worker，不让旧请求永久挂起。主动关闭搜索服务时，待处理请求按关闭语义结束。
7. Product Store 开始关闭后不再接受新写入；关闭前已受理的写入按顺序收口，再关闭数据库和租约。无论是正常退出还是中断恢复，不能把数据库已关闭后的失败误报为写入完成。
8. Session 租约的 owner 记录初次建立也以完整、可原子观察的形式发布。记录损坏或属主身份不可核实时保持保守拒绝，并保留有来源的显式接管路径；不得为消除报错自动删除可能属于活进程的锁。
9. Store 修订冲突后，已有草稿保存要么在有界重试后成功，要么明确告知失败并保留本地草稿供再次保存。仅出现一条诊断日志不代表草稿丢失；此项以实际保存和重启恢复结果验收。

### 现有界面与键盘路径

10. 新建、编辑项目和其他模态弹窗打开时，焦点落在当前主要输入或明确的首要动作上；Tab 与 Shift-Tab 只在可操作的弹窗控件中循环，包括选择框、链接和后续新增的输入类型。中文输入法组词期间 Escape 只取消组词，不误关弹窗；关闭后焦点回到原入口。未保存文件的保存／放弃／继续编辑弹窗遵守同一规则。
11. 窄窗口中的文件检查器按现有覆盖合同提供明确遮罩和退出入口，不使后方对话呈现为被字符截断的可读正文。HTML 预览随容器位置、尺寸、可见性及任务切换同步，不能漂移到新任务画布或裁切许可与结果提示。
12. 已有执行过程摘要在没有正文时只显示有意义的动作和状态，不留下悬空分隔符；关于页在开发和候选环境均显示 D Code 的真实版本及必要的环境区别，不把 Electron 运行时版本称为 D Code 版本；灵感卡片把 Markdown 正文转为可读摘要，不在普通摘要中直接显示标题标记。
13. 文件树、文件标签和 Git 差异的键盘导航可达且与声明的无障碍语义一致。长差异不能因每一行都是独立 Tab 停靠点而使后续操作不可达；减少动态效果和当前输入焦点规则继续有效。

## 已确认边界与证据状态

- 两份审计材料只是候选来源。Mimosa 密封产物的 `175` 条均为静态 advisory，未提供已验证的可达链或运行证据；本版不把这些计数直接转成漏洞修复清单。另份代码／UX 报告中，环境传递、权限与 CSP、模态键盘、部分退出和展示路径有源码或隔离窗口证据；并发后果与草稿丢失仍需目标动作验证。
- 维护启动、Store 关闭、搜索 worker 等项目按“成立的完整用户或 Host 路径”修复和验收。若定向复现证明某个报告推断不成立，应记录边界并关闭该项，而不是修改断言制造绿色结果。
- 主窗口的通用 IPC 已有可信主 frame 检查；“一旦主渲染层被注入可调用更多 Host 方法”是需单独威胁建模的放大面，现有材料未证明主渲染层可被注入。本版不以一个未经设计的全方法禁用表破坏现有工作台；如验证出具体越权路径，在安全修复中按实际入口处理。

## 验收标准

- [ ] 使用隔离数据与合成凭据，在真实 Agent bash、后台命令、模型连接和错误路径上核对：bash 的环境与输出没有 Host 秘密，模型仍可通过既有保密引用正常调用；停止和重启不把秘密写入 Product Store 或诊断。
- [ ] 实际 Electron 主窗口对未经允许的权限请求与权限检查返回拒绝；独立预览的默认网络阻断、当次显式放行、换文件复位与本地资源读取继续成立。生产构建中没有开发用本机 WebSocket 通配规则，开发热更新仍可工作。
- [ ] 注入合成的凭据形状和含引号、尖括号的文件路径，核对 Host 响应、事件、stderr、D Code System Prompt 和来源回执：秘密被遮蔽，文档来源仍可定位，路径文本不能改变文档边界。
- [ ] 同时发起两次检查或构建、让搜索 worker 以零码意外退出并保留在途请求、在写入排队时关闭 Store：每一步都有有限时间内的结果与正确归属；没有孤儿执行、悬挂 Promise 或假成功。租约首次写入中断后，保守拒绝与显式接管都可解释，存量 Session 不被误删。
- [ ] 在真实窗口中用鼠标、Tab、Shift-Tab、方向键、Enter、Escape 和中文输入法完成项目表单、未保存文件弹窗、文件树、标签与长 Git 差异的关键路径；焦点不会逃逸模态或停在已关闭内容上。
- [ ] 在新任务、已有任务、宽窗和最小支持窄窗打开并切换 Markdown／HTML／Diff 文件；预览、检查器、遮罩、Composer 和许可提示没有遮挡或位置漂移。执行摘要、关于页版本及灵感摘要的内容与实际来源一致。
- [ ] 一次有意制造的 Store 修订冲突后，草稿在成功重试或可见失败与再次保存之间有明确结果；关闭并重新打开后核对原文和附件。历史 `0.0.34` 路径、自动检查、候选窗口走查与 507 人工验收分别记录。

## 非目标

- 不在本版新建 Goal 编辑、真实任务内 Workflow、`@` 文件搜索、`$` 子代理选择或 ZCode 风格“＋”菜单；这些新增能力由 `0.0.36` 的 PRD 0033、0034 承接。现有 `@` 成员定向、`/` 技能与命令、附件和草稿继续可用。
- 不把 Mimosa 的 `175` 条 advisory 当成 `175` 个已证实漏洞，不以某次离线依赖公告库零匹配宣称依赖安全。
- 不把模型目录密度、上下文用量、首次引导、会话 minimap、图像生成、架构门禁、通用性能重构或包体裁剪塞进本版修复门槛；这些候选须在后续版本按来源和收益单独判断。
