# 0.0.4 Workspace Tab 与只读文件预览产品需求

状态：Active Implementation（实施中）

适用范围：以本地 `v0.0.3` 为回归基线，交付 Main Workspace（主工作区）中的 Workspace Tab（工作区标签页）、受限的普通文件只读预览、从现有界面打开文件的本机工作流，以及会话级 Plan / 已确认文件变更摘要；同时收口 `v0.0.3` 人工验收后确认的会话栏信息层级、工作轮元信息和 Markdown 呈现问题。

## Problem Statement（问题陈述）

当前 Project 文件树只能展开目录，普通文件不能进入主工作区；助手回答中的本机文件与行引用也不能直接打开。用户必须离开 D Code 才能核对 Agent 提到的文件，且切换外部工具会割裂当前 Session Path、对话滚动位置和输入草稿。

当前只有一个 Source Folder 的 Project 仍重复显示一层同名根目录；打开该 Project 的 Session 后，Information Inspector（信息检查器）又从 Project Files / Changes 整体退化为只有会话计数与 `cwd`。与此同时，会话栏、主工作区、信息检查器和 Composer 主要依赖硬分隔线切割，缺少稳定的 surface / elevation（表面 / 层级）关系，导致工作台看起来像并排表格，而不是可以同时操作的原生工作面。

Project Changes 只能回答“工作目录现在有哪些 Git 变更”，不能回答“当前 Pi Session 已经确认改了哪些文件、发生在哪一轮、从哪一行开始”。活动 Plan 又只属于当前 Session Path。两者缺少一个诚实的会话级摘要，用户无法像成熟 Agent 工作台一样在 Composer 附近快速核对步骤进度与本会话已确认的文件改动。

`v0.0.3` 还把置顶会话分别混在 Recent 与 Project 列表中，并把 Source Folder 与时间常驻为副标题。会话较多时，重要对象不够集中，重复元信息持续挤压标题；用户只能从截断行猜测其 Project、路径和当前 Git 分支。工作轮的时间、Markdown 块级结构与长会话无障碍滚动也需要在进入文件工作流前成为稳定基线。

## Solution（解决方案）

### Workspace Tab 与文件入口

- Conversation 是当前 Session 的唯一主页面，不建立或显示“对话”标签。只有至少打开一个本机普通文件时才出现 Workspace Tab；标签带只承载文件并直接沿用主画布底色，关闭最后一个文件后回到主页面。
- Project 文件树中的普通文件可以打开或聚焦只读 File Preview（文件预览）。从助手正文识别出的、位于已登记 Source Folder 内的本机文件、目录与代码行引用也可以进入同一入口；重复打开同一规范路径只聚焦已有标签。
- 切换内容标签不得重建 Conversation、改变 Pi Session / Session Path、清除活动 Plan、滚动位置或逐字草稿。关闭当前内容标签后聚焦相邻内容；没有其他内容时回到“对话”。
- 文件打开本身不把文件加入模型 Context，不取得 Session Lease，不修改文件、Git、Project 或 Pi Session。

### 只读与安全边界

- 只允许读取当前 D Code Project 已登记 Source Folder 内、规范化后仍处于授权根目录的普通文件。符号链接、路径穿越、文件替换和读取时竞态不得绕过根目录限制。
- 目录、缺失文件、无权限文件、二进制文件、超过有界大小的文件和无法可靠解码的文本必须显示可恢复错误；不得以空白页冒充成功，也不得自动改用系统编辑器读取未授权内容。
- 普通文本与代码采用可选择、可复制的只读呈现，并显示文件名、可区分的路径与必要的行定位。打开后的文件不是消息、Artifact 或 Context 条目。

### Project 上下文与工作台层级

- Project 只有一个 Source Folder 时，Files 直接平铺该根目录的 children（子项），不再重复显示与 Project 同义的根文件夹行；Project 有多个 Source Folder 时保留各根标签，避免同名文件失去来源。
- 在 Project 内新建会话时：没有 Source Folder 则禁用并引导添加；恰好一个时单击直接以该目录为 `cwd` 创建，不显示冗余的一项菜单；两个及以上时才展示 Source Folder 选择菜单。
- 打开 `cwd` 精确归属于已登记 Source Folder 的 Session 后，信息检查器继续提供该 Project 的 Files / Changes，并额外提供 Session 概览；Session 上下文只能叠加，不能替换 Project 工作上下文。未归入 Project 的 Session 继续显示独立会话概览。
- 窗口控制带、主工作区阅读画布与右侧 Inspector rail 延续同一系统 canvas 底色，不形成独立色块或明显分割线。会话栏使用与主工作区阅读画布有轻微色阶差异的下层 surface；信息检查器与 Composer 使用共享的圆角、描边和 shadow（阴影）形成可操作的 raised surface（抬升表面）。外层列关系不再依赖贯穿窗口的硬 Divider（分隔线）；必要的内部 hairline 只服务于单个表面内部的语义分组。
- 会话栏下层 surface 从窗口顶部延续到底部，标题栏左段与下方栏体保持同一像素底色；窗口控制带与中央内容共同组成覆盖其上的一块主工作区 canvas，以统一左侧圆角表达“导航承托工作内容”，但主画布不得向会话栏投射外阴影或材质渐变。控制带和正文不得分别铺背景或留下横向接缝。
- elevation（层级）不能改变 hit-testing、VoiceOver 顺序或响应式语义：`≥880 pt` 的信息检查器仍是非模态常驻区域，只有 `<880 pt` 的互斥覆盖才允许蒙版。

### 顶部会话身份与可调栏宽

- 窗口顶部只有一条控制带：红黄绿窗口按钮、会话栏开关、当前会话名称与菜单、信息检查器开关同排；会话栏不可见时，左上控制带紧跟栏位开关显示“新建会话”，恢复会话栏后退出以避免重复。会话栏标题与会话正文从该控制带下方开始。不在主工作区内容再重复同一标题与菜单，不增加独立的“左右按钮栏”；没有工作对象时不重复产品名，也不使用 macOS Toolbar 的玻璃胶囊。空白控制带单击用于拖动窗口，双击遵循 macOS 的标题栏连按偏好并执行放大 / 还原、最小化或无动作。会话重命名经 Host 调用 Pi SDK 写入真实 Session Name，空名称恢复 Pi 自动名称。
- 信息检查器顶部直接列出当前可用的“会话 / 文件 / 变更”视图；不重复会话标题，不把 Project 作用域伪造成 Session 概览。
- 会话栏与信息检查器均可通过边缘把手调整宽度，并以本机偏好跨重启保留。拖动上限受当前窗口和主工作区至少 `480 pt` 约束；双击恢复默认，键盘与 VoiceOver 可等价调整。
- Settings 页内导航与会话栏共享同一份实际宽度；从 Workspace 或 Settings 任一页面调整后，另一页面立即继承。信息检查器也在全部 Project、Session 与后续页面间共享唯一实际宽度，不允许页面私有默认值。

### 会话栏信息层级

- 已置顶会话集中在会话栏所有普通会话列表之前的全局“置顶”区域，并从 Recent 与 Project 普通列表去重。置顶只改变 D Code 投影，不修改 Session、`cwd`、来源或 Project 归属。
- 普通会话行只常驻显示单行标题。悬停或键盘聚焦后，非模态详情显示完整标题、更新时间、Project、Source Folder、完整 `cwd` 与当前 Git 分支；这里的 Git 分支只描述工作目录当前状态，不冒充会话历史分支。
- 行内置顶与归档仍有右键菜单、当前 Session 菜单和 VoiceOver 等价入口；Hover 不是唯一入口。动作显隐不改变标题、行高或命中区几何。

### 主工作区设置导航

- 齿轮与 `Command-,` 都在当前窗口进入 Settings（设置）工具页面，不创建第二个 macOS 窗口。该页面临时使用完整工作台画布，以继承会话栏实际宽度的页内设置导航组织“外观 / 工作台 / 已归档会话 / 关于 D Code”，右侧正文限制阅读宽度并使用少量语义分组，不铺成跨窗大表或卡片瀑布。
- “已归档会话”沿用同一 Settings 页面外壳与页内导航；归档页面继续保留查看、失败重试和恢复显示能力，不叠加 Sheet。进入 Settings 时只临时隐藏日常会话栏和信息检查器，返回 Workspace 后按进入前偏好恢复。
- “关于 D Code”沿用同一 Settings 页面外壳，显示应用图标、当前版本与构建号、作者 GitHub 主页和项目 GitHub 主页；外部链接只经系统 URL 打开路径处理，不复制账号、仓库或发布资料。
- 会话栏底部在 Host 健康可用时不常驻成功文案；只有正在连接、未连接或连接失败时才显示可解释状态，齿轮与刷新动作始终保留。

### 对话呈现回归

- 助手 Markdown 使用原生块级标题、段落、粗体、列表、引用、分隔线、表格与既有 fenced code / Mermaid 呈现；复制始终返回原始 source。无法安全富渲染的内容完整退回保真文本，不丢正文。
- Pi 结构化 `image` 内容块在会话内显示为有界方形缩略图；点击后在原生预览中按原始比例查看并缩放。原始字节继续只存在于 Pi Session JSONL，D Code 仅在内存中严格解码与验证，不建立第二份图片存储；损坏、不支持或超过安全上限的内容显示可解释占位。
- 任意远程 Markdown 图片链接不自动加载；Composer 中粘贴、选择和发送图片不随本切片开放。
- 已完成工作轮只在最终助手回复悬停或键盘聚焦时，于正文外显示耗时和持久化完成日期；默认阅读面不常驻时间。真实失败仍明确可见，已经恢复的中间失败不继续把整轮标成橙色。
- 长会话滚动容器必须支持普通指针、键盘、VoiceOver 与外部 Accessibility（无障碍）滚动操作，不因滚到首尾而崩溃；搜索定位和会话导航尺仍能定位离屏工作轮。

### 会话级工作摘要与变更账本

- Composer 上方提供紧凑的 Session Work Summary（会话工作摘要）：Plan 进度按当前 Session Path 投影；文件数与增删行数按整个稳定 Session ID 聚合。两者不能混成同一个状态机。
- D Code 为成功完成且具有结构化变更结果的工具调用建立本机 Session Change Ledger（会话变更账本）。首版至少识别 DHashline-compatible（兼容 DHashline 结果合同）的 `edit` 与 `write`，记录稳定 Session ID、D Code Run ID、持久化用户条目锚点、工具调用 ID、文件路径、动作、首个变更行、增加行、删除行和时间。
- 摘要中的 `+ / -` 表示本会话被 D Code 观察并确认的变更活动，不冒充当前 Git 净差异。重复编辑、撤销、提交、reset（重置）或外部写入不会被错误描述成 Git 当前状态；Project Changes 继续独立显示整个工作目录的实时 Git 投影。
- 第一版覆盖度固定诚实显示为“结构化工具已确认 / 可能不完整”。失败工具不写入账本；Bash、其他扩展、Pi CLI、外部编辑器和升级前历史若没有结构化证据，不得被推断或补记。
- 账本只保存变更元数据，不复制源码正文或完整 patch（补丁）。源代码与原始工具结果仍留在原文件和 Pi Session；会话复制生成新 Session ID 后不继承源会话账本，Archive（归档）只隐藏普通投影、不删除账本。

## User Stories（用户故事）

1. 作为在 Project 中核对 Agent 结果的用户，我希望点击文件树中的普通文件就在中央打开只读预览，从而不离开当前任务。
2. 作为阅读助手回答的用户，我希望点击授权范围内的文件与行引用时复用同一文件标签并定位，从而快速验证结论。
3. 作为正在输入或阅读长会话的用户，我希望切换文件后再回到对话时，原 Session Path、滚动位置和逐字草稿保持不变。
4. 作为会话较多的用户，我希望所有置顶会话集中在会话栏最上方，而且普通列表不再重复，从而快速找到重要工作。
5. 作为需要辨认截断标题的用户，我希望悬停或键盘聚焦后看到完整标题、Project、路径与当前 Git 分支，同时普通行保持安静。
6. 作为依赖 VoiceOver 或键盘的用户，我希望文件、标签、会话详情和滚动都具有等价入口，而不是依赖 Hover 或指针坐标。
7. 作为从 Project 会话继续工作的用户，我希望信息检查器始终保留该 Project 的文件与变更，并在单根项目中直接看到根目录内容，而不是先穿过重复目录层级。
8. 作为核对 Agent 工作结果的用户，我希望在 Composer 上方看到当前路径的步骤进度和整个会话已经确认改动的文件数与增删行数，并能展开定位到具体文件和首个变更行。
9. 作为长期使用同一工作台的用户，我希望在顶部辨识、重命名并管理当前会话，也能按自己的阅读密度调整会话栏与信息检查器宽度，而不挤掉主工作区对话。
10. 作为阅读 Pi 图片内容块的用户，我希望先看到紧凑缩略图，点击后查看原图，而不让 D Code 再复制一份附件。
11. 作为核对本机候选版本的用户，我希望在应用内的“关于 D Code”页面看到应用身份、版本、作者与项目入口。

## Confirmed Constraints（已确认约束）

- Pi Session 与配置继续以 `~/.pi/agent` 为唯一权威；Workspace Tab 不建立第二套会话或消息存储。
- 文件预览必须由已登记 Source Folder 的当前权限边界授权；打开文件不能被外推为允许编辑、执行、加入 Context 或访问相邻目录。
- 会话置顶继续使用稳定 Session ID 的本机元数据。Archive 排除优先于 Pin；归档后不在普通列表或全局置顶区泄漏，恢复后按原资格重新投影。
- 相同规范文件路径在一个工作台中只有一个内容标签；同名不同路径必须可区分。
- Markdown 富渲染与文件预览都保留原始 source 作为复制事实，不从展示树反向重建正文。
- Pi 图片只从结构化内容块的内嵌数据进行有界内存解码，不写缓存或附件副本；远程 Markdown 图片与 Composer 图片发送不属于本版本。
- 会话任务看板只作为外部参考，不属于 `0.0.4`，也不由 Workspace Tab 暗示实现。
- Session Change Ledger 是 D Code 本机派生资料，不成为 Pi Session、Git 或文件内容的第二权威；缺少结构化证据时必须显示覆盖不完整，而不是猜测。

## Acceptance Criteria（验收标准）

### Workspace Tab 与文件预览

- [ ] 主页面不显示“对话”标签；没有打开文件时不存在标签带，打开普通文件后只显示文件标签，重复打开同一规范路径只聚焦已有标签，关闭最后一个文件后直接回到主页面。
- [ ] 从 Project 文件树打开普通文本或代码文件后，中央显示可选择、可复制的只读内容、明确文件名与可区分路径；指定行引用能定位到目标行。
- [ ] 从助手正文打开授权范围内的本机文件、目录或代码行引用时使用同一内部路由；`http` / `https` 等外部链接仍按系统安全路径处理，未知或危险 scheme 不执行。
- [ ] 切换文件与“对话”后，当前 Session、Session Path、活动 Plan、对话滚动位置和逐字 Composer Draft 完整保留；文件标签关闭不影响这些状态。
- [ ] 打开文件不会改变文件字节、Git 状态、Project 关系、Pi JSONL 或模型 Context，也不会取得 Session Lease。

### 文件安全与错误

- [ ] 规范化后越出已登记 Source Folder 的路径、越界符号链接、目录、缺失、无权限、二进制、超限和不可解码文件均被拒绝并显示明确原因；旧异步读取结果不能覆盖较新的标签选择。
- [ ] 文件在授权检查与实际读取之间被替换或移动时必须失败关闭；失败页面保留文件身份和可执行的重试或关闭入口，不显示空白成功态。
- [ ] Project 或 Source Folder 关联被移除后，尚未读取的文件不能继续获得新权限；已经加载的内容只保留为标明“来源授权已移除”的只读内存快照，不再从磁盘刷新或重新读取。关闭标签或重启 App 后不得凭旧标签恢复磁盘访问。

### 会话栏、设置与会话详情

- [ ] 置顶任一具备 Recent 或 Project 可见资格的会话后，它只出现在会话栏最上方的全局“置顶”区域；Recent 与 Project 普通列表不重复显示。取消置顶后按原资格和更新时间返回普通列表。
- [ ] 较旧置顶会话跨重启仍在顶部；Project 中的旧 Pi Session 不会因置顶进入 Recent，归档会话不会因置顶重新泄漏。
- [ ] 普通行只常驻单行标题；悬停或键盘聚焦后显示完整标题、更新时间、Project、Source Folder、完整 `cwd` 与当前 Git 分支，移出后隐藏且不造成行布局跳动。
- [ ] 置顶、归档与选择是互不重叠的 sibling controls（同级控件）；行尾纯图标动作使用 `32 × 32 pt` 紧凑目标与 `28 × 28 pt` 状态表面，具有对象化 VoiceOver 名称，并通过右键或菜单提供等价键盘入口。
- [ ] Window control band、会话栏身份行、“新建项目”、Project 与 Session 导航行统一使用 `36 pt` 行高；图标 glyph、视觉表面和 `32 pt` 紧凑目标保持原尺寸，不因统一行高而放大。
- [ ] 会话栏普通会话导航不显示“已归档会话”；齿轮与 `Command-,` 都在当前窗口进入完整 Settings 工具页面。Settings 临时使用完整工作台画布，以页内设置导航和受限宽度分组内容呈现外观、工作台布局与会话管理，不打开第二个窗口。
- [ ] “已归档会话”沿用同一 Settings 页面外壳；归档来源、复制目标、失败重试与恢复显示都在该页面完成，不再叠加 Sheet 或卡片式弹窗。返回 Workspace 后恢复进入设置前的会话栏与信息检查器偏好。
- [ ] Host 健康可用时，会话栏底部不常驻“运行服务已就绪”；正在连接、未连接或失败时显示真实状态，设置与刷新动作仍可达。
- [ ] Project 只有一个 Source Folder 时，Files 首层直接显示其 children；两个及以上 Source Folder 时继续显示各自根标签，所有读取仍受原授权根约束。

- [ ] 当前 Session Path 存在活动 Plan 时，Composer 上方显示当前步骤 / 总步骤；切换兄弟 Path 后只投影新路径可见的 Plan，不把另一条路径的进度冒充为当前进度。
