# D Code 0.0.16 自定义模型供应商与一次性资源调用产品需求

状态：Published Source Tag（公开源码标签 `v0.0.16`；自动门禁已通过，人工验收与后续安全 / 组合回归缺口仍待完成）

本 PRD 冻结 `0.0.16` 的范围与验收边界；界面语义以 [`0002-D-Code-原生界面设计系统`](../10-架构与运行/0002-D-Code-原生界面设计系统.md) 为准，资源合同沿用 [ADR 0024](../决策档案/0024-界面即上下文与-GUI-原生呈现边界.md) 与 0.0.15 本机资源页的数据面。版本演进对应路线图 `0.0.16`（Custom Model Provider）与漂移补交的 `0.0.14` 号"Composer `+` 一次性资源调用"。

## Problem Statement（问题陈述）

自定义供应商与模型定义目前只能手工编辑 `~/.pi/agent/models.json`，没有字段级校验与错误呈现，D Code 也无法管理这些定义（路线图 0.0.16 自 0.0.7 起顺延）。同时路线图 0.0.14 号的"为当次消息选择本机 Skill / Prompt / Command 并展示实际采用的资源"在 0.0.14 主页收口时漂移未交付；0.0.15 的本机资源页已提供真实加载清单，恰好构成它的数据底座。

## Solution（解决方案）

1. **一次性资源调用（Composer `+`）**：Composer 控制行前置 `+` 入口，菜单按 命令 / Skill / Prompt 模板 分组列出 Pi 真实加载的资源（数据来自 `resources.list`，与 0.0.15 资源页同源；打开的会话内与主页草稿一致可用）；选择即把对应调用（命令 `/name`、Skill `/skill:name`、Prompt 模板 `/name`，模板带参数提示时附参数占位）写入当前草稿并聚焦——只预填不发送，实际采用的资源以草稿中可见的调用文本与菜单里的来源描述为准。
2. **自定义模型供应商（models.json 合同）**：设置新增"自定义供应商"页。Host 新增 `modelProviders.list` / `modelProviders.save` / `modelProviders.remove`：读取 `~/.pi/agent/models.json`（支持注释），凭据脱敏返回（`apiKey` / OAuth / header 值只报"已配置"状态与键名，正文永不进入 Swift）；保存时按 provider 合并——Swift 提交非凭据字段与可选的新凭据输入（只写不回显），既有凭据原样保留；结构校验 + `ModelConfig.load` 真实校验通过后原子写入，任一字段非法则返回字段级错误且不写文件（保留上一份可用配置）；写入后刷新模型目录快照。
3. **编辑体验**：供应商列表 + 新建 / 编辑 / 删除；编辑表单含 id（创建后不可改，作为 models.json 键）、名称、baseUrl、api、认证（API Key 只写输入 / OAuth radius 标记）、模型定义列表（id / 名称 / 推理 / 上下文窗口 / 最大输出等基础字段）；高级字段（compat / headers 键 / thinkingLevelMap / cost）以 JSON 文本区编辑并校验可解析；字段级错误行内呈现，来源为 Host 校验结果原文。

## Confirmed Constraints（已确认约束）

- 凭据边界：`apiKey`、OAuth 配置、header 值的正文永不进入 D Code——列表只显示"已配置 / 未配置"，编辑只允许新值写入（只写不回显），既有值由 Host 合并保留；不提供显示、复制或导出。
- 校验权威是 Pi：保存前以 `ModelConfig.load` 对候选文件做真实校验，Host 侧结构检查只做前置拦截；非法变更零写入。
- 一次性资源调用不绕过 Composer：只写入草稿（与 ADR 0024 预填同一语义），不自动发送、不隐式调用；资源清单只展示 Pi 实际加载成功的合同。
- 不做：在线市场、任意 API 适配器、D Code 自建凭据仓库、运行中会话的模型热切换承诺（新目录在刷新 / 新打开后生效，如实标注）。
- models.json 注释在保存后不再保留（Pi 解析支持注释，写入为标准 JSON）；如实记录，不做注释保真。
