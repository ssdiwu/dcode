# D Code 0.0.38 工作台体验与 ZCode 共享界面借鉴产品需求

状态：507 于 2026-10-02 确认将 ZCode 对照的十项能力全部纳入后续 1～2 个版本，并允许对普通 UI／UX 大量借鉴、包括许可适用的源码级组件移植。本次按依赖分为 `0.0.38`、`0.0.39`；本文件拥有前者的需求与验收，[0041](0041-0.0.39-可复用工作流终端与定时自动化产品需求.md)拥有后者。当前只有规划，未开始新增实现；工程基线为当前 `0.0.37` 未提交组合候选，缺失的独立 0.0.35／0.0.36 人工验收不由本规划追认。

## 问题与目标

现有 D Code 已有任务／会话、消息队列、附件预览、结构化变更、模型调用和任务内工作流事实，但长对话定位、每轮文件结果、队列集中呈现、分组浏览和历史用量仍不够方便。用户希望日常工作台达到 ZCode 的信息层级、操作反馈和组件完成度，同时继续使用 D Code 的产品对象。

本版让用户在同一工作台完成“找到一段要求 → 核对本轮文件 → 管理待发送消息 → 预览附件 → 找到任务和运行记录 → 看清本机历史调用”。视觉与交互作为交付内容同步验收，每个入口使用真实 D Code 数据。

| Z15 | App 内统一附件预览 | 查看图片、PDF 和可解码视频的文件名、类型、加载与失败状态，返回原草稿。 |

### 当前对话内查找

1. 入口明确为当前 Session 的当前可见路径，不跨 Task、其他会话或已隐藏历史路径。支持关键字输入、命中总数、当前命中、上一处／下一处、Enter／Shift+Enter 和 Escape；在对话有焦点时支持 `⌘F`，不抢占文件编辑区或终端的键盘行为。
2. 首版默认检索用户输入与助手可见正文，包括可见代码块；附件内容、工具日志、隐藏推理、系统提示词和未加载内容不伪装为已经搜索。覆盖不足时说明范围并提供继续加载历史的操作；空结果只代表实际已查范围。
3. 命中绑定原消息和路径身份。流式追加、历史补加载、筛选、折叠和中英切换不能将当前位置静默移到另一条消息。UTF-8／Unicode、大小写及 Markdown 可见文本与高亮范围必须一致。
4. 查找和关闭只改变阅读状态，不重建 Task／Session、不启动模型、不覆盖输入草稿。离开当前路径清除其临时高亮，回到原阅读位置的行为可核对。

### 本轮只读文件摘要

1. “本轮”绑定明确的 Session Run；成员结果使用其实际 Task／Agent Run／Session Run 来源，不能把当前工作区所有 Git 改动都归为当前协调者本轮成果。
2. 展示已确认的文件、操作来源和可查证差异。相同规范路径合并文件行，必要时保留多次操作来源；只有有界前后版本足以证明时才显示本轮净增删行数，否则显示未知。多次 edit 的行数累计不得冒充最终净差异。
3. 区分已知 edit/write 变更、命令或手工操作的覆盖缺口、以及另行打开的当前 Git 差异。没有记录、读取失败、来源变化与已证明没有改动分别呈现。
4. 文件、Diff、报告或证据继续使用既有来源和目录身份校验。摘要不提供文件撤回／覆盖／回滚动作，不自动添加长期上下文，不从模型自述补造改动或行数。

### 队列集中呈现

1. 面板靠近当前 Composer，按实际目标会话／成员展示待发送、暂停、正在交付、失败和中断；已送达与待送达不混用同一种可编辑行。
2. 保留现有发送时机、暂停、恢复、编辑、取消和重排合同。编辑已排队消息先取得真实暂停／保存结果，提交原文及修改来源仍可回查；操作期间只锁相关对象，错误不丢失原草稿。
3. 支持键盘和按钮排序，拖动作为等价操作；顺序和 revision 冲突以 Host 为准，冲突时重读并保留用户修改。后台更新不偷偷改变用户正在编辑的文本。
4. “补充当前工作”沿用安全边界介入语义，不复制 ZCode stop 当前运行后发送所选项的副作用。界面不因组件存在而新增未知成员或重复发送已完成消息。

### 统一附件预览

1. Composer、消息、工作流产物和生成图进入一致的预览结构：名称／类型、内容区、关闭与可用动作；受管附件和不可变 Artifact 保持各自身份及到期规则。
2. 图片完整适配可视区域，PDF 可切页和调整阅读比例，可解码视频提供播放控件。加载、到期、不可读取、不支持格式／编码与损坏分别给出可行动状态；仍可使用受控系统预览／打开入口。预览格式与模型接收能力分别标识，能预览不等于能作为该模型的输入；不因预览移植改变附件提交语义。
3. 格式组件按需加载，单个预览失败局限于当前内容，不阻断主对话或设置。窗口内预览继续服从受管文件、默认网络限制、脚本隔离及凭据保护，不把文件 URL 扩成任意读取入口。
4. 预览不修改文件、不调用模型、不改变普通草稿、附件引用或任务焦点；关闭回到触发控件，键盘、VoiceOver（旁白）、浅深色和大字号可用。

### 分组任务与长列表

1. 分组属于一个 Project Scope 或当前用户的 User Scope；用户任务仍直接列在“任务”分区。分组只组织同一批 Task 的显示，不能成为 Project 与 Task 之间的新产品身份层。
2. 可新建、重命名、排序、折叠和删除分组；同一 Task 在其所属范围中最多归一个自定义组，未归组者显示在默认列表。支持把任务移到同范围另一组以及组内排序，键盘／菜单／拖动操作等价。
3. 删除组只解除分组，不删除、归档、迁移或复制任务及其会话。拖动不得改变 Task Scope、项目目录或执行目录；跨作用域目标拒绝并保留原顺序。
4. 分组、折叠与顺序由产品偏好持久化；搜索、最近入口和成员回跳仍能定位同一 Task。外部导航到折叠组中的任务时可看见并定位该任务，不能因为虚拟行未挂载就丢失当前项。
5. 大列表按同版本、同数据、同机器的可复验样本验证。列表优化保持滚动、选择和无障碍语义；本版必须交付长列表路径，不以“还未遇到卡顿”为由漏掉已选范围，也不凭采用某库宣称变快。

### 本机历史用量

1. 统计只使用 D Code 已持久化的实际模型调用，按调用身份取其最新状态；普通任务调用与上下文整理均可查，不能因阶段更新、回退记录或多次刷新重复累计。
2. 首版提供最近 7 天、30 天、全部，以及全部本机任务／指定项目、模型的筛选；展示调用次数、已知输入／输出／缓存及总 tokens、每日趋势和模型分布。使用界面明确的本机时区划分日期，刷新时间和范围可见。
3. 缺 usage、失败／中断或旧导入覆盖不足保持未知，并提供统计覆盖说明。开始但未完成的调用不能给出已知最终消耗；没有费用或账户归属依据时不显示实际账单、免费或当前订阅余额。
4. 当前上下文圆环、历史累计调用与账号配额分别命名和呈现。SDK cost 只有来源／估算口径成立才可显示；Codex 生图用量未知不折算成聊天 tokens 或账单。
5. 数据查询按时间／范围有界，切换筛选后旧项目图表不冒充新结果；图表延迟加载并有局部错误状态，不影响发送和其他工作台操作。

### 同任务工作流历史

展示同一个 Task 的所有可读取 Workflow Run，保留各次使用的版本、阶段、状态、起止时间、报告和产物。用户能返回原 Task／Session／运行来源；旧执行不因为新版本或新报告出现而改写。只有具备完整来源和读取权限的对象提供操作，缺失或不可恢复给出原因。本版不定义跨 Task 模板或全局运行汇总，它们由 [0041](0041-0.0.39-可复用工作流终端与定时自动化产品需求.md)拥有。

| 区域 | 应借鉴的普通模式 | D Code 中的适配依据 |

| 导航与任务行 | 分组头、选中、悬停、状态、菜单、虚拟列表和定位 | Project／User Scope → Task 主干、同一任务身份和可恢复阅读位置。 |
| 顶部与输入区 | 标题截断、动作密度、加号分区、检索候选、快捷键提示、队列、附件和模型选择 | `/` 技能、`@` 项目文件、`$` 同任务已创建成员；原文与生效输入分开。 |
| 对话与过程 | 轮次层级、查找、高亮、简短工具摘要、文件结果与渐进展开 | 真实 Run／工具／来源事实；最终结果优先，未知不显示成功。 |
| 概览与检查器 | 成员胶囊、工作流阶段、对象信息、历史行、产物入口和预览布局 | 任务概览浮层与持续检查的右栏职责、一个对象一份编辑状态。 |
| 设置与通用反馈 | 分类、行布局、选择器、表单、空态、加载、错误、确认和保存反馈 | 原生账号／模型／能力、专用凭据通道、统一中文／English 偏好。 |
| 全局视觉细节 | 字重与字号层级、间距、圆角、分隔、图标、明暗主题及克制动效 | D Code 品牌、macOS 语义、减少动态效果和现有共享几何／焦点规则。 |

这是正式交付范围，可按已核许可逐文件移植共享 React 组件和辅助函数，不仅做截图参照。移植必须登记来源和修改、带齐适用许可证／NOTICE；素材独立许可逐项核对。ZCode 的品牌资产、收费／闲时后台、增长入口、远程／Windows 服务、数据格式、Runtime 与权限模式不随视觉借鉴进入 D Code。界面只列已接通或能明确说明不可用原因的真实能力。

## 已确认约束

- Product Store 与 Host 继续拥有事实和写入；界面组件消费 D Code 投影，不能导入第二份产品库或绕过可信 IPC。数据归属、会话／成员、创建／发送和外部副作用保持当前公开合同。
- 中英界面与下一轮沟通语言、用户自定义内容、历史原文、共享焦点、macOS 平台、目录身份和敏感信息边界继续生效。采用 ZCode 外观不覆盖 D Code 当前设计职责。
- 提交原文、模型输入、工具结果、净文件差异、估算用量、实际账单和用户验收分别成立。已保存操作后的读取失败只提示同步问题，不能重复提交或抹掉已确认结果。
- 本文件写需求和验收，具体模块／库选取以总复杂度与真实验证决定；[来源对照](../参考文件/ZCode-组件清单与-D-Code-对照-2026-09.md)供移植核验，不替代需求。

## 验收标准与公开接缝

- [ ] 在真实工作台完成查找、历史补加载、高亮导航、路径切换和关闭；长消息、Unicode、中英、Markdown 与流式追加匹配原消息且草稿保留。
- [ ] 用本轮已知 edit/write、多次修改同文件、无记录、并行成员、手工 Git 变更和来源失效样本核对摘要；文件身份／净差异／覆盖说明正确，没有文件写入或伪造行数。
- [ ] 真实队列的等待、暂停、编辑、取消、恢复、键盘／拖动重排、保存后读取失败和重启恢复通过，只有一份耐久提交，不把 stop-and-send 当 steer。
- [ ] 图片、PDF、可解码视频、不支持／到期／损坏内容分别走预览路径；错误局限于当前内容，键盘／旁白、明暗、大字号和焦点恢复通过。
- [ ] 建组、移动任务、排序、折叠、搜索回跳、删除组、归档恢复和重启保留完整通过；跨 Scope 拖动拒绝且 Task／Session／目录均不变。
- [ ] 固定的大列表样本、操作与工程基线至少覆盖 1000 个 Task、20 个组、已有子会话、两种语言及不同窗口；记录布局／定位、交互耗时与内存，改善目标按同环境基线核定，达标后不扩大无具体疑点的测试。
- [ ] Host 持久化调用到 UI 统计的完整路径验证去重、时间／范围、摘要调用、失败与缺失覆盖；不同筛选不会串线，费用／上下文／配额未被混用。
- [ ] 同 Task 多个 Workflow Run 可各自回到原版本、报告及产物；旧记录和新运行分开，查看历史不启动、停止或复制运行。
- [ ] UI 借鉴在导航、输入／菜单、对话／过程、概览／检查器、预览和设置均形成可见结果；正常、加载、空、失败、禁用、键盘、浅深色、中英、窄窗和减少动态效果按实际路径检查，登记来源／许可。
- [ ] 项目必要检查、`507-review` 只读交付审查、独立 `0.0.38` 本机候选、包体／握手／关于页同号核验与实际窗口分别完成。新增字段迁移／备份／回退边界验证，旧用户数据不因界面移植被覆盖。

## 非目标

不新增文件撤回／自动覆盖，不搜索隐藏推理或任意其他任务，不通过 UI 重建运行成员，不迁入 ZCode 的服务和产品库，不开放新收费／账号／远程业务，也不提前提供 [0041](0041-0.0.39-可复用工作流终端与定时自动化产品需求.md) 的可运行入口。
