# D Code 0.0.6 活动视图与运行状态产品需求

状态：Planned（下一版已确认范围；以 `v0.0.5` 为发布基线，功能实现尚未开始）

本 PRD 冻结 `0.0.6` 的新增范围与验收边界；活动投影、运行事实与用户关注态的边界以 [ADR 0012](../决策档案/0012-活动视图与用户关注状态.md) 为准，`0.0.5` 的 Follow-up Queue（后续消息队列）所有权继续由 [ADR 0011](../决策档案/0011-后续消息队列所有权与派发边界.md)约束。`0.0.6` 不改变 Pi Session 的会话权威，也不提前引入后台多会话执行。

## Goal（目标）

让用户不用逐个打开会话，就能在会话栏中看见当前 D Code 正在执行什么、哪些结果刚刚完成但尚未查看、哪些运行正在等待自己，并能回到原会话继续处理；同时把当前 Session 的活动、后续队列、等待输入、停止与重试收敛到 Composer 附近的连续控制面。

本版成立后，默认会话导航继续回答“我的会话在哪里”，Activity View（活动视图）则回答“现在有什么在发生、什么需要我注意”。两种视图是同一批可见 Pi Session 的不同投影，不创建第二套会话、页面或任务数据库。

## Problem（问题）

- 默认会话栏按置顶、Recent Sessions 与 Project 组织，适合导航，但不能突出当前运行、刚完成结果与等待用户处理的状态。
- 只在当前 Conversation（会话主页面）显示流式状态，用户必须先知道该打开哪个会话，无法快速发现新完成结果。
- Session 的文件更新时间只能证明内容发生过变化，不能证明 Agent 正在运行、正常完成、失败或等待；以时间猜测运行状态会制造虚假事实。
- `0.0.5` 已建立队列与最小收口门禁，但当前活动、等待输入、停止、重试和队列状态仍分散，用户不能在一个连续表面内判断下一步。

## Scope（范围）

### 1. 会话栏双视图

- Session Sidebar（会话栏）默认继续显示既有导航视图：全局置顶、Recent Sessions 与 Project。全新启动默认进入该视图。
- 会话栏标题区在搜索旁提供铃铛按钮。点击后切换到 Activity View；再次点击返回默认导航。切换只替换会话栏列表内容，Main Workspace（主工作区）、当前 Conversation、Workspace Tab、Composer、信息检查器、Session / Path、滚动位置与草稿均保持不变。
- Activity View 不是 Workbench Page、标签、Sheet、信息检查器页面或第二个 macOS 窗口。铃铛选中态和 VoiceOver 标签必须明确当前正在查看“活动”。
- Activity View 只使用 D Code 当前可见会话集合，不因活动状态扩大 Recent / Project 的来源资格，也不暴露未关联的旧 Pi Session。

### 2. 活动优先级与时间排序

- Activity View 顶部依次显示：正在等待用户输入或权限决定的当前运行、D Code 当前实际拥有的运行中 Session、已有新完成结果但尚未查看的 Session。每项必须同时提供非颜色状态文案或可访问标签。
- 新完成结果使用蓝点作为紧凑关注标记。蓝点只表示“该 Session 最新的完成结果尚未在 Conversation 中呈现给用户”，不表示运行成功、仍在执行或存在未读聊天消息。
- 失败、中止与需要用户处理使用各自语义明确的状态，不以蓝点或永久加载圆环代替。完成结果被查看后，该项仍可留在时间列表，但不再显示蓝点。
- 其余可见 Session 按最后可证明的活动时间倒序排列，并以“今天”等时间分组增强扫描。置顶只影响默认导航，不打乱 Activity View 的时间顺序。
- 没有可靠 Run 事实的历史 Session 只能按 Pi Session 的持久化更新时间进入普通时间列表，不得仅凭文件修改时间推断“运行中”“等待”或“刚完成”。时间相同使用稳定 Session ID 形成确定顺序。
- 本版借鉴 Otty 左侧栏对活动与时间的扫描效率，但不提供 No Grouping / By Project / By Date、Created / Updated / Manual 等通用配置矩阵，也不提供手工 Divider。Activity View 的固定顺序属于 D Code 产品语义；默认导航继续承担 Project 与置顶组织。

### 3. 完成关注态

- D Code 为完成关注态保存最小、版本化的本机记录，以稳定 Session ID 和稳定 Run / 完成身份区分不同结果；记录只包含判断是否已经呈现所需的身份、状态与时间，不复制消息正文、Thinking、工具结果或凭据。
- 新完成结果在真实完成证据成立后进入“尚未查看”。仅打开 Activity View、悬停条目、键盘聚焦或看到通知摘要不会清除蓝点。
- 用户选择对应 Session，且最新完成结果已经在 Conversation 中成功加载并可见后，才把该完成身份标记为已查看。App 重启后该状态保持，不会让已查看结果重新变蓝，也不会丢失尚未查看结果。
- 同一 Session 后续产生新的完成身份时可以再次出现蓝点；旧完成身份被查看不能清除更新结果的关注态。

### 4. 运行事实与 Interaction Dock（交互坞）

- Run State（运行状态）必须来自 D Code / Host 能证明的 Session Run 生命周期、等待请求、失败或持久化完成事实，不能从 Session 摘要、动画时长或界面是否打开推断。
- Composer 附近的 Interaction Dock 把当前活动、Follow-up Queue、等待用户输入或权限决定、停止、继续与安全重试收敛到一个连续控制面；队列正文与所有权仍服从 `0.0.5` 合同。
- 停止只能针对当前 D Code 实际拥有的运行；停止请求、运行真正停止和消息持久化是不同事实。结果未知时必须停住并说明，不能把按钮点击立即显示成已经停止或可以安全重试。
- 等待用户输入或权限决定时，专用请求继续使用对应结构化界面回复，普通 Follow-up Queue 不截获答案。完成决定后才根据真实 Run 状态恢复或收口。
- Activity View 中选择当前运行 Session 回到其 Conversation。当前架构仍只有一个活动 Session；运行期间其他 Session 可以保持可见，但若无法安全切换，界面必须说明需要先完成或停止当前运行，不能伪装后台继续执行。

### 5. 单运行边界与未来生长

- `0.0.6` 不新增后台多 Session Runtime、多 Agent、跨 Session 消息或调度器。Activity View 首版最多显示一个由当前 D Code 实例实际拥有的运行中 Session，以及已有可靠完成、失败、等待或时间事实的其他可见 Session。
- 外部 Pi CLI、另一 D Code 实例或其他 Agent 产品的活动，除非以后建立可验证的共享运行协议，否则不得显示成“正在运行”。
- 将来引入后台多会话执行时可以复用 Activity View 的分组和关注语义，但必须另行定义并发所有权、资源、切换、通知与恢复合同。

## User Stories（用户故事）

1. 作为同时保留多个会话的用户，我希望点击铃铛后立即看到当前正在工作的 Agent，而不是在 Project 列表里寻找。
2. 作为切去处理其他事情的用户，我希望刚完成的新结果出现蓝点，并在真正看到最终结果后自动消除。
3. 作为遇到权限请求、问题或失败的用户，我希望活动视图明确告诉我需要做什么，而不是把它和正常运行混成同一种圆环。
4. 作为仍习惯按 Project 和置顶导航的用户，我希望随时切回默认会话视图，且原来的组织方式不被时间排序取代。
5. 作为连续安排后续消息的用户，我希望在当前会话的 Interaction Dock 中同时看到正在做什么、下一条是什么以及为什么停住。

## Confirmed Constraints（已确认约束）

- Pi Session 继续拥有会话、消息和持久化历史；Activity View 是可重建投影，完成关注态是 D Code 最小本机 UI 状态。
- 会话可见资格继续服从 D Code Session Origin、Project / Source Folder 与 Archive 规则；活动状态不绕过这些边界。
- 一个 D Code 实例同时只有一个活动 Session 写入所有者，不支持在途模型生成、工具执行或阻塞交互的热迁移。
- 蓝点及其他状态不能只靠颜色；VoiceOver 必须读出“正在运行”“需要处理”“有新完成结果”“失败”等真实语义。
- 状态记录不得包含 API key、OAuth token、认证文件正文、隐藏 Thinking、完整工具结果或会话正文副本。
- 默认导航与 Activity View 使用同一会话行身份和选择合同；切换视图不创建 Session、不改变 Path、不发送消息，也不清除 Composer Draft。

## Acceptance Criteria（验收标准）

### 会话栏与排序

- [ ] 全新启动仍显示默认会话导航；点击搜索旁铃铛后，只把会话栏列表切换为 Activity View，当前主工作区、Session / Path、打开标签、滚动位置和逐字草稿保持不变，再次点击可原样返回。
- [ ] 当前 Run、一个尚未查看的已完成 Run 与多个普通历史 Session 同时存在时，Activity View 依次显示运行项、新完成项和按最后活动时间倒序的其余项；置顶不会改变该顺序。
- [ ] 只有可靠 Session 时间而没有 D Code Run 证据的历史项不显示运行、等待或新完成状态；相同时间排序稳定。
- [ ] Activity View 与默认导航的可见 Session 集合一致，归档、不可见旧会话和未关联来源不会因活动列表泄漏。

### 蓝点与关注态

- [ ] 当前 Run 正常完成并形成新的稳定完成身份后，对应 Session 出现带有可访问文案的蓝点；仅打开 Activity View、悬停或聚焦不会清除。
- [ ] 打开对应 Session 并成功呈现最新完成结果后蓝点消失；重启 App 后已查看结果不重新出现，尚未查看结果仍保留。
- [ ] 同一 Session 产生更新的完成结果后再次出现蓝点；查看旧结果不会误清除更新结果。
- [ ] 失败、中止、等待输入和等待权限具有不同的非颜色状态，不被蓝点或永久“运行中”动画掩盖。

### 运行控制与真实性

- [ ] Interaction Dock 能同时说明当前活动、Follow-up Queue 队首、等待原因与当前可执行控制；状态变化不会重复发送 Queue Item 或改写 Pi JSONL。
- [ ] 停止、继续和重试只有在对应真实门禁成立时可用；请求停止但尚未确认、派发结果未知或 Lease 冲突时显示真实中间状态并阻止不安全继续。
- [ ] 当前 Run 执行期间其他 Session 仍可在 Activity View 中被看到；不能安全切换时选择动作给出明确原因，不声称当前 Agent 已转入后台。
- [ ] 外部活动或 Session 文件更新时间不会被误报为当前 D Code 正在运行；本版任何时刻最多有一个本实例拥有的运行项。
- [ ] 键盘、VoiceOver、Reduce Motion 与 Increase Contrast 下，铃铛切换、列表状态、蓝点语义和 Interaction Dock 操作均可完成并辨认。

## Out of Scope（非目标）

- 后台多 Session 执行、同时拥有多个 Pi Session Runtime、运行中热切换与跨实例共享活动。
- Goal / Work Map、D Team、多 Agent 成员活动、跨 Session 消息、定时任务与通知中心。
- 把 Activity View 做成新的主页面、Conversation 标签、信息检查器页面、Sheet 或第二窗口。
- 以文件更新时间、旋转动画、界面焦点或超时猜测运行成功、失败、等待或完成。
- 改变 `0.0.5` Queue Item 的所有权、派发顺序、正文范围或幂等合同。
- 把 Otty 的通用 Tab 分组 / 排序器、手工 Divider、终端 Outline、Process 或 Ports 面板加入本版；右侧可信快捷动作、Exact Git Diff 与文件编辑继续服从既定后续版本边界。
