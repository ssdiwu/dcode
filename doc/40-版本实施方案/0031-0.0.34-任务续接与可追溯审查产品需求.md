## 问题与单一用户结果

一个 Task 可以跨多段 D Code Session、多个 Agent Run 持续推进。用户回到任务时，需要知道已确认什么、什么尚未完成，以及结论来自哪里；Agent 也需要按当前问题找到相关的旧对话、项目资料和灵感。现有任务、会话、灵感版本引用、文件差异、团队报告与验收事实已经各有归属，但缺少一条连贯的续接与回查路径。让用户反复转述历史，或只给一段无法点回原文的摘要，都不足以支撑长期工作。

本版交付一个完整结果：**用户回到同一 Task，D Code 有来源地接续已有工作；修改产生后，审查发现沿原工作项得到有限返工与复查，用户能从结论回到原始材料和证据。** 任务对话仍是主入口，任务浮层展示进度、成员与报告，信息检查器承载具体来源、文件与差异；不另建任务类型或平行工作台。

## 用户路径与行为

### 1. 接续同一 Task

1. 同一 Task 开始新会话，或因上下文压缩、成员进程回收后重启而需要续接时，D Code 自动准备一份有界的任务工作摘要，默认供该次续接使用；同一会话的普通连续轮次不重复注入摘要。摘要区分已确认决定、未完成工作、阻塞与下一步，关联原始消息、任务事实、报告和证据；生成时间与来源可查看。摘要是可修订的投影，不覆盖提交原文、历史消息、任务决定或证据。
2. 用户能查看、纠正摘要中的错误或过时判断。纠正留下新的来源与修订关系；不能悄悄改写曾经传给模型的生效输入。摘要缺失、生成失败或来源无法核实时如实显示，不能把上次生成的文本冒充当前事实。Agent 仍可按有权限的原始来源继续工作。
3. 不因为换会话、压缩上下文或成员进程回收就创建第二个 Task、重做已完成操作，或声称消失的模型生成和工具执行已恢复。运行开始时采用的摘要版本与预置来源可从生效输入及回执检查；运行中按需召回的来源由实际读取与引用记录核对，不倒填进启动前的回执。

### 2. 按需召回并引用来源

1. Agent 可在当前 Task 的历史和事实、所属 Project 的可访问资料、507 的全局 Inspiration 中，主动查找与眼前问题相关的内容；其他 Project 的历史会话不属于默认自动召回范围。只读取有界结果，按来源职责与新旧版本判断相关性，不把整库或全部历史静默塞进系统提示词。
2. 自动查找是本次工作的按需读取，不会因被检索到就永久加入 [Task Context Selection（任务上下文选择）](../决策档案/0041-任务上下文选择与-Product-Store-schema-演进边界.md)。用户或明确的 Task 合同选定具体来源版本后，才形成持续生效的任务上下文引用；强制 `AGENTS.md` 与既有显式来源加载规则保持有效。候选结果与真正交给 Agent 使用或在回答中引用的来源必须可区分。
3. 引用灵感时保留稳定节点身份与实际使用的内容版本。会话、项目文档、文件、报告和证据的引用同样保留可核对的来源身份及适用 revision；助手消息、摘要和报告中的引用可以点击，回到对应原文或原始对象。灵感后来编辑时，旧引用仍指向旧版本，并可说明当前版本已不同；不能拿新正文冒充当时所读内容。
4. 来源已归档、移动、删除、无权读取或当时版本不可恢复时，链接给出真实状态和仍可核对的来源信息，不静默跳到同名文件、当前任务或最新版本。检索不到合适材料时，Agent 应说明依据不足，不制造“记得你说过”的结论。

### 3. 在原任务中审查与有限迭代

1. 用户可从当前 Task 的文件差异或相关 Work Item 发起代码审查；协调者也可在已有任务授权内按需要安排审查。审查绑定明确的变更范围与当时版本，结果进入该 Task 既有 Finding、Agent Report 和 Evidence 关系。需要独立判断时由不同于执行者的 Agent Run 检查；主对话呈现简洁结论与来源入口，完整成员过程留在 Child Agent Session。
2. 审查发现具体问题后，协调者沿受影响的 Work Item 安排修改、检查和必要的独立复查。每轮能看出目标、实际变更、检查结果与剩余问题；已通过且未受影响的工作项不无故重做。没有新的事实或范围收窄时，遵守[既有两次无进展停止规则](0029-任务内自适应协作产品需求.md#独立验收复核与返工)，改变方法、重新分工或在真正改变目标、成本、风险时请用户决定。
3. 一次审查通过或自动检查通过不自动成为协调复核、用户接受、Git 提交或发布。未知外部副作用不自动重放；停止、失败、额度不可用与重启后的续接均显示真实状态。迭代服务 Task Goal 与验收条件，不建立无限运行的第二个 loop 引擎。

### 4. 在现有工作台中呈现

- 任务对话展示本次续接实际采用的摘要与关键引用；任务浮层继续负责工作项、团队、等待事项及报告。查看摘要或引用不抢占正在运行的成员。
- 文件、差异、灵感版本、报告及其他需要连续阅读的来源使用既有内容打开规则；进入子会话时保留来源成员与原任务归属。会话搜索、文件导航、上下文构成和报告入口共同服务“找到来源并返回当前工作”，不增设四套平行导航。
- 上下文构成区分显式选定来源、自动召回后实际使用的来源与未采用的候选；只显示可证明的使用事实和估算，不能把搜索命中数写成已注入内容，也不能把摘要写成原始消息。

## 已确认边界

- D Code Product Store 拥有 Task、D Code Session、摘要修订、来源关系、Agent Run、Report 与 Evidence；Pi SDK 和被参考扩展只提供运行或机制来源，不成为持久数据、界面或必须安装的依赖。参见 [ADR 0037](../决策档案/0037-D-Code-原生产品数据权威与-Pi-单向导入边界.md)。
- 提交原文、生效输入和上下文投影保持分离；自动摘要与召回不得原位覆盖用户输入。Project 文件与一等文档以原位置的当前文件为正文权威，历史来源可否重建须如实表达。
- 任务内成员、报告、验收、局部返工及进程边界继续由 [PRD 0029](0029-任务内自适应协作产品需求.md) 与 [ADR 0045](../决策档案/0045-任务内自适应协调与智能体进程边界.md) 拥有。本版补齐连续体验与可回查来源，不重定义团队所有权或验收状态机。
- 本版消费 [PRD 0032](0032-0.0.33-协调者按需探索与路线选择产品需求.md) 已保存的任务路线、反证、采用依据和失效关系。自动摘要与召回保留其来源、版本和适用边界，被否定或已失效的路线不得因摘要或召回再次成为当前决定；路线选择规则仍由该规格拥有。
- 默认自动召回只在当前 Task、所属 Project 和全局 Inspiration 内工作；来源读取仍遵守已有作用域、访问、脱敏与凭据边界。只读查找不授予写入、跨项目工作或外部副作用许可。

## 验收标准

- [ ] 已有 Task 包含两段会话、成员报告、未完成工作项和用户更正。新会话、上下文压缩后继续及成员进程回收后重启时默认得到有来源的任务工作摘要；普通连续轮次不重复注入。查看并修正后再次续接，当前版本与旧运行实际采用版本均可辨认，原始消息及证据字节不被覆盖；曾被否定或已失效的路线保留反证与版本，不被摘要或召回表述为当前已采用路线。
- [ ] 在同一 Task 中提出一个需要回忆的问题，Agent 从本 Task、所属 Project 与全局 Inspiration 中找到相关材料并引用实际使用版本；未使用的检索候选不列为本次上下文。另一 Project 的历史会话不被默认召回，选定来源列表不因查询而暗中增长。
- [ ] 一条灵感在引用后又被编辑。点击旧会话或报告中的引用仍看到当时版本，并能辨认新版本；会话消息、项目文档、文件行和报告引用也回到正确对象。来源缺失或历史版本无法恢复时明确显示原因，不替换为同名或最新内容。
- [ ] 从当前任务的 Git 差异发起审查，结果关联确切变更范围、独立检查者、发现与证据；主对话能进入报告与成员会话。故意引入一项问题后，只有受影响工作项返工并复查；连续无进展触发方法调整，不无限重试。
- [ ] 从任务浮层、消息引用、会话搜索和文件导航进入相同来源时，任务、会话、文件与版本归属一致；返回当前工作后草稿和其他成员运行不被改变。键盘、深浅主题及窄窗口下来源入口仍可使用。
- [ ] 摘要生成或可选召回失败、检索无结果、来源不可访问、审查中止、进程回收及重启时展示真实状态。强制规则或显式选定来源加载失败继续按既有合同阻止运行；可选召回失败不能伪装成功或覆盖原有任务数据。
- [ ] 真实客户端走通“继续旧 Task → 查看并修正摘要 → 引用旧灵感并回到原文 → 修改文件 → 审查 → 局部返工与复查 → 用户验收”的完整路径；自动测试、实际窗口检查、507 人工验收、提交及发布分别记录。

## 非目标与交付边界

- 不接入 Remnic、Magic Context、pi-agenticoding、pi-agents-team 或 pi-agent-extensions 作为 D Code 运行依赖；不共享其他产品的记忆数据库，也不引入固定七角色、Pi TUI 或通用工作流编辑器。
- 不自动把召回结果永久写入 Task Context Selection，不跨所有 Project 自动搜索会话，不把隐藏推理、完整子对话或全部知识库灌进协调会话。
- 不新增 Git 自动提交、合并、推送或发布权限；不把审查、复核或测试通过当成用户验收。
- 本版按可独立验证的能力逐步接通来源回跳、续接召回及审查返工，最后以同一条完整用户路径验收。未通过的中间候选不替换上一可用候选，也不因本规格落盘修改当前构建号。
