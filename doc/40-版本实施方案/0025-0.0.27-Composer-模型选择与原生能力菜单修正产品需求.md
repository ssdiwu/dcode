# D Code 0.0.27 Composer 模型选择与原生能力菜单修正产品需求

状态：Published Source Tag（公开源码标签 `v0.0.27`；自动回归通过；原生菜单鼠标、键盘、VoiceOver 与深浅色人工验收待完成）

本 PRD 修正 `0.0.25` 对 Composer 控制行的误读，并以 [ADR 0033](../决策档案/0033-Composer-模型选择与原生能力菜单边界.md) 固定控件边界，以 [ADR 0034](../决策档案/0034-Composer-剪贴板图片与-Skill-展示边界.md) 固定剪贴板图片与 Skill 展示边界。Project 目录迁移、图片发送协议与模型设置事实源不变。

## Problem Statement（问题陈述）

`0.0.25` 把“去掉模型前图标与外露下拉箭头”错误实现成“删除整个模型选择器”，导致主页和会话 Composer 只剩推理强度，用户无法在开始工作的位置选择模型。

同一版本把 `+` 实现为固定 `300pt` 的自绘 Popover，并在其中叠加标题、padding 与默认胶囊按钮。结果更像一张设置卡片，而不是参考界面的紧凑 macOS 菜单；首项还会出现突兀的蓝色焦点环。

后续实机对照又暴露两项输入回归：Composer 的 NSTextView 没有把剪贴板图片桥接到既有附件状态机；Skill 同时来自 `session.getCommands` 与 `resources.list`，前者被误归为普通命令，导致菜单暴露 `/skill:`，并可能使技能子菜单为空。

## Solution（解决方案）

1. **恢复独立模型选择。** 控制行在推理强度左侧显示当前模型名；点击打开按 Provider 分组的真实模型目录。新会话调用草稿模型选择，已有会话调用 Host `session.setModel`。
2. **模型与推理目录同步。** 已有会话切换模型成功后，立即清除旧推理档位，并重新读取 Host state、模型目录与当前模型支持的 Thinking levels；加载失败时不得继续展示旧档位。
3. **只移除装饰。** 模型入口不显示 CPU / 芯片图标或外露 `▾`；模型、推理强度与速度保持彼此独立，不恢复旧的组合菜单。
4. **`+` 使用原生 Menu。** 删除 `showingAddActions`、面板标题、固定宽度与 Popover；顶层 `+` 直接声明系统 Menu。
5. **能力范围不变。** 菜单只包含添加文件或图片、技能子菜单、命令子菜单、目标与计划；没有插件、扩展、本机资源、网页预览或浏览器控制。
6. **交互保持原生。** 系统负责菜单关闭、子菜单、键盘、焦点和 VoiceOver；选 Skill / 命令 / 目标 / 计划只预填 Composer，不自动发送。
7. **Skill 只显示用户名称。** 两条真实数据来源统一识别 Skill；菜单和 `/` 面板显示 `507-breakdown` 与说明，不显示 `/skill:507-breakdown`，实际预填仍保留 Pi 可执行的内部调用语法。
8. **图片可直接粘贴。** Composer 拦截 PNG、TIFF 等剪贴板图片与全部为图片的 file URL，转入既有附件 chip；同一图片的多种表示只消费一次，纯文本仍原生粘贴。
9. **运行中仍可调整。** 普通 Run 或工具执行期间，模型、推理强度与速度仍可修改，选择从下一次安全模型边界生效；Prompt / Steer RPC 在途、结构化等待、停止中、结果未知、压缩、迁移、冲突或重启准备期间才禁用。
10. **Fast 服从真实能力。** 只有 Host 明确标记支持 Fast Mode 的 OpenAI 模型显示独立“速度 · 标准 / 极速”菜单；切到不支持的模型会清除极速状态，切回时保持标准，不留下隐藏意图。

## Acceptance Criteria（验收标准）

- [x] Composer 控制行显示当前模型名或“选择模型”，点击可访问真实模型目录。
- [x] 新会话模型选择调用现有草稿状态；已有会话模型选择调用现有 Host 切换动作。
- [x] 已有会话切换模型后重新加载 Thinking levels；旧模型档位不会残留为可操作选项。
- [x] 模型入口没有 CPU / 芯片图标和外露下拉 glyph；推理强度仍在旁边独立显示。
- [x] `+` 使用原生 Menu，不存在自定义 Popover 状态、标题、固定 `300pt` 宽或面板式 padding。
- [x] `+` 内容与顺序为文件或图片、技能、命令、目标、计划；不出现被排除能力。
- [x] `session.getCommands` 与 `resources.list` 的 Skill 均显示普通名称、说明和“技能”类型，不在列表或悬停说明中暴露 `/skill:`；选择后仍形成可执行预填。
- [x] PNG / TIFF 剪贴板图片转为一张既有附件，正文不出现 U+FFFC 替代字符；纯文本不被图片分支消费。
- [x] 普通在途 Run 与工具执行不再锁死模型、推理强度和速度；不安全状态仍由同一专用门禁阻止。
- [x] Fast 只在 Host 证明支持的 OpenAI 模型显示；支持模型可选标准 / 极速，切离支持模型后状态归一为标准。
- [x] 回归测试锁定模型入口与原生菜单源码合同；既有模型状态、命令分类、附件和 dgoal 渲染测试通过。
- [ ] 在真实 `D Code.app` 中人工核对菜单外观、鼠标、方向键、Return、Esc、VoiceOver、深浅色和 Increase Contrast。

## Out of Scope（非目标）

- 恢复 CPU 图标、外露 `▾`、旧组合菜单，或在 Host 不支持的模型上显示 Fast。
- 改写 Pi 模型目录、认证、Provider 设置或 Session 模型协议。
- 把插件、扩展、本机资源、网页预览或浏览器控制加入 `+`。
- 用自绘菜单皮肤复刻其他产品；容器与行为继续由 macOS 原生 Menu 提供。
- 仅图片无正文发送、图片拖放、附件持久化或进入后续消息队列。
