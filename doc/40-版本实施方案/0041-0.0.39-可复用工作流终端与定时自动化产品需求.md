# D Code 0.0.39 可复用工作流、终端与定时自动化产品需求

状态：507 于 2026-10-02 确认十项 ZCode 对照能力全部进入后续 1～2 个版本；本次规划在 [0.0.38 工作台体验](0040-0.0.38-工作台体验与-ZCode-共享界面借鉴产品需求.md)之后，由 `0.0.39` 承接 Z28、Z29 的跨任务部分、Z08、Z36。UI／UX 及许可适用的源码组件大量借鉴已获授权，当前未开始实现。首版定时运行按现有本机边界采用“D Code 运行时触发，显式退出停止调度”的方案；这是本轮推荐的成本与运行选择，507 若选择退出后常驻后台，须原位替换相关范围和验收后再实施，不能把未回答的选择记录为 507 已定案。

## 问题与目标

用户已经能在一个 Task 中运行工作流，但成熟安排不能方便地作为模板用于另一项任务；不同任务的运行、产物和失败来源不易统一回查。用户也希望在工作台内手动运行终端命令，并把已明确授权的重复工作按计划执行。

本版形成三个可以各自验证的能力：工作流模板与跨任务运行历史、用户交互终端、定时自动化。它们复用 D Code 的 Task、Session、Agent Run、Artifact、Evidence 和 Host；用户能看清来源、实际运行、停止与恢复状态，所有新运行仍遵守现有单写入和进程边界。

每个能力在自己的完整路径通过后才接入下一项。自动化不能借终端直接绕过 Task／Agent 合同；终端与模板可以独立于定时运行使用。

## 工作流模板与启动

1. 用户可把选定 Task Workflow 的某一版本保存为 Workflow Template，选择当前项目或当前用户范围。模板有稳定身份、名称、说明、版本、来源和必要参数；保存和浏览不创建 Task、不运行模型，也不把未验收来源标成已验证。
2. 模板保存目标、阶段安排、依赖和可复用约束。它不复制原 Task 的运行成员、进程、当前工作项状态、报告、验收结论或凭据。显式保留的上下文请求必须有来源、适用范围和读取边界；移到其他项目不能自动携带旧项目正文或资料。
3. 编辑产生新版本，旧运行固定所采用版本和参数。重命名不改变模板身份；删除／停用模板不删除或改写既有 Task、报告、Artifact 和运行记录。被定时规则引用的模板必须显示关联，删除不得留下可自动启动的悬空引用。
4. 启动前选择明确目标 Project Scope 或 User Scope，核对参数、模型／能力与必要来源。主路径创建一个新 Task 和协调会话，从当前有效配置启动新工作流；只选择模板不产生运行。失败保留表单与原因，已建立对象以真实回执核对，不重复创建任务或运行。
5. 也可把模板内容预填到已有任务的输入草稿，等待用户明确发送；原草稿非空时提供明确的插入／替换选择和恢复原草稿路径。预填不改 Task Goal 或自动启动一轮；发送后继续服从同 Task 工作流的活动、冲突和来源合同。
6. 参数支持可验证的文本、数值、开关及其必填／默认值；占位展开不把用户原文原位覆盖。最终输入保留模板版本、参数与实际上下文的来源关系，非法、敏感或适用范围不足时拒绝开始。模板／规则派生的输入注明生成与授权来源，不能冒充用户当次新键入的原话；原始配置、参数和本轮生效输入分别保留来源。
7. 新 Task 的协调者按需组织成员，实际成员遵循现有模型回退、能力、配额和独立进程规则。模板不锁死 ZCode 的角色人数或复用旧 PID／身份；语言遵循新一轮实际采用的 D Code 偏好，模板与用户参数原文不被自动翻译。

## 跨任务运行历史

1. 模板详情可查看所有属于当前用户且有权限的相关运行，并按项目、时间和状态筛选。每行显示目标 Task／Scope、模板版本、实际参数、状态、开始／结束、耗时和有依据的用量。
2. 点击回到原 Task／Session／Workflow Run 或明确 Artifact；查看历史不重新运行、不恢复已消失进程、不把旧产物归给另一任务。来源丢失、项目不可用和内容变化显示原因。
3. 旧执行的完成、停止、失败、阻塞、中断和结果未知可区分；运行完成不等于 Task 已被用户接受。后续模板更新、任务归档或新报告不改写历史结果。
4. 自动执行和手动启动可共用运行行，但必须标明触发来源；数据由 Product Store 关联，不能通过标题或目录相同推断属于同一模板。

## 用户交互终端

1. 从任务／项目工作区显式打开 Terminal Session，先展示关联 Scope、初始目录和本机执行位置；User Scope 仍是用户任务范围，不伪装默认项目。终端不创建运行成员或 D Code 对话，用户可以并排查看原任务。
2. 终端承接用户手动键入／粘贴命令与输出，支持基础选择复制、滚动历史、键盘、中文输入法、尺寸变化和可用链接。粘贴涉及多行或控制字符时让用户看清实际输入；模型不能通过界面操作或隐式工具向该终端注入命令。
3. 初始环境与 Host／Agent 凭据环境分开，不注入已存 API Key、OAuth token 或认证正文。用户终端以用户本机账号权限运行，所选 cwd 不是操作系统沙箱；界面不能承诺全部手动命令被 Agent 权限规则覆盖。首版默认不加载用户 Shell 初始化脚本；用户可显式启用，先看见其会以本机账号执行启动命令的含义，该偏好只影响后续新终端，仍不得继承 Host 的凭据或把已启动终端热改。
4. Terminal Session 的辅助进程、子进程和目录占用由 Host 归属、核对并管理。关联项目目录维护必须确认终端安全退出；用户手动 cd 不迁移 Task Scope。Agent 写入、项目维护与终端活动的冲突按实际占用处理，不能让一个关闭动画提前释放保护。
5. 切换 Task／页面或隐藏终端只改变呈现，不假装进程退出；停止和关闭明确指出受影响终端及其子进程，等待真实终态，无法确认时保持未知及必要目录占用。退出 D Code 时按正常关闭规则停止所属终端，不能留下无主进程。
6. Host／App 重启不声称原交互进程继续；可保留断开状态和可解释的历史元数据，重新连接是用户明确发起的新终端。终端状态、临时输出与 Agent 执行过程分别记录，不用转绘 Pi TUI 作为实现。
7. 终端输出默认不送入模型或长期知识。用户显式选段引用时先预览目标任务、来源与内容，走现有敏感输入、Raw／Effective Input 分离和可信通道；取消引用不改变终端或普通草稿。

## 定时自动化

### 规则与授权

1. Automation 保存稳定身份、名称、明确目标 Scope、任务说明或固定模板版本／参数、所选模型／能力、时间规则、时区、有效期／次数限制及每轮运行上限。提供每日、每周和固定间隔的易读编辑，显示下一次触发时间；无效规则不能保存为可运行状态。
2. 保存草稿不自动启用。启用前说明会按保存配置调用模型和工具、使用实际账号用量及可能产生的副作用；用户明确开启后才获得该范围内的重复运行授权。未配置结束边界时明确显示“持续到暂停”，不能静默把有限任务变为无限计划。
3. 自动执行只使用已明确保存的目标、资源和运行权限。调度本身不新增外部消息、提交／推送／发布、凭据读取或无关项目访问的授权；每轮必须遵守实际项目规则、活动工具和用户授权，不能从文字模板推导额外能力。
4. 每次到期先核对 Scope／目录／模板版本、启用状态、账户／模型／能力及现有自动准入门槛。缺失、过期、未知、低额度或查询失败留有具体状态，不冒充可运行，也不静默切换收费方式。

### 执行与触发身份

1. 每个到期时间槽建立唯一 Automation Run，并在启动前记录所采用规则版本与来源。相同触发重读、重复通知或 Host 重启不得产生第二次自动启动；修改规则只影响未来触发，不能因新版本重用已消费的到期时刻。
2. 到期准入成立后创建新的 Task／协调会话，若配置模板则创建该 Task 的新 Workflow Run；复用实际模型、成员与证据管线。执行结果只回到该触发拥有的任务和历史，不抢占另一任务或普通草稿。
3. 同一规则同时最多一个活动自动执行。上一轮仍在运行、等待输入或结果未知时，后续时间槽明确记录忙碌／需核对，不无界累积任务；不同规则沿用现有全局 Runtime 和目录并发门槛。
4. “立即运行”是有新身份的显式手动验证，不修改时间规则，也不重放旧未知结果。配置、启动或停止的回包丢失先核对原回执，不能因刷新失败再次创建或消耗用量。
5. 规则暂停／禁用只影响后续触发，停止本次只影响选中 Automation Run；两者有明确操作与状态。运行上限到达后按现有安全停止收口，已发生操作与用量不被撤销或改写为未发生。
6. 需要用户回答、登录或实质新增授权时显示等待用户并暂停该规则的后续自动启动；失败、已确认结束、中断和结果未知分别记录，不能让旧报告充当本次成功。

### 本机生命周期与错过处理

首版计划在 D Code 与唯一 Host 可用时调度；隐藏窗口后进程仍在才可继续，显式退出后停止新触发并正常收口／中断正在运行的工作。没有退出后常驻守护进程，也不承诺关机、休眠或离线期间执行。

重开应用后，错过的到期时间槽记录为未执行及原因，直接计算下一次未来触发，默认不补跑。用户可明确手动运行一次；不能用一个补跑队列重放多次外部操作。时区变更、夏令时、系统时钟前进／回拨和恢复期间都按稳定时间槽去重，并显示实际采用的规则与时间。每日／每周遇到不存在的本地时刻时记为未执行，遇到重复本地时刻只采用较早的一次；时间规则预览须明确这些结果，不能在回拨后再次执行已经消费的时刻。

Host 或 App 中断后，先恢复记录和所属 Task 关系，再核对已证明结果与副作用。已知安全的读取按既有恢复规则处理；未知写入、发布、模型生成或其他副作用不自动重发。未知状态需核对后才能恢复该规则，任务历史与消失进程分别成立。

### 历史与通知

规则页显示启用／暂停、下一次触发、当前运行、上次结果、未执行／阻塞原因及可返回的 Task／报告／产物。提供可关闭的本机完成／失败／需用户操作通知，状态无变化不反复提醒。首版不通过第三方消息、邮箱或云服务发送结果。

## UI／UX 借鉴与适配

模板列表、作用域分组、参数窗、运行历史行、产物 chips（标签入口）、终端标签／控件、时间规则编辑、暂停状态、原因和局部操作反馈均优先按 ZCode 已核组件进行源码级移植或结构适配；颜色、间距、排版、图标和动效复用 [0040](0040-0.0.38-工作台体验与-ZCode-共享界面借鉴产品需求.md)形成的共享规则。

普通组件和可核许可的辅助代码可大量借鉴。模板／任务身份、目录与凭据、自动准入、运行事实及读写仍由 D Code 负责；不引入 ZCode 的收费／闲时后台、远程 Workspace、Windows／云端执行、账户增长和外部脚本 Runtime。移植组件不静默执行外部工作流文件、启动脚本或服务，来源与许可按 0040 的同一规则登记。

## 验收标准与公开接缝

- [ ] 模板保存／版本修改／停用和项目／用户范围选择使用真实 Product Store；不会启动模型、复制成员／报告或泄露凭据，旧运行来源保持不变。
- [ ] 同模板在两个 Task、两个不同目标范围启动，参数、当前规则／模型／工具与语言均正确；选择不启动、失败保留表单、丢回包后的幂等核对及预填草稿保留原文完整通过。
- [ ] 跨 Task 历史按真实模板／版本／Scope／运行身份查询，能回到正确实例、报告和 Artifact；过期、归档及不可读取有真实状态，不把历史查看当恢复或重新运行。
- [ ] 真实本机终端覆盖手动输入、中文输入法、复制／粘贴、持续输出、尺寸变化、切页、隐藏、停止／关闭／退出与重启断开；进程和辅助子进程归属可证明，未注入 Host 凭据，未发送输出给模型。
- [ ] 活动终端、Agent 写入和项目目录维护的冲突按真实占用处理；停止未确认仍保持未知与必要保护，关闭单个终端不终止无关 Task／进程。
- [ ] 用可控时钟和真实持久化／启动接缝验证每日／每周／间隔、时区和时钟变化、重复触发、修改／暂停／立即运行、忙碌、缺资格及次数／运行上限；每个时间槽最多自动启动一次。
- [ ] 隐藏／退出／重开、Host 中断、休眠／离线模拟及错过触发分别验证；首版本机模式不补跑，不自动重发未知副作用，恢复规则前能核对原 Task 与结果。
- [ ] 实际自动触发创建一项隔离 Task 并完成有来源报告；所选模型／能力与配额有效，成员各有独立执行进程；运行结束不自动接受 Task，需用户交互时暂停后续自动启动。
- [ ] 本机通知可关闭且不重复；手动／定时运行历史关联正确，读取／保存／部分失败、中英、明暗、窄窗、键盘和无障碍路径均通过。
- [ ] 所有新 Host／UI 入口完成项目必要检查与 `507-review` 只读收口；形成独立 `0.0.39` 同号候选，核包内版本／握手／关于页、真实用户路径和数据迁移／回退边界，未验证切片不替换在役基线。

## 非目标

本机首版不做退出应用后的 macOS 常驻服务、远程／云调度或保证关机执行，不建立第二套任务系统、外部脚本工作流 Runtime 或权限模式，不自动向第三方发消息，不因能力存在而给予提交／发布授权，也不把当前手动生图试验扩成后台自动生图。
