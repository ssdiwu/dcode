# D Code 0.0.37 任务内图像生成与产物归档产品需求

状态：507 于 2026-09-28 确认将图像生成列为 `0.0.37`，2026-10-01 要求完成同版已确认范围。当前主树已未提交地接通 Task 主对话入口、固定 Codex App Server 的订阅生图、受管产物、预览、附件、导出和中断核对；全量自动检查及受控配置下的真实正向／负向窗口检查通过。入口明确为本机试验，精确用量扣减、稳定分发许可与 507 本人验收仍未成立。`0.0.35` 修复与 `0.0.36` 输入区／协作实现由当前组合候选携带，不追认缺失的独立验收。

## 问题与目标

本版实施前，D Code 能把用户提供的图片作为输入附件并预览，缺少 Task 内生成和可回查产物链路。用户已有适用订阅时，希望从任务对话明确描述一张所需图片，看到真实生成结果，随后在当前任务中预览、引用或导出，不必把外部工具的临时文件当作长期资料。

本版先完成**文本生成单张图片**的完整路径。D Code 负责用户入口、任务归属、操作状态、产物与来源；Codex App Server 是独立的生图能力接缝，不改变 Pi SDK 作为现有 Agent Runtime 的职责，也不成为 D Code Session 或 Product Store 的替代品。

## 用户路径与需求

1. **发起**：当前 Task 主对话的已接通能力入口可选择“生成图片”。用户填写和修改本次图像描述，明确提交后才开始生成；打开入口、返回对话或放弃草稿都不调用服务，也不覆盖当前普通消息草稿。成员子对话和新任务尚未建立 Task 时不伪装有已归属的生成操作。
2. **来源与用量可知**：首次使用及每次来源变化时，界面说明本次描述会发送给 OpenAI，并消耗当前 Codex 账号的适用用量。D Code 只组装本次明确提交的描述和运行所需的最小指令；不自动附带项目文件、完整任务历史、其他附件或凭据。运行环境同时限制 Codex 读取未选资料和调用无关工具，不能只检查发出的首条文本。订阅资格、额度和预计消耗未知时显示未知，不给出虚构余额或免费承诺。
3. **认证与能力**：运行前确认 Codex App Server 的账号处于可用的 ChatGPT 订阅认证状态且图像能力可用；无账号、认证失效、计划不支持、额度不足或能力不可用时给出原因和可执行的连接／重试入口。D Code 现有 Pi 模型连接和 OAuth 状态不充当这项能力的登录证明。API Key 模式不标作订阅用量，也不得在用户不知情时自动切换到 API Key 计费。
4. **运行与反馈**：提交后在所属 Task 显示本次生图的进行、完成、失败、取消或结果待核对状态。主对话仍可阅读与继续普通交流；用户可以停止等待，但停止请求不抹去已发生的用量或可能已经生成的结果。后台结果只能回到发起它的 Task 和会话，不抢占其他 Task 的焦点。
5. **产物归档**：成功图片先核对确实可读取、格式与大小符合 D Code 图片边界，再进入 D Code Data Root 的受管产物空间，由 Product Store 登记为所属 Task 和发起会话的不可变 Artifact（产物），保留操作尝试、来源、时间和内容摘要。外部 App Server 的临时文件或线程本身不成为产品权威；未完成受管保存不得显示为“生成成功”。重启后仍可从 Task 结果或信息检查器打开原图，不因临时文件清理而消失。
6. **继续使用**：用户可预览生成图、在后续消息中明确将它选为输入附件，或显式导出到所选目录。再次使用图片不改写原 Artifact；导出到 Project 时沿用现有目录身份、覆盖提示与写入边界，不静默替换同名文件，也不自动把图片加入长期 Task Context Selection。
7. **失败与恢复**：认证、额度、网络、服务、格式或受管保存失败分别给出真实状态。Host 或 App Server 中断后先核对可证明的结果与受管产物；无法确认是否已经生成时显示“结果待核对”，不得自动重发可能重复消耗用量的请求。历史记录保留原描述、状态和已确认来源，但不保存或回显认证正文。

### 本机试验的运行边界

- 固定使用已独立安装的 `codex-cli 0.157.1`；候选不携带另一份 CLI，不自动升级或下载。缺少组件、版本不符、订阅资格／图像能力未知或隔离前置失败时，显示具体原因并拒绝生成。
- 生图子进程在启动时加载受控单模型目录：复制固定上游 `gpt-6-luna` 完整 ModelInfo，仅清空 `experimental_supported_tools`。避免模型元数据重新引入时钟和询问工具；不改变 D Code 的 Pi 模型目录。空 environments 阻止本地参考图读取及环境工具，随机权限 profile、默认拒绝和完整分页的 MCP／功能核对共同成立；许可与来源随候选 Legal 装配。
- 一个用户提交只建立一个不会自动重放的 D Code Attempt。收到第二个生图开始事件时停止并拒绝登记单图成功，但 App Server 没有客户端可用的前置一次性调用闸；不能保证通知停机早于第二次后端请求。界面明确提示“本试验不能保证单次扣量，额度与实际消耗未知”。一张成功结果与最多一次消耗分别成立。
- 只有完整 `turn/completed=completed` 加 Store 来源证明、可解码图片及一致摘要可以成为正式 Artifact。失败／中断轮次的图片可保留为待核对预览，不提供附为输入或导出；先有证明但无文件不显示“已保存”。Host 停止后的核对只读取已归属文件，不调用模型或重发。
- Codex 自身可能在其数据目录另存结果；D Code 只清理自己的生图临时工作目录，不承诺删除 Codex 自有副本。D Code 的长期权威仍是本地受管图片和 Product Store。

## 已确认约束与来源

- D Code Product Store 继续拥有 Task、D Code Session、Artifact 与证据；Codex App Server 只在这项生图能力中承担独立运行与认证接缝。它的线程、对话记录和暂存文件不能替代 D Code 对象，也不能成为现有 Pi 会话的双写目标。
- [Codex App Server 官方文档](https://learn.chatgpt.com/docs/app-server)提供 ChatGPT 登录、对话轮次、事件及按本机版本生成协议 Schema 的路径；当前文档将 App Server 命令及 WebSocket 传输标为实验性，并说明不支持生产负载。D Code 接入须固定实际验证的版本，并让本机候选完整携带或明确验证所需运行组件；开发机上有 CLI 不等于分发候选可用。分发前须重新核对官方支持状态；若仍不支持生产，不能把这条实验路径直接作为默认稳定能力发布，须由 507 查看可支持路径或明确试验范围后再决定。
- [Codex 图像生成说明](https://learn.chatgpt.com/docs/image-generation)说明内置生图可使用适用订阅的通用 Codex 用量；[计费说明](https://learn.chatgpt.com/docs/pricing)把该路径与 API Key 调用分开。具体账号可用性、用量归属与 App Server 图像结果事件须以隔离的真实单图测试核对，本机能力查询和模拟源码测试只构成前置证据。
- 不读取、复制或记录已存 OAuth token、API Key 或认证文件正文；生图描述、错误、产物路径和诊断按 D Code 现有敏感数据与目录边界处理。外部返回的路径和文件须校验，不能仅凭成功事件就把任意本机文件登记为生成产物。
- 生图线程使用与 Project 分离的临时工作目录和明确的读取边界；通用命令、项目文件编辑、MCP／插件及其他非生图工具不得在该线程执行。App Server 发出的审批请求默认拒绝，不能以“无人响应”或宽松沙箱视作授权。若当前 App Server 版本不能可靠限制这些动作与来源，本版不得将入口标为可用；真实图像结果事件本身不能证明旁路工具没有运行。

## 非目标

- 首版不做参考图编辑、局部蒙版、批量生成、多图变体、Agent 自动生图或跨 Task 图库；这些需要独立范围和验收。
- 同版 [ZCode 候选组件研究与取舍](0037-0.0.37-ZCode-候选组件研究与取舍.md)只是额外候选池，不把终端、自动化、跨任务工作流等十项并入本生图首版或当前 `0.0.36` 实现。
- 不直接调用 OpenAI Images API 并从订阅账号推导 API 额度；也不把 API Key 收费路径作为无提示回退。
- 不把 Codex App Server 接管 D Code 现有对话、Task、团队调度或 Pi Runtime，不因生图新增第二套产品数据权威。
