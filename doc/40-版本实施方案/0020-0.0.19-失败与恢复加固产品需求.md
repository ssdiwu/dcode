# D Code 0.0.19 失败与恢复加固产品需求

状态：Implemented（自动门禁已通过；人工验收待完成）

本 PRD 冻结 `0.0.19` 的范围与验收边界；恢复与幂等边界由 [ADR 0027](../决策档案/0027-中断状态可辨认与恢复边界.md) 固定，且不改变 ADR 0011（停派不自动重试）、0018（显式重接）、0022（不自动回滚）、0025（缓冲区不持久化）。版本演进对应路线图 `0.0.19`（Failure / Recovery Hardening）。范围来自 2026-08-22 双侧盘点的六个真实缺口。

## Problem Statement（问题陈述）

1. Host 意外退出后应用内没有任何重连入口（`start()` 被 `.failed` 锁死），恢复 = 重启 App——直接阻塞 `0.1.0` 晋升门禁"Host 退出后从可解释状态恢复并继续"。
2. Host 在 JSONL 追加中途死亡留下半条记录时，会话以 `INVALID_SESSION` 永久无法打开，无修复路径——"中断后状态不可辨认"的直接实例。
3. 协议强制 `promptId` / `steerId` 但两端都不消费：同一 promptId 重发会被当作新 run 再次执行，无幂等。
4. 五个本机 JSON store 写盘熔断后"本次运行永久"，仅队列与关注有常驻 UI，草稿 / 变更 / 证据熔断用户基本不可见且无重试入口。
5. 验证证据链路全静默：账本写失败静默 no-op、revision 补全失败无呈现，"revision 待补"不区分原因。
6. 自构建重启后恢复会话失败结果被丢弃；Source Folder 撤销对受影响会话与文件标签无提示。

## Solution（解决方案）

1. **Host 重连（决定 3）**：`restartHost()` 放行 `.failed` 复位传输态（保留会话 / 草稿 / 队列 / 账本状态）；连接失败态（侧栏红点、空态）与 `host.restartRequired` 态提供"重新连接 Pi Host"按钮；ready 后刷新会话列表并以可写重开当前会话；run `.unknown` 事实保留。
2. **半条 JSONL 受控修复（决定 4）**：Host 新增 `session.repair`——仅当"尾部恰好一条记录不完整且其余记录完整（可解析、id 唯一、parentId 链完整）"时可修；修复前同目录完整备份（`.bak-<uuid>`），修剪后以严格读取器复验；`session.open` 失败的 `INVALID_SESSION` details 附 `repairable`。Swift 在打开失败呈现修复卡：[备份并修复后打开] / [取消]。
3. **promptId / steerId 幂等（决定 5）**：Host 维护会话级已见 ID（有界 LRU）；重复返回 `SESSION_DUPLICATE_PROMPT` / `SESSION_DUPLICATE_STEER`（details 附原 runId）；Swift 行内呈现该错误并提示核对上一条消息；安全重试条件不变（仍要求 Host 判定未持久化）。
4. **store 熔断可见化 + 显式重试（决定 6）**：各 store 暴露 `isWriteBlocked` 与 `retryFlush()`（清熔断 → 重新 load 校验 → flush）；设置 > Host 诊断新增"本机存储状态"区（各 store 正常 / 熔断 + 原因 + [重试保存]）；会话草稿熔断在 Composer 常驻提示。
5. **验证证据可见化**：证据账本熔断进入存储状态区；工作检查器证据区新增[重新载入]；"revision 待补"区分"补全中 / 账本暂停"。
6. **恢复失败不静默（决定 7）**：自构建重启后恢复会话失败 → notice + 手动打开入口；Source Folder 移除时 notice 告知受影响会话数与撤销的文件标签数。
7. **SIGINT graceful**：Host 注册 SIGINT（同 SIGTERM 走 shutdown，exit 143）。

## Confirmed Constraints（已确认约束）

- 全部服从 ADR 0027：三态辨认、恢复显式触发、修复备份先行且只处理可判定安全的形态、幂等重复诚实报错、不自动重连 / 重试 / 回滚。
- 会话文件修复只在 Host 内执行（Swift 不直接触碰 JSONL）；修复不改变"Pi 会话 JSONL 经 Host 写入"的边界。
- 既有 ADR 0011 / 0018 / 0022 / 0025 条款继续有效，本版不翻案。

## Acceptance Criteria（验收标准）

- [x] Host 重连：意外退出后侧栏 / 主页空态出现"重新连接 Pi Host"；重连后 Host 重启、会话列表刷新、当前会话尝试以可写重开；run `.unknown` 保留；`host.restartRequired` 同入口可用并清除标记（fake-host 状态机用例 2 组）。
- [x] 半条 JSONL 修复：`session.open` 对尾部不完整会话返回 `INVALID_SESSION` + `repairable=true`；修复卡执行 `session.repair`（备份 `.bak-<uuid>` → 修剪 → 严格复验）后尝试重开；中部损坏 / 链断裂拒绝修复且原文件零改动（Host 用例 2 组 + Swift fake-host 全链路 2 组：修复流与拒绝流）。
- [x] 幂等：同一 `promptId` / `steerId` 二次提交返回 `SESSION_DUPLICATE_PROMPT` / `SESSION_DUPLICATE_STEER`（details 带原 runId）且不产生新 run；不同 ID 正常（Host 用例）。
- [x] store 熔断：五个 store（草稿 / 变更 / 队列 / 关注 / 证据）暴露熔断探测与显式重试；设置 › Host 诊断 › 本机存储状态区呈现 + [重试保存]；证据账本熔断时"熔断期间的内存账本恢复后补写"有用例；草稿熔断 Composer 常驻提示（渲染冒烟 + 单元 2 组）。
- [x] 验证证据：账本熔断在存储状态区与证据区提示条可见；证据区[重新载入]；"revision 待补"区分补全中 / 账本暂停。
- [x] 自构建恢复会话失败出现 notice（自动链路单点，人工验收核对实机触发）。
- [x] Source Folder 移除出现受影响范围提示（撤销文件标签数 + 已加载会话数）。
- [x] SIGINT 与 SIGTERM 同走 graceful shutdown。
- [x] `swift test`（238 用例）、`cd host && npm test`（142 用例）全绿；版本统一提升 `0.0.19`（含 Host `HOST_VERSION`）。
- [ ] 人工验收：真实杀掉 Host 进程 → 重连 → 回到当前会话；真实制造尾部不完整 JSONL → 修复卡流程走通并核对备份；存储状态区实机核对；重发同一 prompt 的行内错误实机核对。

## Out of Scope（不进入本版）

自动重连 / 自动重试 / 自动回滚、通用 JSONL 修复（仅尾部不完整）、重复 prompt 的静默合并、编辑缓冲区持久化、多会话并行运行状态标记、跨设备恢复、Host 内部工具执行的中断续跑（在途工具状态如实丢失并以 unknown 呈现）。
