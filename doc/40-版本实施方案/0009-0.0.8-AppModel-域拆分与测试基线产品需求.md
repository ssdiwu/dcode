# D Code 0.0.8 AppModel 域拆分、dgoal 融入与测试基线产品需求

状态：Implementation Candidate（实现候选，待人工验收）

本 PRD 冻结 `0.0.8`（扩容合并版）的范围与验收边界，由三部分组成：工程内构（AppModel 域拆分与测试基线，[ADR 0016](../决策档案/0016-AppModel-域拆分与宿主注入测试边界.md)）、dgoal 结构化状态融入与计划批准卡（[ADR 0017](../决策档案/0017-dgoal-结构化状态融入与上下文构成呈现边界.md)）、上下文构成占比呈现（同 [ADR 0017](../决策档案/0017-dgoal-结构化状态融入与上下文构成呈现边界.md)）。`0.0.8` 不改变 Pi Session 权威与协议版本语义；`0.0.7` 的全部用户可见范围继续以 [0.0.7 PRD](0008-0.0.7-模型设置与回复运行信息产品需求.md) 为准。

## Problem Statement（问题陈述）

`0.0.7` 收口时 AppModel 约为 4,500 行、183 个方法的单一状态容器，`handle(_:)` 单函数超过 200 行；搜索、活动、模型设置、后续队列与转录流式状态无法按域辨认，新增功能没有明确落点。同时 UI 状态机几乎不存在自动回归：宿主客户端直接 spawn Node 进程，测试必须依赖真实 Pi 环境，导致 `0.0.5`–`0.0.7` 的关键收口（失败清理、进程退出、Run 状态、认证事件流）长期只靠人工手测。

dgoal 会话在 D Code 中只有压缩后的 Active Plan 胶囊：paused 目标被丢弃，Plan Contract 保障档位、升级历史、独立审核结果、条目证据与待批提案完全不可见，批准必须回到终端。上下文只有总量，用户无法回答"每一部分各占多少"。

## Solution（解决方案）

工程内构按 ADR 0016 拆分：领域状态迁入 `SearchModel`、`ActivityModel`、`ModelSettingsState`、`FollowUpModel`，事件分发拆为事件族扩展文件；宿主依赖收敛为 `HostProviding` 协议，`FakeHostClient` 与临时目录 store 驱动状态机回归，渲染层采用 ViewInspector + `NSHostingView` 混合冒烟，行为零变化。

dgoal 融入按 ADR 0017：Host 透传 work-v1 条目的 `goal`（含 paused）与 `pendingProposal`，Swift 原生呈现保障档位、验收标准、阶段 / 终审审核结果、证据、暂停原因与耗时；待批提案在 Composer 交互坞获得原生批准卡，批准动作发送 `/dgoal review`，由 dgoal 的原生 `ui.select` 启动门禁完成实际批准 / 拒绝 / 反馈，不建第二控制面。

上下文构成按 ADR 0017：Host 新增 `session.contextBreakdown`（按消息种类估算分项、真实总量锚定、差值反推系统与工具），圆环弹层展示各部分占比条形与剩余可用；环体保持蓝剩余 / 白已用，跌破阈值转橙红，旁侧常显本轮累计增减。

## Confirmed Constraints（已确认约束）

- 工程内构部分不改变任何用户可见行为、协议方法、事件语义与存储格式。
- 不触碰真实 `~/.pi/agent`、用户 `Library/Application Support/D Code` 与真实凭据；全部测试使用临时目录与脚本化假宿主。
- ViewInspector 为测试目标专用依赖（MIT，精确锁 0.10.3），不进入 `D Code.app` bundle。
- dgoal 不是 D Code 的运行时依赖：由用户 Pi 配置加载，D Code 只识别结构化状态；TUI PlanOverlay 与 `custom` / Widget 继续显式忽略。
- 批准语义始终由 dgoal 拥有；D Code 只发送 `/dgoal review` 固定消息并承接标准扩展对话框。
- 构成占比全部标注估算口径（与 Pi 压缩判断一致的 chars/4）；无真实 usage 锚定时只显示消息分项，不伪造系统与工具推算值。
- 转录、流式、Prompt / Follow-up 结算时序本轮不拆，仍留在 AppModel 本体。

## Acceptance Criteria（验收标准）

### 状态拆分

- [x] `SearchModel`、`ActivityModel`、`ModelSettingsState`、`FollowUpModel` 各自拥有本域状态与叶子操作；AppModel 持有子模型并保留跨域协调职责。
- [x] 全部视图经 `model.search.*` 等嵌套路径读写域状态；`@Bindable` 绑定路径不因拆分失效。
- [x] `handle(_:)` 收缩为事件族路由；会话 / Plan、扩展、模型认证、宿主生命周期四组 case 原样迁移到扩展文件，事件行为不变。

### 可测性

- [x] `HostProviding` 协议覆盖 AppModel 全部宿主调用面；`PiHostClient` 为唯一生产实现；client factory 可从 init 注入。
- [x] `FakeHostClient` 支持按 method 脚本化响应、请求记录与主动事件注入；`HostTestHarness` 将全部本地 store 指向临时目录。
- [x] 集成测试覆盖：握手成功 / 失败清理、意外与预期进程退出、Run 状态与完成注意力记录、搜索索引状态、模型认证事件流、重启要求保留观察。
- [x] 渲染冒烟覆盖：RootView 空态 / 打开会话态、ConversationView 轮次 + 流式、Composer 运行中排队态、ModelSettingsView 快照态、UserHomeView 与 ConversationRoundRail 结构断言。
- [x] `THIRD_PARTY_NOTICES.md` 登记 ViewInspector 及其不进入 bundle 的边界。

### dgoal 融入与计划批准

- [x] Host 透传 `dgoal-work-v1` 的 `goal`（含 `paused`）与 `pendingProposal`；paused 不再被当作无计划丢弃，提案被审阅后随最新条目清除（Host 用例）。
- [x] Swift 原生呈现保障档位（含“软性清单”如实标注）、升级历史、验收标准、阶段 / 终审审核结果与审核模型、条目证据、暂停原因、耗时。
- [x] 待批提案在 Composer 交互坞获得原生批准卡；批准发送 `/dgoal review` 固定消息，运行中被门禁拦下；实际批准 / 拒绝 / 反馈由 dgoal `ui.select` 原生对话框完成。
- [x] 解析、提案生命周期、门禁与渲染均有自动化用例。

### 上下文构成占比

- [x] Host 新增 `session.contextBreakdown` 方法与 `contextBreakdown` 能力位；分项估算与 Pi 压缩口径一致，真实总量锚定，差值反推系统与工具；只读会话返回不可用原因。
- [x] 圆环弹层展示各部分占比条形与剩余可用；估算口径如实标注，无锚定时只显示消息分项。
- [x] 环体保持蓝剩余 / 白已用，余量低于 20% / 8% 转橙 / 红；旁侧常显本轮累计新增 / 释放。
- [x] 构成解析、请求链路、增减累计与渲染均有自动化用例。

### 版本与发布

- [x] App / Host / Info.plist / build.sh 版本一致为 `0.0.8`；本地 `v0.0.8` 标签删除，收口时对扩容合并版重新打标。
- [x] `swift test`（167 用例）、`cd host && npm test`（131 用例）全绿。
- [x] `./app/build.sh` 产出 `dist/D Code.app`（0.0.8，434M，签名通过），内嵌 Host 与 App 版本核验为 `0.0.8`。
- [ ] 真实环境人工抽查：正常启动、打开真实会话、发送一轮、模型页只读视图与 `0.0.7` 行为一致；dgoal 真实会话的计划呈现、待批提案批准流与上下文构成弹层；`0.0.7` 遗留的真实 Pi steer、Provider 登录、浅色外观与 VoiceOver 一并执行。

## Out of Scope（不进入本版）

- dgoal 内嵌分发（bundle 随 App 加载）、自动触发升级或审核、多 Goal 管理、Goal / Work Map 耐久产品对象化（仍属 `0.2.x`）。
- 精确 per-section token 统计（Pi 不提供分项数据，伪造精度被拒绝）。
- 转录 / 流式 / 结算时序的进一步拆分（独立决策点，留待后续版本）。
- 自动重连、XCUITest / Xcode 工程包装、像素级 UI 断言。
