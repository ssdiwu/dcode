# D Code 首个可日常使用版本产品需求

状态：Baseline Regression（基线回归）

适用范围：已经成立的原生会话、持续观察、按需写入、聊天、安全与结构化呈现基线；当前版本新增范围由 [0.0.1 用户首页与项目工作台产品需求](0002-0.0.1-用户首页与项目工作台产品需求.md)规定

## Problem Statement（问题陈述）

Pi CLI 已经承载真实会话、模型上下文、自研扩展和开发工作，但终端界面把 Plan、图表、工具结果和长文本限制在字符界面中。用户难以持续查看活动 Plan、缩放 Mermaid、稳定选择复制内容，也无法把未来的原型等产物作为可交互对象查看。

另建桌面专用会话会切断现有工作。首版必须在原生 App 中找到同一个会话、持续看到 Pi 已落盘的新历史，并在需要写入时继续后续工作；新增内容仍属于原 Pi 会话，而不是导入后的副本。

## Solution（解决方案）

提供一个 macOS 原生 Pi 客户端，继续使用既有 Pi 配置、会话与 Pi SDK 运行能力，并把可识别的结构化语义呈现为原生交互：

- 从 Pi 的现有会话权威中列出、新建和恢复会话；
- 在 App 内直接创建新会话；既有会话以正常界面持续观察，发送或修改运行设置时按需取得写入权，不要求 CLI 插件、交接 ID 或 marker；
- 以原生消息流呈现流式回复、工具调用、错误和标准结构化扩展交互；
- 将 dgoal 的 Active Plan 固定呈现在消息流与输入框之间，可展开查看，完成后自动隐藏；
- 将 Mermaid 作为消息内 Artifact 渲染，支持缩放、复制和导出；
- 不渲染任意扩展 TUI；custom、Widget 等界面请求明确阻止或忽略，不调用组件 factory，也不返回虚假成功。

首版应是可从 Finder 启动并用于继续当前工作的本机 App，而不是只读查看器、视觉稿或独立演示会话。

## Product Model（产品模型）

### Pi Session

- 命令行与 App 访问同一个 Pi Session。
- 会话历史、模型上下文和 Pi 已持久化的运行条目以 Pi 会话为权威。
- App 的索引或缓存必须可以从 Pi 会话重建，不能成为第二份历史。
- 同一会话以 Pi 持久化的稳定 session ID 判定；名称、工作目录和更新时间只用于展示与检索，不能替代身份。

### Session Observation 与 Write Ownership

- 选择既有会话后进入正常的 Session Observation：显示完整历史与 Composer，并跟随 Pi CLI 已完整写入 JSONL 的新条目；产品不显示默认“只读模式”或二次“继续会话”动作。
- Host 只轮询当前会话文件身份，变化后通知 App 从已知路径刷新，不在无变化时重复解析完整会话或扫描全部会话目录。
- 发送消息或修改模型、思考强度、极速等运行设置构成 Write Intent；Host 此时以稳定 session ID 原子取得 Session Lease，通过静默窗口复核文件身份，再创建可写 Pi 运行时。
- 只有会话空闲时才能取得写入权。Pi CLI 不参与 Session Lease；若 D Code 写入期间检测到外部变化，Host 立即停止写入，在运行时停止和 owner 身份均可验证时释放租约并回到观察态，App 刷新历史并只保留尚未收到匹配 Prompt 完成确认的草稿；普通消息在本次 RPC 调用自身、且来源仍为 RPC 的 user record 通过 Pi 持久快照复核时确认，不等待整轮助手响应结束；同一调用链内由扩展发出的 user record 必须被来源边界隔离；扩展直接处理且不产生 RPC user record 的命令由该次调用本身返回完成，不能借用其他 user event（用户事件）猜测。否则保留锁、禁止本进程继续写入并要求重启，但观察仍可用。
- 首版允许多端同时观察，但不支持两个客户端同时写，也不迁移在途操作或静默合并两个运行时上下文。

### Active Plan

- Active Plan 是会话当前仍在执行或等待推进的 dgoal 状态。
- App 在消息流与输入框之间显示紧凑浮层，提供当前步骤、进度和展开入口。
- Plan 完成后浮层自动隐藏；完整状态继续保留在 Pi 会话中。

### Artifact

- Mermaid 等产物以不可变快照记录；修改会产生新 Artifact，而不是覆盖旧对象。
- Artifact 默认属于产生它的会话，并保留与来源消息或前一产物的关系。
- 固定到项目和独立资产入口不属于首版范围，但首版数据不得阻碍后续增加该能力。

### Unsupported Extension UI

- 标准选择、确认、输入、编辑、通知和状态交互通过结构化协议进入原生组件，并以 request ID 保证完成或取消只结算一次。
- `ui.custom()` 不执行 TUI factory，发出结构化 `extension.unsupported` 后以 `EXTENSION_UI_UNSUPPORTED` 失败；不得把未执行伪装成取消或成功。
- 非空 Widget、header、footer、theme 和 terminal input 等显示请求不产生终端兼容面；Host 明确报告忽略，重复 Widget 状态按 key 去重，避免刷屏。

## User Stories（用户故事）

1. 作为现有 Pi 用户，我希望 App 自动看到命令行已有的会话，从而无需导入或重新开始工作。
2. 作为在 Pi CLI 与 D Code 间工作的用户，我希望选择同一会话后持续看到已落盘的新消息，并能直接输入；只有真正发送时才需要 D Code 取得写入权。
3. 作为日常开发用户，我希望在原生消息流中发送消息、观察流式回复和工具执行，并能中止当前生成。
4. 作为 dgoal 用户，我希望活动 Plan 始终在输入框上方可快速查看和展开，并在完成后自动让出空间。
5. 作为阅读图表的用户，我希望 Mermaid 在消息内直接显示、缩放、复制源码并导出，而无需手工切换外部工具。
6. 作为阅读长回复和代码的用户，我希望稳定选择并复制消息文本、代码块和工具结果。
7. 作为扩展用户，我希望标准结构化交互使用原生界面；当扩展要求 TUI 时，我能看到该能力已被明确阻止或忽略，而不是得到空白界面或虚假成功。
8. 作为会话所有者，我希望 App 在会话仍被其它客户端写入时阻止并发续写，从而避免历史损坏或分叉不明。

## Confirmed Constraints（已确认约束）

- 平台仅为 macOS；首版不承担 Windows 兼容。
- 既有 Pi 配置和会话目录继续作为权威；App 不要求用户迁移数据。外部扩展不是 D Code 产品界面或产品对象的权威。
- App 不直接修改 Pi 会话 JSONL，所有持久写入经兼容 Pi 运行组件完成。
- 同一会话同时只有一个写入所有者；多端可以同时观察，写入只支持空闲态按需取得，不支持在途热迁移。
- 既有会话写入由用户写入动作、Host 静默检查、原子 Session Lease 与外部写入检测完成；首版不要求额外确认页、CLI 插件、Handoff ID 或写入接管标记。后续 `0.0.1` 的 D Code 创建来源标记只控制 Recent 导航可见性，不参与写入所有权。
- 首版必须能观察并继续本需求形成时使用的现有 Pi 会话，而不仅是新建测试会话。
- App 自带完成首版所需的兼容运行组件，从 Finder 启动时不依赖用户预先启动服务或在 shell PATH 中安装特定 `pi` 命令。
- 可兼容的命令、工具和标准结构化扩展交互可以继续通过 Pi SDK 工作；Goal、Agent Team 等 D Code 产品能力只借鉴外部扩展机制，不要求参考扩展包成为运行时依赖。
- Active Plan、Artifact 和能力动作使用结构化数据；不得把终端字符画面解析结果当作其业务权威。
- 未适配的 TUI 界面能力必须明确阻止或忽略，不提供通用终端卡片或兼容面。
- 凭据只由现有 Pi 认证与运行边界读取；App 日志、协议事件和界面不得包含凭据正文。
- 消息流是内容主空间；首版不设置常驻右侧产物检查器。

## First Version Scope（首版范围）

### 会话与工作区

- 读取现有会话列表，并标识稳定 session ID、会话名称、工作目录、更新时间和可写入状态；session ID 可从会话详情或诊断信息复制。
- 新建会话时选择工作目录；恢复会话时沿用其已有工作目录。
- 打开会话后显示可恢复的完整消息与工具历史。
- 既有会话始终显示正常 Composer；观察期间外部已落盘消息自动刷新。首次发送或修改运行设置时按需取得写入权，失败时保留历史与原草稿并给出真实错误。
- 显示当前模型和 thinking level；允许通过可用模型列表切换。
- 支持发送、流式接收、中止以及宿主重启后的恢复。

### 原生消息流

- 原生呈现用户消息、助手文本、thinking、工具调用、工具结果和错误。
- 工具卡片显示名称、运行状态、输入摘要、结果与错误，并支持展开和复制。
- 支持 slash command 及标准扩展选择、确认、输入、编辑、通知和状态交互。
- 扩展请求首版未原生支持的 TUI 交互时，显示明确的“不支持”通知；等待结果的 custom 请求失败，其他显示请求忽略，且均不执行 TUI factory。

### dgoal Active Plan

- dgoal 提供可恢复的结构化 Plan 快照或增量状态。
- 有 Active Plan 时在消息流与输入框之间显示紧凑浮层。
- 浮层可展开/收起，并实时反映当前步骤、状态和总体进度。
- Plan 完成后浮层自动隐藏；重开会话时只恢复仍活动的 Plan。
- CLI 中 dgoal 的核心计划与状态能力继续有效。

### Mermaid 与复制

- 已完成消息和流式消息中的完整 Mermaid 代码块可转为内联图表。
- 图表支持适配宽度、缩放、全屏查看、复制源码和导出图片。
- Mermaid 语法无效时保留源码并显示局部错误，不影响整条消息或会话。
- 普通文本、Markdown、代码块与工具结果可以选择和复制。

### 本机应用生命周期

- 交付可从 Finder 启动的 `.app`。
- App 启动和退出时正确建立与清理 Pi 运行组件。
- 运行组件异常退出时，App 保留已持久化历史并提供可理解的重连或重启入口。

## Acceptance Criteria（验收标准）

### 同一会话观察与按需写入

- [ ] 验收开始前记录当前 Pi 会话的稳定 session ID 与最后一条持久记录；App 无需导入即可列出并打开完全相同的 session ID。
- [ ] 打开该 session ID 后，用户可核对已有消息、工具历史、工作目录、模型、thinking level 和 Pi 已持久化的运行状态；界面直接显示正常 Composer，不出现默认“只读/继续”流程。
- [ ] 在 Composer 保留未发送草稿时，由 Pi CLI 向同一会话追加一轮完整持久消息；D Code 自动刷新最新历史，草稿逐字不变，且没有创建 Session Lease。
- [ ] 用户首次发送或修改运行设置时才取得写入权，并完成至少一轮真实模型回复和工具调用；无需插件、命令行交接、复制 ID 或额外确认页，新增记录进入原会话。
- [ ] 关闭 App 后用 Pi CLI 恢复同一会话，可以看到 App 新增的记录并继续工作，不需要导入、复制或合并。
- [ ] App 重启后再次打开该会话，历史、活动状态和最近新增内容保持一致，不重复追加消息。
- [ ] 同一 session ID 已被另一个 D Code Host 租用时，本次写入被拒绝且草稿不清空；非协作客户端在 D Code 写入期间追加内容时，App 立即停止、在安全可验证时释放租约、刷新历史并返回观察，不静默并发写入；停止或 owner 校验失败时未知锁不被强删。
- [ ] 模型生成、工具执行或阻塞交互仍在其他客户端继续时，App 不声称已经安全取得写入权，也不把观察态显示为错误或只读模式。

### 日常聊天与结构化扩展交互

- [ ] 用户可以新建或恢复会话、发送消息、观察流式回复、查看工具进度并中止当前生成。
- [ ] 现有 Pi 包和扩展加载失败时逐项显示诊断；成功加载的命令、工具和 Provider 可继续使用。
- [ ] 标准扩展交互可以在原生界面中完成，结果或取消以 request ID 恰好一次返回扩展。
- [ ] `ui.custom()` 不调用 TUI factory，发出 `extension.unsupported` 并以 `EXTENSION_UI_UNSUPPORTED` 失败；界面显示可理解的限制通知。
- [ ] Widget 等无返回值的 TUI 显示请求被明确忽略且按来源 key 去重，不出现终端帧、兼容面板、空白伪成功或持续通知刷屏。
- [ ] 消息、代码块、工具输入与结果均可选择和复制，复制内容不混入隐藏控制字符。

### Active Plan

- [ ] 当前会话存在活动 dgoal Plan 时，输入框上方出现紧凑浮层，并显示当前步骤与进度。
- [ ] 展开浮层可以看到完整步骤、状态和阻塞关系；收起后不遮挡消息与输入。
- [ ] Plan 状态变化后界面无需刷新即可更新；重开会话可以恢复仍活动的 Plan。
- [ ] Plan 完成后浮层自动消失，且完成状态仍保留在原 Pi 会话中。
- [ ] 在 CLI 中恢复该会话时，dgoal 的核心状态与操作仍然成立。

### Mermaid 与错误边界

- [ ] 有效 Mermaid 在消息流内生成可读图表，并支持缩放、全屏、复制源码和导出。
- [ ] 无效或不完整 Mermaid 显示源码与明确错误，且不会导致消息流、会话或 App 崩溃。
- [ ] 重开历史会话时，已有 Mermaid 仍能从会话内容重建，不依赖一次性内存状态。

### 应用与数据安全

- [ ] `.app` 可从 Finder 独立启动，不要求用户先打开终端或手动运行辅助服务。
- [ ] 运行组件缺失、版本不兼容、启动失败，或 Pi/工作目录不可访问时，App 不打开可写会话，并显示组件状态、错误原因及重试或打开诊断入口；原始数据不被改写。
- [ ] 正常退出后没有遗留持有会话写入权的宿主进程；异常退出后可以安全恢复或明确报告锁状态。
- [ ] App 不创建竞争性的会话历史数据库，也不直接改写 Pi 会话 JSONL。
- [ ] 日志、错误报告和界面检查不包含 API key、OAuth token 或认证文件正文。
- [ ] 会话或扩展数据损坏、缺失或版本不兼容时，App 给出可操作错误并保留原始数据，不自动重写以“修复”。

## Out of Scope（非目标）

- Windows、Linux、iPhone 或 iPad 客户端。
- Mac App Store、公开下载、自动更新、Developer ID 公证与正式发布渠道。
- 正在生成、执行工具或等待扩展响应的会话热迁移。
- 同一会话的多客户端同时编辑或协作。
- HTML 原型的内嵌交互预览。
- 项目级 Artifact 资产库、固定入口和跨会话复用界面。
- 完成 Plan 的专门历史浏览入口。
- 为所有现有扩展逐一开发原生界面，或要求桌面与 CLI 视觉严格一致。
- 覆盖或编辑已经写入会话的历史消息与 Artifact。
- 远程仓库创建、提交、推送或发布自动化。

## Further Notes（补充说明）

- 需求验收以用户可观察的会话同步、按需写入、冲突恢复、消息流、扩展交互、Active Plan 和 Mermaid 路径为准，不以内部类名或文件布局作为完成依据。
- 会话兼容测试必须使用真实 Pi 会话格式，并以隔离副本覆盖破坏性场景；mock 只能替代外部模型或不可控网络。
