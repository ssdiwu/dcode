# D Code 0.0.20 Composer 命令面板与附件产品需求

状态：Implemented（自动门禁已通过；人工验收待完成）

本 PRD 冻结 `0.0.20` 的范围与验收边界；附件与统一面板的输入边界由 [ADR 0028](../决策档案/0028-Prompt-图片附件与统一命令面板边界.md) 固定，且不改变 ADR 0024（引用只预填不发送）、0011（后续消息队列仅文本）、0025（缓冲区不持久化）。版本演进对应路线图 `0.0.20`（首个 dogfood 反馈驱动）。

## Problem Statement（问题陈述）

2026-08-22 首次真实 dogfood 的输入区反馈：

1. `pi-marketplace loaded — search/audit/install pi packages` 扩展就绪自报每次打开会话都弹横幅；同类噪声 pi-di18n `lang:` / `i18n:` 已有"只进诊断日志"的过滤，此处漏网。
2. 输入 `/` 只出现扩展命令（`/mcp`、`/tinyfish-*` 等），Skill、Prompt 模板与命令无法经斜杠触达——面板数据源只有 `session.getCommands`，`resources.list` 的资源只藏在 `+` 菜单里。
3. `+` 是 `Menu` 样式，自带下拉指示符，输入行出现多余箭头。
4. `+` 的正确产品语义是"添加附件（图片 / 文件）"：图片应真实进入模型输入（Pi SDK `PromptOptions.images` 已核实可用，协议 v1 缺参数）；文件应插入路径引用。
5. 参照 ZCode：统一面板应混排全部命令类型、行尾标注类型、常显描述、悬停显示完整描述。

## Solution（解决方案）

1. **统一斜杠面板**（决定 1）：`ComposerCommandSuggestion.build` 合并 `session.getCommands`（"扩展"）与 `resources.list`（"命令" / "Skill" / "模板"，同名以 getCommands 去重）；行 = 调用名 + 单行描述 + 行尾类型胶囊；help 悬停显示类型 + 调用名 + 完整描述；选中插入 `invocationText`（模板带 `<hint>` 占位）；面板可滚动（12 行上限、约 7 行高度），↑↓ / Esc 不变。
2. **`+` 附件按钮**（决定 2）：纯 Button 无下拉指示符；NSOpenPanel 多选；图片 → 图片附件（chip：文件名 + 体积 + 移除），非图片 → `insertComposerReference(路径)`。
3. **协议扩展**（决定 3）：`session.prompt` / `session.steer` 可选 `images`（≤8 张、单张 data ≤ 7,000,000 base64 字符、`image/*` MIME）；Host 透传 SDK；协议校验拒绝非法形态。
4. **投递边界**（决定 5）：prompt / steer 携带附件；入队带附件 → notice 拒绝（正文与附件保留）；失败 / steer 未正常完成 → 附件随正文恢复；受理后清空；会话切换清空。附件仅内存（决定 4）。
5. **横幅降噪**（决定 7）：`pi-marketplace loaded` 前缀进入诊断日志过滤，普通扩展通知仍弹横幅。
6. **0.0.19 eval 反馈落地**（[eval 记录](~/.mirasim/eval/sessions/260822-1910-dcode-recovery/feedback.md) 仅本地留存，结论摘要进各文档）：修复卡在执行前展示被修剪尾部记录的全文（协议 `INVALID_SESSION.details.trimmedContent` 与 `session.repair` 结果携带，上限 20,000 字符、超限如实标注指向备份）；`host.hello.capabilities` 补 `sessionRepair` / `promptImages` 能力位；ADR 0027 与 CHANGELOG 的幂等绝对句降级为「同一 Host 进程生命周期内、LRU 256 窗口内」条件句；0.1.0 门禁「权限拒绝」口径改为「会话文件损坏」（ADR 0023 已移除权限闸门）；PRD 0020 四项无对应用例的打勾改回未勾；新增面向用户的[会话恢复支持指引](../20-产品与交互/支持-会话打不开时的恢复指引.md)。

## Confirmed Constraints（已确认约束）

- 全部服从 ADR 0028；既有 ADR 0024 / 0011 / 0025 条款继续有效，不翻案。
- 协议变更是可选参数追加，`PROTOCOL_VERSION` 保持 1；Host `HOST_VERSION` 随版本号提升。
- 图片附件不持久化、不进任何本机 store；不记录、不展示凭据类内容的边界不受影响。

## Acceptance Criteria（验收标准）

- [x] 统一面板：`/` 同时列出扩展命令、命令、Skill 与模板；行尾类型标注正确；同名扩展命令只出现一次（getCommands 版本）；描述常显、悬停显示完整描述；模板插入 `<hint>` 占位（面板合并 / 去重 / 类型 / 悬停文本 / 过滤 4 组单元用例）。
- [x] 附件按钮：`+` 为纯按钮（无下拉指示符）；图片进入 chip 托盘、可移除；数量 > 8 与单张 > 5 MB 被拒绝且给出用户可读原因；非图片文件插入路径引用（状态机用例）。
- [x] 请求携带：`session.prompt` 请求真实携带 `images`（type / data(base64) / mimeType 逐字段断言）；受理后附件清空（脚本化假宿主端到端）。
- [x] 队列拦截：带附件入队被拒绝并 notice，正文与附件保留，移除附件后可正常排队（状态机用例）。
- [x] steer 恢复：steer 未正常完成时附件随正文一起恢复（状态机用例）。
- [x] 协议校验：合法 images 通过；空数组、非 image MIME、超 8 张、非法元素被 `INVALID_PARAMS` 拒绝（协议用例）；Host 透传 prompt `options.images` 与 `steer(text, images)`（Host 用例）。
- [x] 横幅降噪：`pi-marketplace loaded` 只进诊断日志；普通扩展通知仍弹横幅（既有用例扩展）。
- [x] 修复卡全文：`session.open` 的 `INVALID_SESSION` details 与 `session.repair` 结果携带被修剪记录全文（Host 用例逐字断言）；修复卡执行前展示全文、可复制、提示 `.bak` 位置。
- [x] 能力位：`host.hello.capabilities.sessionRepair` / `promptImages` 为 true（Host 用例断言）。
- [x] eval 文档校准：ADR 0027 / CHANGELOG 幂等条件句、门禁口径、PRD 0020 打勾诚实化、协议权威文档 0001 补 `session.repair` / 错误码 / `images` / 能力位、`host/README.md` 能力清单、40-README 版本索引事实、用户恢复支持指引。
- [x] `swift test`、`cd host && npm test` 全绿；版本统一提升 `0.0.20`（含 Host `HOST_VERSION` 与测试 fixture）。
- [ ] 人工验收：实机输入 `/` 核对 Skill / 模板出现与悬停描述；`+` 选择图片发送后模型真实读图；实机核对横幅消失与输入行无多余箭头。
