# D Code 0.0.17 Markdown 编辑缓冲区与安全保存产品需求

状态：Implemented（自动门禁已通过；人工验收待完成。范围含三项 `0.0.16` 及更早遗留缺口收口与 `models.json` 并发写入收紧）

本 PRD 冻结 `0.0.17` 的范围与验收边界；编辑缓冲区、磁盘冲突与原子保存边界由 [ADR 0025](../决策档案/0025-Markdown-编辑缓冲区与原子保存边界.md) 固定，界面语义以 [`0002-D-Code-原生界面设计系统`](../10-架构与运行/0002-D-Code-原生界面设计系统.md) 为准。版本演进对应路线图 `0.0.17`（Markdown 编辑缓冲区与 Source / Preview 切换）。同时收口 `0.0.16` 及更早遗留的三项已知缺口（详见 Problem Statement 第 2 节）。

## Problem Statement（问题陈述）

1. **主线**：`0.0.4` 建立的文件标签只能看：Markdown 文档核对要切到外部编辑器修改，再回 D Code 手动"重新读取"，预览与磁盘事实来回漂移。路线图 `0.0.17` 要求 Markdown 文件从只读进入编辑缓冲区，具备 Source / Preview 切换与安全保存——未保存状态、冲突、保存失败和磁盘事实均可辨认，预览跟随缓冲区而不是假装已写盘。
2. **遗留缺口收口**（40-版本实施方案已知缺口清单，经查证部分已由 `40e02b9` 修复但缺测试与文档同步）：
   - `modelOverrides.<model>.headers` 凭据正文曾随 `modelOverridesJson` 进入 Swift 高级编辑器（0.0.16）；代码已改为"不回传、不可替换、整体保留"，但 Host 测试只覆盖顶层 headers 脱敏，嵌套 headers 无断言。
   - 搜索正文命中打开曾以 writable + `expectedEntryDigest` 组合发送、被 Protocol v1 校验拒绝，正文定位从未打开成功（0.0.2 / 0.0.9 回归）；代码已改为 writable + `expectedEntryId` 且不带 digest，但无回归测试钉住，且 `SessionOpenRequestPlan.searchResult(_:)` 死代码仍在误导审计。
   - `dcode_facts` 的 `evidence` / `project` 曾与 Swift 真实存储文件名、文档形状和退出状态值不一致（0.0.15）；文件名与形状已修，仍残留三处真实不一致：`changes.source` 枚举值错（`"dcode"` vs 生产值 `"structured-tool-v1"`，导致每条变更被错误标注"来源非 D Code"）、project 归属匹配用严格字符串相等而 Swift 侧做符号链接规范化、跨语言 golden fixture 未落地（测试夹具手写、曾造成假绿）。
   - `host/package-lock.json` 根包版本 `0.0.14` 与 `host/package.json` / App 兼容门禁不一致（随本版提版一并修复）。

## Solution（解决方案）

1. **编辑缓冲区（Models / State）**：`WorkspaceFileSnapshot` 增加内容 SHA-256 指纹；`WorkspaceFileTab` 增加内存态 `draft`（缓冲区文本、clean / dirty / saving / conflict / saveFailed 状态、保存基准指纹、错误信息）。仅 `.md`（大小写不敏感）且已成功读取快照的文件可进入编辑；进入 Source 即从快照建立缓冲区，不做新建文件。
2. **安全保存（Writer）**：`WorkspaceFileWriter` 复用只读预览的安全目录遍历（从 `/` 逐级 `openat`、`O_NOFOLLOW`、授权根约束）取得父目录；保存前经安全路径重读磁盘校验 SHA-256 与基准一致（文件不存在或指纹不符即冲突拒绝）；随后在父目录内 `O_CREAT | O_EXCL` 临时文件 → 写入全文 → `fsync` → `renameat` 原子替换（保留原权限位）→ `fsync` 父目录；失败清理临时文件、原文件零改动。保存成功后刷新快照与基准指纹、缓冲区转 clean。
3. **编辑交互（Views）**：Markdown 文件标签提供 Source / Preview 分段切换——默认 Preview（复用会话消息的 `MarkdownDocument` + `MarkdownDocumentView` 渲染**缓冲区**文本，未保存标识如实呈现）；Source 为等宽 `TextEditor` 绑定缓冲区；带行号定位请求（`dcode-workspace-file?line=`）优先 Source 态并保留行高亮。标签条显示脏点；⌘S / 保存按钮触发保存；状态条呈现已保存 / 未保存 / 保存中 / 冲突 / 失败。非 Markdown 文件维持 `0.0.4` 只读行渲染不变。
4. **冲突与关闭保护**：冲突态呈现三选（重新加载磁盘版本、显式覆盖保存、继续编辑）；关闭 dirty 标签弹确认（保存并关闭 / 不保存 / 取消）；授权撤销后缓冲区可继续编辑但保存禁用并说明原因；App 重启如实丢弃缓冲区，不建持久草稿。
5. **缺口收口**：
   - Host `model-providers` 测试补嵌套断言：models.json 含 `modelOverrides.m1.headers.X-Token` 时 `list()` 视图不得出现 token 正文。
   - Swift 补回归测试：`openSearchResult` 发送 `session.open` 参数含 `mode:"writable"` + `expectedEntryId` 且无 `expectedEntryDigest`；删除 `SessionOpenRequestPlan.searchResult(_:)` 死代码及其测试。
   - `dcode-facts.ts`：`changes.source` 判定改生产值 `"structured-tool-v1"`；project 归属匹配对 `cwd` 与 `folder.path` 做符号链接规范化（对齐 Swift `ProjectSessionOwnershipResolver`）；Host 测试夹具改用 Swift 编码器真实输出形状（golden fixture）并以生产值写 `source`。
   - 文档同步：40-版本实施方案 README 已知缺口清单与 PRD 0016 / 0017 对应条目按实际状态刷新。

## Confirmed Constraints（已确认约束）

- 边界全部服从 ADR 0025：Swift 进程内直写、同目录原子替换、内容指纹判冲突、绝不盲目覆盖、缓冲区内存态、关闭确认、授权撤销保存禁用、编辑不进入模型 Context。
- 编辑沿用读取的 2MB 与二进制 / UTF-8 检测上限；超限或非文本文件不可进入编辑。
- 不修改 Host 协议；会话写入所有权（ADR 0018）、会话账本（ADR 0010、0021）不受影响。
- Preview 渲染复用既有 Markdown 呈现合同（含 256KB 富文本上限的降级行为），不引入第二渲染器或 WKWebView。

## Acceptance Criteria（验收标准）

- [x] Markdown 文件可进入编辑：Source / Preview 切换、等宽编辑、⌘S 保存；非 Markdown 文件与带行号定位的只读路径行为不回退（渲染冒烟 + 非 Markdown 不可编辑用例；行定位打开默认 Source 态）。
- [x] 保存原子性与失败关闭：保存成功后磁盘为新内容、权限位保留、无临时文件残留（0o640 权限保留断言）；保存失败原文件零改动、缓冲区与脏状态保留并显示原因（授权撤销 / 越界 / 符号链接 / 超限用例）。
- [x] 磁盘冲突可辨认：外部修改后保存被拒绝并进入冲突态，三选动作（重新加载 / 覆盖 / 继续编辑）各自语义正确（继续编辑后普通保存仍拒绝、覆盖必须显式）；预览跟随缓冲区（`task(id:)` 防抖重渲，脏态提示"尚未写盘"）。
- [x] 未保存状态可辨认：标签脏点、标题栏"未保存"徽标、关闭确认（保存并关闭 / 不保存 / 取消）、停止编辑的放弃确认均落地；App 重启如实丢弃缓冲区，不建持久草稿。
- [x] 授权撤销后保存禁用并说明；缓冲区保留可编辑（用例：零写入、失败消息、缓冲区保留）。
- [x] 嵌套 headers 脱敏：Host 断言 `modelOverrides.<model>.headers` 值正文不进入 `list()` 视图（含 `modelOverridesJson` 恒 null）。
- [x] 搜索打开回归：Swift 断言 `openSearchResult` 为 writable + `expectedEntryId` 且无 `expectedEntryDigest`（回归钉子）；死代码 `searchResult(_:)` 及其测试移除。
- [x] `dcode_facts`：`changes.source` 按生产值 `structured-tool-v1` 判定不再错误标注；project 归属经符号链接路径仍可匹配（专用用例）；测试夹具为 Swift 真实形状（golden fixture，字段完整对齐 Swift 编码器）。
- [x] `swift test`（224 用例）、`cd host && npm test`（139 用例）全绿；App / Host / lock 版本统一提升 `0.0.17`。
- [ ] 人工验收：真实项目内编辑一个 `.md` 文件 → 外部工具并发修改 → 冲突三选各走一遍 → 覆盖保存后磁盘内容与权限核对；⌘S、关闭确认、授权撤销保存禁用实机各一次。
