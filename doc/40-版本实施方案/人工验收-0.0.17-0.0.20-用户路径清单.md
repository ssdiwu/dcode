# D Code 0.0.17–0.0.20 人工验收 · 用户路径清单

状态：Active（验收辅助文档；权威验收条目仍在各 PRD，本页只回答一件事——**以用户的身份走一遍，路径对不对**）

用法：按顺序走，每条做完在 `[ ]` 打勾；不对就记下条目号和你实际看到的样子。判定只看界面可见行为，不需要看日志。准备材料：一个真实项目（含 Source Folder）、一张内容明确的本地图片（比如截一张写着某句话的图）、任意一个非图片文件、可以临时断网的环境。

---

## A. 日常输入路径（0.0.20）

**A1. [ ] 启动即输入** — 打开 D Code,光标直接落在首页输入框，不用点一下才能打字。

**A2. [ ] 斜杠出统一面板** — 在输入框打一个 `/`:应该出现一个面板,里面**同时**能看到扩展命令、命令、Skill、Prompt 模板;每行末尾有一个类型标签(扩展 / 命令 / Skill / 模板),每行有一句描述。
  - 不对的样子:只有 mcp、tinyfish 之类扩展命令,找不到 Skill。

**A3. [ ] 输入过滤** — 接着打几个字母(比如 skill 名的一部分):列表应随之缩小到匹配项;按 `↑↓` 能移动高亮,`Esc` 清空,`回车` 把调用文本填进输入框。

**A4. [ ] 悬停看全文** — 鼠标停在某一行上:出现完整描述(类型 + 调用名 + 完整说明),不再只有截断的一行。

**A5. [ ] 模板带参数占位** — 选中一个 Prompt 模板:输入框出现 `/模板名 <参数提示>` 这样的占位,而不是只有光秃秃的名字。

**A6. [ ] 加号干净了** — 看输入框左下的 `+`:它就是 一个加号按钮,旁边**没有**小下拉箭头;鼠标悬停显示"添加附件"说明。

**A7. [ ] 给模型看一张图** — 点 `+` 选一张图片:输入框上方出现附件条(图片名 + 大小 + 移除叉);写一句话(比如"图里写了什么字?")发送。**模型应能答出图里的内容**——这是图片真的进入模型输入的唯一判据。
  - 不对的样子:回复说看不到图、或答错。

**A8. [ ] 引用一个文件** — 点 `+` 选一个非图片文件(比如某段代码):文件的完整路径出现在输入框里,和手写引用一样可编辑;发送后模型按路径去读。

**A9. [ ] 附件不进队列** — 趁一次运行还没结束时,挂着附件点发送(排队模式):应出现提示"带图片附件的消息不能加入后续消息队列",输入框的正文和附件都还在,没有被清掉。

**A10. [ ] 没有无关横幅** — 打开几个会话:不再出现"pi-marketplace loaded"之类的蓝色提示条;设置 › Host 诊断 里仍能查到这些记录(它们只是不该弹出来)。

## B. Markdown 路径(0.0.17)

**B1. [ ] 打开即双栏** — 从文件树打开一个 `.md` 文件:出现"编辑缓冲区 | 预览"切换,预览是渲染后的样子。

**B2. [ ] 改字即见效** — 在编辑侧改一段文字:预览随之变化,**即使还没保存**;头部如实标注这是跟随未保存内容的预览。

**B3. [ ] 保存与未保存状态** — 改动后 `⌘S`:保存成功后"未保存"标记消失,标题/状态回到干净;再改一个字,标记回来。

**B4. [ ] 外部改动要三选** — 保存前用别的编辑器改同一个文件再保存回来:D Code 应弹出冲突选择(以磁盘为准 / 保留我的 / 取消),不会静默覆盖。

**B5. [ ] 关闭有确认** — 有未保存改动时关闭标签:询问是否放弃,不会直接丢。

## C. HTML 路径(0.0.18)

**C1. [ ] 并排编辑 + 预览** — 打开一个 `.html`:左编辑右预览(窄窗口上下排);改动停顿后预览自动刷新。

**C2. [ ] 脚本默认可跑** — 预览里内联脚本生效(比如一个会显示当前时间的页面能显示出来)。

**C3. [ ] 联网默认拦截** — 预览一个引用了外网资源(如 CDN 字体/图)的页面:默认加载不出来,出现"本次允许 / 保持阻止"的询问条;点"本次允许"后本次能加载。
  - 断网验证更直观:断网打开,页面本地部分照常、外部部分空缺且如实提示。

**C4. [ ] 切走就恢复拦截** — 对当前预览点过"本次允许"后,切到别的文件再切回来:拦截恢复默认,不会一直放行。

**C5. [ ] 保存语义与 B 一致** — HTML 的保存、冲突、关闭确认行为与 Markdown 一致。

## D. 恢复路径(0.0.19 + 0.0.20)

**D1. [ ] Host 断了能重连** — 用活动监视器退出 `node`(D Code Host)进程:侧栏出现失败状态和"重新连接 Pi Host"按钮;点击后回到刚才的会话,输入和草稿没丢。**不需要重启整个 App。**

**D2. [ ] 半条记录的修复卡** — 模拟中断残留:复制一个会话文件,用终端把末尾截短一点(命令见文末"附:制造测试材料"),再打开它:出现橙色修复卡,说明"尾部一条记录不完整";**修复卡里直接展示那条被截断记录的完整内容**(记录的原始文本,通常是一段以你那句话开头的 JSON,能认出正文即可),可选中复制;点"备份并修复后打开"后会话正常打开,被移除的只剩那半条,其余消息一条不少。
  - 不对的样子:修复卡只有一句"尾部不完整",看不到内容;或修复后多了/少了别的消息。

**D3. [ ] 更严重的损坏不硬修** — 把会话文件中间一行改坏再打开:D Code 明确说打不开、不提供"修复"按钮——诚实拒绝,而不是修出一个错版会话。

**D4. [ ] 发送失败不丢也不重** — 制造一次发送失败(比如发送前把 Wi-Fi 关掉):失败的正文和附件**回到输入框**,可以改完再发;恢复网络后再发一次,对话里这条消息**只出现一次**,不会出现两条一样的。
  - 已知边界(按设计):如果 Host 进程中途重启过,防重登记会丢失,同一条消息理论上可能再执行一遍——当前版本如实接受这一点(文档已写明),验收时不算缺陷,遇到就记下来。

**D5. [ ] 存储状态可查** — 设置 › Host 诊断 › 本机存储状态:各条目显示正常;人为弄坏(比如把某个 json 改成乱码)后对应条目显示熔断原因,且有"重试保存"按钮。

**D6. [ ] 移除目录有交代** — 项目设置里移除一个 Source Folder:出现提示,说明多少个已打开的文件标签失去授权、多少会话不再属于这个项目——不是无声消失。

## 附:制造测试材料

**半条记录的会话**(用于 D2):在访达进入 `~/.pi/agent/sessions/`,复制任意一个 `.jsonl` 到同目录并改名(保持 `.jsonl` 结尾),然后终端执行(把路径换成你的文件):

```bash
printf '%s' "$(cat 文件路径)" > 文件路径.tmp && mv 文件路径.tmp 文件路径
```

这会去掉末尾换行,模拟"写到一半"。恢复原状:删掉复制的文件即可,原会话不受影响。

**中部损坏的会话**(用于 D3):同上复制后,用任意文本编辑器把中间某一行改坏(删掉一个引号)保存。
