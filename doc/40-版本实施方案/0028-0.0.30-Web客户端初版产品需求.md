# D Code 0.0.30 Web 客户端初版产品需求

状态：修复候选，未提交、待 507 人工验收。2026-09-05 对 `main@1d4fd48` 审查后，507 授权修复；前次“机器自验通过”不足以证明核心操作可用。范围仍由 ADR 0044、0003 与本 PRD 拥有。

本 PRD 只交付 Web 客户端的**初版画面与壳**：以 Electron + React 壳消费既有 `host/` 与 Protocol v1，落地已拍板的主页面三区布局，验证打包链与动效基线。不新增任何产品能力；发现 Host 或协议缺口回到对应版本修复，不在本版补造。

## Problem Statement（问题陈述）

`0.0.29` 基线的 SwiftUI 客户端迭代速度无法承载「原型逐区拍板后快速落地」的节奏：每次界面合同变更都要付出原生侧重验成本，507 已明确不可接受。同时主页面布局合同（三区、浮动梗概、详情侧栏、稳定几何）已于 2026-09-05 拍板但尚无消费它的客户端。本版用已实证的 Web 技术栈建立新客户端主路径，验证从窗口、核心拉起到真实数据上屏、打包候选的完整链路。

## Solution（解决方案）

### 1. Electron 壳（平台壳）

- 主进程只承担 [0003 议题二](../10-架构与运行/0003-Web客户端技术栈.md) 的七项职责：窗口 / 菜单 / 快捷键、系统通知（设置可开关）、文件选择对话框、系统权限出面、Host 定位 / 启动 / 健康检查 / 受控重启、事件转发、检查更新占位。
- 判断口诀不变：门面职责必须「换个产品也通用」。
- `0.0.30` 只建一个系统窗口；梗概浮卡与详情侧栏均为主窗口内部布局。

### 2. Host 接入（议题一 / 议题六）

- Host 保持独立子进程：主进程以 Electron 二进制 Node 模式（`ELECTRON_RUN_AS_NODE=1`）执行 `host/dist` 入口，环境按现有 Swift `HostLocator` 合同平移（`PI_CODING_AGENT_DIR`、`NO_COLOR`、`NODE_OPTIONS` 告警抑制）；不再单独打包 Node 运行时。
- 传输为 stdio 管道直迁，Protocol v1 零改动；首版消费 `host.hello` 握手、`foundation.snapshot` 查询与既有事件信封。
- 电话线预铺三条约束随首版代码成立：协议编解码与传输解耦（纯 TS 协议客户端模块）、渲染层永不直接触碰传输（一律经主进程桥接的版本化 IPC）、升级路径（本地服务 + token + 就绪探测）只留接口不实现。

### 3. 主页面三区布局（消费既有拍板）

- **导航区**：身份与轻工具、创建动作、最近工作、项目（含 Task 与已启动子会话）、独立任务、底部设置——按[主页面 UI/UX 设计](../20-产品与交互/0002-D-Code-主页面-UI-UX-设计.md)顺序与文案映射。
- **工作区**：默认内容为当前 Task 的任务对话（Coordination Session）；Workspace Tab 合同进入但 `0.0.30` 只读。
- **信息区两态**：梗概 = 右上浮卡（不挤占任务区），内容合并进度追踪与 Agent Team 追踪（HUD 四分区与信息面板五组合并为最终梗概，形态以本版 PRD 冻结稿为准）；详情 = 从侧边新开的整幅子栏，打开时挤压任务区宽度且梗概让位，关闭恢复。
- **稳定几何规则**是验收硬项：任何选中、悬停、展开不得改变既有行的行高、列宽、列位置或滚动位置；当前态只用颜色、描边与图标表达。

### 4. 呈现层（议题三 / 议题七）

- Vite + React + TypeScript；zustand 管画面小账、swr 消费 Host 投影，配自动检查禁止核心数据类型进入 zustand。
- Tailwind v4 + Radix/shadcn + Motion 三件套；动效参数（浮层、悬停、转场）在本版定基线并写入设计系统回写。
- 只读内容用 Shiki 上色；不引入编辑引擎与终端部件。

### 5. Swift 客户端替换与拆除策略（2026-09-05 507 指令）

- **按面替换、验证即删**：0.0.30 开发中，每个界面被 Web 实现并通过对应验收后，同批删除 Swift 侧对应实现；验收时仓库不得残留同一界面的双实现。
- 回退依赖 git 基线（`714a555` 及其后提交），不依赖并行代码；`app/build.sh` 打包链随最后一批 Swift 界面拆除一并退役，由 electron-builder 候选链接管。
- `host/`、`Package.swift` 之外的 Swift 侧共享合同（如 HostLocator 语义）以移植而非保留的方式进入 Electron 主进程。

### 6. 打包与候选

- electron-builder 产出可双击的本地 `.app` 候选；候选隔离、显式重启与回滚沿用 ADR 0022 精神，签名 / 公证要求沿既有发布纪律，完整更新链路归发布专项（本版只有检查更新占位）。

## User Stories（用户故事）

- 作为 507，我双击候选 `.app`，看到真实 `~/.dcode/` 里的项目、任务与会话，而不是模拟数据。
- 我在导航区切换任务，工作区进入任务对话，切换不停止任何后台 Runtime。
- 我打开梗概浮卡，能同时看到任务进度和团队成员（谁在跑、谁在等我）；点开一个对象，详情侧栏展开并挤压任务区，关闭后恢复。
- 我重启 App，工作台选择、梗概分区与阅读位置从 Product Store 恢复。
- 我全选、悬停、展开任何行，已有内容纹丝不动。

## Confirmed Constraints（已确认约束）

- 层级语义服从 [ADR 0042](../决策档案/0042-客户端呈现与-D-Code-Host-写入边界.md) / [ADR 0044](../决策档案/0044-Web客户端与桌面壳技术栈边界.md)：渲染层不写 Product Store、Project Directory 或凭据；凭据红线与存储三档落点服从 0003 议题四。
- 不修改 `0.0.28` Product Store、Runtime Supervisor、Prompt / Tools 合同；不新增能力（无派发、无多目录、无编辑、无终端、无电话线启用）。
- macOS-only；不做跨平台抽象。
- 界面文案简体中文优先，术语服从根 GLOSSARY 与主页面文案映射。

## Acceptance Criteria（验收标准）

1. 可双击 `.app` 候选启动、退出、重开；退出走 Host 优雅停机（等 Run 收口，超时强杀）。
2. 主进程以 Node 模式拉起 Host 并完成 `host.hello` 握手；Host 崩溃时窗口存活并呈现恢复入口，可单独重启 Host。
3. 导航区 / 工作区 / 梗概浮卡 / 详情侧栏按第 3 节合同呈现真实 Product Store 数据（`foundation.snapshot` 及既有查询）。
4. 稳定几何规则通过 507 走查（选中 / 悬停 / 展开零位移）；Motion 动效基线（浮层、悬停、转场参数）成立并回写设计系统。
5. `host/` 全量测试保持绿；client 侧新增自动化（协议客户端单测 + 壳冒烟：拉起 Host → 握手 → 查询 → 退出，不开窗口可跑）。
6. 通知可开关；检查更新为占位。
7. Swift 按面拆除清单执行完毕：已验证面无双实现残留，仓库体积不因并行客户端膨胀。
8. 507 人工试玩确认后，ADR 0044 转 Accepted。

## Eval Scope（评测范围）

- 从打开到看见真实任务数据的链路是否诚实（无模拟数据兜底）。
- 梗概「进度 + 团队」与详情挤压式侧栏是否符合两态心智；几何稳定性是否经得起连续操作。
- 壳 / 核心 / 画面三层职责是否守住（画面无产品写入路径）。

## Out of Scope（非目标）

- 轻量派发、多目录项目（0.0.31 / 0.0.32）；电话线启用与多端接入。
- 编辑缓冲区、终端、命令面板、附件、图片发送等既有能力的完整迁移——未被本版验收清单覆盖的界面保留在 Swift 侧直至被替换。
- 自动更新链路、签名分发、跨平台。
