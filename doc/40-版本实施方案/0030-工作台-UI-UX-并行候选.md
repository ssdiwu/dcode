## 当前验收修正：输入栏入口整合

### 问题与用户路径

新任务的项目选择单独放在输入卡下方，增加一行独立控件；常驻技能按钮与“＋”分散了添加内容的入口。507 要求将项目选择收进输入栏下方的操作区，并将技能放入“＋”菜单，让归属、添加内容和发送设置在同一个输入区域内完成。

1. 新建任务时，在输入框内部、文本区下方的底部工具栏选择项目；它位于左侧“＋”附近，与右侧模型、思考强度及发送控件共用底部工具栏，不再在输入卡外单独占一行。
2. 可选择现有项目或“独立任务”。这里只调整入口位置，不改变 Project Scope / User Scope：独立任务仍是不归属项目的任务，不能被解释为单智能体模式。沿用按归属分别保存草稿的既有行为：切换后显示该归属的草稿，原归属的文字与附件仍保存，返回时可恢复；不把当前草稿搬移到目标归属或覆盖其已有草稿。首次创建使用当前所选的真实归属；已有任务不因此获得隐式迁移归属的入口。
3. 点击“＋”可以选择图片、文件或技能/命令。移除工具栏常驻“技能”按钮；输入 `/` 仍直接打开同一技能/命令选择能力。入口名称和无障碍名称应覆盖其实际用途，不能继续只称“添加附件”。
4. 从“＋”进入技能选择时，添加菜单关闭，技能浮层打开，输入焦点与草稿保持连续。选择内容后回到输入，取消不插入或发送文本。技能的显示名、实际调用标识、参数保留及提交原文规则不改变。
5. 主对话与成员子对话共用一致的添加入口；成员提及、接收者、排到后面/补充当前工作、附件、模型、思考强度和发送/停止继续按既有行为工作。任务归属选择仅出现在适用的新任务草稿。
6. 长项目名允许有界省略并可查看完整名称；窄窗口可在同一个底部工具栏容器内合理换行，不能恢复成输入卡外的独立项目行，也不能遮挡发送/停止或让模型控件无法使用。加载、未连接、读取附件及错误提示仍由真实状态决定，不为压缩行数隐藏必要反馈。

### 验收标准

- [ ] 新任务未选项目、已选项目、无可选项目及长项目名下，归属选择均位于输入卡内底部工具栏，输入卡外不再出现单独项目胶囊；在两份非空草稿之间切换及返回时，各自文字与附件可恢复且不相互覆盖，首次发送的实际 Task 归属正确。
- [ ] “＋”菜单可进入图片、文件与技能/命令；工具栏无重复技能按钮，`/` 快捷入口仍可用。点击、取消或选择不会意外发送消息。
- [ ] 从“＋”打开技能列表后，方向键、Enter、Escape、Tab 与输入法组合态符合既有选择合同；菜单关闭不会误关技能浮层或把焦点留在已消失的控件。长列表可滚动、搜索并选中末尾项目，选入原始调用标识及参数不变。
- [ ] 主对话、成员子对话、运行中排队/补充、附件添加及发送/停止回归通过；已有任务不出现新的归属迁移行为。
- [ ] 深浅主题、项目长名称、项目列表为空、正常及最小支持窗口、已有三档字号下布局可用；共享输入焦点检查和实际 Chromium/Electron 路径通过，实际键盘或人工观感未验证时分别标注。

## 第一批：新任务与主题

1. 新任务由真实草稿入口进入，品牌、标题、输入卡与归属选择在主工作区居中编排；使用当前 C-A 品牌。已有任务即便没有消息也不进入创造背景。
2. 背景仅用于新建任务草稿，使用精确注册的 StructureFlowCollection：`structure-flow`、`speed=1`、`pointSize=.08`、`opacity=.4`、`maskStart=.2`、`maskSolid=.5`。五份源码保持原文和 SHA-256。
3. 深色暗底白粒子、浅色浅底黑粒子；浅色仅反相背景外层，内容不反相。灵感、设置、已有对话不创建该 WebGL 实例。
4. 页面隐藏、退出新任务释放场景；返回重新挂载。减少动态效果、没有 WebGL、上下文丢失或场景加载失败时使用静态背景，输入/草稿/发送照常工作，不用另一种仿制粒子替代。
5. ⌘N、首次提交、输入法确认、Shift+Enter、附件与真实模型选择沿用现有流程；返回之前任务不清空未提交草稿。只有真实创建成功才进入任务。
6. 外观设置沿用 `clientPreferences` 与 Electron `nativeTheme`。颜色扩散以操作按钮当前矩形中心为原点，键盘同样成立；持久化与桌面主题生效后捕获新画面。减少动态效果或不支持 View Transition 时直接切换；保存失败仍显示错误。
