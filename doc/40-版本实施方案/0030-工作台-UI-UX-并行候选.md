## 当前验收修正：项目行操作与文件查看

### 问题与目标

项目行目前只有展开收起和编辑齿轮，用户不能在此直接开始该项目的任务。文件浏览和右侧详情分别已有能力，但文件正文目前占用中央消息区，用户无法同时阅读对话与文件。507 于 2026-09-12 确认：复用现有区域，左侧找文件、中央保留对话、右侧查看内容；需要更大阅读或编辑空间时由用户主动展开。先落文档，再分批实施。

用户提供的 ChatGPT/Codex 截图确认了项目管理菜单与项目内新对话两种动作；本机 ZCode 实际查看确认了“更多 / 查看文件 / 新建任务”、左侧文件树与返回任务入口。它们只提供交互参考，不证明 D Code 已实现，也不使参考菜单的全部能力进入本版。

### 项目行与新任务

1. Project 主行仍负责展开或收起所属任务。右侧依次提供“更多”“查看文件”“新建任务”；分别使用省略号、文件浏览与书写 SVG 图标，具有清楚的提示和无障碍名称。按钮操作不触发行展开，悬停不推动标题位置，键盘可达，不依赖只能鼠标发现的操作。
2. “更多”先承接现有“编辑项目”及既有名称、目录维护合同；本版不增加移除项目、项目置顶、分区、批量归档、永久工作树或 Finder 通用入口，也不展示尚未接通的空菜单项。原项目分区“＋”继续用于创建项目。
3. “新建任务”进入所点 Project 的 Task Draft 并聚焦输入；草稿已有文字、附件和当前发送设置按既有合同恢复。其他 Project / User Scope 草稿保留，不搬移或覆盖；首次发送才创建属于该 Project 的 Task 及其协调会话，不能解释为向当前任务添加成员。
4. 即使目标项目上次停在文件浏览或展开内容中，新建任务仍应让输入入口可见可操作，文件标签与未保存编辑保持可返回的状态。未发送前离开不创建空 Task；创建或运行失败沿用既有真实状态与重试规则，不把失败伪装成成功。全局新任务入口继续可用。

### 区域分工与连续操作

| 区域 | 确认行为 |
|---|---|
| 左侧导航 | 默认项目/任务列表；点击“查看文件”后同一栏切换到所点项目的文件树，显示项目来源与“返回任务”。只浏览文件不要求先创建 Task。已有 Git 文件列表沿用这里，完整文件树不再重复塞入任务概览。 |
| 中央对话 | 默认持续显示原 Task / Session 的消息与输入栏；文件选择不改变对话、滚动位置、草稿、附件、运行身份或后台执行。 |
| 右侧信息检查器 | 选择文件后直接显示正文、预览或差异，以及项目、路径和适用操作。已有产物/报告/证据详情继续使用同一区域；具体产物文件也遵循同一打开方式。 |
| 主动展开 | 用户明确选择展开后，同一内容临时借用中央空间；提供“返回对话”收回至右侧。仅改变呈现空间，不新建窗口、任务、会话或第二份编辑缓冲区。 |

- “返回任务”只恢复左侧导航，不切换中央任务、关闭右侧内容或丢弃未保存编辑；收起右侧详情与关闭一个内容标签是不同动作。收起、切换容器或浏览来源保留当前运行期的编辑缓冲；主动关闭未保存标签沿用保存、放弃、取消保护。进程退出后的缓冲恢复沿用既有合同，不新增未保存正文的持久化承诺。
- 中央讨论 A 项目时可以查看 B 项目：文件导航、标签、读取、保存与差异均绑定 B 的真实来源；对话及输入仍属于 A，不把 B 的文件变化归因给 A 的任务或运行。来源不能仅由当前会话或同名文件推断。切换任务或浏览项目时，已有内容的来源不被重绑；重回同一文件复用其标签和缓冲。
- 文件树、有效消息文件引用、既有 Git 差异和产物文件入口共用默认右侧打开规则；目录引用定位文件导航，行引用定位到目标位置。打开、浏览、展开或收回不自动向模型添加文件/上下文，不产生消息或改变 Git；只有用户明确引用或保存才进入对应既有合同。
- 普通文件、Markdown 富预览/编辑、HTML 隔离预览及 Git 差异沿用现有能力，不因容器变化扩大可写类型或新增 Git 写操作。保存继续经过 Host 与已有冲突检查、目录重验及运行写入保护；只读、受保护、磁盘已改或保存失败应有可见原因且保留缓冲，不因迁移视图绕过保护。
- 无目录、目录不可访问、目录维护未完成、文件已移动/删除、过期行号、读取失败或不支持的类型，应在文件区域显示真实状态与适用的重试/返回操作；不能退到其他项目或用户主目录充当成功。旧来源的迟到读取/预览结果不能覆盖新选择，也不能改写标签保存目标。
- 详情打开时任务概览暂时让出，关闭后恢复此前显示状态；任务概览继续只负责进度、成员、等待事项、交付物与可证明的任务变更摘要。本批不重做其常驻策略或动效。
- 宽窗口保持导航、对话、详情并列；窄窗口沿用现有响应式覆盖规则和明确的收起/返回入口，不因宽度不足自动展开编辑或清空内容。复用共享栏宽及输入焦点规则；进入设置再返回时来源、草稿及已打开内容保持一致。主动展开和收回均保留阅读位置与编辑状态。

### 验收标准

- [ ] 项目行三个独立动作可通过鼠标及键盘操作：更多进入真实编辑项目，文件按钮进入对应文件树，新任务进入该项目输入；它们不触发行展开，不显示未支持的参考菜单动作。
- [ ] 两个项目与独立任务各持非空文字/附件草稿，从项目行新建、返回、再进入时各自恢复；目标曾打开文件或处于扩展视图也不挡住输入。取消不新增 Task，首次发送后的 Task 归属与协调会话正确；原任务和成员后台执行不受影响。
- [ ] 在没有 Task 时直接浏览项目；在 A 对话中浏览 B 项目，同名文件显示并使用准确来源。返回任务导航后 A 对话及其草稿不变，B 的标签、正文和编辑保存目标仍正确；导航操作本身没有调用模型或修改文件。
- [ ] 通过项目文件树、消息文件/行引用、既有 Git 差异和产物入口打开内容，默认全部进入右侧；中央消息继续可读，输入、运行中补充和停止可用。任务概览与详情按原显示状态切换，不重复出现完整文件树。
- [ ] 同一文件反复打开、切换标签、切换浏览项目、切换任务、进入设置再返回均不重复或重绑缓冲；收起详情、主动展开、返回对话后滚动、草稿、附件和未保存编辑保持。主动关闭脏标签的保存/放弃/取消各自成立；关闭最后一个标签回到对话。
- [ ] 真实文件读取与保存、Markdown/HTML 编辑预览、Git 差异回归；覆盖磁盘变更冲突、运行目录写保护、读取/保存失败及文件不存在。失败不能冒充已保存或重建目录；新旧来源交错返回不会串内容或串写入目标，HTML 预览继续隔离且不遮住菜单或输入控件。

## 当前验收修正：输入栏入口整合

### 问题与用户路径

新任务的项目选择单独放在输入卡下方，增加一行独立控件；常驻技能按钮与“＋”分散了添加内容的入口。507 要求将项目选择收进输入栏下方的操作区，并将技能放入“＋”菜单，让归属、添加内容和发送设置在同一个输入区域内完成。

1. 新建任务时，在输入框内部、文本区下方的底部工具栏选择项目；它位于左侧“＋”附近，与右侧模型、思考强度及发送控件共用底部工具栏，不再在输入卡外单独占一行。
2. 可选择现有项目或“独立任务”。这里只调整入口位置，不改变 Project Scope / User Scope：独立任务仍是不归属项目的任务，不能被解释为单智能体模式。沿用按归属分别保存草稿的既有行为：切换后显示该归属的草稿，原归属的文字与附件仍保存，返回时可恢复；不把当前草稿搬移到目标归属或覆盖其已有草稿。首次创建使用当前所选的真实归属；已有任务不因此获得隐式迁移归属的入口。
3. 点击“＋”可以选择图片、文件或技能/命令。移除工具栏常驻“技能”按钮；输入 `/` 仍直接打开同一技能/命令选择能力。入口名称和无障碍名称应覆盖其实际用途，不能继续只称“添加附件”。
4. 从“＋”进入技能选择时，添加菜单关闭，技能浮层打开，输入焦点与草稿保持连续。选择内容后回到输入，取消不插入或发送文本。技能的显示名、实际调用标识、参数保留及提交原文规则不改变。
5. 主对话与成员子对话共用一致的添加入口；成员提及、接收者、排到后面/补充当前工作、附件、模型、思考强度和发送/停止继续按既有行为工作。任务归属选择仅出现在适用的新任务草稿。
6. 长项目名允许有界省略并可查看完整名称；窄窗口可在同一个底部工具栏容器内合理换行，不能恢复成输入卡外的独立项目行，也不能遮挡发送/停止或让模型控件无法使用。加载、未连接、读取附件及错误提示仍由真实状态决定，不为压缩行数隐藏必要反馈。
