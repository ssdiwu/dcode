# D Code 0.0.1 用户首页与项目工作台产品需求

状态：Released（已验收发布，`v0.0.1`）

适用范围：在已经可运行的原生会话基线上，交付第一个按新产品模型组织的可验收版本

基线依赖：[首个可日常使用版本产品需求](0001-首个可日常使用版本产品需求.md)继续作为 Baseline Regression（基线回归）约束；其中已经成立的会话读取、聊天、安全、Active Plan、Mermaid 与结构化交互不得回退，会话入口已按本规格演进为持续观察与按需写入。

## Problem Statement（问题陈述）

当前 D Code 已能读取和继续 Pi Session（Pi 会话），但界面仍把每个 `cwd` 直接当作工作区分组，启动时一次读取 60 条摘要并自动打开第一条完整对话。它没有 D Code 自己定义的 Project（项目），也无法表达一个工作主题包含多个 Source Folder（源文件夹）。项目文件、模型选择、思考强度、极速状态和上下文占用也没有形成已经确认的信息层级。

这会导致后续搜索、会话路径、文件预览、Goal（目标）和 Agent Team（智能体团队）继续依附在错误的导航结构上。`0.0.1` 必须先建立最终工作台骨架与正确的 Project—Source Folder—Pi Session 关系，同时保留现有可运行会话能力。

## Solution（解决方案）

交付一个以 User Home（用户首页）为默认入口、以 D Code Project 为组织对象、以 Pi Session 为对话权威的原生三栏工作台：

- 冷启动只读取并显示最近 10 条由 D Code 创建的 Session Summary（会话摘要），用户选择后才加载完整对话；“查看更多”每次继续读取 10 条更早摘要。未关联到 Project 的旧 Pi Session 不在首页导航中暴露。
- 用户可以创建、编辑 D Code Project，并为一个 Project 添加多个 Source Folder；同一规范化目录同时只能属于一个 Project。
- Project 下把所有 Source Folder 对应的 Pi Session 按更新时间平铺，来源文件夹显示在会话标题下方，不形成文件夹分组。
- 点击 Project 主行直接进入项目作用域并显示只读文件树与真实 Git Changes（变更），不要求先打开任何 Session，也不改变中央当前 Session、对话、滚动位置或 Composer（输入框）草稿。
- 左栏默认展开；右侧 Work Inspector（工作检查器）在宽度充足时自然显示，空间不足时自动隐藏并可覆盖打开。
- 模型、思考强度、极速开关和上下文占用集中在 Composer 底部，使用真实 Host 状态，不在会话标题或工作检查器中重复。
- Composer 不展示通用“能力状态”或 Pi footer；已成立的 Plan、工具、Fast 与 Context 由 D Code 原生组件呈现，被忽略的纯展示提示不打断用户。
- 选择既有 Pi Session 后直接显示正常 Composer，并持续同步其他 Pi 客户端已经完整持久化的新消息；发送或修改运行设置时才按需取得单写入权，不出现默认“只读/继续”流程。
- 左栏底部的齿轮、应用菜单“设置…”与 `Command-,` 打开同一个 macOS 原生设置窗口；`0.0.1` 只管理已成立的系统/浅色/深色外观与工作台布局偏好。

## Product Model（产品模型）

### User Home 与 Recent Sessions（最近会话）

- User Home 是 D Code 的全局入口，以当前 macOS 用户名标识使用者；它不是会话扫描边界，也不把用户主目录设为 Session 的 `cwd`。
- 冷启动不自动选择或打开任何 Session；最近会话只读取摘要，不预加载 transcript（对话正文）。
- Recent Sessions 只包含由 D Code 创建且在同一 Pi JSONL 中保留有效来源标记的 Session。打开、续写或观察旧 Pi Session 不会把它转换为 Recent Session。
- 来源标记是不进入模型上下文的结构化 Pi Custom Entry（自定义条目）；其 `sessionId` 必须与 Session Header（会话头）相同，避免由其他工具复制的会话被误认为 D Code 创建。
- Recent Sessions 首批与每次“查看更多”均为 10 条，在来源筛选后按最后更新时间降序排列。
- 同一稳定 Session ID 可以同时出现在 Recent Sessions 与所属 Project 中；两处选择后打开的是同一个 Pi Session。

### D Code Project 与 Source Folder

- Project 是 D Code 自有的本机组织元数据，包含稳定 ID、名称、顺序与 Source Folder 集合；它不是 Pi Session、Pi 会话目录、Git 仓库或任一 `cwd`。
- Source Folder 使用规范化真实目录作为身份。同一目录同时最多属于一个 Project；再次添加时必须显示当前归属，并由用户明确确认“移动到此项目”。
- 创建、编辑、删除 Project 或移动 Source Folder 只改变 D Code 组织元数据，不移动真实文件、不改写 Git，也不修改 Pi Session JSONL。
- Project 会话只关联规范化 `cwd` 与 Source Folder 完全相同的 Pi Session；不会因登记父目录而自动吸收任意后代目录会话。
- 旧 Pi Session 只有在用户把它的确切 `cwd` 登记为 Project Source Folder 后，才出现在该 Project 的会话列表；关联不会为会话追加 D Code 来源标记。
- Project 会话首批与每次“查看更多”均为 10 条，跨全部 Source Folder 按最后更新时间平铺；每条显示标题、来源文件夹与时间。
- 在 Project 内新建 Session 时，必须从该 Project 已登记的 Source Folder 中选择一个；选择结果成为新 Session 的真实 `cwd`。

### Work Inspector 与文件树

- Work Inspector 的 Project 作用域显示该 Project 全部 Source Folder，每个文件夹是一个可展开根节点。
- `0.0.1` 文件树只用于查看真实目录结构：文件不打开中央标签、不加入模型 Context（上下文）、不创建消息，也不改变文件或 Git 状态。
- 文件树按需读取展开目录；不可访问、已移除或读取失败的目录显示就地错误，不伪装为空目录。
- 符号链接作为节点显示，但不递归跟随，避免逃离 Source Folder 范围或产生目录循环。
- Project 作用域同时提供 Changes，只读查询各 Source Folder 所在 Git 仓库的当前工作区事实；多个 Source Folder 位于同一仓库时按规范化仓库根目录去重。
- Changes 显示仓库根目录、当前分支及变更路径与状态；非 Git 目录、Git 不可用和查询失败均显示真实状态。它不提供 stage、discard、commit、push 或文件回退。
- 选择 Project 与选择 Session 是两个独立状态。选择 Project 只改变检查器作用域；选择 Session 才打开对话并返回会话作用域。

### 响应式三栏

- `≥1280 pt`：左栏、中央对话与右栏并排；右栏可由用户主动隐藏并可再次恢复。
- `880–1279 pt`：左栏常驻；右栏因空间自动隐藏，用户打开时覆盖中央右侧。
- `<880 pt`：中央优先；左右栏均以互斥覆盖面板打开，关闭后必须完全离开命中与可访问性树。
- “自动隐藏”与“用户主动隐藏”是不同状态；窗口恢复到足够宽度时，只有用户没有主动隐藏的右栏才自然重现。
- 原生设置窗口可选择跟随系统、浅色或深色外观，切换“中宽与宽窗口中显示左栏”和“宽窗口中显示工作检查器”，并可恢复默认布局；窄窗口的覆盖面板仍是临时导航状态。设置不复制 Session 模型、极速或上下文控件。

### Composer 运行控制

- 模型与思考强度沿用 Pi SDK 提供的可用值及当前 Session 状态；切换后立刻更新 Composer，且不得清空未发送草稿。
- 上下文占用来自 Pi SDK 的真实 `tokens`、`contextWindow` 与 `percent`。当前无法计算时明确显示“暂不可用”，不得以固定样例或消息数冒充 token 用量。
- 极速是 D Code 自有的会话级发送能力，机制借鉴 `pi-dfast`，不要求安装或调用该扩展包：
  - 新 Session 默认关闭；状态随当前 Pi Session 的活动路径持久化和恢复。
  - 开启且当前模型属于 D Code 明确支持的 `openai-codex` 模型时，仅在下一次符合条件的 Provider Request（提供方请求）中请求 `service_tier: priority`。
  - 当前 Provider（提供方）或模型不支持时，界面显示“已开启但当前模型不支持”，请求载荷保持不变。
  - 极速只表达本地请求 Priority Service Tier（优先服务等级）的意图，不承诺账户资格、服务端接受或实际延迟改善。
- 模型、思考强度、极速与上下文占用不在会话标题和 Work Inspector 中重复显示。

### 共享会话观察与按需写入

- Pi Session 仍是 Pi CLI 与 D Code 共同访问的唯一会话对象。D Code 不复制桌面专用会话，也不要求用户在两个客户端之间执行交接命令。
- 选择既有 Session 后，Host 以内部分离的观察态挂载快照并监控当前 JSONL 文件身份；只有发生变化时才从已知路径刷新，不周期性重扫全部会话目录。
- 观察态是正常产品状态：中央显示完整 transcript 与 Composer，用户可以持续输入草稿；界面不显示“只读”标签或二次“继续会话”按钮。
- 发送消息或修改模型、思考强度、极速属于明确 Write Intent，D Code 此时才通过静默窗口与 Session Lease 取得单写入权。
- D Code 持有写入权期间若检测到外部写入，必须立即停止本次写入、在安全可验证时释放租约、刷新最新历史并回到观察态；未确认发送的草稿逐字保留。停止或 owner 校验失败时保留锁、禁止本进程继续写入并要求重启，但观察仍可用。两个客户端同时写不在 `0.0.1` 支持范围内。

## User Stories（用户故事）

1. 作为日常使用者，我希望启动后先看到最近 10 条由 D Code 新建的会话摘要，而不是用全部 Pi 历史淹没首页。
2. 作为同时维护多个目录的使用者，我希望用一个 D Code Project 组织多个 Source Folder，并在同一列表查看它们的旧会话。
3. 作为项目管理者，我希望一个 Source Folder 只有一个明确归属，移动归属时得到清楚提示，避免同一会话在多个项目中重复分类。
4. 作为正在对话的使用者，我希望点击 Project 查看文件与当前 Git 变化时不丢失当前 Session 和未发送内容。
5. 作为模型使用者，我希望在输入位置附近切换模型、思考强度与极速，并准确知道当前上下文占用。
6. 作为窄窗口使用者，我希望左右栏可完整隐藏和恢复，中央对话始终保持可用。
7. 作为同时使用 Pi CLI 与 D Code 的用户，我希望 D Code 自动显示同一会话新落盘的消息；我可以一直看到输入框，真正发送时再由 D Code 安全取得写入权。

## Confirmed Constraints（已确认约束）

- 平台为 macOS 14+，主界面使用 SwiftUI/AppKit 原生组件；不引入 Web/Electron 产品壳。
- `~/.pi/agent` 继续是 Pi 配置和会话的唯一权威；Project 元数据不得成为第二份会话历史。
- Swift 前端不得直接改写 Pi Session JSONL；所有会话写入继续经过嵌入 Pi SDK 的 D Code Host。
- D Code 只在创建新 Session 时由 Host 将会话头与来源标记作为同一初始文档写入；不追溯改写旧 Pi Session，不根据路径、时间或文件名猜测来源。
- 会话头与有效来源标记一旦作为完整初始文档发布，该 Session 即视为创建成功；后续写入激活失败不得删除、重写、隐匿该 Pi Session 或向用户误报“创建失败”，而应返回已创建对象及可写、观察或暂不可用的激活结果。
- 单写入所有权、静默窗口、Session Lease（会话租约）和外部写入检测不得因持续观察而弱化；观察本身不创建租约。
- 产品界面默认使用简体中文；模型名、命令、文件路径与代码标识符保留原文。
- 现有聊天、工具、流式回复、中止、Active Plan、Mermaid 和结构化标准交互继续可用，但不在 `0.0.1` 增加 Goal、Agents 或 Artifact 的新产品入口。
- Project 组织元数据写入失败或损坏时必须保留原文件、报告可操作错误，不得自动重置成空项目集合。
- 文件树和 Changes 只有读取权限；`0.0.1` 不通过它们执行打开、编辑、删除、移动、stage、discard、commit、push 或其他 Git 写操作。

### User Home 与会话读取

- [x] 隔离 Pi 目录预置至少 12 条不带 D Code 来源标记的旧会话时，冷启动 Recent Sessions 为空，中央保持 User Home，不回退为扫描并显示用户主目录的会话。
- [x] 用 D Code 新建至少 11 条 Session 后，Recent Sessions 首批只显示其中最新 10 条摘要；点击“查看更多”显示第 11 条，重启 App 后仍成立，未选择会话前不发起 `session.inspect` 或加载正文。
- [x] 较新的旧 Pi Session 不会挤掉较早的 D Code Recent Session；来源筛选必须先于 10 条分页限制。
- [x] Recent 扫描只接受 Header 后第二条非空 JSONL 记录中的有效来源标记；未标记旧会话只读取用于判定来源的有界前缀，文件尾后来追加的伪标记或复制后 Session ID 不匹配的标记均无效。
- [x] 新 Session 初始文档发布后，即使可写激活失败，App 仍立即显示该已创建 Session；可进入观察态时明确处于正常观察，观察也失败时提供可重试错误，不出现“创建失败”后重启才突然出现的幽灵会话。
- [x] 新 Session 在初始文档发布前因目录无效或写入失败时，不产生 Recent 条目，也不关闭或伪装关闭当前已打开 Session；原会话仍可继续使用。
- [x] 选择 Recent Session 后打开相同稳定 Session ID，并保留基线中的完整历史、持续观察、按需写入、发送、流式回复、工具、中止与恢复能力。
- [x] 选择既有 Session 后直接显示正常 Composer，标题、右栏和输入区域均不出现“只读”或二次“继续”动作；尚未发送时不创建 Session Lease。
- [x] 在 Composer 输入包含空格和换行的未发送草稿后，由 Pi CLI 向同一 Session 追加完整持久消息；D Code 在 2 秒内自动刷新该消息，草稿逐字保持，且不会重扫全部会话目录。
- [x] 首次发送或修改运行设置时才取得写入权；获取失败不产生 D Code 用户消息、不清空草稿，并继续同步外部历史。
- [x] D Code 写入期间发生外部写入时，Host 中止本次运行并在安全可验证时释放租约；App 刷新外部消息、保留未确认草稿并回到正常观察界面，不继续隐式多写。若停止或 owner 校验失败，未知锁不被强删，观察仍可用，后续写入明确要求重启。

### Project 与 Source Folder

- [x] 用户可以创建一个包含至少两个 Source Folder 的 Project；重启 App 后 Project 名称、顺序和文件夹归属保持一致。
- [x] 两个 Source Folder 的旧 Pi Session 在 Project 下按更新时间平铺；列表中没有 Source Folder 分组行，每条 Session 的副标题显示来源文件夹与时间。
- [x] 未关联 Source Folder 前，旧 Pi Session 不出现在 Recent 或任何 Project；关联后它们才出现在对应 Project，移除关联后消失，全过程不改变 JSONL 字节。
- [x] 由 D Code 在已归属 Project 的 Source Folder 内新建的 Session 可同时出现在 Recent 与 Project，两处的稳定 Session ID 相同，不产生导入副本。
- [x] 把已经属于 Project A 的 Source Folder 添加到 Project B 时，界面显示原归属；未确认时不改变任何项目，确认移动后只改变组织归属。
- [x] Project 的创建、编辑、删除和 Source Folder 移动前后，真实目录、Git 状态、Pi Session ID 与 JSONL 内容保持不变。
- [x] Project 内新建 Session 时必须选择一个已登记 Source Folder；新 Session 的规范化 `cwd` 与选择完全相同。
- [x] Project 会话“查看更多”每次继续取得最多 10 条更早摘要，不读取无关 Session 的完整对话正文。

### 项目选择、文件树与三栏

- [x] 在已经打开 Session 且 Composer 有未发送内容时点击 Project，当前 Session ID、transcript、滚动位置和草稿保持不变；右栏立即显示该 Project 的全部 Source Folder 根节点。
- [x] 文件夹可逐层展开并显示真实子项；不可访问目录显示明确错误；符号链接可见但不会被递归展开。
- [x] 点击文件不会打开中央内容标签、修改文件、改变 Git、加入 Context 或创建消息。
- [x] Changes 按规范化 Git 仓库根目录展示真实分支、路径与工作区状态；同一仓库不重复，非 Git 目录和查询失败有明确说明。
- [x] 打开、刷新或切换 Files/Changes 前后，工作区文件内容、暂存区、分支与提交历史均不改变。
- [x] `1280/1279/880/879 pt` 边界分别符合三栏、右栏覆盖与双侧互斥覆盖规则；用户隐藏后的左右栏均有可见恢复入口，隐藏面板不残留命中区域。
- [x] 右栏因窗口变窄自动隐藏后，恢复宽度会自然重现；用户主动隐藏的右栏不会因放宽窗口擅自重现。

### Composer 运行控制

- [x] 模型、思考强度、极速、上下文占用和发送动作都位于 Composer 底部；会话标题与 Work Inspector 不重复这些状态。
- [x] Composer 不显示通用“能力状态”；`getToolsExpanded` 等纯展示查询不产生全局警告，真正无法完成的交互仍明确失败。
- [x] 空 Composer 的占位文字与输入光标共用首行基线；Return 换行、`Command-Return` 发送，输入超过 7 行后在控件内滚动。
- [x] 切换模型或思考强度、开关极速、展开上下文占用前后，Composer 草稿逐字保持。
