# D Code 0.0.25 项目目录迁移与 Composer 收口产品需求

状态：Published Source Tag（公开源码标签 `v0.0.25`；自动回归已通过，人工验收待完成）

本 PRD 冻结 `0.0.25` 的 Project（项目）目录模型、会话 `cwd`（工作目录）迁移与 Composer（输入区）收口范围。数据身份与迁移边界由 [ADR 0029](../决策档案/0029-Project-目录一一对应与会话-cwd-迁移边界.md) 固定；输入区层级由 [ADR 0030](../决策档案/0030-项目优先-Composer-与能力入口收口.md) 固定。它取代旧 Project 多 Source Folder（源文件夹）模型与“项目改目录只改组织关系”的行为，但不改变 Pi Session 作为会话权威。

## Problem Statement（问题陈述）

当前主页把会话前草稿直接绑定到裸目录，且 Composer 同时放置模型、能力与作用域信息。用户无法在开始任务前一眼判断“这项工作属于哪个项目”；模型名、资源栏目、网页预览与插件入口又占据了本不该属于一级输入区的注意力。

现行 Project 可关联多个 Source Folder，改目录不会迁移既有会话。它与用户的工作心智不一致：一个 Project 应对应一个工作目录；改 Project 目录时，原目录关联会话应保持稳定身份并直接切换到新 `cwd`，而目录内文件是否同行应由用户另行选择。

## Solution（解决方案）

1. **Project ↔ Directory 一一对应。** 每个 Project 恰有一个规范化、可访问的工作目录；同一目录最多属于一个 Project。主页只显示当前 Project 名称，目录、分支和“此项工作归属”等说明不出现在 Composer。
2. **项目目录显式迁移。** 在项目编辑路径选择新目录后，D Code 找出旧目录精确匹配的可见 Pi Session；在所有 Session 空闲、租约稳定且目标目录可用时，保持原 Session ID 与历史，直接改写它们的 Header `cwd`。这不是“复制到项目”，也不创建新 Session ID。
3. **文件迁移是第二步选择。** 目录迁移表单明确提供“同时迁移目录内文件”。不选择时，只迁移 Project 目录与 Session `cwd`；选择时，D Code 在无覆盖、可恢复的文件迁移条件下移动项目目录内容。文件迁移失败不得伪装成功。
4. **Composer 只保留一级任务动作。** 控制行只含 `+`、独立的推理强度和发送；不显示 CPU 图标、模型名或模型下拉。模型选择继续属于设置，当前 Session 的真实模型事实仍可在会话运行信息中查看。
5. **`+` 直接呈现具体能力。** 菜单只出现“添加文件或图片”“Skill”“命令”“目标”“计划”。目标与计划不附加来源名；插件、扩展、本机资源和网页预览不进入此菜单。已有 Workspace HTML 预览与设置中的资源管理不因本 PRD 被删除。

## User Stories（用户故事）

1. 作为持续使用多个代码项目的用户，我希望在开始输入前只选择一个 Project，从而知道本次会话、文件与历史属于同一工作上下文。
2. 作为迁移项目目录的用户，我希望现有会话保留身份但切换到新 `cwd`，从而不必复制或重新开始会话。
3. 作为迁移本机文件的用户，我希望明确决定是否连同目录文件一起移动，从而不会把文件移动误当成项目元数据修改。
4. 作为输入任务的用户，我希望一级界面只保留任务、推理强度与发送，并从 `+` 找到文件、Skill、命令、目标和计划，从而减少不相关控件。

## Confirmed Constraints（已确认约束）

- 只有 Pi Host 可以改写 Pi Session JSONL；Swift 不得直接写 Session 文件。
- `cwd` 迁移只处理旧 Project 目录的精确匹配 Session，不吸收父目录、子目录或不相关路径。
- 迁移前任何目标 Session 运行中、等待交互、租约不稳定或文件版本变化时，操作必须拒绝或中止，不出现部分“已迁移”状态。
- Project 旧数据存在多个 Source Folder 时，必须以显式、无损的迁移路径转换；不得静默丢弃目录或把多个目录合并为一个。
- 文件迁移默认关闭；目标目录冲突、不可访问、跨目录部分失败或无法恢复时不得覆盖现有文件。
- `+` 的 Skill、命令、目标与计划只在对应真实能力已加载时可操作；界面不以来源名、插件名或假开关代替真实能力。
- 固定完全访问的产品决定不变；本 PRD 不恢复权限模式、授权下拉或权限审计。

## Acceptance Criteria（验收标准）

- [x] 新建和编辑 Project 都只接受一个工作目录；同一规范化目录不能归属两个 Project。
- [x] 主页下挂条只显示可操作的 Project 名称，不显示目录、分支、“此项工作归属”或第二个目录选择器。
- [x] 旧多 Source Folder Project 进入明确的无损迁移路径；没有用户可理解的迁移结果时，不写入新 Project 数据。
- [x] 项目目录迁移能在隔离数据中保持所有受影响 Session ID、消息、路径、计划与自定义状态，同时把 Header `cwd` 更新为新目录。
- [x] 迁移中任一 Session 不稳定、目标目录不可用或 Header 校验失败时，Project 目录与所有 Session Header 保持迁移前状态。
- [x] 未勾选“同时迁移目录内文件”时，不改变项目目录中的文件；勾选时只在目标无冲突且完整验证后迁移文件，失败给出可理解结果且不伪装完成。
- [x] Composer 控制行不显示模型名、CPU 图标或模型下拉；推理强度保持独立可见、可操作。
- [x] `+` 菜单只呈现文件或图片、Skill、命令、目标和计划；不出现插件、扩展、本机资源或网页预览。目标与计划的产品标签不出现来源括注。
- [x] 模型设置、已有 `/` 命令面板、图片附件、Workspace HTML 预览和设置中的本机资源管理不发生未授权回归。
- [ ] Host、Swift 回归与隔离迁移端到端测试通过；人工走查主页、`+` 菜单、目录迁移（文件迁移开 / 关）和迁移后打开会话路径。

## Out of Scope（非目标）

- 删除 Pi Session、把目录迁移伪装成会话复制，或为迁移创建新的 Session ID。
- 自动移动、合并或覆盖用户文件；跨目录冲突的智能合并。
- 在 Composer 重新引入插件市场、网页浏览器、权限模式或模型选择器。
- 改写 Pi CLI 的全局模型设置、凭据或不属于目标 Project 的会话。
- 将 dgoal、Skill 或命令来源作为用户界面标签强制展示。
