# D Code 0.0.26 Sol 自迭代候选闭环产品需求

状态：Published Source Tag（公开源码标签 `v0.0.26`；Automated / Web Eval Passed，Native Manual Pending）

本 PRD 冻结 `0.0.26` 的自迭代候选范围。它延续 [0.0.13 第一次 Self-build Loop](0014-0.0.13-第一次-Self-build-Loop-产品需求.md)，并由 [ADR 0031](../决策档案/0031-自迭代候选来源快照与本机分发边界.md) 固定来源、测试、脏工作树与重启边界。Sol 是可选执行模型，不成为构建、测试或验收事实来源。

## Problem Statement（问题陈述）

当前 Self-build 只能从写死的本机源码目录构建；Agent 修改 D Code 后工作树必然变脏，而构建脚本会拒绝脏工作树，导致“改动完成后构建候选”在真实自迭代路径中直接中断。候选卡只验证签名与 App / Host 版本一致，无法证明它来自哪个 checkout、包含哪些未提交变化、是否通过 Swift 与 Host 回归，也无法在重启后核对当前运行构建的来源。

这使得“在 D Code 中使用 Sol 修改 D Code”只能完成代码生成，不能形成可信、可恢复、可验收的自迭代候选。

## Solution（解决方案）

1. **显式源码 Checkout。** 自构建页显示当前 D Code 源码 checkout，可从已选择的 Project 或系统目录选择器改选；目录必须通过 D Code 源码形状校验。自动发现只提供初始候选，不再依赖写死的个人路径。
2. **脏工作树本机候选。** Self-build 可以构建包含未提交改动的候选，但必须标记为 Local-only Candidate（仅本机候选），不得冒充发布包。普通发布构建继续拒绝脏工作树。
3. **固定自动门禁。** 构建候选前运行 Swift 与 Host 完整回归；任一失败时不生成或启用候选。每项门禁记录命令、退出状态、耗时与有界输出。
4. **来源快照与稳定性。** 构建前生成包含 Git revision、工作树状态摘要、内容 digest、变更文件数量与测试结果的 Candidate Manifest（候选清单）；构建结束后再次核对来源 digest，期间源码变化则拒绝候选。
5. **清单进入签名产物。** 候选清单在签名前进入 App bundle；候选校验除签名和版本外，还验证清单形状、来源 digest 与自动门禁结果。重启后当前 App 可以只读展示本次候选来源。
6. **人工门禁不自动化。** “重启到候选”继续由用户显式确认；重启后恢复原会话。原生 UI 感受、真实 Pi 行为和正式分发仍是独立人工门禁。
7. **模型边界保持诚实。** Sol 只有在 Pi 已认证、已启用并作为新会话所选模型时参与修改；Self-build 不自动切换当前会话模型，也不把 Sol 文案当作验证证据。

## User Stories（用户故事）

1. 作为使用 Sol 迭代 D Code 的开发者，我希望改完代码后可以从当前 checkout 直接构建本机候选，而不会因未提交改动被错误挡住。
2. 作为准备重启到候选的用户，我希望在确认前看到源码 revision、工作树状态和全部自动门禁，从而知道即将运行的到底是哪份 D Code。
3. 作为重启后的验收者，我希望能核对当前运行 App 的候选清单与来源，从而把“已启动”与“已验收、可发布”分开。
4. 作为维护多个 worktree 的开发者，我希望自构建源目录是显式、可切换且可校验的，而不是依赖作者机器上的固定路径。

## Confirmed Constraints（已确认约束）

- 普通 `app/build.sh` 的干净工作树发布门禁不放宽；只有 Self-build 显式创建的候选可以带本机脏工作树标记。
- 候选清单不得包含源码正文、凭据、环境变量值或完整 diff，只保存可核对的摘要、digest 与测试证据。
- 测试、候选构建、签名、重启、人工验收、commit、tag 与发布分别成立；任一步不能替代后续门禁。
- 构建期间源码快照必须稳定；不从正在变化的 checkout 生成可重启候选。
- 自动发现源码根失败时必须要求用户选择，不回退到个人硬编码路径或当前用户主目录。
- 候选替换继续保持单备份、显式确认、失败回退和无后台静默更新。
- App 端自动 GUI eval 当前不可用；本版本的 eval 只覆盖隔离网页原型中的信息理解与决策路径，不能冒充原生 App 验收。

## Acceptance Criteria（验收标准）

- [x] 自构建源码根不含个人硬编码路径；合法 checkout 可自动发现、从当前 Project 采用或经系统目录选择器设置并跨重启保留。
- [x] 非 D Code checkout、缺失构建入口或不可访问目录被拒绝，原有有效配置保持不变。
- [x] Self-build 在脏工作树中可以生成明确标记为仅本机的候选；同一脏工作树直接执行普通发布构建仍被拒绝。
- [x] Swift 与 Host 完整回归全部通过后才进入候选构建；失败时保留有界输出、当前 App 与备份不被替换，旧候选不会冒充新候选。
- [x] 候选清单包含 schema、revision、dirty、changed-file count、source digest、两项自动门禁与生成时间，不包含源码或凭据正文。
- [x] 构建期间源码变化会使候选失败；候选签名、App / Host 版本、清单与门禁结果均通过后才允许重启。
- [x] 自构建页能区分 Source Checkout、Verification、Candidate 与 Active Build，并明确仅本机 / 不可分发语义。
- [ ] 重启仍需用户确认，重启后恢复原会话；当前构建的来源清单可被只读核对。
- [x] 自动回归、未提交本机调试构建和隔离 eval 通过；原生 App 的 Sol 真实任务闭环与视觉验收另行人工执行。

## Out of Scope（非目标）

- 自动提交、推送、打 tag、创建 Release、签名公证或对外分发。
- 后台持续自改、无人确认重启、watchdog 自动回滚或多版本备份历史。
- 自动安装、认证或强制选择 Sol；改写当前或历史 Session 的模型事实。
- 通过 eval 驱动真实 macOS App，或把网页原型通过冒充原生 App 体验通过。
