# D Code 0.0.10 Project Trust 与动作级权限产品需求

状态：Superseded（历史源码标签 `v0.0.10` 已推送；其机制已被 [ADR 0023](../决策档案/0023-固定完全访问与动作级权限闸门移除.md) 整体取代——`0.0.14` 起权限固定完全访问，闸门扩展、授权表、审计、`permission.*` 协议与权限 UI 已从代码中移除。本 PRD 仅保留当时的范围与验收记录。）

本 PRD 冻结 `0.0.10` 的范围与验收边界；动作级权限的闸门位置、授权语义、默认策略与审计以 [ADR 0019](../决策档案/0019-Project-Trust-与动作级权限边界.md) 为准。

## Problem Statement（问题陈述）

`0.0.9` 打开即接管后，模型在 D Code 会话内执行的 bash 与文件写入没有任何工具级询问，成为无门禁的外部副作用。产品模型 0001 预留的 Permission Policy / Effective Grant / 审计事件尚未落地。

## Solution（解决方案）

Host 打开可写会话时注入隐藏闸门扩展（Pi `tool_call` 钩子）：读取放行；bash 与写入先查授权表（bash 命令前缀 + 会话 cwd 域，写入按授权根内）；未决动作挂起并发 `permission.request`，Swift 权限卡提供"本次允许 / 范围允许 / 拒绝"（项目外写入与自定义工具无范围键）；决策持久化与审计落 `agentDir/pi-dcode/permissions-v1.json`；设置页新增"动作权限"管理授权与查看最近决策。

## Confirmed Constraints（已确认约束）

- 闸门只在 D Code Host 内生效；Pi CLI 不受约束并如实说明（诚实降级）。
- 项目外写入与自定义工具不支持范围授权；无全局"永不询问"。
- 授权域为会话 cwd（非 DCodeProject 聚合）；高风险命令只影响呈现，不改变询问规则。
- 会话关闭 / 冲突时未决请求全部按"会话已关闭"拒绝，不悬挂。
- Skill 即权限、无限期全局授权、操作系统沙箱承诺不进入本版。
