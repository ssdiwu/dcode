# D Code 0.0.36 协作过程可视化与工作台质感产品需求

状态：507 于 2026-09-28 确认目标、范围与 ZCode 共享 React UI 的源码级借鉴方向，要求参考“＋”添加面板、`/` 查找技能和 `@` 搜索文件，最初计划在 `0.0.35` 实施。核对两份审计材料后，507 认可先用 [0.0.35 修复规格](0035-0.0.35-现有功能与安全加固产品需求.md)收口现有能力与安全，再将本文件调整为 `0.0.36` 的协作展示、执行过程与输入区需求。真实工作流运行合同由同版 [PRD 0034](0034-0.0.36-任务内工作流产品需求.md) 拥有。507 已确认 `$` 只选择当前 Task 已创建的子代理成员进行协作。2026-09-29 主树未提交地接入 `$`、长对话导航、上下文估算、成员／过程展示、独立 Task Goal、“＋”能力面板及 Project Task 的 `@` 文件搜索；实际窗口和定向检查分层通过，整版候选、性能基线与 507 人工验收仍未完成。`0.0.34` 人工验收与 `0.0.35` 修复验收各自独立，不能由本版代为宣布。

## 问题与目标

D Code 已拥有 Task、Agent Run、Child Agent Session、工作项、交办、报告、检查和执行证据，但当前工作台较难一眼回答“谁正在做哪项工作、遇到什么阻塞、结果到了哪一步”。团队区以姓名和状态列表为主，执行过程以通用折叠块呈现；新任务、导航和输入区的层级、密度及状态反馈也未达到 507 期望的成熟工作台质感。

本版让用户在主对话中持续掌握任务内真实协作：先看到有界的团队和过程概览，再进入成员子对话、具体报告、差异或证据。同步打磨承载这条路径的导航、任务标题、空任务及输入区。完成信号是实际 D Code 任务在运行、失败、返工和待验收时都可读、可进入、可继续操作，并经 507 对真实窗口的视觉与操作验收。

## 用户路径与需求

### 任务内成员概览

1. 当前 Task 有真实成员时，Task HUD 的团队分区以紧凑的成员组件呈现协调者与本轮实际成员。每名成员显示身份或职责、当前交办的短摘要、可证明的运行或等待状态，以及可得的耗时；多名成员有准确的总数与阶段计数。协调者作为组织入口展示，不计入非协调成员数量。若有尚未结束的 Team Run，概览显示该轮；否则显示最近一轮并明确标作历史结果，不继续称其“正在运行”。更早轮次可按需展开，成员的稳定子对话入口继续可达；各轮计数彼此隔离。尚未创建成员时保持真实空状态，不展示模拟团队或为了视觉效果虚构成员。
2. 同一 Task 可以有多轮 Team Run、多个 Work Item 和多个 Agent Run。界面按这些真实关系组织成员；只有已记录的关系才能画连接、分组或依赖。成员使用同一 Profile、重启执行进程或切换模型，不得因此误增一个用户可见成员。
3. 成员从创建、等待资源、运行、请求输入，到完成、失败、停止、中断或状态未知，均显示与来源一致的文字状态；状态色和动画只能辅助辨认。等待容量、目录写入或模型额度时说明可核对原因；缺少可靠状态时显示“待核对”，不能沿用旧的“运行中”或推断成功。
4. 点击成员可进入其稳定的 Child Agent Session；从子对话返回主对话时，原主对话的草稿、阅读位置与已打开内容保持。查看成员不停止其他成员。协调者为新成员提供的用户可见工作名称默认使用简短、具体的简体中文，技术标识保留原文；用户明确指定的语言或名称优先。已有名称继续按保存原文显示，不自动翻译或改写历史。需要持续检查的成员交办、活动、报告与证据可从现有信息检查器路径按需打开，概览本身不堆叠完整日志。
5. 成员结果与 Task 完成分开：成员报告、独立验收、协调复核以及 507 对 Task 的接受分别显示。某成员完成或检查通过不使整个 Task 自动显示完成；失败或待返工也不得被总体“已完成 N 项”掩盖。

### 执行过程与结果呈现

1. 主对话和成员对话将一次执行中的思考、工具、协作交办与最终回答分层呈现。默认摘要说明发生了什么、目标是什么和结果状态；展开后才显示对应的完整参数、输出或错误，不以原始 JSON 或长段通用文本作为主要扫描面。
2. 文件读取、修改、命令检查、差异审查、成员交办与等待等常见动作使用与动作相符的摘要。可确认的文件、行、差异和报告引用能进入 D Code 已有的内容与来源查看路径；正文与引用不重复打印成两份结果。没有结构化事实的工具保持清楚的通用回退呈现，不补造文件数、步骤数、耗时或结论。
3. 流式、完成、失败、停止、中断与未知的过程在切换任务、展开详情和恢复历史后保持准确归属。失败摘要能读到原因及下一步入口；旧结果不能替代本轮输出，后台成员更新不抢占用户当前对话或焦点。

### 长对话导航

1. 升级现有 Conversation Rail（对话轮次导航条），借鉴 ZCode 可滚动、每条提问可独立命中的组件模式；不在中央对话旁再建第二条 minimap。导航项来自用户真实提交且可见的提问或补充，同一执行轮里的多次用户补充仍各有稳定跳转目标；工具事件和后台系统输入不冒充用户提问。当前所在项随阅读位置更新，历史跳转继续保留“暂停自动跟随／回到最新”的既有合同。
2. 每项在鼠标悬停或键盘聚焦时显示有来源的提问与所属回答摘要，点击、方向键、Home／End、Enter 或空格可精确跳至原消息。大量轮次时轨道可在自身滚动并只渲染必要的可见项，当前项仍可找到；窄窗口和减少动态效果下保留可达的等价入口，不照搬 ZCode 的固定几何或品牌样式。
3. 这一导航解决跨提问查找，不把一轮长回答按像素高度伪装成多轮，也不宣称能定位长工具输出内部的错误。若后续要做轮内全文搜索或错误标记，须另行以真实场景定义数据来源和验收。

### 工作台质感收口

1. 新任务与空任务界面让标题、目标说明和输入动作形成明确的阅读顺序；装饰场景服务品牌识别，不挤开主要动作、遮挡真实状态或在窄窗口制造大片无效空间。
2. 同一 Task 在“最近工作”和所属 Project 下出现时，导航只表达一个当前选择；其他出现位置可保留入口，但不同时呈现两个当前页。项目、成员和内容的层级、图标、字级、间距与悬停反馈使用一致的工作台规则。
3. 顶部 Task / Session 身份优先；长目录和其他运行依据可按需查看，不挤占标题和主要操作。子对话中的“主对话”返回按钮保持完整单行、位于标题栏内；任务和成员的长名称省略显示并可核对原名，不能把按钮挤成竖排或使文字越过窗口顶部。输入区在新任务、主对话和子对话中保留既有项目归属、附件、技能、成员定向、模型与发送时机，窄宽度下控件能换行或收纳且不失去明确名称和操作结果。
4. 共享的字级、语义表面、状态和组件交互规则同时适用于浅色与深色；焦点、禁用、加载、错误和减少动态效果遵守既有设计系统与输入控件约束。视觉统一不能靠为每个页面复制一套私有几何或状态常量。

### 当前会话上下文用量

1. 已创建且正在查看的 D Code Session 在 Composer 附近显示紧凑上下文圆环：有效的当前 Runtime 提供上下文已用 token **估算**与模型上下文容量时，按既有设计合同以蓝环表示约剩余、浅色覆盖表示约已用；展开可读到约已用量、总容量和约剩余比例。它表示本会话当前可归属的上下文估算，不是 Task 所有成员的合计、精确计费数或模型额度。新任务尚无 Session 时不显示假占用。
2. 主对话与成员子对话分别绑定各自的 D Code Session／Runtime。切换成员、模型、会话路径、成功压缩或重启后，界面重新核对来源；旧模型或其他成员的数值不能沿用为当前值。最近一次模型响应有真实 usage 时可将其时间标为估算锚点，后续消息推高的数字仍须说明包含估算；没有这样的响应或有效容量时显示“未知”，不绘制代表零占用的满环。压缩失败不能冒充成功并清空旧用量。
3. 展开后的用户、助手、思考、工具结果及系统／工具构成只在对应 Runtime 可读时提供，并逐项标明“估算”；估算不能写成精确计费数或缓存命中率。没有活动 Runtime 的历史会话目前不伪造当前占用；以后若保存用量快照，须带会话、模型、路径、时间与来源，并标为“上次记录”，不能把历次模型调用的 input/output/cache token 相加成当前上下文。

### 输入区“＋”添加面板

1. “＋”打开与 Composer 对齐的非模态添加面板。在新任务草稿与 Task 主对话中，顶部“添加”分区依次呈现“附件”“目标”“工作流”；成员子对话只展示其当前可用的附件及输入能力，Task Goal 修订和工作流发起仍回到协调者主对话。下方按可核对来源显示当前作用域真正可调用的技能、命令、模板和已注册且可由输入区调用的扩展命令。名称、简短说明和可用状态同时可读；列表可滚动，底部说明不随长列表消失。插件工具、配置页或市场项目没有对应输入区调用动作时不列成可点项；未安装、未启用、无访问权或尚未接通的能力不冒充可点项目，读取中、空结果和失败有明确状态。
2. “附件”合并既有图片与文件入口，打开同一文件选择路径；拖入、粘贴、缩略图、预览、移除、类型与大小校验、保存期限和失败反馈沿用现有附件合同。选择文件只加入当前草稿，不发送消息或隐式加入其他任务。
3. “目标”作用于 D Code 的 Task Goal。新任务可在首次提交前单独填写短期结果及验收目的，选择归属或返回输入时保留该草稿；已有 Task 可查看并明确修订目标，修订形成可追溯新版本，使受影响的计划、路线与后续执行在安全边界重新核对。它不是 ZCode 的会话级自动续跑模式，不以输入一个无效的 `/goal` 文本代替真实产品写入；用户消息提交原文保持不变。
4. “工作流”进入同一 Task 的真实工作流创建与续接路径，具体执行语义及失败恢复以 [PRD 0034](0034-0.0.36-任务内工作流产品需求.md) 为准。选择后可继续输入目标、范围和约束；未提交前不启动成员，已有 Task 的历史工作流可查看并选择合法续接。该项只有在对应能力实际接通后才作为可操作入口出现。
5. “＋”下方的能力列表消费真实注册目录；点击技能、命令、模板或可从输入区调用的扩展命令，只预填当前草稿，用户仍可编辑并显式发送。`/` 的查找面板聚焦已启用、当前作用域可用的技能，显示名称、说明和来源；现有命令与模板的完整手输 invocation 继续有效，其可发现入口保留在“＋”面板，不因技能查找收窄而静默失效。扩展命令须有当前实际注册的 invocation 与来源；普通插件工具、插件市场或插件本体不包装成命令。长列表可用文字筛选与键盘选择；打开、选择、取消和关闭后草稿与输入焦点保持。
6. `@` 在本版完成成员入口迁移后只搜索当前 Task 可访问目录中的文件并插入准确的文件引用，不把文件内容自动附为附件，也不把命中项永久加入 Task Context Selection。Project Scope 以当前项目已授权目录为范围；User Scope 没有明确授权的源目录时显示选择范围的空态，不能因为默认 cwd 是 Home 就遍历整个用户目录。搜索与真正引用均经过 Host 的目录、路径和凭据边界核验；同名文件显示可辨别的相对路径，失效、越界或目录变化在发送前明确反馈并保留草稿。文件引用与“附件”是两种不同操作，引用可回到原文件，附件沿用受管副本合同。
7. `$` 在 Task 主对话中只查找**本任务已创建的子代理成员**，列表显示稳定成员身份、职责与当前状态；选中后形成有可撤销目标的草稿，并继续使用现有 `targetAgentRunId` 定向投递，协调者获知来源与变更。同一条消息只指向一个成员；重新选择要替换目标而非隐式群发。当前无成员时说明“暂无子代理，可直接请协调者分工”；已停用、其他 Task 或不可接续的成员不能以同名文字蒙混投递。Agent Profile 只是可复用配置，`$` 选择不创建 Agent Run、Child Agent Session 或执行进程；请求新分工仍在主对话告诉协调者。
8. 底部说明只解释 D Code 当版已经接通的输入方式。基础文案为“输入名称查找可用内容；`/` 选择技能，`@` 引用文件”；当前 Task 有可联系成员且 `$` 已接通时追加“`$` 选择子代理”。快捷符号以易扫读的键帽形态呈现。不得照抄 ZCode 的“搜索插件、文件和对话”，因为本版没有承诺这些来源全部可搜索。说明不替代操作结果或错误反馈。
9. 当前 D Code 的 `@` 还承担已有 Task 成员定向；迁到 `$` 须复用稳定 `targetAgentRunId`，不能只把提示文案换成文件搜索。新入口完成验证之前，现有 `@` 成员定向及可见成员按钮继续可用，不单独发布会夺走成员入口的 `@` 文件搜索。旧会话的原始消息、已保存草稿与目标成员身份不被新前缀重新解释；迁移前后的实际投递结果和协调者知悉事件须一致。`@`、`$` 只在明确的输入边界唤起候选，邮箱、代码与普通文字中的同形字符保留原文。文件或成员必须经用户点击或键盘明确移动到候选后确认，输入候选字样本身不自动选中第一项；没有明确选择时 Enter 按正常发送行为处理，不把同名文件或成员误插入草稿。

## 已确认约束与来源

- 产品对象继续由 D Code Product Store 拥有；本版消费已有 Task、Work Item、Team Run、Agent Run、Assignment、Session、Report、Verification 和 Evidence。若某项用户可见活动缺少可靠读取接缝，实施须先建立有来源的只读投影或收敛该项展示，不能从模型文案、工具名或 UI 计时器猜测产品状态。
- 507 允许按源码级借鉴公开的共享 React UI，包含适用许可允许的局部组件实现和样式。ZCode 是优先研究和可移植候选，PI-Desktop 的 Subagent 显示与 Kimi／MiniMax 的运行状态呈现作为补充参照。是否移植某一文件由实现阶段按适用许可、来源、依赖及复杂度判定；引入的代码保留必要的许可、署名、修改和第三方声明。D Code 使用自己的品牌资产、术语与状态合同，不因参考源码接入外部产品 Runtime、会话数据库或配置权威。可追溯的一手来源见[外部产品与仓库参考](../参考文件/README.md)。
- 成员组件、过程摘要和菜单会增加长会话中的渲染与状态更新；实施前以固定的长 Task／长会话样本记录输入响应、滚动、任务切换与内存基线，完成后在相同环境核对回归。出现可复现退化才选择局部优化，不预先把 `useMemo`、虚拟化或某个包体缩减比例写成解决方案。源码级借鉴必须通过可执行的最小模块边界检查，保证客户端展示不引入参考产品 Runtime、第二 Product Store、Pi TUI 或直接越过 Host 的写入路径；这项检查接入本项目已有验证入口，不要求为它先建立一整套新 CI 平台。
- Task HUD 负责轻量概览，Information Inspector 负责持续检查具体对象；中央对话与 Composer 保持可用。具体几何和共享基础组件仍由 D Code 设计系统与客户端实现拥有。本版不能用新增全高团队栏或第二任务页面覆盖这些边界。
- 自 `0.0.36` 起，本文件的“＋”面板内容取代 [0.0.25](0022-0.0.25-项目目录迁移与-Composer-收口产品需求.md) 与 [0.0.32](0030-工作台-UI-UX-并行候选.md) 对菜单项目的旧限定；两版已验证的附件、技能／命令调用、草稿、焦点和输入安全行为仍是回归基线，不因增项而撤销。
- 本版明确把 `@` 用于文件搜索的目标重新纳入范围；它曾出现在[版本演进表](../20-产品与交互/原型/版本演进/README.md)，但当前客户端仍以 `@` 定向成员。[PRD 0029](0029-任务内自适应协作产品需求.md) 的已创建成员定向与协调者知悉行为继续有效；只有 `$` 新入口完成验证后，本版才替换其输入符号，不能把历史 PRD 文案当成当前源码实现，也不能因迁移符号撤销协作合同。
- `0.0.34` 的任务摘要、来源回查、审查与返工路径在本版继续可用；视觉重排不改变原始提交、报告、差异快照或用户接受事实。

## 验收标准

- [ ] 在真实 Host 与独立客户端中，从一个无成员 Task 开始，协调者实际创建一名及多名成员。团队概览依次显示创建、等待、运行和终态；同名 Profile 的不同实例、同一成员重启或模型回退的数量与身份正确。未启动成员没有伪造的执行进度。
- [ ] 两名以上成员并行时，分别制造完成、失败或停止，以及独立检查待处理与返工。聚合计数、各成员状态、交办和报告链接一致；Task 仍待用户接受，不因成员或检查通过而自动完成。历史重读与重启后不留下假“仍在运行”。
- [ ] 同一 Task 先后经历两轮 Team Run：第二轮运行时概览只计第二轮，第一轮仍能展开并进入原成员子对话；第二轮结束后概览明确是最近一轮历史结果。若恢复一轮既有 Team Run，该轮重新成为当前轮，但不复制成员身份或合并两轮计数。
- [ ] 从主对话打开成员、补充要求、返回主对话并继续发送；主草稿、附件、阅读位置和已打开内容保持，无关成员继续执行。成员回复及其对协调者的更新保留真实来源。
- [ ] 一次真实文件修改、一次命令检查、一次成员交办和一次失败分别有可扫读摘要；展开可核对原始工具输出、差异、来源及错误。结构化数据缺失、读取失败或结果未知时有诚实回退，不打印伪造结论或重复报告。
- [ ] 用含 100 条以上真实用户提问、同一执行轮内多次补充以及长工具输出的会话验证导航：每条用户输入有独立可聚焦目标，滚动、预览、键盘跳转与当前项一致；工具输出不会生成假轮次。历史跳转后流式回复不抢回阅读位置，回到最新可恢复跟随；窄窗、放大字号与减少动态效果仍可用，长列表不因一次渲染全部轮次而破坏本版性能门槛。
- [ ] 对照新任务、正在协作、失败返工、待用户验收四种实际界面，核对浅色／深色、标准与放大字号、宽窗与最小支持窗口、鼠标、键盘、屏幕阅读器和减少动态效果。当前项唯一、长路径不挤标题、输入及等待操作可达；自动布局检查、实际 Electron 走查与 507 视觉接受分别记录，不能互相代替。
- [ ] 在同一 Task 的主对话和两名成员子对话分别产生可核对的上下文估算，切换会话后圆环与明细始终对应当前 Session；模型或路径切换、成功压缩和 Host 重启后不沿用不适用的旧数字，压缩失败不误报成功。无 Session、无活动 Runtime、无真实 usage 锚点或有效容量时按各自真实状态隐藏或显示“未知”，不显示假零值。展开明细把总量与分项的估算性质、最近真实 usage 响应的时间及当前模型容量说明清楚；鼠标和键盘均可读取，不将其混称为模型额度或计费数。
- [ ] 在同一机器、同一固定长 Task／长会话样本和相同窗口条件下，分别对 `0.0.35` 基线与本版预热后重复 7 次输入、流式更新、滚动和任务切换动作，保存原始耗时与中位数；本版任一路径中位数同时增加超过 25% 和 50 毫秒即为回归。按相同五分钟操作序列测量进程内存，增加同时超过 25% 和 100 MB 即为回归；测量波动过大时重新控制环境，不以单次有利结果判通过。若基线本身已明显不可用，分别记录原有问题与本版增量，再修复受影响路径；不凭未经测量的“立即见效”优化宣称通过。
- [ ] 新任务与 Task 主对话的“＋”面板显示有来源的三项添加入口与能力列表；成员子对话只显示附件及该会话可调用的输入能力，不从子对话直接修改 Task Goal 或启动工作流。“附件”实际选择图片和普通文件，“目标”保存独立于消息原文的 Task Goal，“工作流”完成 PRD 0034 的创建及合法续接入口。无能力、读取失败、长列表、长描述、窄窗与深浅色均可用；不能点出空白功能页或仅插入无效斜杠文本。
- [ ] 菜单的鼠标、方向键、Enter、Escape、Tab 与中文输入法确认操作保持选择和焦点正确；说明文案只声明实际支持的快捷入口。选择技能或命令后只预填，不自动发送；取消附件／目标／工作流草稿不影响其他归属或已保存的原始消息。
- [ ] `/` 查找当前可用技能并保持真实调用身份；命令、模板仍能从“＋”找到，已有合法 invocation 仍可手输并按原合同执行。`@` 在 Project Scope 中从两个同名、不同路径的文件选定一个，发送后引用与打开目标一致；删除、改目录、越权或凭据路径不产生假引用，原草稿可继续修改。切换任务或目录后，旧搜索结果不能进入新作用域；User Scope 不静默搜索整个 Home。
- [ ] 现有 `@` 成员定向迁往 `$` 后，同任务已创建成员仍可被选择，跨任务、已删除或不可接续成员被拒绝；历史原始消息和已有定向草稿的 `targetAgentRunId` 不被重解释为文件，协调者继续收到有来源的变更。
- [ ] 主对话用 `$` 选中同任务已创建成员后发送，成员和协调者各收到一次有来源的消息；选择第二成员会替换而不群发。无成员、同名 Profile、成员跨 Task、成员不可接续，以及普通 shell `$HOME` 文本均不会偷偷创建成员、误投递或丢失用户原文。
- [ ] 在 `$` 尚未接通的候选中，原 `@` 成员定向与可见成员按钮仍能实际投递；不能只发布 `@` 文件搜索并丢掉这条路径。邮箱、代码、普通文字中包含与可搜索文件同名的 `@` 片段时，直接 Enter 仍发送原文；仅点击候选或先用方向键明确选中后确认才插入文件引用。
- [ ] 若移植公开源码，交付记录能指出原始仓库、固定 revision、涉及文件、适用许可、修改和必要声明；打包产物保留适用许可正文。源码移植不改变 D Code 的产品身份、数据写入所有者或公开权限边界。
- [ ] 使用项目现有验证入口运行最小模块边界检查：新增的共享 UI 及其调用方只消费 D Code 已授权的客户端读取／操作合同，不能直接导入外部 Agent Runtime、Pi TUI、另一套产品存储或绕过 Host 写入；检查失败时不给本版候选通过标记。
