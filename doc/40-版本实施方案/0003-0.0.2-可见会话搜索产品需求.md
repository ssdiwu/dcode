# D Code 0.0.2 可见会话搜索产品需求

> 后续收窄：本版“点击即创建”的历史验收自 `0.0.5` 起由 [ADR 0014](../决策档案/0014-新会话延迟创建与本地草稿边界.md) 取代；当前点击只进入本地会话前草稿，首次发送才创建 Pi Session。`cwd` 默认值与 Host 初始文档提交语义仍继续成立。

状态：Published Regression Tag（已推送回归标签，`v0.0.2`；人工验收未全部完成）

适用范围：在已经发布的 `v0.0.1` 原生工作台上，交付可见 Pi Session（Pi 会话）的全文搜索、筛选与消息定位

基线依赖：[0.0.1 用户首页与项目工作台产品需求](0002-0.0.1-用户首页与项目工作台产品需求.md)与[首个可日常使用版本产品需求](0001-首个可日常使用版本产品需求.md)继续作为回归约束；Project（项目）、Source Folder（源文件夹）、Recent Sessions（最近会话）与单写入安全边界不得回退；当前会话所有权以 [ADR 0018](../决策档案/0018-打开即接管与单写入所有权.md) 的打开即接管为准。

## Problem Statement（问题陈述）

`0.0.1` 为了克制冷启动读取，只在左栏展示最近 10 条 D Code 创建的会话，并允许 Project 分批显示所关联 Source Folder 中的旧 Pi Session。更早的可见会话虽然仍然存在，但用户必须反复点击“查看更多”并依靠标题辨认；消息正文无法成为找回历史工作的入口。

简单扩大左栏数量或只过滤已经加载的摘要不能解决这个问题：它既找不到首屏之外的正文，也无法区分同名会话，还可能绕过既有可见性边界暴露未关联的旧 Pi Session。`0.0.2` 需要在不改变 Pi 会话权威、不预读全部正文到 Swift 前端、不取得写入权的前提下，提供快速、可恢复且能定位消息的全文搜索。

## Solution（解决方案）

在现有三栏工作台上增加 Codex 风格的轻量 Search（搜索）浮层：

- 用户可通过左栏搜索按钮或全局 `Command-K` 打开；左栏隐藏时快捷键仍可使用。
- 修正全局新建会话入口：从 User Home 或左栏新建时直接以当前 macOS 用户目录作为 `cwd`，不再要求先选文件夹；Project 内新建仍只从该项目已登记的 Source Folder 中选择。
- 浮层覆盖当前工作台但不替换它；当前 Session、左右栏状态、对话滚动位置与 Composer（输入区）草稿保持不变。
- 搜索范围严格等于“D Code 创建的 Recent Sessions”与“已关联 Project Source Folder 投影出的会话”的并集，而不只包含当前已经加载的 10 条摘要。
- 搜索会话标题、当前活动 Session Path（会话路径）中的用户消息正文与助手消息正文；不搜索其他路径、隐藏 thinking、原始工具输入、工具结果、认证内容或其他可能包含凭据的非对话正文。
- 结果按 Session 去重，每个 Session 显示一条最佳命中并标明总命中数；正文命中显示消息角色和片段。
- 结果显示 Session 标题、更新时间、`cwd`、所属 Project 与 Source Folder；可按 Project 和 Source Folder 缩小范围。未归属 Project 的 D Code Recent Session 显示“未加入项目”与工作目录名称。
- 选择标题命中时打开同一稳定 Session ID；选择正文命中时还要定位对应消息并短暂高亮。打开失败时保留浮层、查询和选择状态。
- 搜索使用可删除、可重建的本机索引缓存；Pi JSONL 继续是唯一权威。索引不可用时显示建立、重建或失败状态，不把它伪装成“没有结果”。

## Search Behavior（搜索行为）

### 打开与关闭

- 空查询默认按更新时间展示最近的可见 Session，不自动读取或展示未关联历史。
- 搜索框打开后立即获得键盘焦点；`Up` / `Down` 移动选择，`Return` 打开，`Escape` 关闭。
- 浮层在交互上使用模态焦点约束，键盘焦点不会进入被覆盖的工作台；关闭后焦点返回原触发位置。
- 只有成功打开目标 Session 后才关闭浮层；失败时用户可以直接重试或选择其他结果。

### 匹配、排序与去重

- 有查询时，标题命中优先于正文命中；相同匹配等级按相关度排序，仍相同时按更新时间降序。
- 同一稳定 Session ID 即使同时属于 Recent 与 Project，也只显示一次；Project 与 Source Folder 信息来自当前 D Code 组织关系，不写回 Pi Session。
- 同一 Session 多条消息命中时，只展示最佳命中并显示“共 N 处”；打开该行定位最佳命中。
- 查询连续变化时立即发起最新搜索，不设置固定 `250 ms` 等待；过期结果不得覆盖更新查询的结果。
- 索引就绪后，在验收机和当前可见会话数据上，常规查询从输入变化到首批结果可交互的 `P95` 不超过 `100 ms`。

### 可见性变化与恢复

- 创建 D Code Session 后，它可进入索引和空查询结果；删除来源文件、Session 不再存在或解析失败时，不以陈旧缓存冒充仍然存在。
- 添加 Source Folder 后，对应旧 Pi Session 才可进入搜索；移除或移动 Source Folder 后，旧归属结果必须立即从查询可见集合中消失，即使缓存尚未完成物理清理。
- 索引缺失、版本不兼容、损坏或内容过期时可以自动重建；重建不阻塞正常聊天、Project 浏览或 Composer 草稿。
- 建立或重建未完成时明确显示状态，不用不完整结果断言“没有找到”。

## User Stories（用户故事）

1. 作为长期使用者，我希望直接搜索首屏 10 条之外的历史工作，而不必不断点击“查看更多”。
2. 作为记得讨论内容但忘记标题的使用者，我希望通过自己或助手说过的话找回原会话。
3. 作为维护多个项目与目录的使用者，我希望用 Project 和 Source Folder 缩小结果，并能区分同名会话。
4. 作为同时使用 Pi CLI 与 D Code 的用户，我希望搜索只读现有权威历史，不复制、导入或改写 Pi Session。
5. 作为键盘使用者，我希望不用离开当前工作台就能打开搜索、选择结果、定位消息，并在取消后回到原位置。

## Confirmed Constraints（已确认约束）

- 平台为 macOS 14+；搜索浮层使用 SwiftUI/AppKit 原生界面，产品文案默认简体中文。
- `~/.pi/agent` 继续是 Pi Session 与消息的唯一权威；搜索缓存不得成为第二套会话历史或写入来源。
- Swift 前端不直接遍历或解析 Pi JSONL；可见性判断、正文提取、索引与查询由 D Code Host 的结构化协议提供。
- 搜索自身不创建 Session Lease（会话租约）、不触发 Write Intent（写入意图）、不修改 Session、Project、文件或 Git 状态。
- 搜索可见性在查询时仍必须强制执行，不能只依靠缓存建立时的范围；陈旧缓存不得泄漏已经取消关联的旧 Pi Session。
- 本地索引只保存本版本允许搜索的标题、用户正文、助手正文及定位所需元数据；不得索引隐藏 thinking、工具原始载荷、认证信息或其他排除内容。
- 本版本只搜索每个 Session 的当前活动 Session Path。其他路径要等 `0.0.3` 具备查看、切换与定位路径的产品能力后再纳入。
- 搜索结果使用稳定 Session ID 与消息 Entry ID（条目标识）定位；不得通过标题、文件名或数组位置猜测目标。
- 宽、中、窄窗口继续遵守 `0.0.1` 响应式三栏规则；窄窗口可以近全宽显示搜索浮层，但不得删除区分同名 Session 所需的归属信息。

## Acceptance Criteria（验收标准）

### 可见范围与正文边界

- [ ] 隔离数据包含至少 12 条 D Code Recent Session 时，不点击“查看更多”也能搜索到第 11、12 条的标题和当前活动路径正文。
- [ ] 已关联 Project 的两个 Source Folder 中存在旧 Pi Session 时，可以跨文件夹搜索标题、用户正文和助手正文；Project 列表是否展开、摘要是否已加载不影响结果。
- [ ] 未关联 Source Folder 的旧 Pi Session 不出现在空查询、全文结果或筛选计数中；关联后才出现，移除关联后立即消失。
- [ ] 同一 D Code Session 同时属于 Recent 与 Project 时只显示一个结果，并保持同一稳定 Session ID。
- [ ] 隐藏 thinking、工具输入、工具结果和认证类非对话正文中的独有词不会被命中；可见用户与助手正文中的相同词可以命中。
- [ ] 非当前 Session Path 的独有正文不在 `0.0.2` 结果中出现。

### 结果、筛选与定位

- [ ] 空查询按更新时间展示最近的可见 Session；有查询时标题优先、正文其次，相同等级按相关度和更新时间稳定排序。
- [ ] 同一 Session 多处命中时只显示一行最佳片段并标出总命中数；结果明确显示消息角色、Project、Source Folder、`cwd` 与时间。
- [ ] Project 与 Source Folder 筛选可组合且只展示当前真实归属；D Code Recent 但未归属 Project 的结果显示“未加入项目”。
- [ ] 选择标题结果打开原稳定 Session ID；选择正文结果打开同一 Session，并滚动到对应 Entry ID 后短暂高亮，不创建导入副本或新 Session。
- [ ] 目标 Session 已移除、正文更新或打开失败时，浮层与查询保持，显示可操作错误且不误切换当前 Session。

### 状态保持、性能与恢复

- [ ] 通过按钮或 `Command-K` 打开搜索后，`Up` / `Down`、`Return`、`Escape` 与鼠标均可完整操作；关闭后焦点回到触发位置。
- [ ] 打开、关闭、筛选或搜索失败前后，原 Session、Composer 草稿、Active Plan、对话滚动位置、左右栏显示偏好和 Project 选择均保持。
- [ ] 搜索与索引建立全程不创建 Session Lease，不改变任何 Pi JSONL、Project 元数据、工作区文件或 Git 状态。
- [ ] 索引就绪后，连续输入不等待固定 `250 ms`；最新查询结果不会被较慢的旧查询覆盖，首批结果可交互延迟达到本规格 `P95 ≤ 100 ms` 的验收线。
- [ ] 索引首次建立、增量更新、删除、损坏和版本不兼容均有明确状态；删除或损坏后可从 Pi Session 重建，重建期间正常聊天与草稿不受影响。
- [ ] 系统、浅色、深色，以及 `1280/1279/880/879 pt` 响应式边界下浮层内容清晰、不会溢出；键盘焦点、VoiceOver 名称和 40 pt 最小命中区域成立。
- [ ] Host 与 Swift 自动测试覆盖本规格的可见范围、正文排除、筛选去重、查询竞态、索引恢复、无写入、消息定位与状态保持，并持续通过 `0.0.1` 全部回归。

### 全局新建会话回归

- [ ] 从 User Home 或左栏点击“新建会话”后不出现目录选择器，直接创建一个 `cwd` 为当前 macOS 用户目录的 D Code Session，并进入 Recent Sessions。
- [ ] 从 Project 行内新建时仍必须选择该 Project 已登记的 Source Folder；该行为不因全局入口简化而改变。

## Out of Scope（非目标）

- 搜索同一 Pi Session 的非当前 Session Path；路径查看、切换、编辑并重走与复制属于 `0.0.3`。
- 文件、代码、Git Changes、Artifact、Goal 或 Agent Team 搜索。
- Workspace Tab、文件预览、Markdown/HTML 编辑或即时预览。
- 拼音转换、同义词、Embedding（向量嵌入）、语义搜索、AI 摘要或搜索建议。
- 云端索引、跨设备同步、多人共享索引或把搜索正文发送给外部服务。
- 会话删除、导入、合并、重命名、Project 自动归类或修改 Source Folder 归属。
- 会话路径、复制到项目、复制并归档到项目，以及已归档会话管理；这些能力属于 `0.0.3`。
- 为 `0.0.3` 及以后版本预放空的路径、文件、Goal 或 Agent Team 入口。

前置技术探针在 25,000 条、15.41 MiB 对话正文样本上记录到 joined query `P95 1.640 ms`；它只证明索引方案的查询余量，不替代当前 App 的端到端人工延迟验收。上述事实不等于 507 已完成界面、响应式、焦点、VoiceOver 与日常工作流验收，因此本页人工验收项保持未勾选。该实现已提交为 `ffaacd8663a6788f059ca23d387af9e59ae849a8`，并以 annotated tag（带注释标签）`v0.0.2` 固定和推送为历史源码回归基线；未创建独立 GitHub Release（GitHub 发布页），也未发布二进制。

2026-08-22 后续只读审计发现当前 `main` 回归：正文命中携带 `expectedEntryDigest`，App 又以 writable 模式发起 `session.open`，而 Protocol v1 明确拒绝该组合。标题命中仍可打开，正文命中会保留浮层并显示打开失败。历史 `v0.0.2` 标签事实不改，但第 91 项当前持续回归尚未成立；修复需同时贯通 Swift 调用与真实 JSONL Protocol 测试。
