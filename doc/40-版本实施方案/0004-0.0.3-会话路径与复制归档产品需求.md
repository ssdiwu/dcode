# D Code 0.0.3 会话路径与复制归档产品需求

状态：Confirmed Scope（已确认范围，等待 `v0.0.2` 发布后实施）

适用范围：在 `0.0.2` 可见会话搜索与既有原生会话基线上，交付同一 Pi Session（Pi 会话）的路径操作、逐路径草稿，以及把完整会话复制到 Project（项目）的两种明确动作

基线依赖：[0.0.2 可见会话搜索产品需求](0003-0.0.2-可见会话搜索产品需求.md)、[0.0.1 用户首页与项目工作台产品需求](0002-0.0.1-用户首页与项目工作台产品需求.md)与[首个可日常使用版本产品需求](0001-首个可日常使用版本产品需求.md)继续作为回归约束。搜索可见性、Project / Source Folder（源文件夹）关系、持续观察、按需写入、单写入安全与 Composer（输入区）状态不得回退。

## Problem Statement（问题陈述）

`0.0.2` 可以从可见历史中找到并打开同一个 Pi Session，但用户仍只能看到当前活动 Session Path（会话路径），不能在原生界面中安全查看路径谱系、从较早消息继续，或为不同路径分别保留未发送草稿。

用户还需要把一段已有工作带到另一个 Project 的 Source Folder。Pi 的真实能力会保留源会话，并创建拥有新 Session ID（会话标识）与新 `cwd` 的完整会话副本；如果产品把它称为“移动”或“迁移”，用户会误以为原会话身份和文件被原地搬走。D Code 必须使用与底层事实一致的两个操作：普通复制，以及复制成功后仅在 D Code 中归档原会话。

## Solution（解决方案）

### 会话路径与逐路径草稿

- D Code 提供所选 Session 的路径谱系，明确标出当前路径、路径起点和更新时间；日常左栏仍只显示 Session，不把全部路径永久展开。
- 用户消息提供“编辑并重走”，助手消息提供“从这里继续”。触发后进入标明来源的“新路径草稿”，但不会立即改写 Pi 会话树。
- 只有第一条非空消息成功持久化时，才在同一 Session 中形成新路径并切换过去；空消息、发送被拒绝或写入失败都不创建空路径。
- 当前路径草稿和尚未创建的新路径草稿按稳定 Session ID 与路径身份分别保存在本机。切换 Session、切换路径或重启应用后逐字恢复。
- 进入新路径草稿前，当前 Composer 中已有的未发送内容自动留在原路径，不弹确认框；取消新路径草稿或切回原路径时原文仍在。
- 路径操作只改变对话历史与模型上下文。项目文件、Git 状态、工作树和分支始终保持当前现实。

### 复制到项目

- Session 操作菜单提供两个并列且独立的动作：
  - `复制到项目…`
  - `复制到项目并归档原会话…`
- 两个动作都先选择目标 Project 与该 Project 已登记的 Source Folder。目标只有一个 Source Folder 时可以预选，但确认界面仍要明确显示最终 `cwd`。
- 没有 Project、目标 Project 没有 Source Folder，或所选 Source Folder 已不存在时，复制提交不可用，并就地引导用户先创建 Project、添加或修复 Source Folder；提交时必须再次校验目标目录。
- 复制范围是源 Session 在操作提交时已经完整持久化的全部 Pi 非 Header 条目与当前路径状态，包括消息路径、模型与思考强度记录、压缩摘要、标签和自定义状态；不包含未发送 Composer 草稿，也不声称只截取当前活动路径。
- 目标是新的 Pi Session：使用新的稳定 Session ID、所选 Source Folder 作为 `cwd`，并保留指向源 Session 的谱系关系。源 Pi JSONL、Session ID、`cwd` 与文件路径不被改写。
- 目标 Session 必须建立与新 Session ID 匹配的 D Code 创建来源，因而可以进入 Recent Sessions（最近会话）；其 `cwd` 同时使它进入目标 Project。继承自源 Session、但仍指向旧 ID 的来源条目不构成目标来源证明。
- 复制成功后自动打开目标 Session。普通复制提供“查看原会话”；复制并归档则提供“在已归档会话中查看”，不得从普通导航绕过归档状态。目标继承复制提交点的全部已持久化状态，但从新 Session ID 建立后与源独立演进，不共享后续消息、模型设置变更或草稿。

### 复制后归档原会话

- `复制到项目并归档原会话…` 必须先完成并验证目标 Session，最后才写入原会话的 D Code Archive（D Code 归档）状态。
- 目标验证至少包括：新 Session ID、目标 `cwd`、完整已持久化历史、有效 D Code 来源与可打开状态。
- 归档只改变 D Code 的可见性，不删除、移动、重命名或改写原 Pi JSONL。Pi CLI 仍可发现并打开原会话。
- 已归档原会话默认从 Recent、Project 普通列表和 Search（搜索）结果中排除；过滤必须发生在排序、分页、数量限制和搜索结果截断之前。
- 左栏提供“已归档会话”入口。用户可以查看来源、归档时间与复制目标，并执行“恢复显示”；恢复只移除归档排除状态，随后按原有 D Code 来源与 Project `cwd` 关系重新参与普通候选集合，不凭空改变来源身份或 Project 关联。
- 归档不删除原会话的本机逐路径草稿。恢复原会话后，原草稿仍逐字存在；这些草稿不会复制到目标 Session。
- 如果复制成功但归档写入失败，目标 Session 继续保留并可打开，原会话继续显示；界面明确报告“复制成功，归档未完成”，不得删除目标或把整项操作误报为完全失败。

## User Stories（用户故事）

1. 作为正在探索多个解法的用户，我希望从较早消息继续而不破坏原路径。
2. 作为经常切换 Session 与路径的用户，我希望每条路径的未发送草稿都能在重启后准确恢复。
3. 作为维护多个 Project 的用户，我希望把完整会话复制到目标 Source Folder，并明确知道它是新会话而不是原地迁移。
4. 作为希望收起旧入口的用户，我希望复制成功后可以归档原会话，但底层 Pi 历史仍然保留并可恢复显示。
5. 作为同时使用 Pi CLI 与 D Code 的用户，我希望 D Code 的归档不会删除、搬动或阻止 Pi CLI 使用原会话。

## Confirmed Constraints（已确认约束）

- 产品文案不得把 Session 复制称为“移动到项目”或“迁移到项目”。“移动 Source Folder”仍是另一项合法操作，只改变 D Code Project 组织元数据。
- 独立会话复制遵循 Pi SDK 的完整会话 Fork（分叉）语义：源保留，目标获得新身份、新 `cwd` 和来源谱系。`0.0.3` 不自定义同 Session ID 的物理迁移器。
- 复制开始前必须取得完整、稳定且可验证的源 Session 快照。源 Session 正在生成、执行工具、等待结构化交互或发生外部写入变化时，不启动复制并给出可操作说明。
- 复制目标在完整发布和验证前不得进入正常导航；实现必须使用隐藏暂存后原子发布，或达到同等提交边界。即使在 Header 写入后进程中断，失败目标也不得被 Recent、Project 或 Search 发现；失败不得归档源 Session，并应允许安全重试或清理暂存物。
- D Code Archive 是 D Code 自有、可逆的展示元数据，不是 Pi Session 状态，不进入模型上下文，也不成为第二套消息历史。
- Recent、Project、Search、已归档列表与会话谱系必须使用同一稳定 Session ID 归档判断；不能只在 Swift 列表末端隐藏。
- 全局搜索默认不返回已归档 Session；已归档列表负责查找和恢复归档对象。恢复后搜索索引按正常可见集合更新。
- 路径草稿与归档元数据仅保存在本机，不跨设备同步，不写入 Pi JSONL，不进入 `0.0.2` 全文索引，也不进入诊断日志。
- `~/.pi/agent` 继续是 Session ID、Header、消息、路径和模型上下文的唯一权威；D Code 不直接修改源 Session 的 Header 或 `cwd`。

## Acceptance Criteria（验收标准）

### 会话路径与草稿

- [ ] 路径谱系能显示当前路径和其他真实路径；切换路径后 transcript 与模型上下文对应所选路径，不改变文件或 Git 状态。
- [ ] “编辑并重走”与“从这里继续”先进入新路径草稿；点击动作、取消、空消息和发送失败均不创建路径。
- [ ] 当前路径已有包含空格和换行的草稿时，进入新路径草稿会自动保留原文；取消或切回后逐字恢复，且新旧草稿不会串线。
- [ ] 第一条非空消息成功持久化后才形成新路径；原路径始终保留，切回后其 transcript 和草稿仍正确。
- [ ] 当前路径草稿与尚未创建的新路径草稿在切换 Session、切换路径和应用重启后仍逐字恢复；只清除被成功发送或用户明确清空的目标草稿。

### 复制到项目

- [ ] Session 操作菜单同时提供“复制到项目…”和“复制到项目并归档原会话…”，不出现“移动会话”或“迁移会话”。
- [ ] 目标 Project 有多个 Source Folder 时可以明确选择；新 Session 的规范化 `cwd` 与所选 Source Folder 完全相同。
- [ ] 没有 Project、Project 没有 Source Folder、Source Folder 已失效或提交时目录发生变化时，两个动作均不可误提交，并给出创建、添加或修复目标的明确入口。
- [ ] 复制后的源、目标 Session ID 不同；目标保留复制提交时源 Session 的全部已持久化历史与路径，并能通过谱系回到源会话。
- [ ] 目标继承复制提交点的模型、思考强度、压缩上下文、标签、自定义状态与当前活动路径；复制完成后在任一 Session 修改这些状态都不会同步到另一 Session。
- [ ] 源 Session 的 JSONL 字节、路径、Header、`cwd` 与稳定 ID 在复制前后不变；项目文件、Git 分支、工作树和暂存区也不改变。
- [ ] 目标 Session 拥有与新 ID 匹配的有效 D Code 来源，可同时进入 Recent 与目标 Project；源会话继承而来的旧来源条目不会被误认成目标来源。
- [ ] 复制成功后自动打开目标 Session；原 Session 的未发送草稿仍只属于原 Session，目标 Composer 初始为空。
- [ ] 源 Session 忙碌、外部写入变化、目标目录不可用或目标验证失败时，操作明确失败，源保持可见且不产生正常导航可见的半完成目标。
- [ ] 复制进行期间同时刷新 Recent、Project 与 Search，看不到半完成目标；在目标 Header 已写入但历史尚未完成时模拟进程中断，重启后仍不进入普通导航，并可安全清理或重试。

### 复制并归档

- [ ] 普通“复制到项目…”完成后，原 Session 继续按原有 Recent / Project / Search 规则显示。
- [ ] “复制到项目并归档原会话…”只有在目标完整发布且验证成功后才归档源；失败或取消不会隐藏源。
- [ ] 归档源 Session 后，它不会因“查看更多”、重新打开搜索、搜索缓存、Project 展开或重新关联 Source Folder 而泄漏回普通列表。
- [ ] 已归档会话入口能列出原 Session、复制目标和归档时间；普通复制可直接“查看原会话”，复制并归档只能“在已归档会话中查看”，不能绕过归档状态。
- [ ] 执行“恢复显示”后，原 Session 只按正常来源与 `cwd` 规则重新参与投影：有有效 D Code 来源才进入 Recent；`cwd` 对应的 Source Folder 已关联才进入 Project 与全局可见集合；没有任何成立来源时仍不出现在普通导航。
- [ ] 恢复矩阵覆盖 D Code 创建 / 旧 Pi 两种来源，以及对应 Source Folder 已关联 / 未关联两种状态；恢复不得为旧 Pi Session 补写 D Code 来源。
- [ ] 归档状态跨应用重启保持；Pi CLI 对源 Session 的后续读取或写入不会自动取消归档。
- [ ] 归档与恢复均不修改源 Pi JSONL；隔离验收中 Pi CLI 仍能发现并打开归档源会话。
- [ ] 复制成功但归档写入失败时，目标保留并可打开，原会话仍可见，界面给出可重试归档的明确说明。
- [ ] 归档后再恢复源会话，原有逐路径草稿逐字保持；目标 Session 不获得这些未发送草稿。

### 回归与界面

- [ ] `0.0.2` 搜索、`0.0.1` Project / Recent、持续观察、按需写入、Composer、设置与响应式三栏自动门禁持续通过。
- [ ] 系统、浅色、深色及 `1280/1279/880/879 pt` 边界下，路径谱系、目标选择、复制状态、归档列表和错误均清晰可用。
- [ ] 两个复制操作、归档恢复与路径动作具备完整键盘操作、VoiceOver 名称、可见焦点与至少 40 pt 命中区域。

## Out of Scope（非目标）

- 保持同一 Session ID 并物理改写 Header `cwd`、重命名会话目录或迁移 Pi JSONL。
- 从任意消息截取单一路径并创建独立 Session，或只复制当前活动路径；`0.0.3` 的跨项目复制范围是完整已持久化 Session。
- 复制未发送 Composer 草稿、文件快照、Git 分支、工作树、暂存区、Project 配置或搜索索引。
- 删除 Pi Session、清空归档源 JSONL、自动清理 Pi CLI 可见历史或不可恢复的永久删除。
- 在模型生成、工具执行、结构化交互或外部写入变化期间热复制。
- 云端同步归档状态、跨设备恢复草稿或多人共享归档列表。
