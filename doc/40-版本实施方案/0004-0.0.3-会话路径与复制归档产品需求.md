# D Code 0.0.3 会话路径与复制归档产品需求

> 后续收窄：本版快速创建记录仍是 `v0.0.3` 的历史行为；自 `0.0.5` 起，App 的创建触发时机由 [ADR 0014](../决策档案/0014-新会话延迟创建与本地草稿边界.md) 取代为“首次发送才调用 `session.create`”。Host 创建提交后立即进入 Recent、不可伪装回滚的合同继续有效。

状态：Published Regression Tag（已推送回归标签，`v0.0.3`；人工验收未全部完成）

适用范围：在 `0.0.2` 可见会话搜索与既有原生会话基线上，交付同一 Pi Session（Pi 会话）的路径操作、逐路径草稿、完整会话复制、直接归档与置顶整理，以及非模态 Work Inspector、轮次级原生会话呈现与长会话导航尺

基线依赖：[0.0.2 可见会话搜索产品需求](0003-0.0.2-可见会话搜索产品需求.md)、[0.0.1 用户首页与项目工作台产品需求](0002-0.0.1-用户首页与项目工作台产品需求.md)与[首个可日常使用版本产品需求](0001-首个可日常使用版本产品需求.md)继续提供选择性回归约束。搜索可见性、Project / Source Folder（源文件夹）关系、单写入安全与 Composer（输入区）状态不得回退；会话所有权以 [ADR 0018](../决策档案/0018-打开即接管与单写入所有权.md) 的打开即接管为准。

## Problem Statement（问题陈述）

`0.0.2` 可以从可见历史中找到并打开同一个 Pi Session，但用户仍只能看到当前活动 Session Path（会话路径），不能在原生界面中安全查看路径谱系、从较早消息继续，或为不同路径分别保留未发送草稿。
长会话在折叠工具过程后仍可能包含数十个工作轮。仅靠滚动条无法看出轮次结构，也难以回到某个问题与最终回答。导航必须是当前路径内的纯滚动定位，不能被误解为新分支或侧边回复。

用户还需要把一段已有工作带到另一个 Project 的 Source Folder。Pi 的真实能力会保留源会话，并创建拥有新 Session ID（会话标识）与新 `cwd` 的完整会话副本；如果产品把它称为“移动”或“迁移”，用户会误以为原会话身份和文件被原地搬走。D Code 必须使用与底层事实一致的两个复制操作。与此同时，日常整理还需要不依赖复制目标的直接归档，以及只改变现有列表顺序的置顶；这些操作都不能改写 Pi 会话事实或扩大原有可见范围。

## Solution（解决方案）

### 会话路径与逐路径草稿

- D Code 提供所选 Session 的路径谱系，明确标出当前路径、路径起点和更新时间；日常左栏仍只显示 Session，不把全部路径永久展开。
- 用户消息提供“编辑并重走”，助手消息提供“从这里继续”。触发后进入标明来源的“新路径草稿”，但不会立即改写 Pi 会话树。
- 只有第一条非空消息成功持久化时，才在同一 Session 中形成新路径并切换过去；空消息、发送被拒绝或写入失败都不创建空路径。
- 当前路径草稿和尚未创建的新路径草稿按稳定 Session ID 与路径身份分别保存在本机。切换 Session、切换路径或重启应用后逐字恢复。
- 进入新路径草稿前，当前 Composer 中已有的未发送内容自动留在原路径，不弹确认框；取消新路径草稿或切回原路径时原文仍在。
- 路径操作只改变对话历史与模型上下文。项目文件、Git 状态、工作树和分支始终保持当前现实。

### 快速新建与空会话清理

- `session.create` 只在完整 Header 与 D Code 来源标记原子发布后确认创建，不等待旧可写 Runtime 的 abort、扩展关闭或 Lease 同步。
- App 收到创建提交后立即把新 Session 放入 Recent，再用独立的 `session.open(readOnly)` 请求安全切换观察对象。旧 Runtime 清理变慢不得让用户误以为新会话没有创建。
- 由 D Code 创建、尚无任何消息且没有子会话引用的 Session 提供“移到废纸篓…”；不使用“归档”冒充删除，也不提供不可恢复的 `unlink`。
- Host 按稳定 Session ID 唯一解析文件，取得临时 Lease 后再次校验 D Code 来源、消息数、路径身份和子会话关系，成功后才移入 macOS 用户废纸篓。任何校验或移动失败都保留原文件。
- 成功后同一 ID 从 Recent、Project、Search 和当前会话中消失，并清除其本机未发送草稿；Finder 废纸篓中的 Pi JSONL 仍可人工恢复。

### 复制到项目

- Session 操作菜单提供两个并列且独立的动作：
  - `复制到项目…`
  - `复制到项目并归档原会话…`
- 两个动作都先选择目标 Project 与该 Project 已登记的 Source Folder。目标只有一个 Source Folder 时可以预选，但确认界面仍要明确显示最终 `cwd`。
- 没有 Project、目标 Project 没有 Source Folder，或所选 Source Folder 已不存在时，复制提交不可用，并就地引导用户先创建 Project、添加或修复 Source Folder；提交时必须再次校验目标目录。
- 复制范围是源 Session 在操作提交时已经完整持久化的全部 Pi 非 Header 条目与当前路径状态，包括消息路径、模型与思考强度记录、压缩摘要、标签和自定义状态；不包含未发送 Composer 草稿，也不声称只截取当前活动路径。
- 目标是新的 Pi Session：使用新的稳定 Session ID、所选 Source Folder 作为 `cwd`，并保留指向源 Session 的谱系关系。源 Pi JSONL、Session ID、`cwd` 与文件路径不被改写。
- 目标 Session 必须建立与新 Session ID 匹配的 D Code 创建来源，因而可以进入 Recent Sessions（最近会话）；其 `cwd` 同时使它进入目标 Project。继承自源 Session、但仍指向旧 ID 的来源条目不构成目标来源证明。
- 复制成功后自动打开目标 Session。普通复制提供“查看原会话”；复制并归档则提供“在已归档会话中查看”，不得从普通导航绕过归档状态。目标继承复制提交点的全部已持久化状态，但从新 Session ID 建立后与源独立演进，不共享后续消息、模型设置变更或草稿。

### 复制后归档原会话

- `复制到项目并归档原会话…` 必须先完成并验证目标 Session，最后才写入原会话的 D Code Archive（D Code 归档）状态。
- 目标验证至少包括：新 Session ID、目标 `cwd`、完整已持久化历史、有效 D Code 来源与可打开状态。
- 归档只改变 D Code 的可见性，不删除、移动、重命名或改写原 Pi JSONL。Pi CLI 仍可发现并打开原会话。
- 已归档原会话默认从 Recent、Project 普通列表和 Search（搜索）结果中排除；过滤必须发生在排序、分页、数量限制和搜索结果截断之前。
- 左栏提供“已归档会话”入口。用户可以查看来源、归档时间与复制目标，并执行“恢复显示”；恢复只移除归档排除状态，随后按原有 D Code 来源与 Project `cwd` 关系重新参与普通候选集合，不凭空改变来源身份或 Project 关联。
- 归档不删除原会话的本机逐路径草稿。恢复原会话后，原草稿仍逐字存在；这些草稿不会复制到目标 Session。
- 如果复制成功但归档写入失败，目标 Session 继续保留并可打开，原会话继续显示；界面明确报告“复制成功，归档未完成”，不得删除目标或把整项操作误报为完全失败。

### 会话置顶与直接归档

- Recent 与 Project 的会话行在指针悬停或键盘聚焦时显示“置顶 / 取消置顶”和“归档”操作；同样动作必须存在于右键菜单与当前 Session 操作菜单，Hover（悬停）不能成为唯一入口。
- 置顶以稳定 Session ID 保存为 D Code 本机元数据，不写 Pi JSONL、不修改 `cwd`、来源或 Project 关系。同一 Session 同时出现在 Recent 与 Project 时共享置顶状态。
- 置顶只改变会话在其已经成立的可见集合中的排序，不能把旧 Pi Session 注入 Recent，也不能绕过归档。已置顶候选必须在分页前参与排序，重启后较旧的置顶会话仍留在首屏。
- 用户可以不经过复制直接归档任何当前可见的空闲 Session。直接归档与复制后归档使用同一可逆可见性边界，但直接归档记录没有虚假的复制目标。
- 归档优先于置顶；归档后会话从 Recent、Project 与 Search 排除，但保留置顶状态和逐路径草稿。恢复显示后按原来源与 `cwd` 资格重新投影，并恢复原置顶状态。
- 直接归档当前 Session 前先保存草稿；归档资料原子保存成功后才移除普通导航。保存失败时列表、搜索、当前详情与 Pi JSONL 全部保持原样。

### 原生工作台呈现

- Work Inspector 是与会话并行的非模态右栏。在 `≥880 pt` 且存在检查作用域时，它优先原位常驻，不压暗、禁用或隐藏左栏与中央会话；`880–1105 pt` 时左栏改用临时覆盖以保留中央宽度，`<880 pt` 才使用左右互斥模态覆盖。
- 产品会话以用户消息为 Conversation Round（工作轮）边界。一个工作轮可含多个 Pi turn、Thinking、中间助手叙述和工具调用。
- 运行中主阅读区只显示当前 Thinking 片段或当前工具；工具或阶段结束后原位替换，不持续堆叠。`agent_end(willRetry=true)` 不能让活动提前消失，直到 `agent_settled` 才结束实时状态。
- 工作轮完成后默认只显示最终助手回答；中间 Thinking、过程回复、工具调用和结果收入一个可展开摘要，摘要显示耗时、工具数与完成时间。错误或中止结果默认可见。
- 助手最终回答必须保留原始 Markdown 的段落、空行、无序列表与有序列表换行；呈现层不得把块级结构压成一段连续文字，复制仍返回原始正文。
- 历史耗时与完成时间使用本轮 JSONL 用户 entry 到最后已接受 entry 的持久化时间。这是可跨重启恢复的近似口径，不冒充 provider 或 `agent_settled` 的精确时刻。
- 中央会话空间充足且当前路径至少有两个工作轮时，左缘显示 Conversation Navigation（对话导航）。一个刻度对应一个工作轮；悬停预览“用户问题 + 最终回答”，点击只滚动定位并短暂高亮该轮。
- 对话导航跳到历史轮后暂停自动追尾，显示“回到最新”恢复跟随。它只投影当前所选 Session Path，不修改 Pi JSONL、模型上下文、路径选择或本机草稿；从某条消息继续仍必须显式使用路径动作。
- `pi-dhashline` 等已启用普通扩展可继续经 Host/Pi SDK 注册并执行 headless 工具，但 D Code 不调用其 `pi-tui` renderer。read/edit/write/search 使用 D Code 自有 SwiftUI presenter：默认显示安全动作摘要，展开显示必要行锚点、read 首尾边界、search 匹配和精简 diff；write/edit 正文默认隐藏，未识别结构保留通用 fallback。

## User Stories（用户故事）

1. 作为正在探索多个解法的用户，我希望从较早消息继续而不破坏原路径。
2. 作为经常切换 Session 与路径的用户，我希望每条路径的未发送草稿都能在重启后准确恢复。
3. 作为维护多个 Project 的用户，我希望把完整会话复制到目标 Source Folder，并明确知道它是新会话而不是原地迁移。
4. 作为希望收起旧入口的用户，我希望复制成功后可以归档原会话，但底层 Pi 历史仍然保留并可恢复显示。
5. 作为同时使用 Pi CLI 与 D Code 的用户，我希望 D Code 的归档不会删除、搬动或阻止 Pi CLI 使用原会话。
6. 作为长时间会话的用户，我希望完成后先阅读最终结论，需要时再展开 Thinking 与工具过程。
7. 作为正在等待工作轮完成的用户，我希望只看到当前正在做什么，并在完成后看到耗时与完成时间。
8. 作为依赖 DHashline 文件安全能力的用户，我希望保留它的执行语义，同时获得 D Code 原生锚点与 diff 界面。
9. 作为快速开始工作的用户，我希望新会话一旦落盘就立即出现，不为上一个 Runtime 的安全清理等待十几秒。
10. 作为误创建空会话的用户，我希望可以将它移到废纸篓，但不误删有消息或有谱系引用的会话。
11. 作为需要回看长会话的用户，我希望从侧边轮次刻度预览并定位某个问题和最终回答，而不改变会话路径。
12. 作为会话较多的用户，我希望把重要会话置顶，而且重启或加载更多后仍保持在原有列表顶部。
13. 作为只想收起旧入口的用户，我希望直接归档会话而无需先复制，并能保留草稿、置顶状态与底层 Pi 历史。

## Confirmed Constraints（已确认约束）

- 产品文案不得把 Session 复制称为“移动到项目”或“迁移到项目”。“移动 Source Folder”仍是另一项合法操作，只改变 D Code Project 组织元数据。
- 独立会话复制遵循 Pi SDK 的完整会话 Fork（分叉）语义：源保留，目标获得新身份、新 `cwd` 和来源谱系。`0.0.3` 不自定义同 Session ID 的物理迁移器。
- 复制开始前必须取得完整、稳定且可验证的源 Session 快照。源 Session 正在生成、执行工具、等待结构化交互或发生外部写入变化时，不启动复制并给出可操作说明。
- 复制目标在完整发布和验证前不得进入正常导航；实现必须使用隐藏暂存后原子发布，或达到同等提交边界。即使在 Header 写入后进程中断，失败目标也不得被 Recent、Project 或 Search 发现；失败不得归档源 Session，并应允许安全重试或清理暂存物。
- D Code Archive 是 D Code 自有、可逆的展示元数据，不是 Pi Session 状态，不进入模型上下文，也不成为第二套消息历史。
- Session Pin（会话置顶）同样是本机展示元数据，只能在来源与 Project 资格已经成立后参与分页前排序；它不能扩大可见集合或覆盖 Archive。
- Recent、Project、Search、已归档列表与会话谱系必须使用同一稳定 Session ID 归档判断；不能只在 Swift 列表末端隐藏。
- 全局搜索默认不返回已归档 Session；已归档列表负责查找和恢复归档对象。恢复后搜索索引按正常可见集合更新。
- 路径草稿与归档元数据仅保存在本机，不跨设备同步，不写入 Pi JSONL，不进入 `0.0.2` 全文索引，也不进入诊断日志。
- `~/.pi/agent` 继续是 Session ID、Header、消息、路径和模型上下文的唯一权威；D Code 不直接修改源 Session 的 Header 或 `cwd`。
- Work Inspector 的常驻是非模态布局，不得仅通过删掉蒙版但保留对兄弟区域的 hit-testing 或 VoiceOver 禁用来伪装。
- 工具的模型执行内容与用户可见 presenter 分离；Swift 不得为了呈现重写 DHashline 的 hash、stale 检查或文件写入引擎，也不得解析终端画面。
- 对话导航是纯 Swift 的当前路径轮次投影，不新增 Host/IPC 写入能力；不将悬停、点击、键盘调整或“回到最新”解释为 Write Intent（写入意图）。
- 创建提交与会话激活是两个独立完成信号；不得为了界面速度跳过旧 Runtime 的安全关闭、Lease 释放或观察身份校验。
- “移到废纸篓”是可恢复的文件操作，不是 D Code Archive；Host 不得在废纸篓失败后回退为永久删除。

## Acceptance Criteria（验收标准）

### 会话路径与草稿

- [ ] 路径谱系能显示当前路径和其他真实路径；切换路径后 transcript 与模型上下文对应所选路径，不改变文件或 Git 状态。
- [ ] “编辑并重走”与“从这里继续”先进入新路径草稿；点击动作、取消、空消息和发送失败均不创建路径。
- [ ] 当前路径已有包含空格和换行的草稿时，进入新路径草稿会自动保留原文；取消或切回后逐字恢复，且新旧草稿不会串线。
- [ ] 第一条非空消息成功持久化后才形成新路径；原路径始终保留，切回后其 transcript 和草稿仍正确。
- [ ] 当前路径草稿与尚未创建的新路径草稿在切换 Session、切换路径和应用重启后仍逐字恢复；只清除被成功发送或用户明确清空的目标草稿。

### 新建与空会话清理

- [ ] 已有可写会话时新建 Session，Header 与来源标记提交后新会话立即出现于 Recent；即使随后打开请求仍在等待旧 Runtime 清理，也不回滚或隐藏已创建对象。
- [ ] 创建请求不扫描全库 Session ID、不获取新 Session Lease、不加载扩展，也不关闭当前可写 Runtime；首次发送仍按原有 on-demand write 边界取得写入权。
- [ ] Recent 行右键菜单与当前 Session 操作菜单为空的 D Code 会话显示“移到废纸篓…”和二次确认；非空、旧 Pi、正在可写、身份重复或存在子会话时不误移动。
- [ ] 移入废纸篓成功后，原路径消失、废纸篓副本存在，Recent / Project / Search / 当前详情与本机草稿同步清理；失败时文件和界面投影全部保留。

### 复制到项目

- [ ] Session 操作菜单同时提供“复制到项目…”和“复制到项目并归档原会话…”，不出现“移动会话”或“迁移会话”。
- [ ] 目标 Project 有多个 Source Folder 时可以明确选择；新 Session 的规范化 `cwd` 与所选 Source Folder 完全相同。
- [ ] 没有 Project、Project 没有 Source Folder、Source Folder 已失效或提交时目录发生变化时，两个动作均不可误提交，并给出创建、添加或修复目标的明确入口。
- [ ] 复制后的源、目标 Session ID 不同；目标保留复制提交时源 Session 的全部已持久化历史与路径，并能通过谱系回到源会话。
- [ ] 目标继承复制提交点的模型、思考强度、压缩上下文、标签、自定义状态与当前活动路径；复制完成后在任一 Session 修改这些状态都不会同步到另一 Session。
- [ ] 源 Session 的 JSONL 字节、路径、Header、`cwd` 与稳定 ID 在复制前后不变；项目文件、Git 分支、工作树和暂存区也不改变。
- [ ] 目标 Session 拥有与新 ID 匹配的有效 D Code 来源，可同时进入 Recent 与目标 Project；源会话继承而来的旧来源条目不会被误认成目标来源。
- [ ] 复制成功后自动打开目标 Session；原 Session 的未发送草稿仍只属于原 Session，目标 Composer 初始为空。
- [ ] 源 Session 忙碌、外部写入变化、目标目录不可用或目标验证失败时，操作明确失败，源保持可见且不产生正常导航可见的半完成目标。
- [ ] 复制进行期间同时刷新 Recent、Project 与 Search，看不到半完成目标；在目标 Header 已写入但历史尚未完成时模拟进程中断，重启后仍不进入普通导航，并可安全清理或重试。

### 复制并归档

- [ ] 普通“复制到项目…”完成后，原 Session 继续按原有 Recent / Project / Search 规则显示。
- [ ] “复制到项目并归档原会话…”只有在目标完整发布且验证成功后才归档源；失败或取消不会隐藏源。
- [ ] 归档源 Session 后，它不会因“查看更多”、重新打开搜索、搜索缓存、Project 展开或重新关联 Source Folder 而泄漏回普通列表。
- [ ] 已归档会话入口能列出原 Session、复制目标和归档时间；普通复制可直接“查看原会话”，复制并归档只能“在已归档会话中查看”，不能绕过归档状态。
- [ ] 执行“恢复显示”后，原 Session 只按正常来源与 `cwd` 规则重新参与投影：有有效 D Code 来源才进入 Recent；`cwd` 对应的 Source Folder 已关联才进入 Project 与全局可见集合；没有任何成立来源时仍不出现在普通导航。
- [ ] 恢复矩阵覆盖 D Code 创建 / 旧 Pi 两种来源，以及对应 Source Folder 已关联 / 未关联两种状态；恢复不得为旧 Pi Session 补写 D Code 来源。
- [ ] 归档状态跨应用重启保持；Pi CLI 对源 Session 的后续读取或写入不会自动取消归档。
- [ ] 归档与恢复均不修改源 Pi JSONL；隔离验收中 Pi CLI 仍能发现并打开归档源会话。
- [ ] 复制成功但归档写入失败时，目标保留并可打开，原会话仍可见，界面给出可重试归档的明确说明。
- [ ] 归档后再恢复源会话，原有逐路径草稿逐字保持；目标 Session 不获得这些未发送草稿。

### 置顶与直接归档

- [ ] Recent 与 Project 会话行悬停或键盘聚焦时显示独立的置顶和归档按钮；点击图标不打开或切换会话，行高和标题位置不跳动。
- [ ] 置顶、取消置顶与直接归档同时可通过行内按钮、右键菜单、当前 Session 操作菜单、键盘和 VoiceOver 完成；每个动作拥有至少 `40 pt` 命中区域和明确对象名称。
- [ ] 置顶一条已掉出 Recent / Project 首屏的旧会话后，它立即进入对应列表顶部并跨重启保持；取消置顶后恢复按更新时间排序。
- [ ] Project 中的旧 Pi Session 可以在该 Project 内置顶，但不会因此进入 Recent；同一可见 Session 在 Recent 与 Project 两处的置顶状态同步。
- [ ] 直接归档不要求复制目标；已归档列表显示来源与归档时间而不伪造“复制目标”。恢复后保留归档前的逐路径草稿与置顶状态。
- [ ] 置顶会话归档后不会因分页、Project 展开或 Search 重新出现；归档资料写入失败时所有普通投影与当前详情保持不变，Pi JSONL 字节不变。

### 原生工作台呈现

- [ ] `≥1106 pt` 时左/中/右三栏并排，`880–1105 pt` 时右栏常驻且左栏按需覆盖，`<880 pt` 左右互斥；右栏常驻时左栏与会话不变暗、可点击并仍在 VoiceOver 树中。
- [ ] 含多次 Thinking / 工具 / 中间回复的完成工作轮默认只显示最终回答；展开摘要后可按原顺序查看完整过程，折叠不影响消息搜索定位与真实 Session Path 动作。
- [ ] 模型运行中只显示当前 Thinking 或当前工具；工具切换后旧活动不继续堆叠，retry 期间不提前消失，settled 后转为持久化轮次且不重复闪烁。
- [ ] 完成摘要显示可读耗时、去重后工具数与完成时间；重启后仍按 JSONL 持久化时间稳定恢复，界面不声称这是精确 `agent_settled` 时刻。
- [ ] 一个当前路径含多个工作轮时，对话导航的刻度与轮次一一对应；悬停只预览问题与最终回答，点击精确滚动并短暂高亮，不切换路径或产生 Pi 写入。
- [ ] 对话导航定位历史轮后，streaming 和新持久化条目不把视图拉回底部；点击“回到最新”后立即到底部并恢复自动跟随。
- [ ] 长会话刻度在有限高度中有界采样，但指针位置仍能映射到最近工作轮；中央宽度不足时隐藏常驻导航，不挤压消息最小阅读空间。
- [ ] 对话导航拥有至少 `40 pt` 命中区域、可见键盘焦点、上下方向键和 VoiceOver adjustable action（可调节操作）；读出“第 X 轮 / 共 Y 轮 / 问题摘要”，悬停卡不重复进入旁白树。Reduce Motion（减少动态效果）开启时取消动画滚动。
- [ ] 真实 `pi-dhashline` read/edit/write/search 可在 D Code Host 中加载和执行；界面不出现 TUI，原生卡片只显示安全摘要、read 首尾边界、search 匹配、diff 和必要错误，展开 write/edit 也不泄漏完整正文。
- [ ] 包含多个段落、空行、粗体、无序列表与有序列表的历史或流式最终回答保留原换行与列表标记，不再压成连续文字；复制结果仍与原始消息正文一致。

## Out of Scope（非目标）

- 保持同一 Session ID 并物理改写 Header `cwd`、重命名会话目录或迁移 Pi JSONL。
- 从任意消息截取单一路径并创建独立 Session，或只复制当前活动路径；`0.0.3` 的跨项目复制范围是完整已持久化 Session。
- 复制未发送 Composer 草稿、文件快照、Git 分支、工作树、暂存区、Project 配置或搜索索引。
- 非空会话、旧 Pi 会话、有子会话谱系引用的会话、归档源 JSONL 的物理清空，或任何不可恢复的永久删除。`0.0.3` 只支持将空的 D Code 创建会话移入废纸篓。
- 在模型生成、工具执行、结构化交互或外部写入变化期间热复制。
- 跨 Session Path 混合轮次总览、侧边回复线程、点击导航即隐式分叉，或为紧凑宽度另建一套模态对话导航。
- 云端同步置顶或归档状态、跨设备恢复草稿或多人共享归档列表。
