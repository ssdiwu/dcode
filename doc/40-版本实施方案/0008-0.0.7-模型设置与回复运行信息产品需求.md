# D Code 0.0.7 模型设置与回复运行信息产品需求

状态：Published Source Tag（公开源码标签 `v0.0.7`；自动门禁与 App bundle 记录已成立，人工验收仍待完成）

本 PRD 冻结 `0.0.7` 的新增范围与验收边界；Pi 模型目录、认证、缓存刷新、全局 `enabledModels`、默认模型、项目覆盖与当前 Session 模型之间的关系以 [ADR 0015](../决策档案/0015-Pi-模型目录与全局选择设置边界.md) 为准，运行中介入与耐久队列的差异以 [ADR 0011](../决策档案/0011-后续消息队列所有权与派发边界.md) 为准。`0.0.7` 不改变 Pi Session 的会话与消息权威，也不提前引入 Project Trust 或自定义供应商编辑。

## Problem Statement（问题陈述）

`0.0.6` 的 Composer 已经能消费 Pi 当前生效的模型范围，但用户仍需要离开 D Code 才能查看完整模型目录、刷新在线目录、理解缓存状态、管理 `enabledModels` 或设置默认模型。目录、认证、启用范围、项目覆盖和当前 Session 模型也容易被误解为同一件事。

完成一轮工作后，D Code 目前把完成日期和耗时隐藏在 Hover（悬停）或键盘焦点后，并且完全忽略 Pi Assistant Message 已持久化的 token usage（令牌用量）。用户无法在阅读回复时稳定判断这轮何时完成、用了多久、实际花费多少 token。

最终候选手测还暴露出交互噪声与控制缺口：Context 圆环没有表达已用量，少量轮次导航被拉散到整列，完成后的 Interaction Dock 重复解释“本轮已完成”，Return 没有提交 Composer，Thinking 在工具边界后消失，运行中普通消息只能进入耐久队列；模型页还同时暴露手写规则输入与全部未认证内建模型。

## Solution（解决方案）

Settings 新增“模型”页面，以 Pi Host 返回的真实模型目录为唯一来源：首次缓存优先读取、显式在线刷新，主目录只展示已认证 Provider；未认证 Provider 收拢到页面底部的关联入口，并通过 Pi `ModelRuntime.login` 完成 API Key / OAuth 认证。全局启用只从具体模型行加入或移出，不提供平行的手写规则输入；既有通配规则继续透明展示。项目级覆盖只读标明，设置写入通过 Pi `SettingsManager`，认证持久化通过 Pi 自有凭据合同完成。

每条已经稳定完成的最终助手回复下方增加低对比度、常驻的运行信息行，就近显示完成状态、完成时间、从本轮用户消息到最终结果的耗时，以及本轮所有 Pi Assistant Message 持久化 `usage.totalTokens` 的合计。缺少某项真实数据时只省略该项，不估算、不以当前 Context Usage（上下文用量）代替。

Composer 的 Context 圆环以完整蓝环表示未使用状态，已消耗比例从顶部逐渐覆盖为白色；轮次导航从顶部按固定最大间距累积。Return 直接提交，最终稳定回复仍保留时间 / 耗时 / token，但完成态不再占据 Interaction Dock。运行中的 Thinking 与工具状态可以同时查看；普通消息可在“立即介入”（Pi steer）和“排队等待”（D Code 耐久队列）之间显式切换。

## User Stories（用户故事）

1. 作为使用多个 Provider 的用户，我希望在 D Code 中按供应商查看 Pi 当前知道的模型及其认证、缓存和选择状态。
2. 作为经常离线或遇到目录接口波动的用户，我希望刷新失败后仍能看到上一次可辨认目录，而不是得到空白页。
3. 作为使用精确与通配 `enabledModels` 的用户，我希望看清每个模型由哪条规则启用，并且一次点击不会暗中破坏其他规则。
4. 作为同时使用全局和项目 Pi 设置的用户，我希望知道当前项目为什么没有采用刚修改的全局值，并且 D Code 不越权写项目配置。
5. 作为回看一轮工作结果的用户，我希望无需悬停就看到它的完成时间、耗时和本轮 token，用来判断执行成本与新旧程度。
6. 作为运行中补充约束的用户，我希望决定这条信息立即介入当前 Run，还是等当前 Run 结束后再执行。
7. 作为尚未关联 Provider 的用户，我希望从统一入口完成 Pi 支持的 API Key / OAuth 流程，而不是先浏览一整页不可用模型。

## Confirmed Constraints（已确认约束）

- Pi `ModelRuntime`、`SettingsManager`、`settings.json`、`models.json`、目录缓存和认证合同分别保持权威；D Code 只提供原生呈现与受控调用。
- `enabledModels` 是 Composer 选择器与快捷切换范围，不是模型存在性、供应商认证状态或 Session 历史事实。
- `0.0.7` 只修改全局 Pi 设置；项目覆盖可以读取并解释，但不能修改。
- API Key / Provider 配置值只允许在一次认证交互中短暂经过 SecureField 与本机 IPC，提交或取消后立即从界面状态清除；D Code 不保存、不回显、不写日志，OAuth token 与认证文件正文始终不进入 Swift。
- 当前及历史 Session 的实际模型不随全局默认或启用规则变化而改写；范围外当前模型仍可见。
- 回复 token 只来自对应工作轮中 Pi 已持久化的 Assistant Message `usage.totalTokens`；多次模型调用按轮求和，未知字段不推断为零。
- 回复完成时间与耗时继续使用 Pi Entry 的持久化时间边界；没有稳定最终助手回复或失败事实时不伪造完成状态。

## Acceptance Criteria（验收标准）

### 模型目录与刷新

- [ ] 无论当前是否已经打开 Pi Session，进入“设置 → 模型”都能从当前工作目录读取 Pi 目录；主目录只按已认证 Provider 分组显示安全模型元数据，未认证 Provider 不展开内建模型。
- [ ] 首次进入不发起网络刷新；动态 Provider 有缓存时显示缓存检查时间，没有缓存时明确显示，静态 Provider 不冒充在线缓存。
- [ ] 用户显式刷新后，成功的 Provider 显示新目录与新检查时间；单个 Provider 失败、整体离线或超时仍保留刷新前目录，并在对应位置给出可恢复状态。
- [ ] 未认证 Provider 收拢到页面底部“关联 Provider”入口；API Key / OAuth 使用 Pi 原生登录合同，环境型认证说明外部配置方式，成功后目录自动刷新，取消或失败不泄漏凭据。
- [ ] 目录暂无模型、缓存损坏或 Pi 设置读取失败均显示明确边界，不把它们统一伪装成“模型已关闭”。

### 启用范围与默认模型

- [ ] 全局 `enabledModels` 未配置或为空时，页面明确说明所有已认证模型均在 D Code 选择范围；页面不会为了关闭单个模型而静默展开成大量精确规则。
- [ ] 精确、通配和带推理强度后缀的既有规则原样显示并标明匹配数或无匹配警告；页面不提供手写规则输入框或“恢复全部”的平行捷径。
- [ ] 已存在有限范围时，未命中的已认证模型通过模型行“加入全局启用”追加精确 `provider/model`；只有模型不再受其他规则覆盖时才允许从模型行移出，由通配规则命中的模型只说明规则来源。
- [ ] 设置全局默认模型前验证它存在、已认证且位于全局选择范围；不满足时不写入并给出先启用的恢复路径。已有不一致默认值只警告，不自动替换。
- [ ] 当前 `cwd` 存在项目级默认或 `enabledModels` 覆盖时，页面同时展示全局值与当前生效值，并明确项目覆盖只读；所有修改都只写全局 `settings.json`。
- [ ] 修改后新建会话模型菜单与已有会话下一次显式模型选择使用最新生效范围；当前范围外模型仍按真实名称显示，当前与历史消息不被改写。

### 助手回复运行信息

- [ ] 已稳定完成的最终助手回复下方常驻显示完成状态、完成时间和耗时；无需 Hover，深浅外观和键盘导航下均可辨认且不遮挡正文。
- [ ] 工作轮包含一个或多个 Pi Assistant Message 用量时，状态行显示各条 `usage.totalTokens` 的合计并使用紧凑等宽数字；缺少真实用量时省略 token，不显示 `0` 或估算值。
- [ ] 工具调用产生多次 Assistant Message 时不会只取最终文本消息的 token，也不会把当前会话 Context Usage 当作本轮花费。
- [ ] VoiceOver 能一次读出完成或失败、完成时间、耗时与 token；视觉状态不只依赖绿色或红色。
- [ ] 复制、编辑并重走、从这里继续等消息动作仍可按 Hover 或键盘焦点渐进出现；运行事实常显不会造成回复宽度或纵向布局跳动。

### Composer 与运行交互

- [ ] Context 默认显示完整蓝环，已用比例从顶部逐渐覆盖为白色；Popover 的已用 / 窗口 / 剩余数值与圆环方向一致，缺少真实数据时不伪造比例。
- [ ] 左侧轮次导航从顶部以最多 `22pt` 间距向下累积；少量轮次不再分散到整列，密集长会话仍有界采样且保留首尾。
- [ ] Return 在 Composer 聚焦时直接发送或按当前运行发送方式提交，不再触发轮次选中；轮次跳转只滚动并更新左侧刻度，不给整轮绘制持续蓝框。
- [ ] 运行中 Thinking 不因 Assistant / Tool 边界被清空，Thinking、当前工具与流式正文可以同时查看；完成后展开一次“中间过程”即可看到思考正文，不再嵌套第二层折叠。
- [ ] Interaction Dock 只保留运行、等待、停止、失败、结果未知、介入中与队列等需要理解或行动的状态；稳定完成与普通中止不再显示冗余卡片。
- [ ] “立即介入”调用 Pi steer，只在运行态、无结构化等待且正文不是斜杠命令时可用；正文先保留为路径草稿，Run 正常完成才清除，失败 / 中止 / 断连 / 结果未知会恢复。切到“排队等待”时仍使用可编辑、可重排、可恢复的 D Code Queue Item。

## Out of Scope（非目标）

- 编辑 Pi `models.json`、新增或删除自定义 Provider、修改模型价格与 API 合同。
- Provider 登出、查看或编辑已保存凭据正文，以及绕过 Pi 登录合同的自建认证存储。
- 写入项目级 `.pi/settings.json`，以及 Project Trust、权限请求、撤回和审计。
- 强制切换当前 Session、回写历史消息模型，或把范围外模型说成不存在。
- 单轮费用金额、上下文占比、点赞 / 点踩、复制 / 重试工具栏的竞品复刻，以及跨会话用量统计和账单分析。
