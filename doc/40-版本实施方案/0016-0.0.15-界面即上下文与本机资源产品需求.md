# D Code 0.0.15 界面即上下文与本机资源产品需求

状态：Published Source Tag（公开源码标签 `v0.0.15`；自动门禁已通过，人工验收与后续审计发现的 `dcode_facts` 生产合同缺口仍待完成）

本 PRD 冻结 `0.0.15` 的范围与验收边界；呈现与上下文边界以 [ADR 0024](../决策档案/0024-界面即上下文与-GUI-原生呈现边界.md) 为准，界面语义以 [`0002-D-Code-原生界面设计系统`](../10-架构与运行/0002-D-Code-原生界面设计系统.md) 为准。

## Problem Statement（问题陈述）

ADR 0024 指出四处决策与实现的落差：D Code 的大量只读对象（文件、hunk、变更账本、证据账本、Session Path、计划）只能被"看"，用户仍须在输入框用自然语言复述刚看到的东西；上下文压缩（`isCompacting` 已在 Host wire 上）在界面完全不可见；Pi 已发现的本机 Skill / Prompt / Command / Extension 没有任何真实加载状态的呈现，"可调用工具只展示 Pi 实际加载并注册成功的结构化合同"未兑现，D Code 独有的派生事实对模型不可见。另有 `0.0.14` 遗留：文件树无键盘操作、`40` 目录记录的四处性能隐患（O(n²) 预览、行级可见性回写、非 lazy diff/树、双 `Task.yield` 等待）。

## Solution（解决方案）

1. **Composer 预填（界面即上下文，ADR 0024 决定 2）**：信息检查器的文件行、Git diff 文件行 / hunk、会话变更账本行、验证证据行，Session Path 谱系节点与 Active Plan 条目提供"引用到输入框"动作，把精确引用（路径、行区间、hunk 定位、账本归因、revision）写入当前 Composer 草稿；用户仍可编辑、仍须显式发送。不自动发送、不隐式注入。
2. **压缩可见性（ADR 0024 决定 4）**：Swift 解码 `HostState.isCompacting`；压缩进行中在会话上下文行显示状态 pill（"正在压缩上下文…"），压缩是影响成本与结果的最大单一 harness 行为，不得再静默发生。
3. **本机资源管理（ADR 0024 + 契约 0001）**：设置新增"本机资源"页，按 Pi `resourceLoader` 真实加载结果展示扩展（含注册的工具 / 命令计数、加载错误）、Skill（名称 / 描述 / 来源 / 是否禁止模型调用）、Prompt 模板（名称 / 描述 / 参数提示）与命令（扩展命令 / prompt / skill: 前缀）四类，含资源诊断；扩展包提供"停用 / 启用"（经 Pi `SettingsManager.setPackages` 真实配置写 + `resourceLoader.reload()` 热重载，停用清单影子存于 `pi-dcode/disabled-packages.json` 以便恢复）；Skill / Prompt / Command 无 Pi 配置合同，只读展示不提供开关（诚实降级）。
4. **首个只读工具 facade（ADR 0024 决定 3）**：注册 `dcode_facts` 只读工具进入同一个 Pi Agent Loop，按判据只暴露 D Code 独有、模型无法等价重建的事实：当前会话的变更账本归因摘要、验证证据摘要、Session Path 谱系、所属 Project 的 Source Folder 集合。不做任何写动作。
5. **遗留收口**：文件树行支持键盘（焦点 + 左右键展开 / 收起、回车打开）；只读文件预览 `lines` 由计算属性改为缓存（消除每次访问全文 split 的 O(n²)）；Git diff 与文件树改 lazy 构建；替换双 `Task.yield()` 硬等布局（以显式帧请求 / 任务依赖替代）；行级可见性回写收窄为惰性去重（不逐行触发 List 失效）。命令描述本地化维持排除（扩展自带文案不属 D Code 自有文案，已在 0.0.14 PRD 记录）。

## Confirmed Constraints（已确认约束）

- 预填只写 Composer 草稿：不得绕过输入框直接发送、不得隐式创建 Run、注入的上下文必须在发送前对用户完全可见且可改。
- 不引入任何审批 / 沙箱 / 模式开关（ADR 0024 决定 5 重申 0023）；facade 是只读事实，不是门禁。
- 工具 facade 必须进入同一个 Pi SDK Agent Loop（`registerTool`），不建第二套调度；不满足三条判据（D Code 独有 / 模型无法等价重建 / 存在明确模型动作）的能力不注册。
- 资源启停只经 Pi 真实配置写（`setPackages`）与资源热重载；不建立第二套资源配置权威；`npm:` 包停用即从 Pi `packages` 移除（文件不删），影子清单只记录原始来源串以便恢复。
- GUI 原生唯一呈现：资源页、压缩状态、预填动作全部原生组件；扩展原始输出 / 诊断文本是"被呈现的数据"，不是终端面板。
- 不动 `AppModel` 整体架构拆分；性能修复不改变对外行为。

- [x] 本机资源页：快照单元用例（隐藏扩展过滤、工具 / 命令计数、诊断、影子包状态）+ 设置页快照 / 加载态渲染冒烟；扩展包停用 / 启用经 PiHost 端到端用例（settings.json 移除 / 影子清单 / 原样恢复 / 列表状态翻转）；Skill / Prompt / Command 只读。
