# 扩展关闭事件原因与收束

本记录保留两项独立验收：普通扩展关闭事件的真实收束，以及桌面启动前的数据目录隔离。两者的来源和检查不能合成一轮结果。具体用户行为见[开发任务路径](../../../spec/开发任务路径.md)与[任务暂停与恢复](../../../spec/任务暂停与恢复.md)。

## 目标红灯与修复

关闭事件沿原所有者区分资源重载、暂停后待继续和最终退出。关闭期间只允许原历史和元数据记录，拒绝新输入、模型及工具作用。旧实现缺少原因字段；修复期间先等资源线程全部结束再关执行会话，又使在途模型无法取消。两类失败分别保留。

独立审查随后发现，关闭回调的一个被拒动作会令等待提前报错并跳过真实清理；另一个普通工具的收尾还可能拿走关闭批次，让关闭在派生名称回调结束前返回。实际旧源反例分别命中缺少子进程清理标记、测试门放行前关闭已返回。现按调用范围保存动作，关闭等待同批及派生动作全部收束，再完成运输、任务和进程清理，最后仍返回原失败。原审查关于证据目录的错误描述另有纠正，不能据此丢弃失败史。

## 后续修复：隔离 Electron userData 在启动前传入（2026-10-16）

首次普通桌面启动虽然主进程存活，图形和网络辅助进程仍指向默认用户目录并出现缓存错误；只回收了本次精确进程组，默认目录没有查看或删除，不能宣称从未触及。先前仅前移目录设置仍未保证目录存在，也没核渲染进程，因而未放行。

最终启动器在启动前传隔离目录，异步准备目录后再设置应用路径；冷启动逐一核主进程、图形、网络与渲染辅助进程的真实路径。该修复完整八项检查通过：运行集成486项、契约14项、隐藏界面126项，并独立三项限定通过。[隔离修复恢复副本与原报告](/Users/diwu/Workspace/Archives/dcode-prototype-implementation-2026-10-10/main-after-extension-desktop-userdata-isolation-accepted-20261016/manifest.json)。

一次旧记录器把带空格路径截断，不作路径结论；更正后普通启动无导入或缓存错误，但未核可见性、焦点或人工接受。用户所附导入错误图来自独立变异夹具，既不证明普通入口失败，也不证明成功。真实账户、用户项目与人工接受仍未由本记录验证；当前后续取舍见[Pi能力复用与演进](../../Pi能力复用与演进.md)。
