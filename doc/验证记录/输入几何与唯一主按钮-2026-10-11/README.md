### 输入区几何

- 单行：输入行与操作行并排、垂直居中（原型 `.composer.compact`）。卡片 58px（1440×900、空稿）。
- 折行／换行：按内容向上展开，**不设固定行数上限**。展开上限按滚动视口真实高度 × 0.4 派生。
- 长内容：在卡片内部滚动，内侧滚动条默认不可见且不占位。
- 高度来自字号尺度派生，不写独立常数。

### 暂收与恢复

暂收是几何变化不是状态变化：只改 textarea 高度，元素不卸载，草稿／光标／选区／输入法组合与运行状态因此天然保留。恢复用暂收前实测的高度（`restoreHeightRef`），不重新估算。

### 紧凑判定的稳定性（507 限定点 1）

初版实现把 `compact` 建立在**当前** textarea 宽度上，而紧凑形态本身会收窄该宽度：

1. 全宽测量 → 文本一行 → `setCompact(true)`；
2. 紧凑形态使 textarea 让出操作行宽度 → 同一段文本折成两行 → 高度变 42 → `setCompact(false)`；
3. 外壳高度变化触发 ResizeObserver → 回到第 1 步。

红反例实测（`ab-flap-red`）：40 帧内高度在 `21 ↔ 42` 之间翻转 41 次，紧凑形态被切换 40 次。

修法是让紧凑判定只用与当前形态无关的量：全宽下的内容高度、操作行的固有宽度（临时 `max-content` 读回）、以及输入区需要的宽度（草稿本身单行宽度，空稿时以占位文案为准，均为真实内容，不写常数）。由此：

- 判定结果唯一，不会被自身宽度切换逆转；
- 操作行放不下时不进入紧凑形态，仍走堆叠，避免负剩余空间把 `flex: 1 1 0%` 的编辑区压成 0 宽（该缺陷在 720×480 ＋ 检查器打开时实测到 textarea `clientWidth = 0`）；
- 目标高度按**当前**实际宽度再量一次，紧凑形态下临界文本宁可长高也不裁掉内容——判定仍只用全宽结果，所以不会因此抖动。

### 流式追加与跟随（507 限定点 2）

- 观察窗内改用逐帧高度取样 + ResizeObserver 记录 textarea 经历过的**全部**实际高度 + 紧凑形态切换次数，不再用「等 500ms 取单次样」；后者会把「闪收又恢复」验成从未暂收。
- 流式收束条件改按真实运行相位（快照里不再有 `running`／`pausing`）。主按钮文案不能当运行相位用：此时已填 6 行新草稿，运行中本来就显示「发送」，旧条件会立即成立。

过程性缺陷与成因（均为实路缺陷，非用例掩盖）：

1. **`flex-basis: 0%` 架空实测高度**：`InputGroupTextarea` 带 `flex-1`，列方向 flex 用基准 0 参与主轴分配，把实测高度压成单行。修法是在 `.composer-input` 非紧凑形态下把基准还回内容高度，紧凑形态再显式恢复 `flex: 1 1 0%`。
2. **程序化标记吞掉阅读意图**：`onScroll` 早退时只消费标记、跳过 `followingRef = atBottom()`，导致进入会话后 `following` 一直是 false，后续贴底不再发生。修法是程序化位移仍落定意图（贴底就是跟随），但不触发暂收。
3. **`flex: 1 1 0%` 在负剩余空间下被压成 0 宽**：720×480 ＋ 检查器打开时，状态说明的固有宽度超过卡片内容宽度，编辑区宽度实测为 0。修法并入紧凑判定的宽度门槛。

### 1. 浅色键盘焦点外壳对比度不足（真实缺陷，已修）
