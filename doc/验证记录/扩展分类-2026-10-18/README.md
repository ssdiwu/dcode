## 关键失败与修复

独立审查发现模型对象的属性读取可能在错误保护外抛出；修后只接收有限的普通数据字段，并安全拒绝代理或伪造取消信号。随后又发现一个特殊自有字段会在复制时被静默丢弃，导致本应拒绝的未知选项真正发请求；原反例失败后，在复制前按允许字段拒绝。两项均保零分类请求和零模型子任务的修后证据。

一次自定义后端验证漏传隔离端点，实际 SDK 只携本轮生成的假密钥向内建端点请求并获拒；它不算本地对端成功或真实账户验收。修的是验证装配的端点透传，没有放宽正常产品端点规则。

第一轮完整界面出现原有预设场景正常关闭超时。后续有限诊断与无插桩完整复验没有再现，生成物也已恢复原字节；原超时仍为根因未定，不能称环境故障或已定位修复。因新发现而在等待界面锁、尚无子进程时主动停止的旧检查，不是产品界面失败或完整绿。
