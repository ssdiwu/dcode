# 扩展图片消费者

本片接收 Pi 1.0 有限 OpenRouter 图片模型：原工具的 Durable 子任务先保存实际响应回执，再核验图片；成功图、错误及真实费用保持原结果身份，不伪造成聊天助手。已覆盖五种图片格式及动画容器的相关解码、实际工具渲染、后续请求和暂停恢复路径。具体容量与行为仍见[开发任务路径](../../../spec/开发任务路径.md)。

## 关键失败与修复

真实响应已到、核验线程已启动后暂停或关闭，最初费用维护先写后读，违反事务顺序；修为先核全体所有者和正式结果，再统一写入。独立审查又发现合法图片加文本装不进旧结果封套，以及线程已经退出后、最终发布前发生较新停机时仍会发布图片。旧源反例分别命中错误结果和越过停机发布，修后区分原始容量与传输封套，并在原事务末尾重新核所有者、资源代次和取消状态。

原始图片数量、容量和新输入限制没有放宽。近容量图片与转义正文真实进入原工具、下一请求和只读历史；停机只给无图的有限取消结果，已确认费用恰一次。核验预算不是操作系统或原生内存沙箱，未持久提交前的崩溃也不保证内存回执恢复。

旧自定义模型只有文本能力，不能为图片测试放宽。补齐路径是在原会话保持全局自定义配置，冷重开或新增认证后由真实选择器明确采用已核图片输入能力的预设，再发未来输入。旧类型目录测试等待抛错的失败，则按现有有限错误合同修正测试，不改产品准入。
