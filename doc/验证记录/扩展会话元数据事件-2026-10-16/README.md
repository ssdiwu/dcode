# 扩展会话元数据事件

本片接收 Pi 1.0 会话名称变更事件。名称由原 Durable 会话保存，按 SDK 规则整理换行和首尾空白；原事务比较规范化后的实际名称并保存变化回执，只有真实变化才追加记录和投递事件。回调读取同一写后名称，普通异步快照不能覆盖新名称，只读重开不装资源或重放事件。

## 目标反例和验证

最初实现没有事件，后续又发现名称整理规则与 SDK 不一致。首轮独立审查指出：旧普通请求快照仍能回滚新名称，导航还指向不存在的记录；两项均按各自范围修正。

第二轮发现相反顺序的问题：普通新快照先到，稍后的名称回执会误以为事件已经交付而吞掉通知。旧实现的受控交错断言真实失败，修后通过。第三轮则发现同一处理器连续设置规范化后同名，会因各自捕获旧本地名称而重复通知；该候选虽然完整检查已绿，仍被拒绝。最终把变化判断放入原 Durable 事务，重复同名和快照交错两类原反例同时通过，不依靠本地缓存猜是否发生变化。
