# 全局创造模式与 D Code 自举开发边界

状态：Accepted（已接受；扩展 ADR 0022、0031 与 0032 的自构建和自进化边界）

## 背景

D Code 当前仍主要由外部 Codex 环境开发，但产品目标是让 D Code 使用自己的 Project、Task、D Code Session、Agent Team、Knowledge、一等项目文档与能力模块持续开发自己。若把这项能力附着到任意项目或普通任务，它会与普通开发工作混淆；若把它理解成权限档位，又会错误重开 ADR 0023 已移除的动作级权限模式。

## 决定

1. Creation Mode（全局创造模式）是 D Code 的全局产品模式，只用于开发和自进化 D Code 自身。它不是普通项目的任务类型，也不是权限、沙箱或开发者账户档位。
2. 进入创造模式后，D Code 围绕自己的源码 Project 和相关 Task 提供能力开发、Agent 协作、验证、自构建候选、受控切换、原任务恢复、人工验收与回滚闭环。普通任务仍使用同一 Project → Task → Session → Agent Run 主干，不建立第二套工作模型。
3. 创造模式不承诺在途模型生成、工具调用或进程热迁移。新候选启动后可以恢复 D Code Task、Session 关系、草稿、队列、回执和证据，但不能伪装恢复已经消失的 Runtime。
4. ADR 0022、0031 与 0032 已成立的隔离候选、来源清单、显式重启、人工验收和回滚继续作为安全基础；当前设置页“自进化”只是创造模式的一段已实现能力，不等于完整模式已经交付。

## 影响

- Codex 是现阶段的引导开发环境，不成为 D Code 的长期产品依赖。
- D Code 的基础能力必须最终能够承载开发 D Code 自己这一真实场景；创造模式因此是项目、任务、会话、能力和自进化闭环的综合验收场，而不是单独的调试页。
- ADR 0023 的固定完全访问保持不变；创造模式不会增加“标准 / 完全访问”权限开关。

## 未选择的方案

- **项目级或任务级创造模式**：可以服务任意能力项目，但不能表达“整个 D Code 正在开发自己”的全局产品状态。
- **把创造模式作为权限模式**：混淆自举开发与执行授权，并重新引入已被明确移除的高频打断。
- **运行中热替换 D Code 自身**：难以诚实恢复进程与外部副作用，弱于现有候选、重启和回滚合同。
