# 任务内自适应协调与智能体进程边界

状态：Accepted（产品与进程边界已由 507 于 2026-09-06 确认）；实现未交付。完整行为、实施切片与验收由 [PRD 0029](../40-版本实施方案/0029-任务内自适应协作产品需求.md)拥有。

## 决定与原因

507 希望在同一个任务的主对话中持续表达想法，同时让具体工作在后台由按需召集的智能体推进、验收和返工。每个任务都有自己的协调者；用户也可以直接和子智能体交流。需要后台持续推进本身就是派发理由，不以工作项数量、固定团队人数或机械耗时阈值作为前提。

协调者从任务首次对话起就存在。简单工作可以自己处理，适合派发时自主转为专注协调；这只是同一角色的工作方式变化，不新建任务、主对话或第二个协调者。Task 内可以有多个工作项、多名执行成员和多名验收成员，成果及验收仍回到同一 Task。

Task 不等于某一段对话或一轮消息。主对话持续存在，用户可以在其中提及同任务已创建成员，向其定向交办；协调者同时获知，回复保留实际成员来源。运行成员的创建权属于该任务协调者，用户可以要求协调者召集成员，但客户端不提供直接新建运行成员入口，提及不存在的成员也不能隐式创建。Profile 编辑和已创建成员回收后的进程重启不等于新建运行成员。

每个正在运行的智能体执行实例以一个独立的操作系统进程为主执行锚点，落实为活动 Agent Run 与 Agent Execution Process 同时一对一；同一智能体可以另有多个辅助进程。一个执行进程只承载一个 Agent Run；一个 Agent Run 不能同时占用多个智能体执行进程。多个 Agent Run 共享同一宿主进程、各自创建 Runtime 实例，不能满足这一要求。Profile 和历史记录不需要永远常驻；进程退出后可保留执行身份与历史，新尝试在确认旧进程终止后建立新绑定，不复用旧 PID 冒充持续运行。

此处的进程是智能体执行进程。窗口、Host、存储写入服务和工具调用产生的 shell、浏览器等辅助进程不是新增智能体；辅助进程必须能归因到调用方并独立处理其停止和清理，不以这一区分规避一对一约束。

## 空闲回收与重新启动

507 补充确认：工作完成后可以让主执行进程短暂空闲驻留，再由系统回收；再次需要该智能体时，依据已经持久化的会话上下文和相关记忆启动新进程。驻留时长属于工程策略，不把口语中的“几分钟”冻结为产品参数。回收前须确认运行收口、上下文与成果已保存、无在途工具或未决外部副作用，并明确辅助进程的归属和去留；等待用户输入但尚未安全收口不等于可直接回收。重新启动保存新绑定与来源，不依赖旧 PID 存活，也不自动重放已完成操作。

## 与既有决定的关系

- 延续 [ADR 0035](0035-项目任务主干与任务拥有多会话边界.md)：Task 拥有主会话、子会话、工作项、执行、成果与验收，既不等于一条消息，也不等于其中某段持续对话；主对话中的定向成员交流不改变任务归属。
- 收窄 ADR 0035 决定第 9 条的工作项提升条件：独立成员、子对话、独立验收或产物本身不要求创建 Subtask。只有确需独立任务身份、目标和验收生命周期时才拆为 Subtask；原决定保留为历史并标记本次取代，当前术语按此规则解释。
- 补充 [ADR 0042](0042-客户端呈现与-D-Code-Host-写入边界.md) 与 [ADR 0044](0044-Web客户端与桌面壳技术栈边界.md)：独立进程不改变 Host 对产品事实和外部副作用的所有权。执行进程通过 Host 合同请求和报告，不各自建立 Product Store 写入者或客户端后门。
- 不改变单写入、独立可写工作树、提交原文与生效输入分离、可追溯工具事实以及诚实恢复约束。
- Team 的“显式启动”指存在有身份、范围、完成信号和停止边界的真实启动动作；在任务授权内可由协调者发起，不等于每次需要用户点击组队。跨任务消息的采纳与启动边界仍独立成立。

## 取舍与后果

同进程多 Runtime 的管理成本较低，但不满足本次明确的执行进程隔离要求，因此只作为现有实现事实保留；一个逻辑智能体内部同时启动多个智能体执行进程也不采用，需要并行时创建可追踪的新成员。

一对一进程关系增加启动、通信、资源回收与故障恢复成本。系统须能证明成员身份、进程绑定与终态，单个成员失败不应连带终止协调者和其他成员。并发不足时明确排队或报告容量问题，不无限复制进程，不伪装成员已经启动。

本决定不新增云电脑、移动端、应用退出后常驻服务、权限模式或外部 Agent Runtime 依赖。MiniMax 仅提供[协作机制参考](https://minimaxi.com/blog/minimax-agent-team-long-running-1779893521)，其内部实体名、账户系统及进程结构不成为 D Code 的事实或实现依据。
