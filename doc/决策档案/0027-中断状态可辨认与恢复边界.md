# 中断状态可辨认与恢复边界

状态：Accepted（已接受；约束 `0.0.19` 及后续版本的失败恢复路径；不改变 [0011](0011-后续消息队列所有权与派发边界.md) 停派语义、[0018](0018-打开即接管与单写入所有权.md) 显式重接、[0022](0022-自构建与受控重启协议.md) 不自动回滚与 [0025](0025-Markdown-编辑缓冲区与原子保存边界.md) 缓冲区不持久化）

## Context（背景）

路线图把 `0.0.19` 定为失败与恢复加固：覆盖 Host、构建、重启、写入、权限和验证中断，完成信号是"中断后能辨认已完成、未完成和未知状态，并从最近安全点继续"；`0.1.0` 晋升门禁要求"至少一次在 Host 退出、构建失败、App 重启或权限拒绝后，从可解释状态恢复并继续"（2026-08-22 eval 校准：权限闸门已随 ADR 0023 整体移除，门禁口径改为「会话文件损坏」等实际存在的中断源；权限中断未进入 0.0.19 交付）。`0.0.19` 实施前的两轮盘点确认了六个真实缺口：Host 意外退出后应用内无重连入口（恢复 = 重启 App）；半条 JSONL 让会话永久无法打开（`INVALID_SESSION` 无修复路径）；协议强制 `promptId` / `steerId` 但两端都不消费（无幂等）；五个本机 JSON store 写盘熔断后"本次运行永久"且大多不可见、无重试；验证证据账本与 revision 补全全链路静默；自构建重启后恢复会话失败静默。

## Decision（决定）

1. **三态辨认原则**：任何中断影响的动作，其状态必须可呈现为 已完成 / 未完成 / 未知 之一（对齐 [0021](0021-验证证据身份与账本边界.md) 的退出三态）；未知态必须提供核对入口（查看账本 / 重开 / 重载），不得以自动重试掩盖。现有 `run .unknown`、follow-up `dispatchUnknown` / `runOutcomeUnknown` 即此原则的既有实例，本决定将其推广为全恢复路径的统一要求。
2. **恢复一律用户显式触发**：重连 Host、修复会话文件、重试保存、恢复接管，全部由用户点击触发，不自动执行、不循环重试（延续 0018 无乒乓重接、0022 不自动回滚）；自动恢复只保留既有的一次性重启标记（0022 的 `pendingSessionId`）。
3. **Host 重连**：App 内提供"重新连接 Pi Host"入口（连接失败态与 Host 要求重启态均可触达）；重连成功后刷新会话列表并以可写重开当前会话（打开即接管语义不变）；中断造成的 run `.unknown` 事实如实保留，不因重连被清写。
4. **受控修复半条 JSONL**：仅当"尾部恰好一条记录不完整（无尾换行或 JSON 解析失败）且其余记录完整（全部可解析、entry id 唯一、parentId 链不断）"时判定可修；修复前将原文件完整备份到同目录（`.bak-<uuid>`），修剪尾部不完整记录后以严格读取器复验，任一环节失败即中止且原文件不动。修复是用户显式动作（打开失败时呈现"备份并修复后打开"）；其余形态的损坏拒绝修复并如实报告原因，不做通用 JSONL 手术。
5. **promptId / steerId 幂等由 Host 消费**：Host 维护每个会话已见的 `promptId` / `steerId`（内存级，有界）；重复提交返回诚实错误 `SESSION_DUPLICATE_PROMPT` / `SESSION_DUPLICATE_STEER`（details 附已关联的 runId），不重复执行。Swift 不自动重发（0011 边界不变）；"安全重试"仍只允许在 Host 判定"未持久化"（`retryable`）时进行，重试使用全新 ID。
6. **store 熔断可见 + 显式重试**：本机 store 写盘熔断状态常驻可见（设置诊断区 + 受影响界面的常驻提示），并提供用户显式"重试保存"（清除熔断 → 重新 load 校验 → flush）；重试失败如实回到熔断态。验证证据账本、revision 补全同样暴露失败状态；"revision 待补"区分"补全中"与"账本暂停"。
7. **恢复失败不静默**：自构建重启后的会话恢复、重连后的会话重开等自动链路中的失败步骤，必须以 notice 呈现并提供手动入口，不得丢弃结果。
8. **不做**：自动重连、自动重试、崩溃自动回滚、编辑缓冲区持久化（0025 边界）、多会话并行运行状态标记（单活动边界）、通用 JSONL 修复、跨设备恢复。

## Consequences（影响）

- `0.0.19` 交付：Host 失败后可从应用内重连并回到当前会话；尾部不完整的会话文件可显式修复后打开；同一 prompt / steer ID 在同一 Host 进程生命周期内且仍在已见 ID 窗口（LRU 256）内不会重复执行；store 熔断与验证证据失败可见、可显式重试；自构建恢复失败与 Source Folder 撤销不再静默。
- **幂等不跨进程**（2026-08-22 eval 校准）：决定 3（重连）与决定 5（幂等）的交叉点必须说清——Host 意外退出正是本版主场景，而已见 ID 只在内存里；重启后的 Host 对旧 ID 一无所知，同一 `promptId` 会被再次执行。判定「上一次是否已落盘」只能靠正文比对 + `parentId` 链（`promptId` 不写入会话 JSONL，协议亦无按 ID 查状态的方法）。是否把已见 ID 落盘或提供按 `promptId` 查状态，属未决产品取舍，采纳前本决定维持「内存级、有界」的原定义。
- 半条 JSONL 的修复改变了"会话文件永不写入"的边界：修复仅在用户显式触发时发生、原文件有完整备份、且只删除可判定的尾部不完整记录；备份保留在同目录供人工回退。
- 幂等错误 `SESSION_DUPLICATE_PROMPT` 进入协议错误合同；Swift 端以行内错误呈现（含原 runId），提示用户核对上一条消息而非重发。
- Host 重连不复活任何在途状态：中断时未完成的工具执行、扩展交互如实丢失，以 run `.unknown` 与队列停派呈现，用户核对后继续。
- 本决定为 `0.1.0` 晋升门禁的"Host 退出后从可解释状态恢复"提供机制；是否成立仍以真实 dogfood 记录为准。

## Rejected Alternatives（未采用方案）

- **自动重连 / 指数退避重试**：与 0018"无乒乓自动循环"、0011"绝不用再次发送猜测结果"冲突；自动重试会把"未知"伪装成"已完成"。
- **打开时自动修复 JSONL**：静默改写会话权威文件违反"Pi 会话 JSONL 不直接修改"的精神——修复必须显式、可核对、有备份。
- **Swift 侧绕过 Host 直接修剪 JSONL**：违反"会话写入必须经 Host"的架构边界；修复属于会话文件操作，归 Host。
- **promptId 重复时静默返回上次结果**：上次结果可能尚未完成或已失败，静默合并是欺骗；诚实报错 + 用户核对才是三态辨认。
- **store 熔断自动重试**：写盘失败原因（磁盘满、权限）不会自愈；自动重试只会刷屏，显式重试配合可见状态足够。
