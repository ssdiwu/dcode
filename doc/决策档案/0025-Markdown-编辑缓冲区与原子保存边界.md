# Markdown 编辑缓冲区与原子保存边界

状态：Accepted（已接受；约束 `0.0.17` 及后续版本的文件编辑路径；HTML 预览与 sandbox 策略属 `0.0.18`，不在本决定内冻结）

## Context（背景）

`0.0.4` 建立的文件标签是纯只读快照：Swift 进程内逐级 `openat` 安全读取（拒符号链接、限授权根、2MB 上限），无任何写入路径。版本演进路线把"Markdown 文件从只读进入编辑缓冲区、Source / Preview 切换与安全保存"定为 `0.0.17`，进入 PRD 前需先固定编辑缓冲区、磁盘冲突与原子保存边界（路线图决策门禁）。

需要决策的点：保存路径走 Swift 直写还是新增 Host 命令；外部修改如何检测；未保存缓冲区的生命周期与持久化边界。相关既有事实：文件读取本就在 Swift 进程内完成、不经 Host；ADR 0023 后 Host 完全访问、无权限闸门；AGENTS.md 只约束 Pi 会话 JSONL 必须经 Host 写入，工作区文件不在 Pi 会话权威域内。

## Decision（决定）

1. **保存走 Swift 进程内直写，与读取对称**：复用只读预览的安全目录遍历（从 `/` 逐级 `openat`、`O_NOFOLLOW`、授权根约束）取得目标父目录，不经 Host、不新增协议命令。工作区文件不属于 Pi 会话或配置权威，建立 `fs.write` 一类 Host 命令只会复制一条已存在且更受约束的路径。
2. **编辑对象仅限已登记 Source Folder 内的 `.md` 普通文件**（扩展名大小写不敏感）：进入编辑前文件必须已被安全读取为快照；不做新建文件、重命名、删除；非 Markdown 文件维持只读呈现（"通用代码 IDE"由路线图排除）。
3. **缓冲区是内存态，身份 = 标签 path**：脏文本只存在于 App 内存，不落盘、不建持久草稿层；App 重启如实丢弃。关闭有未保存修改的标签必须显式确认（保存并关闭 / 不保存 / 取消），不静默保存、不静默丢弃。
4. **保存 = 同目录临时文件 + 原子替换**：在目标父目录内以 `O_CREAT | O_EXCL` 创建随机名临时文件，写入全文并 `fsync`，再 `renameat` 原子替换目标文件，最后 `fsync` 父目录；替换前保留原文件权限位。任一步失败即清理临时文件并如实报错，原文件零改动，缓冲区与脏状态保留。
5. **磁盘冲突以内容指纹判定，绝不盲目覆盖**：加载与每次保存成功后记录文件内容 SHA-256 作为基准；保存前经安全路径重读磁盘并计算指纹，与基准不匹配（或文件已不存在 / 类型改变）即拒绝写入、进入冲突态，由用户三选：重新加载磁盘版本（放弃缓冲区）、显式覆盖保存、继续编辑。不做自动合并（OT / CRDT 属未来决策）。
6. **预览跟随缓冲区，不假装已写盘**：Source / Preview 切换中的 Preview 渲染当前缓冲区文本；未保存修改在预览中如实呈现（含标题栏 / 标签的未保存标识），保存成功前不得把预览内容表述为磁盘事实。
7. **授权撤销后缓冲区可编辑、保存禁用**：延续 `0.0.4` 边界——Source Folder 授权移除后不得凭旧标签恢复磁盘访问；缓冲区保留可继续编辑，保存按钮禁用并说明原因。
8. **文件编辑不自动进入模型 Context**：延续 `0.0.4`"文件打开不把文件加入模型 Context"的边界，编辑与保存同样不隐式注入对话。

## Consequences（影响）

- `0.0.17` 交付 Markdown 编辑闭环：进入编辑 → 修改 → 预览核对 → ⌘S 安全保存；未保存状态、磁盘冲突、保存失败与磁盘事实均可辨认。
- 读取与写入共享同一套安全路径实现（目录遍历、授权判定），符号链接与越界路径对写入同样失败关闭。
- Host 协议不变化；会话写入所有权（ADR 0018）与会话账本（ADR 0010、0021）不受影响。
- `0.0.18` 的 HTML 编辑缓冲区复用本决定的缓冲区与保存模型，但预览的 HTML sandbox 与本机 / 网络资源策略必须另行决策，不得默认继承。
- 两个 D Code 实例（或 D Code 与外部编辑器）同时编辑同一文件时，后保存方会进入冲突态而不是覆盖对方；用户以三选动作自行裁决。

## Rejected Alternatives（未采用方案）

- **新增 Host `fs.write` 命令**：把文件写入引入 IPC 协议会带来命令面扩大、参数校验与凭据面，而收益仅是"写入也走 Host"；读取已证明 Swift 内安全路径可行，且工作区文件不是 Pi 权威数据。
- **mtime / size 指纹判冲突**：文件系统时间戳粒度与外部工具行为不可控，内容 SHA-256 在 2MB 上限内成本可忽略，判定才可靠（与 Host `modelProviders.save` 的源指纹思路一致但更严）。
- **持久化未保存草稿（App 重启恢复）**：为内存缓冲区建第二持久层会与"关闭确认 + 如实丢弃"的诚实边界冲突，且引入草稿与磁盘的新冲突维度；真有此缺口按 dogfood 事实再决策。
- **自动保存 / 保存时静默采用磁盘版**：掩盖冲突与丢弃用户修改，违反"磁盘事实可辨认"的完成信号。
- **编辑全部文本文件**：路线图把 `0.0.17` 收窄为 Markdown；通用编辑（语法高亮、多语言）属"通用代码 IDE"，明确排除。
