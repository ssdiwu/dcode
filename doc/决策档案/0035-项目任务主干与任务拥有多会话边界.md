# 项目—任务主干与任务拥有多会话边界

状态：已接受（取代 ADR 0013 中“主会话是团队协作根”的产品所有权，保留其子会话隔离、单写入、结构化报告与诚实恢复边界）

## 背景

D Code 先前以 Pi Session（Pi 会话）作为主要导航与团队协作根，并在目标态中增加 Goal（目标）、Work Item（工作项）、Team Run（团队执行）和子会话。该模型仍让产品对象围绕一段主会话生长，无法自然表达一项工作跨多次讨论、多个模型、串行接力、并行调查和多轮返工后仍保持同一身份。ADR 0037 进一步把目标产品会话权威从 Pi 迁到 D Code；本文中的当前产品 Session 因而统一指 D Code Session。

现有 `pi-dgoal` 已证明短期目标、计划、工作清单、依赖、验收和证据需要稳定所有者；`pi-dteam` 已证明每个执行成员需要独立上下文、实际模型、工具范围和结构化报告。D Code 不桥接这两个 Pi 拓展，而是吸收其已验证机制，重新建立自有产品合同和原生界面。

## 决定

1. D Code 的任务归属主干固定为 `User Scope（用户作用域）或 Project Scope（项目作用域） → Task（任务）`。Project 是长期持续的产品与工作容器，拥有唯一项目目录、项目规则、设计原则、局部知识、长期愿景和任务集合；未选择 Project 的 Task 属于当前用户 User Scope，默认执行目录为 Home Directory，但不伪造默认 Project。每个 Task 必须恰好属于其中一个作用域，并作为具有短期结果、范围、状态和验收条件的基本完成单位。
2. 不在项目与任务之间建立独立 Goal 对象。Goal（目标）是附着于项目或任务的结果语义：项目目标表达长期方向，任务目标表达本次短期结果；“目标”可以有原生视图和交互，但不形成 `项目 → 目标 → 任务` 的额外身份层。
3. 一个任务可以拥有零个、一个或多个 D Code Session。会话保存提交原文、生效输入、对话、上下文投影和运行结果；任务保存跨会话不变的当前状态、计划、工作清单、知识引用、Agent 运行、产物、证据和验收。任一会话结束、归档或切换模型都不会结束或改写任务身份。
4. 用户首次提交一项新工作时，产品语义是在当前 User Scope 或 Project Scope 创建任务并建立其首个任务会话，而不是创建一个无任务归属的耐久会话。首次提交前可以存在同作用域的本机任务草稿；创建任务本身不自动启动额外 Agent 或团队执行。
5. Agent Team（智能体团队）属于任务。任务可以直接启动单个 Agent 运行，也可以显式启动一轮团队执行；团队执行可按任务计划串行或并行组织多个 Agent 运行。Task 可以指定一个 Coordination Session（协调会话）作为用户与 Coordinator Agent（协调智能体）持续沟通、派发与综合结果的默认入口，但该会话和协调智能体都不拥有任务。
6. 每个 Agent Run（Agent 运行）保存职责、实际模型、工具集合、声明范围、来源上下文、执行目录、状态、报告和独立 D Code 子会话引用。模型是运行事实，不是 Agent、任务或会话的稳定身份。
7. 任务完成只由其验收合同和证据成立。模型回复结束、Agent 运行完成、团队执行关闭、自动测试通过、人工验收、提交、推送和发布分别成立，不自动逐级推导。
8. 多个可写 Agent 运行不得共享同一可写工作树；子会话只接收有界上下文。重启可以恢复任务、会话关系、报告、证据和未处理工作空间，但不得伪装恢复已经消失的模型生成、工具调用或进程。
9. 当前 `Work Item` 产品术语收敛为 Task（任务）；任务内部工作清单中的单个步骤继续称 Work Item（工作项）。只有需要独立会话、独立 Agent、独立验收或独立产物时，工作项才提升为子任务。
10. 项目管理是项目对同一批任务提供的组织与观察能力，不建立第二份任务状态。列表、看板、路线图、Agent 执行、用户关注等 Task View（任务视图）只筛选、排序、分组和投影任务。

## 影响

- ADR 0013 的运行安全边界继续有效，但其中 `主会话 → 团队执行 → 成员执行 → 子会话` 的产品所有权改为 `User Scope / Project Scope → Task → Team Run → Agent Run → Child Agent Session`。
- `pi-dgoal` 的当前 Goal 语义吸收为 D Code Task 的目标、计划、工作清单和验收能力；`dgoal` 名称、命令、状态键、Pi 会话唯一所有权和终端界面不进入 D Code 产品。
- `pi-dteam` 的 Worker 机制吸收为 Task 下的 Agent 运行与子会话；`dteam` 名称、模型档位产品语言、会话级 Manager 所有权和终端界面不进入 D Code 产品。
- Recent Sessions（最近会话）可以保留为快速入口，但会话不再是 User Scope 或 Project 的主要完成单位；打开 D Code Session 应能够返回其所属 Task 与作用域。
- 现有产品契约、术语表、参考文件和后续版本规格需要按本决策校准；当前源码尚未实现 Task、Agent Team 或多活动会话，不能把本决策冒充已交付能力。

## 未选择的方案

- **继续以主会话为协作根**：无法稳定表达一项任务跨多会话、多模型和多轮执行。
- **项目 → 独立目标 → 任务**：增加一个与项目长期愿景和任务短期目标重叠的管理层，容易使 D Code 退化为沉重的项目管理软件。
- **一个任务强制等于一个会话**：无法支持独立调查、实现、审查、返工和多 Agent 协作。
- **模型直接拥有子会话**：模型不是稳定身份，同一模型可承担多个 Agent 职责，同一会话也可能切换模型。
