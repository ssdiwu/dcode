# 空会话可恢复清理边界

状态：Accepted（已接受，约束 `0.0.3` 及后续版本）

D Code 将“归档”与“移到废纸篓”视为两种不同操作。Archive（归档）只改变 D Code 导航可见性，Pi JSONL 不动；“移到废纸篓”会从 Pi 会话发现目录移走文件，但仍保留可人工恢复的副本。产品不得用“删除”文案实际执行归档，也不得在废纸篓操作失败时回退为 `unlink`（永久删除）。

`0.0.3` 只允许清理同时满足以下条件的 Session：由 D Code 创建且来源标记与 Header ID 一致；消息数为零；没有其他 Session 的 `parentSession` 指向它；当前不处于可写 Runtime、模型生成、工具或结构化交互中。有内容、旧 Pi 会话或存在谱系引用时，界面应引导使用归档，不放宽物理清理。

Host 是该文件操作的唯一执行者。它先用稳定 Session ID 唯一解析真实路径，取得临时 Session Lease 和静默窗口，再次检查路径身份、D Code 来源、消息数与子会话关系，最后才将文件移入当前 macOS 用户的废纸篓。重复 ID、文件变化、外部 Lease、身份不明、移动失败或废纸篓不可用都必须保留原文件并返回可操作错误。

只有 Host 确认文件已移走后，App 才能从 Recent、Project、Search 和当前详情中清理同一稳定 ID，并删除该 Session 的本机未发送草稿。用户取消确认、Host 拒绝或废纸篓操作失败时，App 不得先行移除任何投影或草稿。

未来若要删除有内容会话、连带处理子会话、提供 App 内恢复或永久删除，必须重新定义谱系、草稿、搜索缓存和多客户端写入安全边界，不得从本决策自动外推。
