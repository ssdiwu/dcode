# 共享观察与按需写入

Pi Session 是 Pi CLI 与 D Code 共同访问的会话权威。现阶段 D Code 不包裹或复制一套新的桌面会话，因此选择既有会话后进入 Session Observation（会话观察态）：界面始终呈现正常 transcript 与 Composer，不把 Host 内部的 `readOnly` 快照实现暴露成用户“只读模式”。

Host 只监控当前活动会话的规范路径、device、inode、size 与 mtime；文件身份发生变化时发出 `session.changed`，App 再通过 `session.refresh` 从已知路径读取最新活动分支。没有变化时不重复解析完整 JSONL，也不重新扫描全部会话目录。自动刷新只承诺已经完整持久化的 Pi 条目，不镜像其他进程尚未落盘的逐 token 流；半条 JSON、截断、前缀改写或父子链损坏不会替换最后一次完整快照，也不会推进已接受版本。

发送消息或修改模型、思考强度、极速等运行设置属于明确写入意图。此时 D Code 才通过静默窗口与原子 Session Lease 取得单写入权，再交由 Pi SDK 写入。用户不需要先通过一张“继续会话”确认页；写入动作本身就是本次写入意图。Session Lease 仍只约束 D Code Host，不能迫使 Pi CLI 遵守。

如果 D Code 持有写入权期间发现外部追加、替换或未知条目，Host 立即标记冲突并中止本次运行，不尝试把两个运行时的上下文静默合并。每次 D Code RPC Prompt 都携带 Session ID 与 Prompt ID，并在独立 async context（异步上下文）中运行：普通消息只有在该上下文仍处于 RPC source boundary（RPC 来源边界）时，其 user record 进入 verified owned snapshot 才立即匹配确认，不等待长响应结束；扩展在同一异步链中嵌套发送的 user record 会进入独立来源边界，不能确认外层 RPC；扩展直接处理且不产生 RPC user record 的命令在同一次调用返回后确认。Host 不从全局 user event 队列猜测来源。App 只恢复尚未收到匹配确认的草稿，不把已成功完成的旧 Prompt 或其他 Session 的 Prompt 拼回当前输入框。能够确认运行时停止且 owner 身份仍一致时，D Code 释放自己的租约、回到同一会话的观察态并刷新最新历史；下一次写入动作重新争取所有权。若停止超时、停止失败或租约 owner 无法验证，Host 保留锁且禁用本进程后续写入，仍允许观察，并要求用户重新打开 App；不得为了恢复写入而强删未知锁。

该决定允许多端同时观察同一 Pi Session，但不支持两个客户端同时写。Swift 不直接修改 JSONL；stable session ID、规范路径、静默窗口、原子租约、未知 owner 不强删、写入前后指纹复核与冲突后停止等安全边界全部保留。
