# Web 客户端与桌面壳技术栈边界

状态：Accepted（2026-09-07，507 确认当前 Web 工作台与灵感等基础功能验收通过。接受 Electron + React 主路径及既有分层边界；Swift 拆除和未迁移内容面仍是迁移收尾，不据此宣称已经完成。扩展 [ADR 0042](0042-客户端呈现与-D-Code-Host-写入边界.md)。）

## 背景

ADR 0042 已确立 Client Presentation 技术中立、Platform Shell 只做系统集成、D Code Host 是唯一写入者，并明确"UI 技术选型、桌面壳选择、具体协议传输仍是后续独立决策，须以可运行原型和资源 / 体验证据收口"。本 ADR 即该后续决策。

推动选型的现实约束：

- SwiftUI 客户端的 UI/UX 迭代节奏无法满足"原型逐区拍板后快速落地"的需要；`0.0.29` 周期的教训是界面合同变更在原生侧重验成本过高，507 已明确原生开发速度不可接受。
- D Code 的产品事实（Product Store、Runtime Supervisor、Protocol v1、Prompt / Tool Receipt）全部在 Node `host/` 内；Swift 侧只是呈现层与平台壳。替换呈现层不动产品权威。
- 外部实证（2026-09-05 对本机两个一线产品的只读解包）：

| 产品 | 平台壳 | 呈现层 | 本地运行时 | 存储 / 终端 |
|---|---|---|---|---|
| ZCode 3.11.2 | Electron 41 | React 19 + Tailwind v4 + Radix/shadcn + Motion | 自研 host，Electron 二进制 Node 模式独立子进程（进程树核验） | conf / 文件；xterm + node-pty |
| MiniMax Code 3.0.68 | Electron 42 | Next.js 静态导出 + React + Tailwind | **Pi 全家桶**，运行于 Electron utility 子进程 | better-sqlite3；xterm + node-pty |
| ChatGPT（Codex）26.901 | Swift/AppKit 原生壳 + 内嵌改名 Electron | Vite + React + Radix + Tailwind | 独立 Rust sidecar 二进制，JSON-RPC / MCP | better-sqlite3、node-pty（主进程库） |
| Mirasim 0.0.286 | Electron | `@mirasim/ui` 全屏工作台 | 独立 server 子进程 + 本地 WebSocket（带 token）；`ax-window` 原生 sidecar | — |

其中 MiniMax Code 与 D Code 使用同一个 Pi 运行时，其"Electron 壳 + React 呈现 + Pi 本地运行时"组合已构成对目标架构的商用级验证。2026-09-05 二次核验（运行中进程树）修正了首次解包「嵌入主进程」的误判：四家产品无一将运行时嵌入主进程，进程拓扑详见 [0003](../10-架构与运行/0003-Web客户端技术栈.md)。

## 决定

1. **D Code 客户端主路径转向 Web 技术栈桌面壳。** 具体选型为 Electron + React + TypeScript，栈细节与版本锚点由 [`0003-Web客户端技术栈`](../10-架构与运行/0003-Web客户端技术栈.md) 拥有并维护；本 ADR 只拥有选型结论与边界。
2. **层级语义不变，全部沿用 ADR 0042。** Electron 主进程按 Platform Shell 实现：只提供窗口、菜单、快捷键、通知、文件选择与系统权限，不拥有 Project / Task / Session / Run 产品语义；渲染进程是 Client Presentation 的实现，不写 Product Store、Project Directory 或凭据；D Code Host 仍是唯一写入者。
3. **macOS-only 边界不变。** Electron 仅作为 macOS 桌面壳使用，不建立跨平台抽象，不做 Windows / Linux 适配与分发。
4. **SwiftUI 客户端按面替换、验证即删（2026-09-05 507 修订）。** `app/` 不作为长期并行回退基线冻结：`0.0.30` 开发中，每个界面被 Web 实现并通过对应验收后，同批删除 Swift 侧对应实现；验收时仓库不得残留同一界面的双实现，`app/build.sh` 打包链随最后一批 Swift 界面拆除退役。回退依赖 git 基线而非并行代码；`host/` 与协议不动。
5. **本 ADR 明确不冻结的细节**：结构化协议的传输方式、客户端本地存储与 Product Store 的分工、终端（pty / xterm）归属、代码编辑器选型。Host 与主进程的进程关系已于 2026-09-05 收口为独立子进程（ZCode 同款 Node 模式启动，见 0003 待决细节 #1），不改变本 ADR 任何层级语义。其余细节由 0003 的"待决细节"清单承接，收口结论以增量方式回填 0003；若任一细节需要改变 ADR 0042 的层级语义（例如把产品语义引入主进程），必须修订相应 ADR，不得静默实现。

## 验证与迁移边界（`0.0.30`）

2026-09-07，507 明确表示“暂且基础功能验收通过”，并授权提交与推送。技术路线和已交付基础范围据此转 Accepted；以下原门禁中的未交付项仍保留，具体覆盖与缺口由 [PRD 0028](../40-版本实施方案/0028-0.0.30-Web客户端初版产品需求.md) 记录。该确认不等于 Swift 清理、完整文件 / Git 阅读面和签名分发均已完成。

- Electron 壳产出可双击的本地 `.app` 候选，安装 / 启动 / 退出 / 更新占位可验证；候选隔离与回滚精神沿用 ADR 0022。
- 消费真实 `host/`（Protocol v1）：呈现真实 Product Store 的 Project → Task → 任务对话导航、浮动信息面板五组信息、只读文件 / 变更 / Git 视图。
- 同一布局内的选中、悬停与运行刷新保持几何稳定；任务概览关闭时正文与输入区居中，打开时让位。显式开合遵循 507 于 2026-09-06 更新的布局合同；Motion 动效基线有确定参数。
- `host/` 全量测试保持绿；Swift 侧无新增未测代码。
- 507 已确认当前基础功能可作为后续工作的基线；新增或尚未迁移的面继续分别验证，不能借此确认自动通过。

## 影响

- [`AGENTS.md`](../../AGENTS.md) 与根 `README.md` 中"自有 SwiftUI/AppKit 组件"的表述改为技术中立措辞，指向 0003。
- 版本演进中 `0.0.30` 由"主页面三区（纯 UI 版）"改为"Web 客户端初版（布局合同 + 技术栈验证）"；三区布局合同来自已拍板的[主页面 UI/UX 设计](../20-产品与交互/0002-D-Code-主页面-UI-UX-设计.md)与[原型拍板记录](../20-产品与交互/原型/dcode-home-three-region-prototype-验证.md)。
- 原生界面设计系统（[0002](../10-架构与运行/0002-D-Code-原生界面设计系统.md)）中的 SwiftUI 实现细则保留为回退基线资产；Web 客户端复用其中的几何、状态与无障碍语义，不复制实现。
- 术语表只补充 Platform Shell 层级词条；Electron、React 等技术名不进入术语表。

## 未选择的方案

- **Tauri**：系统 WKWebView 更轻，但 WebView 行为差异、Rust 侧维护成本与团队既有 Node / Web 资产不匹配；损失两个参照产品的直接可抄性。
- **继续 Swift-only**：迭代速度已由 `0.0.29` 周期证明不可接受；且"界面是可见上下文"的产品判断不依赖任何特定 UI 技术。
- **Swift 壳 + WKWebView 混合**：保留现有窗口壳只换内容区，过渡最平滑，但两头维护、动效与集成深度受限于 WKWebView，不解决根本速度问题。
