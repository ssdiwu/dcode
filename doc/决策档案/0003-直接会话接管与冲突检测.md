# 直接会话接管与冲突检测

Pi 0.84.1 的 `SessionManager` 以 JSONL append/rewrite 持久化会话，但不提供跨进程 lock、lease 或 owner 协议。`D Code` 允许用户在 App 内直接创建新会话，或选择既有会话并确认其他客户端已经关闭或不再使用该会话后继续；产品不要求安装 CLI 扩展、生成 Handoff ID 或向会话写入交接 marker。

对既有会话的可写打开必须携带 App 已完成独占使用确认的结构化信号。Host 随后以稳定 session ID 定位文件、原子取得该 ID 的 Session Lease，并在静默窗口前后验证规范路径、device、inode、size、mtime 与 leaf ID 未变；只有全部通过才创建 `AgentSession`。新建会话由 Host 自己创建并立即取得租约，不需要额外确认。

如果锁目录中的 owner 记录可验证且 PID 已不存在，Host 会先将旧锁原子移出固定租约路径，再删除隔离副本并重新竞争租约；仍存活、损坏或无法验证的 owner 一律保留并返回 `SESSION_IN_USE`，避免误删有效租约。

Session Lease 只约束协作的 D Code Host，不能把非协作 Pi CLI 的短暂静默变成永久所有权证明。因此用户确认“其他客户端已停止使用”是直接接管的必要边界；租约期间每次写入前后及定时轮询继续核对文件指纹和 Pi runtime 快照。发现外部追加、替换或未知条目时立即中止运行、拒绝后续写入并报告冲突，而不是继续生成隐式分支。首版仍不支持在途热迁移或同一会话多写入方。
