# Git 差异事实来源与只读边界

状态：Accepted（已接受；约束 `0.0.11` 及后续版本）

## Context（背景）

版本路线要求 `0.0.11` 从"已确认变更数量"进入逐文件、逐 hunk 的行级 Exact Git Diff，并保持 staged / unstaged 语义诚实。D Code 自 `0.0.1` 起 Swift 侧已只读直跑 `/usr/bin/git`（repo 定位、porcelain status、分支查询）；Pi SDK 无 Git API，会话级"已确认变更"账本（ADR 0010）只覆盖结构化 edit 工具的已确认事实，不是 Git 净差异。

## Decision（决定）

1. **事实来源**：Exact Git Diff 的唯一事实是 `/usr/bin/git` 的真实输出。Swift 只读直跑（`GIT_OPTIONAL_LOCKS=0`、`GIT_TERMINAL_PROMPT=0`、`LC_ALL=C`），单文件按需读取 `git diff -- <path>`（unstaged）与 `git diff --cached -- <path>`（staged）分流解析，untracked 文件以受护栏的文件内容作新文件预览。不引入 Host / 协议改动，不引入第二 Git 客户端。
2. **双轨诚实**：会话变更账本（结构化工具已确认）与 Git 净差异并存、各自如实标注；Active Plan 的账本文案与变更 Tab 的"真实 Git 差异"声明互指，不合并为单一来源。
3. **护栏**：单文件 diff 超 512KB 或 3000 行诚实截断（标注"仅显示前 N/M 个 hunk"，丢弃阈值后的整个 hunk）；二进制如实标注；读取沿用 WorkspaceFileReader 的授权根 / 2MB / UTF-8 约束。
4. **只读边界**：不提供 stage、discard、commit、push 或任何写操作；行级渲染只用于核对（+ 绿 / − 红 / 上下文，a/b 双行号）。

## Consequences（影响）

- 用户可在变更 Tab 内核对每个文件的真实 staged / unstaged 行级差异，多 repo / 多 source folder 沿用既有 repo 去重。
- 超大差异只展示有限内容但明确告知截断，不伪装完整。
- 未来若提供 Git 写操作（stage / commit），须另立 ADR 并与 0.0.10 权限闸门联动。

## Rejected Alternatives（未采用方案）

- **Host 侧运行 git**：增加协议面与子进程边界，无新增事实价值。
- **用账本推导 Git 差异**：把"已确认变更"伪装成净差异，违背双轨诚实。
- **libgit2 / 第三方 Git 库**：引入新依赖与版本漂移，直跑 git 即事实。
