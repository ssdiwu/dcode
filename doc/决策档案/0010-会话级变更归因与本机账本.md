# 会话级变更归因与本机账本

状态：Accepted（已接受）

## Context（背景）

Project Changes 能描述工作目录当前的 Git 状态，Pi Session 能保存对话与工具结果，Active Plan 能投影当前 Session Path 的计划；三者都不能单独回答“整个稳定 Session 已经被 D Code 确认改过哪些文件”。直接从当前 Git diff 反推会话归因会混入会话开始前、其他 Session、外部编辑器或提交后的变化；直接把 DHashline 的局部事件称为完整事实也会漏掉 Bash 与其他工具。

会话复制还会保留源 Session 的非 Header 历史。若把归因资料作为普通 Pi custom entry 写入 JSONL，新 Session 可能继承旧 Session 的变更身份；为了记录 UI 元数据而写 Pi Session 也会额外取得 Lease 并改变共享会话字节。

## Decision（决定）

1. D Code 建立版本化的本机 `Session Change Ledger（会话变更账本）`，以稳定 Pi Session ID 为第一身份，以 D Code Prompt ID 为 Run ID，并以持久化用户条目 ID 作为 Session Path 锚点。
2. Host 只在成功工具结果满足 D Code 认识的结构化合同后发出变更记录。首版支持 DHashline-compatible `edit` / `write`，记录工具调用 ID、规范文件路径、动作、首个变更行、增加行、删除行和时间；失败或未知形状不记录。
3. 账本只保存上述元数据，不复制文件正文、完整 diff 或 patch。Pi JSONL 与工作区文件仍是内容事实；Project Git Changes 仍是工作目录当前状态事实。
4. 会话摘要把整个 Session 的已确认变更活动聚合为文件并集与增删行总数；它必须显示 coverage（覆盖度）为“结构化工具已确认、可能不完整”，不得称为 Git 净差异。
5. Active Plan 继续按当前 Session Path 投影。界面可以把 Plan 进度和 Session 变更放在同一个紧凑表面，但必须保持两个作用域与状态来源可区分。
6. 本机账本随原 Session ID 保留，Archive 只影响可见性；复制产生新 Session ID，不继承源账本。Store（存储）损坏时保留原字节并停止继续写入，但普通 Pi Session 导航保持可用。

## Consequences（影响）

- D Code 可以在不修改 Pi Session 或源码正文的情况下跨重启呈现会话级变更摘要，并按 Run / 文件定位已确认活动。
- 老会话、外部 Pi CLI、Bash 和非结构化工具不会自动拥有完整归因；界面会诚实显示局部覆盖。以后扩大覆盖必须新增结构化 adapter（适配器）或明确的运行事件合同，不能靠工具名或文本猜测。
- 同一文件被多次修改时，文件数去重，增删行表示观察到的活动累计；它不能替代 Git 的最终净差异。若未来需要跨提交仍精确的净内容，需要另立包含基线、隐私与存储成本的决策，不在本 ADR 中暗示。

## Rejected Alternatives（未采用方案）

- **用当前 Git diff 作为 Session 变更**：无法区分会话开始前、其他 Session 与外部写入，提交后还会消失。
- **把 DHashline custom snapshot 直接当完整账本**：只覆盖对应扩展工具，且复制会话时会继承旧记录；snapshot 还包含完整源码，不适合再复制到 D Code 本机元数据。
- **向 Pi JSONL 追加 D Code 账本 entry**：会为了派生 UI 资料修改共享会话、引入 Lease 与复制继承问题。
- **只保存在内存**：重启后丢失，无法形成可验收的会话级历史。
