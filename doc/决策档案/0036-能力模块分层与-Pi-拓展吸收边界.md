# 能力模块分层与 Pi 拓展吸收边界

状态：已接受（扩展 ADR 0005 的 Pi SDK 与原生呈现边界）

## 背景

D Code 已经从 507 自有的 Pi 拓展中验证了目标、计划、工作清单、Agent 协作、模型额度、媒体理解、浏览器自动化等大量机制。如果按原仓库边界直接桥接，D Code 会继续暴露 `dgoal`、`dteam` 等 Pi 产品语言和会话所有权；如果把所有能力都硬编码进单一 Host，又会失去独立演化、按需启用和未来拓展的边界。

DeepSeek Harness 的“万物皆插件”说明实现可以通过统一服务、事件和模块装配；但产品仍需要默认能力、稳定合同和明确身份。D Code 因此采用“架构上模块化，产品上有明确基础能力与可选拓展”的分层。

## 决定

1. D Code Capability Module（D Code 能力模块）是统一实现单位；内部能力都可以使用相同的注册、事件、状态、工具和原生界面接缝，但产品分类不由代码是否可插拔决定。
2. Basic Capability（基础能力）默认随 D Code 提供，定义项目—任务—会话—Agent 运行主干或所有能力共同依赖的交互、安全与运行事实。它不能作为普通拓展被卸载，正常用户不需要理解其模块边界。
3. Extension Capability（拓展能力）是可选安装或启用、拥有独立生命周期的能力。它通常只服务部分任务，或依赖外部账户、网络、系统权限、持久对象和独立额度。安装后仍必须是一等能力：拥有结构化状态、原生界面、Agent 操作、明确权限、失败和卸载边界。
4. First-class Capability（一等能力）描述集成质量，不描述是否必装。基础能力和拓展能力都可以是一等能力；窄的一次性输入输出操作继续作为 Skill（技能）或工具，不因可调用就升级为产品区域。
5. Capability Provider（能力提供方）只实现某项能力的具体传输、模型或外部服务，不成为独立产品入口。Pi SDK 属于 Runtime Adapter；模型供应商、额度查询、媒体理解路线和凭据执行接缝属于提供方或内部适配。D Code 自己拥有模型资源、能力配置与认证状态语义，提供方不得反向成为产品权威。
6. 现有 Pi 拓展只作为机制、迁移和验证证据来源。D Code 不加载它们作为 Goal、Agent Team 等原生能力的运行时依赖，不复制其 TUI、命令、状态键和品牌；旧名称只在来源追溯、旧数据读取和诊断中出现。
7. 首阶段只承载 D Code 自有内置模块和少量 507 明确采用的可选拓展，不建立任意第三方市场。至少两个形状不同的真实拓展成立后，才从真实消费者中结晶公共拓展合同。
8. 拓展不能绕过 D Code 的凭据脱敏、输入校验、macOS 系统权限、外部账户授权、外部副作用、错误、恢复、作用域和证据合同。这里的权限不是 ADR 0023 已移除的工具执行审批。卸载或不可用时不得损坏项目、任务、会话或其他能力的核心数据。

## 首批能力归属

### 基础能力

- 任务、任务草稿、任务视图与项目管理；
- 目标、计划、工作清单、依赖、验收与证据；
- Agent Team、Agent 运行、子会话关系、结构化报告与有界控制；
- 选择提问与人类协作；
- 模型资源，包括 D Code 原生模型目录、供应商与认证状态、模型可用性、额度、重置时间和路由事实；
- 安全文件操作、附件与媒体合同、语言与本地化、上下文压缩；
- 关注与通知、智能命名、执行用时和可靠运行状态；
- 项目规则、项目知识、全局知识、项目愿景和全局愿景的引用与呈现。

### 可选一等拓展

- 工作洞察，包括使用情况、活动分析和工作日报；
- 网页研究与自动化；
- 图像工作室；
- Apple 提醒事项；
- Agent Mail（Agent 邮箱）及后续明确采用的外部系统能力。

### 提供方或内部适配

- 快速模式的模型请求适配；
- 各模型供应商的额度查询、凭据执行接缝与故障转移；
- 媒体理解所需的视觉模型、语音识别、抽帧和本机命令；
- Ollama Cloud、火山方舟 Agent Plan 等模型供应商接入。

### 不迁移为产品能力

- Pi TUI 状态栏、Pi TUI 本地化补丁和 Pi 专用压缩摘要拓展；
- Pi 包市场与 Pi 包管理器；其发现、审计、确认和作用域机制只供未来 D Code 拓展管理参考；
- 额度探测脚本等临时验证仓库；
- PDF 水印等没有独立状态与生命周期的窄操作，继续作为 Skill 或工具；
- 已被工作洞察覆盖的旧独立工作日报。

## 影响

- `dgoal`、`dteam` 不属于可选拓展，而是 D Code 任务与 Agent Team 基础能力的历史机制来源，必须原生重做。
- `pi-sense` 不作为名为 Sense 的独立产品拓展；D Code 拥有附件与媒体合同，具体媒体理解路线按提供方可用性启用。
- Agent Mail 属于可选一等拓展：它可以拥有独立页面、邮箱状态、额度、收发记录、Agent 工具和自动化，但不能成为所有任务的依赖。
- Pi Provider、额度探针和快速模式不会进入拓展中心；用户只在 D Code 模型资源与模型控制中看到对应事实。Pi 旧配置只作为迁移来源，不是目标产品权威。
- 一个能力是否一等，不由它是否基础决定；一个仓库是否是 Pi 拓展，也不自动使其成为 D Code 拓展。
