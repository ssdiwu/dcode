# 界面即上下文与 GUI 原生呈现边界

状态：Accepted（已接受；约束 `0.0.15` 及后续版本；扩展 [0005](0005-Pi-SDK-与原生呈现边界.md) 的呈现边界，重申 [0023](0023-固定完全访问与动作级权限闸门移除.md) 的无审批结论）

## Context（背景）

2026-08-21，OpenAI 以 [Codex as a platform](https://developers.openai.com/blog/codex-as-a-platform) 公开 harness 与宿主应用的分层定位（`codex exec`、官方 SDK、`app-server` 文档化客户端协议）。其核心论点与 D Code 既有的 [0002](0002-原生前端与-Pi-宿主分离.md)、[0005](0005-Pi-SDK-与原生呈现边界.md) 高度一致：宿主应用拥有界面、上下文、工具与业务规则，harness 只提供 Agent Loop（智能体循环）。但它明确表述了 D Code 只写了一半的一层——界面不只是呈现结果，界面本身就是上下文（"the interface tells the agent what the user is looking at"）。这不构成 D Code 的方向调整，而是照出了四处既有决策与实现之间的落差。

- [0005](0005-Pi-SDK-与原生呈现边界.md) 是从"不做什么"写成的：确立了所有用户可见界面由 D Code 自有 SwiftUI / AppKit 实现、不调用 `pi-tui`、不把字符帧或 ANSI 输出转成界面。它拒绝了 TUI 兼容层，但没有正面表述界面承担什么职责，也没有约束"字符界面"以外来源的临时文本形态。
- 到 `0.0.14`，D Code 已经积累了大量只读对象：只读 Files（`0.0.4`）、逐 hunk Exact Git Diff（`0.0.11`）、会话变更账本（[0010](0010-会话级变更归因与本机账本.md)）、验证证据账本（[0021](0021-验证证据身份与账本边界.md)）、Session Path、Active Plan、上下文构成（[0017](0017-dgoal-结构化状态融入与上下文构成呈现边界.md)）。这些对象只能被"看"：用户核对完差异或证据后，仍须在 Composer 用自然语言把自己刚看到的东西复述一遍，模型才知道上下文。`0.0.14` 的主页收口进一步强化了 Composer-first（占位符"@ 添加上下文，/ 使用命令"），把组织上下文的责任交回用户。
- [REF-012](../参考文件/README.md#ref-012-otty) 记录的"可信 Project 快捷动作"先后写作 `0.0.8` 与 `0.0.9`，至今没有实现（`app/Sources/` 无对应代码）；其原有依托 [0019](0019-Project-Trust-与动作级权限边界.md) 的权限闸门又已被 [0023](0023-固定完全访问与动作级权限闸门移除.md) 整体移除。这条线目前没有决策归属。
- [0005](0005-Pi-SDK-与原生呈现边界.md) 已要求"D Code 自有能力需要由模型主动调用时，必须把名称、说明、输入 schema 与执行器注册进同一个 Pi SDK Agent Loop"，但 `host/src/` 至今没有任何工具注册，只有对 `tool_execution_start` / `tool_execution_end` 的观察。该机制是纯声明、零实现；D Code 独有的派生事实对用户可见、对模型不可见。
- Host 已在 wire 上返回 `isCompacting` 并处理 `compaction_end`（`host/src/pi-host.ts`），Swift 侧只把 `compaction_end` 与 `thinking_level_changed`、`session_info_changed` 一起当作刷新触发器，`isCompacting` 未被任何界面消费。上下文压缩这一真实运行事实在 D Code 中完全不可见，而按 OpenAI 公布的 ARC-AGI-3 数据（保留推理 + 上下文压缩使 GPT-5.6 Sol 从 13.3% 升至 38.3%，输出 token 减少六倍），它是影响成本与结果最大的单一 harness 行为。

## Decision（决定）

1. **GUI 原生呈现是唯一呈现路径。** 一切用户可见事实由 D Code 自有 SwiftUI / AppKit 组件或受控内容渲染器表达。字符界面、ANSI 帧、终端兼容面板，以及把外部程序输出原样贴进窗口充当界面，都不是 D Code 的呈现形式——对未来任何新增能力同样成立。未原生适配的能力按 [0005](0005-Pi-SDK-与原生呈现边界.md) 诚实失败或明确忽略，不允许"先用文本凑一下"的过渡形态。本条把 [0005](0005-Pi-SDK-与原生呈现边界.md) 从"不调用 `pi-tui`"扩展为"任何来源的字符界面都不成为产品界面"。

   明确例外是**原始文本作为内容**：用户命令、模型正文、工具 stdout、diff 文本、只读日志当然可以显示，但它们由 D Code 拥有的、可选择可复制的原生文本 / 代码 / diff 组件承载，属于"被呈现的数据"，不是"外部程序的界面"。设置 > Host 诊断的只读日志是内容，不是终端。

2. **界面是上下文来源，不只是结果呈现。** 用户当前正在看的对象——文件、hunk、变更记录、证据记录、Session Path 节点、计划条目——应当能直接成为下一次输入的上下文，而不要求用户用自然语言复述。唯一实现形态是 **Composer 预填**：界面对象上的动作把精确引用写入当前 Composer 草稿，用户仍可编辑、仍须显式发送。

   边界：这类动作不得绕过 Composer 直接发送 prompt，不得隐式创建 Run，不得把界面选中态变成看不见的隐式上下文注入。上下文必须在发送前对用户完全可见且可改——否则"界面即上下文"就变成了"看不见的上下文"。本条为 [REF-012](../参考文件/README.md#ref-012-otty) 的"可信快捷动作"提供决策归属；具体动作清单与版本仍由 PRD 决定。

3. **D Code 独有的派生事实可以经受控 facade 进入模型可调用面。** 当某项事实只有宿主拥有、且模型自行重建成本高或不可能时，可以按 [0005](0005-Pi-SDK-与原生呈现边界.md) 既定机制注册为小型只读工具 facade（门面）。准入判据三条须同时成立：(a) 该事实只有 D Code 拥有；(b) 模型无法用 bash、文件读取等既有工具等价重建；(c) 存在明确的模型动作会用到它。当前符合判据的候选是会话变更账本的按会话归因、验证证据账本、Session Path 谱系与 Project 的 Source Folder 集合。仅为"看起来能力更强"而暴露的观察能力不注册，继续遵循"`pi-dusage` / `pi-dstatus` 一类观察能力优先进入设置、状态或证据界面"的既有吸收规则。

   注册必须进入同一个 Pi SDK Agent Loop，不建立第二套 loop 或工具调度器；系统提示、Skill 与 Prompt 不能让未注册能力变得可调用。

4. **宿主与运行的真实事实必须可见。** 影响用户理解成本与结果的运行事实不得静默发生。上下文压缩是首个明确纳入的对象：`isCompacting` 与 `compaction_end` 已经在 Host wire 上存在却未被界面消费，属于对 [`DESIGN.md`](../../DESIGN.md) *Truth before reassurance* 的直接违背。呈现形态由 PRD 决定，但"发生了压缩而界面看不出"不再是可接受状态。

5. **不引入人为审批机制。** Pi 的设计理念是没有工具审批——Pi `0.84.1` 无内置审批 API，命令与写入直接执行。Codex 提供 approval policy 不构成 D Code 增加审批的理由：Codex 的审批服务于多角色业务系统写入系统记录（示例应用 Relay 中的重新订舱），D Code 是单用户开发工具写自己的 Git 工作树。本次对照 Codex as a platform 重新检视后**维持 [0023](0023-固定完全访问与动作级权限闸门移除.md) 不变**：不恢复动作级闸门，不引入沙箱边界，不设"问 / 不问"模式开关。"界面即上下文"只增加上下文的来源与可见性，不增加任何执行前的门禁。

   沙箱策略与审批策略在 Codex 中是两条独立策略。这一区分在此记录，且同样不采纳；记录的目的是未来若真出现事故，不必重新发现该轴。重新引入任何一侧都必须走新 ADR，不得把本条当作"暂时不做"。事后核对材料（[0021](0021-验证证据身份与账本边界.md) 证据账本、[0010](0010-会话级变更归因与本机账本.md) 变更账本）继续是唯一约束形态：事后可核对，而非事前门禁。

## Consequences（影响）

- [0005](0005-Pi-SDK-与原生呈现边界.md) 从"拒绝 TUI 兼容层"升级为"GUI 原生是唯一呈现路径 + 界面承担上下文职责"；其 `pi-tui`、`custom`、Widget 具体条款不变。
- [REF-012](../参考文件/README.md#ref-012-otty) 的"可信快捷动作"重新获得依据，可进入版本 PRD；形态被限定为 Composer 预填，不是自动执行，因此不依赖任何权限闸门，与 [0023](0023-固定完全访问与动作级权限闸门移除.md) 无冲突。
- 工具 facade 有了准入判据；`0.0.15`（本机 Skill / Prompt / Command / Extension 管理，"可调用工具只展示 Pi 实际加载并注册成功的结构化合同"）可据此考虑第一个 facade。
- 压缩可见性成为一个可独立验收的缺口，不再隐藏在"刷新触发器"里。
- [0023](0023-固定完全访问与动作级权限闸门移除.md) 的结论获得一次外部对照后的显式重申，避免后续被"业界产品都有审批"反复挑战；同时明确任何回退都需新 ADR。
- 本 ADR 只定决策边界，不定版本、动作清单与验收；具体交付由 [40-版本实施方案](../40-版本实施方案/README.md) 的 PRD 承接。

## Rejected Alternatives（未采用方案）

- **接入 Codex harness / `app-server` 作为 D Code 的运行基座**：与 [0001](0001-Pi-会话作为唯一权威.md)（Pi 会话唯一权威）和 [0005](0005-Pi-SDK-与原生呈现边界.md)（不建立第二套 Agent Loop）直接冲突，等于同时存在两个会话权威；[REF-005](../参考文件/README.md#ref-005-flue) 已对同类 harness（Flue）给出"Reference Only，不作为 D Code 基座"的结论。Codex 的价值是宿主分层与客户端协议的外部设计参考，不是运行时。
- **界面动作直接发送 prompt（跳过 Composer）**：把上下文变成用户看不见、改不了的隐式注入，与"状态必须诚实"和渐进呈现冲突，也会绕过 [0011](0011-后续消息队列所有权与派发边界.md) 已确立的派发所有权与 steer 边界。
- **把界面选中态作为持续的隐式上下文注入模型**：用户无法知道模型看到了什么；未持久化的隐式上下文不在 Pi JSONL 中，与 [0001](0001-Pi-会话作为唯一权威.md) 的对话事实边界冲突。
- **为对齐 Codex 而恢复动作级审批或增加沙箱边界**：见决定 5。Pi 无审批是设计理念而非缺失，不人为补齐。
- **用文本 / 字符形态临时承载尚未原生化的能力**："先用文本凑一下"会长期固化为第二条 UI 路径，正是 [0005](0005-Pi-SDK-与原生呈现边界.md) 花代价移除的东西。
- **把全部宿主观察能力注册成模型工具**：违反决定 3 的判据 (c)，也与既有的"观察能力优先进入设置 / 状态 / 证据界面"吸收规则冲突。
