# 打开即接管与单写入所有权

状态：Accepted（已接受；取代 [ADR 0006](0006-共享观察与按需写入.md) 的"默认观察、按需写入"立场，约束 `0.0.9` 及后续版本）

## Context（背景）

ADR 0006 确立了"选择既有会话即进入持续观察（只读），写入动作按需取得租约"的模型。`0.0.8` 的 dogfood 暴露出该模式的系统性代价：只读是一个隐藏的二等会话状态——上下文用量是硬编码空值、命令列表清空、构成占比直接不可用，用户还要理解一个本不该感知的模式。产品判断（507，2026-08-20）：**只读观察模式的存在是错误的，D Code 是一等公民，打开会话即取得写入所有权。**

同时，Pi 会话的单写入所有者仍是硬边界：同一会话同时只能有一个写入者。session-lease 是 D Code 实例间的互斥机制（Pi CLI 不持此租约，其写入靠文件指纹检测发现）。

## Decision（决定）

1. **打开即接管**：`session.open` 一律走可写路径——关闭当前会话（释放其租约）→ 校验目标（版本、搜索目标摘要，失败不动当前会话）→ 取得目标租约。只读观察模式、其 1 秒文件轮询、独立 ModelRuntime 与全部降级 UI 从产品中删除。
2. **租约抢占**：取得租约遇到存活属主（另一个 D Code 实例）时，`force` 语义原子抢占——rename 旧锁目录后重建，新属主写入新 nonce。旧属主的每秒属主自检发现 owner 消失或 nonce 变化即抛 `LEASE_STOLEN`，停止写入并以 `session.conflict`（code=LEASE_STOLEN）诚实退出；不伪装仍可写，用户可在旧窗口显式重新接管（再次抢占）。
3. **静默窗口保留为安全护栏**：接管时目标文件在静默窗口内仍在变（Pi CLI 在途写入）时轮询到稳定再完成接管（有限重试，超时如实报 `SESSION_NOT_IDLE`）。这是等文件稳定，不是等用户。
4. **冲突不再静默回退观察**：持约期间外部写入仍按既有指纹检测触发 `session.conflict`（abort、保留草稿、暂停队列），Swift 呈现原生冲突卡（区分"外部写入"与"写入权被接管"），用户一键"重新接管"重新可写打开。`writeIntent`、`preserveActive` 参数随模式一起删除；`SESSION_READ_ONLY` / `WRITE_INTENT_REQUIRED` 错误不再存在。
5. ModelRuntime 与 cwd 无关，Host 生命周期内单例复用（修复新会话每次激活都全量解析模型库的性能问题）。

## Consequences（影响）

- 打开任何会话即获得完整一等能力：真实上下文用量、命令、构成占比、dgoal 呈现，不再有二等状态。
- 两个 D Code 窗口打开同一会话：后开者接管，先开者一秒内收到明确的 LEASE_STOLEN 冲突卡；双方都可以显式抢回，不存在静默降级或乒乓自动循环（重接只由用户点击触发）。
- 与 Pi CLI 并用：D Code 打开时若 Pi 正在写，接管等待文件稳定后完成；D Code 持约期间 Pi 强写仍触发既有冲突流。
- Host 协议删除只读分支与多个错误码；App 与 Host 继续按版本锁同步发布。
- 打开过期搜索目标不再关闭当前会话（校验前移）。

## Rejected Alternatives（未采用方案）

- **占用时等待或硬拒绝**：等待把一等公民变成排队者；硬拒绝连查看都做不到。
- **保留显式"仅查看"逃生口**：仍保留二等实现与两套状态语义，与"模式的存在是错误的"判断矛盾。
- **自动抢占重连（乒乓）**：两个窗口互相自动抢回会形成循环；重接必须由用户显式触发。
