# HTML 隔离即时预览与网络询问边界

状态：Accepted（已接受；约束 `0.0.18` 及后续版本的 HTML 预览路径；编辑缓冲区与保存边界沿用 [0025](0025-Markdown-编辑缓冲区与原子保存边界.md)，本决定只新增预览沙箱与网络策略）

## Context（背景）

路线图把"HTML 编辑缓冲区与隔离即时预览，脚本、网络和本机资源默认受限"定为 `0.0.18`，进入 PRD 前需先固定 HTML sandbox 与本机 / 网络资源策略（0025 明确把这块留给本决定）。界面原型对 0.0.18 的形态是并排双栏（左编辑缓冲区、右即时预览）+ 空 sandbox iframe + srcdoc 注入，文案"未开放脚本权限"。

用户于 2026-08-22 裁决实际策略：**默认放宽脚本，仅禁联网；检测到联网尝试时呈现询问，用户可"本次允许"**。该裁决取代原型的"未开放脚本权限"形态——理由是唯一使用者的真实 dogfood：HTML 产物普遍内嵌脚本，静态截图式预览没有核对价值。同时预研确认：项目此前没有任何 web 渲染组件，WKWebView 将是首例；WebKit 对子资源（图片、脚本、fetch 等非主框架请求）没有逐条"询问后放行"的 API，只有规则批量阻断。

## Decision（决定）

1. **编辑复用 0025，零第二套**：HTML（`.html` / `.htm`，大小写不敏感）编辑使用与 Markdown 完全相同的缓冲区、原子保存（同目录临时文件 + renameat）、内容指纹冲突三选、关闭与放弃确认、授权撤销语义；仅扩展准入判定，不新建模型。
2. **脚本默认允许**：预览的 `javaScriptEnabled = true`——预览是可以运行内联脚本的动态预览；脚本运行在沙箱化的 WKWebView 进程内，与 App 权限隔离。
3. **网络默认阻断 + 询问**：默认以 WKContentRuleList 阻断全部 `http(s)` 子资源、WKNavigationDelegate 拦截外部导航。检测到导航尝试时，预览头部呈现询问条（"该页面尝试联网，已阻止 / [本次允许] [保持阻止]"）；子资源受 WebKit API 限制无法逐条询问，以常驻"联网资源：已阻止 · [本次允许]"状态呈现。**"本次允许"仅当前预览会话有效**（切换文件或重启即恢复阻止），不持久化授权。允许联网仅指该次预览内的资源加载；不提供地址栏、前进后退与自由浏览，D Code 不成为浏览器。
4. **本机资源限定授权根**：预览内容从**内存缓冲区**注入（`loadHTMLString`），baseURL 使用自定义 `dcode-asset://` scheme 配合 `WKURLSchemeHandler`——HTML 中的相对资源引用回到 Swift 侧，复用 0025 的安全路径（从 `/` 逐级 `openat`、`O_NOFOLLOW`、限 Source Folder 授权根）读取；越界路径、符号链接与缺失文件直接失败，不提供任意文件系统访问。相对资源的可见范围与文件标签只读预览一致，预览不越过授权根。
5. **并排双栏、跟随缓冲区**：HTML 文件打开即"编辑缓冲区 | 即时预览"双栏（窄窗口退化为上下堆叠），不做源码 / 预览切换；编辑停顿（约 400ms 节流）后自动把缓冲区文本重新注入预览。预览头部常显"跟随未保存缓冲区"与联网策略状态，未保存修改不冒充磁盘事实（沿用 0025 决定 6 的诚实语义）。
6. **WKWebView 隔离配置**：`websiteDataStore = .nonPersistent()`（不留 cookie、缓存与存储）、禁新窗口与下载；预览内容不自动进入模型 Context（延续 `0.0.4` 边界）。
7. **不做**：允许联网后的自由网页浏览、逐条子资源联网询问（WebKit API 限制，如实呈现为状态开关而非伪装逐条批准）、跨文件 / 持久联网授权、远程 URL 作为主资源加载、HTML 语法高亮。

## Consequences（影响）

- `0.0.18` 交付 HTML 编辑闭环：打开即双栏、编辑即时预览、内联脚本可运行、相对资源限定授权根、联网默认阻断且尝试可辨认可放行（会话内）。
- 项目首次引入 WKWebView（NSViewRepresentable 包装）；此前唯一的内容渲染先例是 Mermaid 的结构化文本回传（`content.renderMermaid`），web 渲染不改变"GUI 原生是唯一呈现路径"（ADR 0024）——WKWebView 是受控内容渲染器，不是终端转绘。
- 允许联网的页面在会话内可加载远程资源；用户已知悉并接受该敞口（与 ADR 0023 固定完全访问的裁决一致性由用户自行掌握）。
- 原型 HTML 文件中"未开放脚本权限"的 0.0.18 示意文案与本决定不一致，以本决定为准；版本演进 README 的引用关系不变。
- WKWebView 内部渲染行为不在自动测试范围（无可靠断言路径），以配置断言 + scheme handler 安全校验单元测试 + 人工验收收口。

## Rejected Alternatives（未采用方案）

- **空 sandbox 静态预览（原型形态）**：脚本全禁导致动态 HTML 无法核对；用户裁决默认放宽脚本。
- **脚本 / 网络 / 本机全禁 + 显式档位开关**：三档状态机与"档位提升"交互复杂度远超收益，且与用户"仅禁联网"的裁决不符。
- **`loadFileURL` 直读磁盘**：无法呈现未保存缓冲区（读的是磁盘事实），且 WebKit 对 file 子资源访问缺乏授权根粒度控制。
- **逐条子资源联网询问**：WebKit 无此 API；伪装逐条批准是欺骗，改为状态开关 + 会话内放行，如实标注限制。
- **持久化联网授权**：扩大授权面且无真实 dogfood 需求；会话内放行已覆盖"临时看一眼远程图"的场景。
