# Composer 模型选择与原生能力菜单边界

状态：Accepted（局部取代 ADR 0030 关于“Composer 不显示模型选择”和 `+` 容器形态的决定）

Composer 控制行保留五类直接任务控件：`+`、当前模型名、推理强度、按模型能力出现的速度与发送。模型名本身是独立、可点击的原生 `Menu`，显示当前模型的用户可读名称；没有默认模型时显示“选择模型”。它不显示 CPU / 芯片图标，也不显示外露的 `▾` 或其他下拉 glyph。新会话选择写入会话前草稿，已有会话选择经 Pi Host 切换当前 Session 模型；切换成功后必须重新读取 Host state 与 Thinking levels，旧模型推理档位不得残留。模型目录、Provider 分组、当前项勾选与 Pi 默认标记继续复用既有真实合同。

推理强度保持为模型名旁边的独立文本菜单，不与模型重新合并。速度同样是独立文本菜单，只在 Pi Host 明确证明当前模型支持 Fast Mode 时显示“速度 · 标准 / 极速”；当前合同只覆盖 Host 白名单中的 OpenAI 模型。切离支持模型时必须立即归一为标准，切回后不得暗中恢复旧极速意图。速度入口不恢复 CPU 图标或旧的组合式运行参数控件。

普通在途 Run 与工具执行不禁用模型、推理强度和速度；用户在运行中所作选择作用于下一次安全模型边界，不中断正在执行的工具。Prompt / Steer RPC 自身在途、结构化等待、停止中、结果未知、压缩、路径迁移、冲突、Host 不可写或重启准备仍会禁用设置。UI 与状态写入必须共享这条专用 Runtime Settings 门禁，不能复用“有活动 Run 就全部锁住”的 Prompt transaction 总门禁。

Composer 前置 `+` 必须直接使用 macOS 原生 `Menu`，而不是带标题、固定宽度、内边距和胶囊按钮的自绘 Popover。菜单顺序为：添加文件或图片、技能子菜单、命令子菜单、分隔线、目标、计划。Skill、命令、目标与计划只在对应真实能力可用时执行；Skill 的展示名与剪贴板图片边界由 ADR 0034 固定。目标与计划不展示 dgoal 来源名。插件、扩展、本机资源、网页预览与浏览器控制不进入该菜单。

顶层 `+` 与模型名都隐藏系统菜单指示符，但保留真实 Menu 语义、键盘导航、Esc / Return 行为和 VoiceOver 名称。隐藏 glyph 只减少视觉噪声，不得用无语义点击层或自绘浮层替代系统菜单。
