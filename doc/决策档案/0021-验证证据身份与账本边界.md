# 验证证据身份与账本边界

状态：Accepted（已接受；约束 `0.0.12` 及后续版本）

## Context（背景）

版本路线要求 `0.0.12` 把命令、退出状态、时间、revision、环境与覆盖范围组成可复核记录，并显式拒绝"仅凭 Agent 文案宣称已验证"与"自动发布"。Pi 的 bash 工具结果没有结构化 exit code 字段——错误以 `isError` + "Command exited with code N" 文本呈现；Host 已把 `tool_execution_start/end` 原样转发给 Swift（带 sessionId / runId / args / result）。

## Decision（决定）

1. **证据身份**：一条运行证据 = Host 转发的一次真实 bash 工具执行事实——命令（start 事件的 args）、退出推导（非 error → ok；error 且文本含 "exited with code N" → failure(N)；无法辨认 → unknown）、起止时间与时长（Swift 自记）、环境（会话 cwd、当次模型）。**模型在回复里的"已验证"文案永不入账**。
2. **revision 为异步补全事实**：落账后用既有只读 git 直跑补 `rev-parse HEAD`（按目录缓存 5 分钟）；缺席时如实显示"待补"，不阻塞、不伪造。
3. **覆盖范围用联结而非采集**：展示时按 runId 联结 `0.0.4` 会话变更账本中该 Run 的已确认文件；不新增覆盖采集面。
4. **账本**：Swift 侧 `verification-evidence-v1.json`（版本化 + 原子写 + 5000 条上限 + 失败熔断，仿会话变更账本）；记录身份 `sessionId:runId:toolCallId`。`0.0.12` 只记 bash；其他工具的执行事实仍由变更账本承担。
5. **非门禁声明**：证据视图是核对材料，不构成测试、构建、人工验收、合并或发布的任何自动门禁；发布门禁仍全部人工（AGENTS 纪律）。

## Consequences（影响）

- 用户可以在会话检查器复核每条命令的真实退出、耗时、模型与 revision，区分"真跑过且通过"与"Agent 声称"。
- 退出码是推导事实（ok/failure(code)/unknown 三态诚实标注）；revision 可缺席。
- 后续 `0.0.13` 自构建闭环可直接引用该账本作为"验证证据身份"的实现基础。

## Rejected Alternatives（未采用方案）

- **Host 侧建账本**：事件已到 Swift，无第二事实源价值。
- **解析测试框架输出推导"通过率"**：伪装精度，覆盖语义不可靠。
- **把证据接成自动发布门禁**：显式反目标。
