# Pi 模型目录与全局选择设置边界

状态：Accepted（已接受；约束 `0.0.7` 及后续版本）

## Context（背景）

`0.0.6` 已经能在已有 Session 与会话前草稿中读取当前 `cwd` 生效的 Pi `enabledModels` 范围、精确默认模型与安全模型元数据，但 D Code 仍没有管理这些设置的原生页面。用户只能返回 Pi 配置文件或其他客户端修改默认模型和选择范围，也无法在一个界面里区分“Pi 知道这个模型”“认证可用”“当前项目允许选择”和“当前 Session 实际正在使用”四种不同事实。

Pi 0.84.1 已提供 `ModelRuntime` 的完整模型目录、缓存恢复、按供应商在线刷新与安全认证状态，以及 `SettingsManager` 对全局 `settings.json` 的锁定、合并式写入。`enabledModels` 是允许列表规则，支持精确引用和通配模式；它约束模型选择与循环，不等同于供应商认证、模型存在性或当前 Session 的实际模型。

项目级 `.pi/settings.json` 会覆盖全局设置，但 D Code 的 Project Trust（项目信任）、项目写入授权、撤回和审计要到后续版本才建立。`0.0.7` 不能为了模型设置提前绕过这条边界。

## Decision（决定）

1. Pi 的 `~/.pi/agent/settings.json`、`models.json`、`models-store.json` 与认证合同继续分别拥有模型选择设置、自定义供应商、目录缓存和认证事实。D Code 不建立平行模型数据库，也不复制凭据正文。
2. Settings（设置）新增独立“模型”页面。页面通过 Pi Host 读取 `ModelRuntime` 当前目录；主目录只按已认证 Provider（供应商）分组展示安全模型元数据、缓存状态、默认模型以及当前 D Code 选择范围。未认证 Provider 不展开其内建模型，只在页面最下方的“关联 Provider”入口中显示 Provider 身份与可用认证方式。
3. 页面首次进入只做 Cache-first（缓存优先）读取，不隐式发起网络访问。用户显式刷新时，Host 才在有界超时内请求 Pi 在线目录；刷新失败、中止或离线不会清空已经恢复的目录，界面按供应商标明仍在使用的缓存或无缓存状态。
4. `enabledModels` 继续使用 Pi 原生规则语义。未配置或空规则表示所有已认证模型均可选择；既有精确规则、通配规则和带 Thinking Level（推理强度）后缀的规则必须原样可辨认。普通用户不手写规则：未匹配模型通过对应模型行的“加入全局启用”追加精确 `provider/model`，也只能在移除后确实关闭该模型时从该行删除单条精确规则；由通配规则或隐式全量范围启用的模型只说明规则来源，不能静默展开通配规则、批量生成精确规则或删除其他模型的范围。
5. `0.0.7` 只通过 Pi `SettingsManager` 修改全局默认模型与全局 `enabledModels`，并等待合并式写入完成。当前 `cwd` 存在项目级覆盖时，D Code 只读取并明确标出“当前项目覆盖全局设置”，不写入、删除或绕过该项目设置。
6. 设为全局默认前，目标必须存在于当前 Pi 目录、认证可用并处于全局选择范围。范围不满足时界面给出可恢复说明，用户先显式加入范围再设为默认；D Code 不暗中改写规则、选择列表第一项或替换成其他模型。已经存在但不一致的默认配置只显示警告，不自动修复。
7. 修改全局规则或默认模型只影响之后重新读取选择范围的新会话和显式模型切换。当前 Session、历史 Assistant Message（助手消息）及其实际 Provider / Model 事实都不被改写；当前 Session 使用范围外模型时仍继续显示该真实模型，并说明它已不在 D Code 的新选择范围。
8. `0.0.7` 的“关联 Provider”只调用 Pi `ModelRuntime.login` 支持的认证合同：API Key 或 Provider 配置值在原生 `SecureField` / 文本步骤中短暂存在，并只通过本机 Host 请求交给本次 Pi 登录流程；Swift 在提交或取消后立即清空输入，Host 不记录请求值，错误只返回通用脱敏信息，D Code 不建立凭据存储。OAuth 的 URL、设备代码与说明可以原生展示并由用户显式打开，但最终 token 只由 Pi 保存，不回传 Swift。环境型、系统型或不可交互认证只说明需在 Pi / 系统环境完成。登出、查看或编辑已保存凭据正文仍不进入本版；自定义供应商继续由后续 `models.json` 版本处理。

## Consequences（影响）

- D Code 的 Composer（输入区）和 Settings 共享同一 Pi 选择规则，不会出现设置页显示一套、发送菜单使用另一套的平行事实。
- 用户可以在离线状态辨认上次目录并安全修改全局选择范围；在线刷新失败不会让所有模型突然消失。
- 未认证内建目录不再占据模型管理主空间；认证完成后由 Pi 重建安全目录快照，对应 Provider 才进入主目录。
- 项目级覆盖会暂时形成“可见但不可在 D Code 修改”的状态，这是 Project Trust 尚未交付时的诚实边界，不以直接写文件绕过。
- 通配规则使模型行不总能提供可直接关闭的 Toggle（开关）；规则来源和不可直接关闭的原因必须比视觉整齐更优先。

## Rejected Alternatives（未采用方案）

- **把模型目录、认证和启用范围合并为一个开关**：会把未认证误写成未启用，也无法解释当前 Session 仍在使用的历史模型。
- **关闭通配命中的单个模型时自动展开为所有其他精确模型**：在线目录变化后语义漂移，且一次点击会产生大规模、不可见的配置改写。
- **在 `0.0.7` 直接编辑项目 `.pi/settings.json`**：提前绕过 Project Trust、写入授权与审计边界。
- **刷新失败时清空目录或退回内置固定列表**：会丢失 Pi 已缓存的真实目录，并把网络故障伪装成模型被删除。
- **让 D Code 自己保存、回显或记录凭据正文**：会建立竞争认证资料并扩大泄漏面。当前只允许一次认证交互中的短暂本机传递，持久化仍完全交给 Pi。
