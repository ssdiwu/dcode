### 明确保留的差异

ZCode 的最高字体约束要求统一字阶，但调字号不缩放几何，并给代码、差异、终端单独字号设置。D Code 采用单一字号旋钮，字体与几何一起派生；不复制上游固定移动字号、Zai 品牌、等待绿色、九色头像或流程编辑器规则。几何和颜色的具体目标须结合本项目界面确定。

ZCode 的工作空间标签、多窗口、运行拓扑和路径身份回退不随 UI 参考一并采用。D Code 的对象模型、授权及暂停规则继续由对应规格约束。

## 体验研究问题

以下保留早期体验判断候选，供研究时检验，不新增产品要求：

| 要解决的问题 | 初步判断 | 后续如何判断是否成立 |
|---|---|---|
| 打开后是否知道从哪里开始 | 让工作对象、继续已有工作和开始新工作有清楚的主次 | 在真实首屏指出当前环境、可继续内容和下一步操作 |
| 工作过程中是否看得懂 | 默认突出当前状态、结果和需要用户处理的事；详细过程保留可达入口 | 用长任务核对用户能否快速定位状态，并在需要时回查原始过程 |
| 是否能连续工作 | 阅读、输入、查看文件及切换对象应保持上下文和未完成编辑 | 用一项实际工作验证切换、返回、中断和继续的行为 |
| 不同区域是否像同一个产品 | 共享排版、间距、表面层级、控件状态和反馈语言 | 以同一组正常／空／加载／失败／禁用场景对照各入口 |

任务归档／置顶呈现和图标库（MingCute／Remix／lucide）仍是观察项。记忆默认共享范围见 [长期记忆](../spec/开发任务路径.md#长期记忆)；其保存与冲突处理、上下文、用户提醒、能力包及外网具体方案的未决边界回查相应 spec、[协作安排](协作约定.md)和架构研究，不由词义或参考项目自动定案。

## 样式与验证依据

2026-10-07 补充的 [ZCode 交互组件借鉴](ZCode-交互组件借鉴.md) 对应逐页交互规格，记录基础原语、实际会话按钮／滚动、任务归档等来源及取用边界；它是组件研究入口，不替代产品规格或实际引入登记。

ZCode DESIGN 包含具体字体、颜色、尺寸、圆角和控件状态表。D Code 应在共享规则之外维护可执行的样式表；2026-10-06，507 明确要求 Kimi 在 UI／UX 工作中补齐，由主树写入者整合。目标值、实现值及渲染验证须分别有依据，现有 CSS 注释或数值不自动成为设计定案。

原型的样式与共享组件入口按 [协作约定](协作约定.md#第二轮原型开工入口) 定位至独立 UI 树；该树 `doc/第二轮原型验证.md` 的变量和组件清单保留历史用途。当前运行接线与故障状态回查 [PROGRESS](../PROGRESS.md)，详细结果见 [客户端集成记录](验证记录/客户端集成-2026-10-06/README.md)；早期底层证据见 [Pi 验证](Pi-1.0.0-虚拟模型与运行恢复.md#2026-10-05-实际运行证据)，不在规范中复制一份易过期快照。
