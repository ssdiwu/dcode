## 参照实证（2026-09-05 本机只读解包）

| 层级 | ZCode 3.11.2 | MiniMax Code 3.0.68 |
|---|---|---|
| 平台壳 | Electron 41；Helper GPU / Plugin / Renderer；Squirrel + electron-updater | Electron 42.8；同构 Helper 结构；electron-updater（generic feed） |
| 呈现层 | React 19 + Tailwind v4 + Radix/shadcn + Motion（framer-motion）；Vite 系打包；Redux Toolkit + zustand + swr | Next.js 静态导出 + React + Tailwind + immer；Monaco / Shiki / KaTeX / xterm / PDF.js |
| 本地运行时 | 自研 Node host 嵌入主进程（`out/host`） | **Pi 全家桶**（pi-agent-core / pi-ai / pi-coding-agent / pi-tui）嵌入主进程；better-sqlite3 |
| 工作区副作用 | node-pty、playwright-core、sharp | node-pty、@vscode/ripgrep、@nut-tree/nut-js |

结论：两家一线产品在"Electron 壳 + React 呈现"上完全一致；差异在呈现层构建方式（Vite SPA vs Next.js 静态导出）与运行时挂载位置（都选择嵌入主进程）。D Code 与 MiniMax 共用 Pi 运行时，但其"嵌入主进程"做法与 D Code 的单写入边界存在张力，见"待决细节"。

## 初版选型

| 层级 | 选型 | 版本锚点 | 立场 |
|---|---|---|---|
| 平台壳 | Electron | 41+（跟随稳定版，锁 minor，升级走候选验证） | 主进程只做 Platform Shell：窗口、菜单、快捷键、通知、文件选择、系统权限 |
| 呈现框架 | React | 19.x | 渲染进程为 Client Presentation 实现 |
| 呈现构建 | Vite SPA | — | 本地单窗口、无 SSR / SEO 需求，不采用 Next.js |
| 样式 | Tailwind CSS | v4 | 与[原生界面设计系统](0002-D-Code-原生界面设计系统.md)共享几何 / 状态 / 无障碍语义，token 重译为 Tailwind 配置 |
| 组件基座 | Radix 原语 + shadcn/ui | — | 浮层、菜单、命令面板、分栏的可及性行为直接可用 |
| 动效 | Motion（framer-motion） | — | 动效参数（浮层、悬停、转场）是 `0.0.30` 验收对象 |
| 状态 | zustand + swr | — | 服务端事实以 Host 查询为唯一来源，不预装 Redux |
| 语言 / 工程 | TypeScript；并入现有仓库，包管理沿用 npm | Node ≥ 22（与 `host/` 一致） | 不引入第二包管理器；workspace 划分在实现时定 |
| 打包 / 更新 | electron-builder + electron-updater | — | 候选隔离与回滚沿用 ADR 0022 精神；签名与公证要求沿既有发布纪律 |
| 通信 | 复用 Protocol v1 结构化合同 | — | 初版立场：渲染层经主进程桥接访问 Host；传输细化见待决细节 |

## 与 `host/` 的关系（初版立场）

- `host/` 保持独立 Node 进程、D Code Product Store 唯一写入者；Electron 主进程负责定位、启动、健康检查与受控重启 Host（对应现有 Swift `HostLocator` 的职责迁移）。
- 渲染层不直接建立与 Host 的传输；一切经主进程桥接的结构化请求 / 响应 / 事件（保持 request ID、revision、目标身份合同）。
- 现有 Swift 客户端是同一协议的另一个消费者；协议本身不因换壳改变。

## 待决细节（下一轮讨论清单，收口后回填本节）

1. **Host 进程关系**：独立子进程（现状迁移，边界最纯）vs 嵌入 Electron 主进程（MiniMax / ZCode 做法，部署简单，但主进程不再纯壳）。若选择嵌入，必须先修订 ADR 0042 / 0044 的 Platform Shell 语义。
2. **存储分工**：Product Store 留在 Host（SQLite，现状）不变；客户端本地偏好（窗口状态、视图选择）落点——electron-store / conf / 渲染层 storage，按 ADR 0042"只影响本设备的呈现状态"判据划线。
3. **终端**：node-pty 归属（Host 侧 pty 经协议流 vs 壳侧直开）；xterm 渲染在呈现层是共识。
4. **传输**：stdio + 主进程桥接（现状协议最近）vs 本地 WebSocket（ZCode 路线）；影响多窗口与 Task HUD 独立浮窗的事件分发。
5. **代码编辑器**：Monaco vs CodeMirror vs 沿用受控内容渲染器路线；`0.0.17–0.0.18` 的编辑缓冲区 / 原子保存合同必须继续成立。
6. **多窗口与 Task HUD 浮窗**：HUD 独立浮窗用独立 BrowserWindow 还是同窗口浮层；与宽窄屏合同的衔接。
7. **自动更新**：`0.0.x` 阶段是否只做"检查更新"占位；完整更新链路（签名、公证、feed）延后到发布专项。
