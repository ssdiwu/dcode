# D Code Web 客户端技术栈

状态：Design Candidate（初版选型；[ADR 0044](../决策档案/0044-Web客户端与桌面壳技术栈边界.md) Proposed 的实现事实文档。`client/` 已有未提交修复候选；自动验证与候选运行结果见 PRD 0028，未完成人工验收，不转 Confirmed）

## 文档职责

- 拥有 Web 客户端的具体技术选型、版本锚点、参照实证、与 `host/` 的关系立场，以及待决细节清单。
- 不拥有层级语义（归 [ADR 0042](../决策档案/0042-客户端呈现与-D-Code-Host-写入边界.md) 与根 `GLOSSARY.md`）；不拥有版本范围与验收（归 `0.0.30` PRD）；不复制主页面布局合同（归[主页面 UI/UX 设计](../20-产品与交互/0002-D-Code-主页面-UI-UX-设计.md)）。

## 参照实证（2026-09-05 本机只读解包；进程拓扑经运行中进程树二次核验）

| 层级 | ZCode 3.11.2 | MiniMax Code 3.0.68 | ChatGPT（Codex）26.901 | Mirasim 0.0.286 |
|---|---|---|---|---|
| 平台壳 | Electron 41；Squirrel + electron-updater | Electron 42.8；electron-updater | Swift/AppKit 原生壳（Sparkle）内嵌改名 Electron（Codex Framework） | Electron |
| 呈现层 | React 19 + Tailwind v4 + Radix/shadcn + Motion；Vite；Redux Toolkit + zustand + swr | Next.js 静态导出 + React + Tailwind + immer；Monaco / Shiki / KaTeX / xterm / PDF.js | Vite + React + Radix + Tailwind + framer + xterm | 自述为围绕 `@mirasim/ui` 的全屏工作台 |
| 运行时进程拓扑 | 自研 host 以 Electron 二进制 Node 模式独立子进程运行（`ELECTRON_RUN_AS_NODE`，process.title `zcode-host-local-N`），host 再派生多个 CLI 子进程；另见 node.mojom.NodeService utility | **Pi 全家桶**（pi-agent-core / pi-ai / pi-coding-agent / pi-tui）运行于 Electron utility 子进程（node.mojom.NodeService）；asar 另含 `ELECTRON_RUN_AS_NODE` spawn 代码与 mavis-local-runtime-mcp | 独立 Rust sidecar `codex` 二进制；JSON-RPC + MCP | 独立 `@mirasim/server` 子进程：spawn + 就绪探测 + 本地 WebSocket（带 token） |
| 工作区副作用 | node-pty、playwright-core、sharp | node-pty、@vscode/ripgrep、@nut-tree/nut-js | better-sqlite3、node-pty（主进程内嵌库） | `ax-window` 原生 Mach-O sidecar（辅助功能窗口探测） |

结论（2026-09-05 二次核验修正）：首次解包曾依据 asar node_modules 判断 ZCode / MiniMax 将运行时嵌入主进程，属误读——asar 依赖为主进程与子进程共享代码，不证明执行位置。以运行中进程树为准：四家产品无一将 agent 运行时嵌入主进程，分别采用独立子进程、Electron utility 子进程或独立二进制；D Code 现行「客户端进程 + 独立 host 进程 + 协议」拓扑与行业现役实践一致。

初版选型中地基（Vite）、记账（zustand + swr 两本账）、面子（Tailwind v4 + Radix/shadcn + Motion）已于 2026-09-05 由 507 拍板；配套守护规则：以自动检查禁止核心数据类型进入 zustand（两本账边界不靠自觉）。记账纪律：产品事实以 Host 为唯一来源，画面刷新 / 重开 / 换窗一律从 Host 投影重建；画面小账不冒充产品事实。

## 平台壳职责清单（2026-09-05 议题二收口，507 拍板）

主进程只承担以下与产品无关的职责：

1. 窗口、菜单、快捷键、文件选择对话框；
2. 系统通知（任务完成 / 等待反馈；设置可开关——507 明确要通知）；
3. 系统权限出面（屏幕录制、麦克风等）；
4. Host 定位、启动、健康检查与受控重启（现有 Swift `HostLocator` 职责迁移）；
5. 事件转发：核心消息广播给主窗口内各视图；
6. 检查更新占位（完整更新链路归发布专项）。

判断口诀：门面职责必须「换个产品也通用」——「启动核心」通用，「显示任务列表」不通用。

呈现两态（修正表述，与 PRD 0027 / 主页面设计 0002 对齐）：

- **梗概（浮卡）**：悬于留白区、不挤占任务区宽度；内容必须同时包含进度追踪与 Agent Team 追踪（HUD 四分区与信息面板五组合并成最终梗概，归 `0.0.30` PRD）。
- **详情（信息检查器）**：自主窗口侧边新开的整幅子栏，打开时**挤占任务区宽度**且梗概让位，关闭后恢复；它是主窗口内部的布局分栏，不是独立系统窗口。
- 因此 `0.0.30` 只需一个系统窗口；梗概未来出窗（拖出 / 第二屏）作为增量，由主进程转发机制支持。

## 与 `host/` 的关系（进程关系已于 2026-09-05 收口，见待决细节 #1）

- `host/` 保持独立 Node 进程、D Code Product Store 唯一写入者；Electron 主进程负责定位、启动、健康检查与受控重启 Host（对应现有 Swift `HostLocator` 的职责迁移）。
- 渲染层不直接建立与 Host 的传输；一切经主进程桥接的结构化请求 / 响应 / 事件（保持 request ID、revision、目标身份合同）。
- 现有 Swift 客户端是同一协议的另一个消费者；协议本身不因换壳改变。

## 待决细节（全部七项已于 2026-09-05 由 507 逐题拍板收口；后续按版本落地回填实现事实）

1. **Host 进程关系（已收口，2026-09-05 507 拍板）**：Host 保持独立子进程，渲染层经主进程桥接消费 Protocol v1；`host/` 与协议测试零改动直迁。启动采用 ZCode 同款机制：以 Electron 二进制 Node 模式（`ELECTRON_RUN_AS_NODE=1`）执行 host 入口，不再单独打包 Node 运行时。依据：四家产品进程树实测无一嵌入主进程；多 Runtime 并发由 host 内 Runtime Supervisor 承担（`0.0.28` 已交付），进程拓扑不约束多会话异步；真实 Provider 的协调者 + 子智能体并行留待 `0.0.30` 人工验收。后续演进（utilityProcess、独立二进制）均为增量决定，协议 schema 不变。
2. **存储分工（已收口，2026-09-05 507 拍板）**：三档落点——产品事实与需恢复的工作台状态、草稿留 Product Store（`~/.dcode/product-store.sqlite3`，只有 Host 写，延续 `0.0.29` 工作台状态入仓先例）；产品设置（通知开关、主题等需跨客户端同步项）走 Host 设置；纯设备杂项（窗口大小位置）由壳写应用支持目录小 JSON（electron-store），**不进 `~/.dcode/`**。分界线：重启后仍需记起的进核心数据库；忘了无所谓的进壳 JSON；仅瞬时有用的不落盘。凭据红线不变：核心独占，客户端与壳配置零接触（实证 ZCode `credentials.json` / Codex `auth.json` / MiniMax `local-runtime.auth.json` 均为点目录独立凭据文件，较宽松；我们刻意收紧，0.0.16 审计教训）。实证：ZCode `~/.zcode/v2/tasks-index.sqlite` + 应用支持偏好 store、Mirasim `~/.mirasim`（含 device.json）、MiniMax `~/.minimax`、Codex `~/.codex`——四家产品数据全部住家目录点目录，壳目录仅浏览器档案与设备偏好，无人把产品数据埋进应用支持。
3. **终端（已收口，2026-09-05 507 拍板）**：`0.0.30` 不引入终端部件与 pty 依赖（「不预建空入口」）；命令输出照 `0.0.23` 合同以结构化文本块渲染（折叠 / 查找 / 长输出滚动），不做终端仿真。未来若立项交互终端：pty 归 Host（一切执行过核心、进证据账本与 Task Scope，不在壳侧开后门），xterm 仅作渲染层零件，届时独立 PRD。
4. **传输（已收口，2026-09-05 507 拍板）**：`0.0.30` 以 stdio 管道直迁（进程树实证：ZCode / MiniMax / ChatGPT 边车均为管道，本地 WebSocket 仅 Mirasim）；「关窗不停工 / 多端同时接入」为远期能力，触发时只换传输不换协议。电话线预铺设为三条设计约束：协议编解码与传输解耦（帧格式不绑定 stdio，Host 与客户端的传输层各自做成薄片）；渲染层永不直接触碰传输（一律经主进程桥接，换传输不动界面代码）；升级路径预先定形——Host 起本地服务（`127.0.0.1` 临时端口 + token 文件 + 就绪探测，Mirasim 与 ZCode computer-use broker 同款做法），多客户端接入时的「谁当家」语义（`0.0.9` 租约扩写）届时独立 PRD 收口。
5. **代码编辑器（已收口，2026-09-05 507 拍板）**：`0.0.30` 只读视图用 Shiki 上色（ZCode / MiniMax 同款，按需加载语言）；编辑引擎预定为 CodeMirror 6（ZCode 同款，合身「不做通用 IDE」边界；Monaco 留作未来 IDE 级体验选项），编辑落地时须完整承接 `0.0.17–0.0.18`（缓冲 / 原子保存 / 冲突辨认）与 `0.0.21`（行号 / 查找替换 / 滚动性能）合同；变更对照优先复用 CodeMirror 对照视图，不为只读需求引入编辑器全家桶。预铺约束：`0.0.30` 只读查看组件接口按「原地升级为编辑组件、调用方不改」设计。
6. **多窗口与 Task HUD 浮窗（部分收口，2026-09-05）**：梗概（浮卡）与详情（挤压式侧栏）均为主窗口内部布局，`0.0.30` 只建一个系统窗口；梗概出窗（独立 BrowserWindow / 第二屏）留作增量，实现时经主进程广播同步。状态方案（zustand + swr）需经得起该演进。
7. **自动更新（已收口，2026-09-05 507 拍板）**：`0.0.x` 阶段只做「检查更新」占位（设置内手动触发、提示新版本即止）；完整更新链路（签名、公证、feed、增量）归发布专项，届时按 ADR 0022 候选隔离精神独立立项。

## 2026-09-05 修复候选实现补充

`client/` 使用 swr 消费 Host 投影，zustand 仅存面板瞬时状态；类型检查覆盖整个 React 目录。新任务草稿、阅读位置、通知偏好为修复既定恢复目标，经新增的 Protocol v1 方法由 Host 持久化。此处是加法扩展，不再将最初骨架的“Host / 协议零改动”当作当前实现事实。

平台壳消费原 Swift 应用图标；打包脚本在临时目录安装 Host 生产依赖，并明确复制依赖目录，避免资源匹配器默认忽略 `node_modules`。本地候选未签名、未发布；本机偏好与完整更新链路未扩展。

设置恢复继续遵循同一所有权：模型及资源偏好、档案、归档任务和自进化回执均由 Host 写入。平台壳只读取原 Swift 域名下的界面偏好白名单，交给 Host 单次导入，新客户端已有值优先；不枚举或读取凭据。Web 候选切换先核验应用与完整资源摘要、数据版本，再确认旧 Host 已退出，等待新窗口恢复原任务后交接；失败返回原应用，不创建并行写入者。


模型选择路径的职责落实（2026-09-06）：`components/ModelPicker` 和输入区只呈现选项、收集选择；`workbench/useModels` 统一查询、提交、刷新、错误与中文呈现；`dcodeModels.*` 由 Host 判定默认设置或当前 Runtime、检查可用性和请求身份。在线目录先经核心同步到产品目录，原生会话与目录查询共用 `~/.dcode/models-cache.json`，Pi 只保留原有连接引用。删除的原生来源不会因发现刷新而重新导入。模型展示路径有直接 API 依赖检查，其他呈现与自进化模块仍按既有审查清单逐步收口。
