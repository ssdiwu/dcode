# D Code 版本界面演进

状态：Draft Reference（草案参考）

[打开可切换版本的界面演进](dcode-version-evolution.html)

本原型用于比较 `0.0.1` 至 `1.0.0` 的用户可见变化。顶部版本按钮切换的是各版本具有代表性的真实工作状态，不表示相应能力已经由当前 Swift App 实现。

`0.0.1` 已完成验收并发布，范围与验收以 [0.0.1 用户首页与项目工作台产品需求](../../../40-版本实施方案/0002-0.0.1-用户首页与项目工作台产品需求.md) 为唯一权威；`v0.0.2` 与 `v0.0.3` 已固定为本地回归基线并等待 507 联合人工验收，分别以 [0.0.2 可见会话搜索产品需求](../../../40-版本实施方案/0003-0.0.2-可见会话搜索产品需求.md) 与 [0.0.3 会话路径与复制归档产品需求](../../../40-版本实施方案/0004-0.0.3-会话路径与复制归档产品需求.md) 为版本权威；`0.0.4` 及以后仍是版本切割参考。

## 当前版本骨架

1. `0.0.1`：用户首页、项目与最终三栏工作台；Project 可直接选中，无需先打开 Session 即可在右栏看到所有 Source Folder 的文件树与当前 Git Changes。项目下跨文件夹平铺会话，来源文件夹作为会话副标题；模型与思考强度、极速开关、上下文占用从首版起集中在 Composer 底部。此时文件树与 Changes 都只读，不预放未交付的中央编辑能力。
2. `0.0.2`：参考 Codex，以浮层搜索 D Code Recent 与已关联 Project 中的可见会话；当前对话、左栏与会话概览保持原位。
3. `0.0.3`：会话路径、完整会话复制与 D Code 归档；当前输入先自动保存为本机原路径草稿，消息动作再进入标明来源且单独保存的“新路径草稿”，只有第一条消息成功发送才创建路径。Session 菜单提供“复制到项目…”与“复制到项目并归档原会话…”：两者都保留源 Pi Session 并创建新 ID、新 `cwd` 的完整副本；后者只在目标验证成功后归档原会话，归档可恢复且不删除 Pi JSONL。产品不使用“移动会话”或“迁移会话”。
4. `0.0.4`：本地 Workspace Tab（工作区标签页）与只读文件工作流。第一个“对话”固定且不可关闭；Project 文件树以及助手正文中的文件、目录和代码行引用都能在第二个开始的标签中打开并定位普通文件。打开文件不自动加入 Context，不改变文件或 Git；切换标签后原 Session Path、活动计划、对话滚动位置、逐字草稿与已打开文件保持。本版不加入 Terminal（终端）、Browser（浏览器）或文件编辑器。
5. `0.0.5`：Markdown 默认富预览并可进入源码/预览分栏，HTML 以编辑缓冲区与隔离预览并排呈现；两种预览都跟随未保存内容，二者同时完成才算该版本交付，具体刷新阈值由实作验证确定。
6. `0.0.6`：Goal（目标）与 Work Map（工作地图）。D Code 建立自有、可恢复的 Goal 与 Work Item（工作项）：稳定身份、状态、依赖、验收条件、完成证据与需要用户介入的门禁。Goal 可从 Composer（输入区）附近或命令入口创建，定义最终结果、验收证据、允许范围、不可退步条件、停止 / 阻塞条件与时间或尝试上限；输入区上方持续呈现当前阶段、耗时、最近证据、待决定事项和阻塞原因。编辑 Goal 不自动执行；暂停 / 继续只作用于用户明确启动的当前执行，不直接改变 Work Item 的验收状态。
7. `0.0.7`：D Team（智能体团队）与 Agent Profile（智能体档案）。用户先建立可复用的本机智能体档案，明确稳定身份、名称、职责说明、可选默认工作范围与模型路由；档案本身不启动 Worker。当前 Session 可围绕一个 Work Item 显式启动 Team Run（团队执行），并按当次任务分配协调、执行与验证职责。每个 Team Member Run（团队成员执行）保存所用档案版本、任务、实际模型、有效工具授予、声明写入范围、状态、可见事件与报告；右栏呈现 queued / running / waiting / completed / failed（排队 / 运行 / 等待 / 已报告 / 失败）、当前活动、耗时 / 用量、卡住与重试，中央只突出需要用户处理的 Request（请求）、Finding（发现）、控制记录、Verifier（验证者）退回原因与结构化 Report（报告）。短任务默认保持单 Agent；成员协作首版由主智能体中转，不声称 Worker P2P（工作智能体点对点通信），不自动调度依赖项，不展示隐藏的原始思维链。
8. `0.0.8`：跨 Session 交接与通信。以耐久 Work Item 为协作锚点，记录稳定消息身份、来源与目标 Session / Path、关联 Team Report、送达、已读、失败、幂等重试与重启恢复。送达不自动启动新 Session 或 Run；只有接收方或用户明确采纳交接后才可显式启动，且不伪装恢复已经销毁的 Worker Runtime（工作智能体运行时）。
9. `0.0.9`：本机能力、安全与恢复收口。D Code 为 Pi 已发现的本机 Skill（技能）提供来源、作用、启用状态和兼容性视图，并把版本化 Skill 引用与 Permission Policy（权限策略）加入 Agent Profile；启动 Team Member Run 时再解析成不可变的 Effective Grant（有效授予）。Skill 说明“如何做”，不自行授予工具、文件、网络或凭据权限；声明写入范围也不冒充操作系统级沙箱。只有接通 Pi 的真实配置合同后才允许启用 / 停用 Skill，不建立在线市场。权限请求明确显示动作、目标路径或命令、风险理由与作用范围，并区分本次允许、当前范围允许和拒绝；删除、覆盖与外部副作用始终保留人工门禁。统一 D Team 的 HARD / SOFT（硬性 / 条件性）风险、审计事件、可确认的本地上下文 / 用量、异常恢复与脱敏持久化语义，不建立 TUI 兼容呈现路径，也不建立与 Pi 平行的模型或 BYOK 配置。
10. `1.0.0`：候选版通过会话、恢复、原生能力与日常工作流验收后晋升，不突然增加新的主界面。

## Work Map 与 D Team 分层约束

- D Code 借鉴 Todos 的稳定工作项、多次 Run 历史、版本化 Plan / Changes（计划 / 变更）和人工确认门禁；不照搬它的 Cloud（云端）权威、全局 Chief（主管智能体）、“一个 Todo 就是一个 Pi Session”、常驻角色团队、定时重跑或远程机器模型。
- Work Map 是 Durable Control Plane（耐久控制层）；D Team 是当前 Session 内的 Execution Plane（执行层）。Work Item 负责“要完成什么”，Team Run 与 Member（成员）负责“这次怎么执行”，两者不共用一个状态机。
- 工作项生命周期、执行运行态和用户关注态分开表达。“Worker 已提交合法报告”、“主智能体已综合关闭 Team Run”和“Work Item 验收成立”是三个不同结果，不得自动逐级推导。
- `pi-dteam` 的模型分级、有界任务、只读默认、显式写入范围、Finding / Request / Control / Report 作为 `0.0.7` 机制参考；D Code 仍然拥有产品对象、Host IPC（宿主进程协议）、持久化边界与 SwiftUI 原生界面，不解析 `/dteam` TUI 或要求用户另外安装扩展。
- Work Map 耐久保存；活动 Worker Runtime 保持在 Host 内存中。需要跨重启恢复的只是脱敏后的团队摘要、可见事件和结构化报告，不持久化隐藏 Thinking（思考）、完整 Worker Transcript（工作智能体对话）或凭据。

## MiniMax Code 本地能力参考边界

- 本轮只借鉴 MiniMax Code `3.0.60` 已确认的本地 UI / UX（界面 / 交互）与 Agent（智能体）能力组织：对话与文件并行、非模态右栏、Goal 状态控制、Agent 档案、团队运行可观测性、权限理由与本地用量反馈。
- D Code 保留自己的成立边界：SwiftUI / AppKit 原生界面、Pi 配置与 Session 权威、固定“对话”首标签、耐久 Work Map、显式 Team Run、主智能体有界中转，以及完成后只突出最终回答的工作轮呈现。
- Remote Control（远程控制）、IM（即时通讯）、云端 / 定时任务、账号积分与签到、在线部署、Chrome Cookie 导入、BYOK、Skill 市场和增长反馈入口不进入本路线；后续外部连接器也不得成为本机核心工作流的运行前提。
- 本次对齐不改变 `0.0.5` 的 Markdown / HTML 编辑预览范围，也不扩大 `0.0.8` 的跨 Session 可靠交接边界。

## 后续版本进入 PRD 前的决策门禁

- `0.0.6–0.0.7` 进入实现 PRD 前，先由 ADR 固定 Goal / Work Item / Agent Profile / Team Run / Team Member Run 的身份、存储权威、恢复、删除与 Pi Session / Path 引用边界。
- `0.0.9` 进入实现 PRD 前，先由 ADR 固定 Skill 的来源与版本身份、Profile Permission Policy 到 Member Run Effective Grant 的解析、声明写入范围的强制等级、凭据引用方式与审计保留边界。

## 界面语言

产品界面默认使用简体中文。`D Code`、扩展包名、模型名、命令、文件路径和代码标识符保留原文；项目、会话、目标、智能体、上下文、文件、变更和工作清单等产品概念使用中文标签。

## 证据边界

- 每个版本必须在上一版本可运行基线上增加真实能力，不能先显示没有数据和行为的空标签。
- `0.0.1` 就建立最终三栏空间关系；后续版本只向既有区域增加真实能力，不再以重排主界面制造版本变化。
- 工作检查器中的具体值仍是原型样例；“真实”指字段与状态在该版本必须接通真实数据，不表示本 HTML 已读取本机会话。
- 本文件只表达当前版本切割草案；版本范围在对齐完成并进入 `40-版本实施方案/` 前不是交付承诺。
- 当前实现与测试事实仍以项目源码、[架构与运行](../../../10-架构与运行/README.md)和实际验证结果为准。
