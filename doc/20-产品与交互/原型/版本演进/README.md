# D Code 版本界面演进

状态：Draft Reference（草案参考）

[打开可切换版本的界面演进](dcode-version-evolution.html)

本原型用于比较 `0.0.1` 至 `1.0.0` 的用户可见变化。顶部版本按钮切换的是各版本具有代表性的真实工作状态，不表示相应能力已经由当前 Swift App 实现。

`0.0.1` 已完成验收并发布，范围与验收以 [0.0.1 用户首页与项目工作台产品需求](../../../40-版本实施方案/0002-0.0.1-用户首页与项目工作台产品需求.md) 为唯一权威；`0.0.2` 及以后仍是版本切割参考。

## 当前版本骨架

1. `0.0.1`：用户首页、项目与最终三栏工作台；Project 可直接选中，无需先打开 Session 即可在右栏看到所有 Source Folder 的文件树与当前 Git Changes。项目下跨文件夹平铺会话，来源文件夹作为会话副标题；模型与思考强度、极速开关、上下文占用从首版起集中在 Composer 底部。此时文件树与 Changes 都只读，不预放未交付的中央编辑能力。
2. `0.0.2`：参考 Codex，以浮层搜索 D Code Recent 与已关联 Project 中的可见会话；当前对话、左栏与会话概览保持原位。
3. `0.0.3`：会话路径与复制；当前输入先自动保存为本机原路径草稿，消息动作再进入标明来源且单独保存的“新路径草稿”。只有第一条消息成功发送才创建路径；取消、切回原路径、切换会话或重启应用后都能逐字恢复对应草稿。草稿不自动过期；仅发送成功、明确清空或删除对应 Pi 会话时清除，移除项目关联不会清除。空消息或失败不留下空路径，保存草稿本身不改写 Pi 会话树。沿用三栏骨架与会话概览。
4. `0.0.4`：从已有项目文件树打开 Workspace Tab；第一个“对话”固定且不可关闭，第二个开始承载普通文件的只读预览。打开文件不自动加入 Context，切回对话后原会话、活动计划、滚动位置与逐字草稿保持。
5. `0.0.5`：Markdown 默认富预览并可进入源码/预览分栏，HTML 以编辑缓冲区与隔离预览并排呈现；两种预览都跟随未保存内容，二者同时完成才算该版本交付，具体刷新阈值由实作验证确定。
6. `0.0.6`：目标与工作清单。
7. `0.0.7`：智能体团队与团队通信。
8. `0.0.8`：跨会话通信。
9. `0.0.9`：自有原生能力与不支持边界收口候选；不建立 TUI 兼容呈现路径。
10. `1.0.0`：候选版通过会话、恢复、原生能力与日常工作流验收后晋升，不突然增加新的主界面。

## 界面语言

产品界面默认使用简体中文。`D Code`、扩展包名、模型名、命令、文件路径和代码标识符保留原文；项目、会话、目标、智能体、上下文、文件、变更和工作清单等产品概念使用中文标签。

## 证据边界

- 每个版本必须在上一版本可运行基线上增加真实能力，不能先显示没有数据和行为的空标签。
- `0.0.1` 就建立最终三栏空间关系；后续版本只向既有区域增加真实能力，不再以重排主界面制造版本变化。
- 工作检查器中的具体值仍是原型样例；“真实”指字段与状态在该版本必须接通真实数据，不表示本 HTML 已读取本机会话。
- 本文件只表达当前版本切割草案；版本范围在对齐完成并进入 `40-版本实施方案/` 前不是交付承诺。
- 当前实现与测试事实仍以项目源码、[架构与运行](../../../10-架构与运行/README.md)和实际验证结果为准。
