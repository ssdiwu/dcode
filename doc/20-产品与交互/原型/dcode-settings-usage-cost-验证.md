# D Code 设置“用量与费用”原型验证

状态：Supported Reference（已支持的参考）

[打开交互原型](dcode-settings-usage-cost.html)

## 验证问题

本机 Pi 会话的跨会话 Token（令牌）与费用统计，是否适合作为“设置 → 数据 → 用量与费用”的独立页面，而不占用日常工作台或单个会话的信息检查器？

## 假设与信号

- 假设：全局历史统计属于本机数据管理与回顾，应从设置进入；单次 Session（会话）或 Team Run（团队执行）的即时用量仍留在对应运行上下文。
- 支持信号：入口归属清晰；费用、Token、时间范围、趋势和会话明细能在同一页面形成从总览到下钻的阅读路径；未知价格不会被误读为零费用。
- 否定信号：用户需要在每次会话中持续查看这些全局指标，或设置页无法容纳高频回顾与会话下钻。

## 运行方式与范围

- 在 macOS 中直接打开 `dcode-settings-usage-cost.html`。
- 原型使用内置模拟数据，不读取 `~/.pi/agent`，不连接网络，也不修改任何 Pi JSONL。
- 可切换费用 / Token、最近 7 天 / 最近 30 天，并选择会话查看输入、输出、缓存读取和推理拆分。
- 原型明确没有验证真实 JSONL 聚合、模型价格来源与版本、增量索引、统计性能、原生 SwiftUI 实现或生产级无障碍表现。

## 观察

- 507 已确认“设置 → 数据 → 用量与费用”符合功能归属。
- 独立设置页面不改变当前三栏工作台，也不与会话内即时“耗时 / 用量”混用。
- 页面把费用标为估算口径，并对没有价格的模型显示“不可用”，避免把未知费用显示成 `US$0.00`。
- 会话表格与所选会话拆分提供了足够的第一层下钻；当前未知已经从“放在哪里”收敛为后续数据合同和实现问题。

## Verdict（结论）

- `supported（支持）`。
