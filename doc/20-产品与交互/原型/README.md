该原型使用模拟数据表达已经确认的目标交互，供后续设计、版本切割和 AI 实现参考。它不是当前 Swift App 的运行截图，也不能单独证明任何 Host、Pi 扩展、搜索索引、文件树或 Git 能力已经接通；版本状态与验收记录统一由[版本实施方案](../../40-版本实施方案/README.md)路由，当前实现仍以对应源码、测试和[架构文档](../../10-架构与运行/README.md)为证。

会话任务看板原型是一个已完成调查、暂不进入版本路线的外部参考：它保留“从左栏拖入现有 Session，建立轻量 Work Item 引用，并让可证明的 Run / Gate 事件驱动四列看板”的研究结果。卡片点击仍打开原 Session，Pi Session、`cwd` 与 Project 归属不变；它不映射到 `0.1.0` 前任何版本，也不将 Kanban（看板）界面写成 `0.2.x` Goal / Work Map 的预设形态。

设置“用量与费用”原型已经支持全局历史统计进入“设置 → 数据”的产品归属，但当前不绑定具体版本；`0.0.9` 已改为 Structured Verification Evidence（结构化验证证据）。该原型只验证入口、信息层级、模拟筛选与会话下钻；真实 Pi JSONL 聚合、价格合同、索引、性能和原生实现仍须在未来独立 ADR 与 PRD 中确认。

界面文案默认使用简体中文；只为 `D Code`、扩展包名、模型名、命令、文件路径和代码标识符保留原文。文档中的双语术语用于解释边界，不代表产品界面采用英文优先标签。

## 主要入口

- 左上“新建会话”：全局入口直接以当前 macOS 用户目录作为 `cwd`；Project 行内的新建入口才从该项目已登记的 Source Folder 中选择。
- 搜索按钮：参考 Codex 以浮层演示跨可见会话标题、用户消息与助手消息的全文搜索；范围只包含 D Code Recent 与已关联 Project 会话，当前工作台保持原位。
- “项目”旁加号：演示创建 D Code 项目、添加多个源文件夹，以及旧 Pi 会话被发现后进入项目列表。点击项目主行会直接将右栏切到项目文件，不需要先打开会话，也不改变中央当前会话与草稿。
- 会话导航：已置顶会话集中在左栏最上方的独立区域，并从 Recent 与 Project 普通列表去重；普通行只常驻显示单行标题。悬停或键盘聚焦后再显示完整标题、更新时间、Project、Source Folder、完整 `cwd` 与当前 Git 分支；分支表示工作目录当前状态，不冒充会话历史分支。
- “查看更多”：演示最近会话和项目会话按批次增加，而非预加载全部对话正文。
- 消息下方动作与“查看谱系”：演示编辑并重走、从这里继续；同会话路径操作先自动把原路径的未发送草稿保存到本机，再进入独立的“新路径草稿”，只有成功发送才创建。Session 操作另提供“复制到项目…”与“复制到项目并归档原会话…”：复制完整已持久化会话并创建新 ID、新 `cwd`，源 Pi Session 保留；归档只改变 D Code 可见性且可恢复。产品不把它称为移动或迁移。
- Composer：参考 Codex，把上下文占用、极速开关、模型与思考强度集中在输入框底部；上下文占用可展开查看容量，模型和极速状态可直接切换，且不会清除输入草稿。右栏 Context 只保留当前路径与已加载来源。
- 工作检查器：演示会话作用域中的目标、智能体、上下文，以及项目作用域中的多个源文件夹、文件与变更。点击文件会在中央打开或聚焦内容标签，不会自动加入上下文。
- 中央标签页：第一个“对话”固定且不可关闭；第二个开始承载普通代码只读预览、Markdown 富预览/编辑分栏或 HTML 隔离即时预览。本原型让两种预览都跟随未保存草稿，用来确认信息形态；生产实现的刷新调度与性能阈值尚未由本原型确定。切回“对话”后，原会话路径、活动计划、滚动位置和逐字草稿保持。
- 后续本机能力：`0.0.4` 建立只读 Workspace Tab；`0.0.5–0.0.10` 依次补齐后续消息队列、运行控制、项目权限、精确差异、验证证据与首次自构建恢复；`0.0.11–0.0.12` 交付一次性资源调用和本机 Skill / Prompt / Command / Extension 管理，`0.0.13–0.0.14` 交付 Pi 模型目录、启用范围与自定义供应商管理，`0.0.15–0.0.16` 再交付 Markdown / HTML 工作流，`0.0.17` 收口失败恢复。`0.1.0` 只在连续自迭代证据成立后晋升；Goal / Work Map、Agent Profile / D Team 与跨 Session 编排移至其后。具体版本边界以[版本界面演进](版本演进/README.md)为准。

## 预览参考与取舍

- 借鉴 [Orca 的 Tabs、Panes 与 Split Layouts](https://www.onorca.dev/docs/model/tabs-panes-splits)：让一种内容占用一个可恢复标签；D Code 首版只采用单组中央标签，不把多 Pane 与任意拖拽拆分一起带入。
- 借鉴 [Orca 的 Rich Markdown Editor](https://www.onorca.dev/docs/editing/markdown)：Markdown 默认富预览并可查看源码；本原型只表达信息形态，不复刻完整编辑器、批注或表格编辑能力。
- 借鉴 [Orca 的 Viewers](https://www.onorca.dev/docs/editing/viewers)：这里讨论的是 Workspace 文件查看器；图片文件、PDF、CSV/TSV 与 Notebook 仍是后续候选，`0.0.4` 的 Workspace Tab 只确认普通代码、Markdown 与 HTML。与此分开，Pi Session 已内嵌的结构化 `image` 内容块在 `0.0.4` 以消息缩略图和原图查看器只读显示，不建立第二份图片存储；任意远程 Markdown 图片与 Composer 图片发送仍不开放。
- HTML 原型使用无脚本权限的嵌套沙箱表达隔离边界；编辑只改变原型内的临时缓冲区，不写入本机文件。这不等于生产版安全实现已经确定或验证。
- MiniMax Code 只提供本地工作台、Goal、Agent Team 与权限信息层级参考；Remote Control、IM、云端 / 定时任务、账号增长、在线市场、BYOK 和部署不进入 D Code 版本演进。

## 响应式检查

- `≥1106 pt`：左右栏与中央并排。
- `880–1105 pt`：右栏保持非模态常驻，左栏按需从左侧临时覆盖。
- `<880 pt`：左右栏均以覆盖层打开，打开一侧会关闭另一侧。
- 用户主动关闭的右栏保持关闭；右栏只有在窄于 `880 pt` 时才进入覆盖态。

## 证据边界

- 原型中的 Project、Session、搜索结果、Agent、文件和 Git 数据均为样例。
- 原型只验证信息层级、文案、状态切换和响应式意图，不验证真实数据量、性能、权限、持久化或并发安全。
- 当前实现事实以 [架构与运行](../../10-架构与运行/README.md)、根 `DESIGN.md`、源码与实际测试结果为准。
- 目标产品行为以 [D Code 完整形态产品模型与交互契约](../0001-D-Code-完整形态产品模型与交互契约.md) 为准；版本交付以 [版本实施方案](../../40-版本实施方案/README.md) 为准。
