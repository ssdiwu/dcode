# 主页面三区 A/B 原型验证结论与边界

状态：Reference（参考；已拍板：2026-09-05 由 507 确认信息区采用浮动面板形态，常驻右栏否决。本原型不构成原生实现、Host 能力或验收证据）

[打开 A/B 原型](dcode-home-three-region-prototype.html)；原样收存的浮动形态为 [dcode-task-session-relationship-prototype.html](dcode-task-session-relationship-prototype.html)。

## 来源

本原型族来自 2026-08-25 的一次外部原型会话（任务-会话关系页），2026-09-05 原样收进仓库并派生 A/B 变体。它表达 [主页面 UI/UX 设计](../0002-D-Code-主页面-UI-UX-设计.md) 的导航区 / 工作区骨架，以及其中"信息区"的两种候选承载形态。

## A/B 内容

同一文件内由顶栏「信息区：浮动 / 常驻」按钮切换，两种形态消费同一份模拟任务数据：

- **浮动形态**（即原样收存文件的全部行为）：信息面板以浮动卡片悬浮于工作区右上，五个标签（任务 / 成员 / 文件 / 变更 / Git）切换。
- **常驻形态**（本仓库新增变体）：右侧固定 316 pt 信息区，自上而下同时堆叠任务摘要（目标、项目、当前阶段、执行成员、等待事项）、文件管理器（项目目录与演示文件树）、任务 / 文件变更管理器（可证明变更与来源 Run）；任务摘要中的等待事项可直接进入对应子会话。

## 已验证

- 两种形态切换即时不丢任务选择；常驻形态下切换任务，三段内容正确联动。
- 浮动形态原有行为（标签切换、子会话进入、灵感画布、新建任务草稿）未回归。
- 变更管理器在两种形态读取同一演示数据（`重构 507-rednote` 任务两条变更）。

## 边界（未验证、刻意不模拟）

- 常驻信息区的中宽 / 紧凑响应式（整体覆盖或收起为入口）未实现；本变体在任何宽度都保持固定右栏。
- 文件管理器是静态演示树；"点击文件在工作区打开文件标签"是目标行为，本原型未模拟。
- "当前阶段"由子会话状态演示推导，不代表结构化阶段事实。
- Git 在浮动形态是信息面板标签，在常驻形态不在信息区（符合设计草案"Git 页面是工作区页面"）；两种形态并列本身是拍板材料。
- 导航区顺序与设计文档的已知差异（灵感入口位置、最近工作位于底部）未在本轮调整，留待导航区拍板。
- 所有数据为 seed 模拟；本原型不证明 SwiftUI、Host、Product Store 或任何运行时行为，也不构成 `0.0.29` 基线或 `0.0.30` PRD 的验收证据。

## 拍板记录（2026-09-05，507）

- **信息区形态：浮动面板胜出。** 常驻右栏形态否决。任务信息继续以与窗口边缘分离的浮动卡片承载（任务 / 成员 / 文件 / 变更 / Git 五组信息），具体对象详情仍走全高 Information Inspector；[主页面 UI/UX 设计](../0002-D-Code-主页面-UI-UX-设计.md) 信息区章节已按此回写。
- **稳定几何是硬性约束：任何选中、悬停或状态切换不得引起既有内容位移。** 本原型选中行改变右侧标注导致列表漂移，属于原型偷懒，不进入任何实现合同；实现必须以固定行高加颜色 / 描边 / 图标表达当前态。
- **动效质量基准参考 ZCode**（Electron + Motion 的浮层、悬停与转场手感）；`0.0.30` PRD 冻结合同时落到具体参数，原型静态布局不再补动效。

## 拍板方式（历史）

507 在同一文件内切换两种形态直接对比；倾向确认后，由 `0.0.30` PRD 冻结相应布局合同，并回写主页面 UI/UX 设计文档、[原生界面设计系统](../../10-架构与运行/0002-D-Code-原生界面设计系统.md) 与根术语表。HUD 浮窗形态（[0.0.29 原型](dcode-task-hud-workbench-prototype.html)）与本页两形态的三方对比在原生实现轮次进行。
