## 设计前提

- D Code 的完成根是 Task（任务），Project（项目）是长期容器，D Code Session（D Code 会话）是 Task 拥有的对话与上下文容器。
- 工作台沿用安静的纵向导航骨架：身份与轻动作、创建、最近工作、项目列表和设置；项目操作就近出现，不另造控制面板式侧栏。
- 主页面的目标不是同时展示最多内容，而是让用户在导航、工作和核查之间始终知道自己位于哪个对象、可以做什么、会影响什么。

## 主页面三区

```mermaid
flowchart LR
  N[导航区] --> W[工作区]
  W --> I[信息区]
```

### 导航区

导航区位于左侧，负责选择、组织和继续工作，不承载主内容阅读。

从上到下的稳定顺序：

1. 身份与轻工具：搜索、活动提示、侧栏控制。
2. 创建动作：“新建任务”是顶层工作入口；新建项目保留项目分区标题旁的“＋”，不增加同名重复入口。
3. 最近工作：按最近活动时间排列的安静列表；它是时间投影，不是第三种工作对象分区。打开条目后进入所属 Task 的任务对话。
4. 项目：Project 行下显示其 Task；主行负责展开收起，右侧依次为“更多”“查看文件”“新建任务”。新任务图标为书写图标，进入该项目草稿而非全局默认草稿；首次发送才创建 Task。Task 展开后才显示已实际启动的子会话。
5. 任务：不属于 Project 的 Task 直接列出，不显示 User Scope（用户作用域）、用户主目录或“未选项目”容器。
6. 底部工具：设置、账户与其他非工作对象入口。

Agent Profile（智能体档案）、导入、搜索、活动、归档、插件和能力资源都是功能入口或投影视图，不成为导航区中的第三种工作对象分组。

点击项目行“查看文件”后，同一左侧导航区域临时切换为所点项目的文件树，显示项目名称并提供“返回任务”。返回只恢复导航，不切换中央任务或关闭已打开内容；中央正在讨论 A 项目时可以查看 B 项目，两个来源应当各自清楚。完整文件树不再放进任务概览浮层。“更多”只呈现当前已支持的项目动作，本版先承接编辑项目；参考产品的移除、置顶、分区或永久工作树等动作不因图标借鉴自动加入。

### 工作区

中央默认保留当前任务对话、阅读位置与输入栏；协调者不另建独立的导航行或标签。

- 文件正文、预览、差异以及产物、报告等具体对象默认在右侧信息检查器查看，对话与内容并列；不再因选择文件而替换中央聊天记录。
- 多个真实内容以 Workspace Tab（工作区标签）切换，标签属于内容区域；同一文件复用已有标签，不重复创建编辑缓冲区。
- 需要更大阅读或编辑空间时，用户主动展开同一内容到中央扩展视图，再通过“返回对话”收回至右侧。展开和收回保留文件滚动、编辑缓冲、预览状态，以及原对话、草稿、附件与后台执行，不创建第二窗口或新的任务。
- 没有内容时不显示空标签。关闭最后一个内容标签后收起内容区；未保存编辑继续适用保存、放弃或取消的保护。

### 信息区

信息呈现分为任务概览与对象详情，职责不同。

- **任务概览浮层**展示任务目标、阶段、成员、等待事项、交付物及可证明的任务变更摘要，成员入口进入对应子对话，具体对象入口打开右侧详情。它不承载完整项目文件树、长正文或第二套文件编辑器。
- **信息检查器**是按需出现的全高右栏，显示所选文件、产物、报告或证据的正文、预览、差异、来源及相关操作。选择文件直接打开这里，不需要先打开中央文件页再查详情；展开查看只改变同一内容的空间。
- 打开详情时任务概览暂时让出，关闭后恢复原先的显示状态；不会因为浏览另一个项目而把其文件或 Git 差异归因给当前任务。
- 任务概览关闭时，正文、空态和输入区居中；打开后统一向左让位，关闭后恢复。宽窗详情栏并列时在剩余空间居中；窄窗沿用临时覆盖与明确返回入口，不自动切到扩展编辑模式，不丢弃被遮挡的对话或编辑状态。

**稳定几何规则**（适用于导航区、工作区与信息面板）：在同一布局状态内，选中、悬停与运行状态刷新不得改变既有行的行高、列宽、列位置或滚动位置；当前态只用颜色、描边与图标表达。用户显式打开或关闭任务概览、对象详情属于结构切换，按上述规则调整阅读列；此例外取代此前“任何展开或状态切换零位移”的过宽限制。梗概内部的内容刷新仍不移动阅读列。

## Git 页面与变更阅读

Git 阅读按明确 Project 来源查看，不属于当前 Task 的变更管理器；可用的 Git 文件列表沿用左侧导航，所选差异默认进入右侧信息检查器。

- Git 页面显示项目的历史提交列表；选择某条提交后显示提交信息、作者、时间、涉及文件和相对父提交的变更。
- 点击提交涉及的文件，默认在右侧打开与当前任务变更共用的差异阅读标签，持续保留项目及历史提交来源。
- 当前任务 / 文件变更管理器回答“这项任务现在改了什么”；Git 页面回答“这个项目过去提交了什么”。历史提交不会自动归因给当前 Task，当前 Task 变更也不伪装为已提交历史。
- Git 历史与差异读取不提供提交、暂存、重置、切换分支、回滚或合并动作。当前版本只迁移已经存在的读取能力，不因本节目标新增尚未实现的提交历史浏览功能。

## 用户文案与位置映射

| 产品对象 / 概念 | 用户文案 | 出现位置 | 不得出现的位置 |
|---|---|---|---|
| Navigation Sidebar | 导航区 | 左侧主区域 | “项目区”这种排除直接任务的名称 |
| Recent projection | 最近工作 | 创建动作之后、项目之前 | 第三种工作对象分区、单个大按钮 |
| Task | 任务 | 项目下或「任务」分区 | User Scope 容器 |
| Coordination Session | 任务对话 | 工作区默认内容 | 左侧独立子会话行 |
| Child Agent Session | 子会话 | 展开 Task 后 | 顶层工作对象列表 |
| Workspace Tab | 内容标签 | 右侧内容区顶部，主动展开时跟随内容 | 默认取代中央对话、空标签占位 |
| Task summary | 任务摘要 | 浮动信息面板首组 | 工作区正文内漂浮卡、常驻右栏 |
| Project files | 查看文件 | 项目行入口、左侧文件导航、右侧所选正文 | 完整文件树塞入任务浮层、默认替换对话 |
| Task-related changed files | 任务 / 文件变更 | 任务概览入口、右侧差异 | 常驻右栏、完整项目文件树 |
| Project commit history | Git 历史 | 项目来源的历史列表及右侧详情 | 当前任务变更列表、未实现能力的空按钮 |
