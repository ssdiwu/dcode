# D Code 主页面 UI/UX 设计

状态：Design Candidate（主页面第一版设计共识；待完整原型逐区确认后，才升级为跨版本 UI 合同并回写版本验收。2026-09-05 信息区形态已由 507 拍板为浮动面板，A/B 记录见[原型验证文档](原型/dcode-home-three-region-prototype-验证.md)）

## 设计前提

- D Code 的完成根是 Task（任务），Project（项目）是长期容器，D Code Session（D Code 会话）是 Task 拥有的对话与上下文容器。
- 当前原生 `SidebarView` 已建立安静的纵向导航骨架：身份与轻动作、创建、最近工作、项目列表和设置。目标工作台应沿用这套视觉语法，只替换它承载的对象关系，不能另造控制面板式侧栏。
- 主页面的目标不是同时展示最多内容，而是让用户在导航、工作和核查之间始终知道自己位于哪个对象、可以做什么、会影响什么。

## 主页面三区

```mermaid
flowchart LR
  N[导航区] --> W[工作区]
  W --> I[信息区]
```

### 导航区

导航区位于左侧，负责选择、组织和继续工作，不承载主内容阅读。

从上到下的稳定顺序：

1. 身份与轻工具：搜索、活动提示、侧栏控制。
2. 创建动作：新建任务、新建项目；使用当前原生的纵向单行动作，不做卡片网格。
3. 最近工作：按最近活动时间排列的安静列表；它是时间投影，不是第三种工作对象分区。打开条目后进入所属 Task 的任务对话。
4. 项目：Project 行下显示其 Task；Task 展开后才显示已实际启动的子会话。
5. 任务：不属于 Project 的 Task 直接列出，不显示 User Scope（用户作用域）、用户主目录或“未选项目”容器。
6. 底部工具：设置、账户与其他非工作对象入口。

Agent Profile（智能体档案）、导入、搜索、活动、归档、插件和能力资源都是功能入口或投影视图，不成为导航区中的第三种工作对象分组。

### 工作区

工作区位于中央，是唯一的主阅读和编辑容器。

- 默认内容是当前 Task 的任务对话；协调者活在其中，不建立独立的协调会话导航行或标签。
- 工作区可同时保留多个 Workspace Tab（工作区标签），但同一时刻只展示一个活动标签；不默认分屏并行展示网页、预览、文件、Diff 或产物。
- 文件、网页 / HTML 预览、Artifact（产物）、Agent Report（智能体报告）、Git 页面和变更阅读都在工作区以标签打开。切换标签后保留各自的滚动位置、预览状态与未保存缓冲区。
- 关闭最后一个内容标签后，工作区回到原任务对话；任务对话不是普通内容标签。

### 信息区

任务信息不常驻占据右侧栏：默认隐藏，由工作区顶栏入口打开，以与窗口边缘分离、有限高内部滚动的浮动卡片呈现（2026-09-05 由 507 在三区 A/B 原型上拍板，否决常驻右栏形态）。它不使用“信息检查器”作为用户文案。浮动面板同时包含：

1. **任务摘要**：Task Goal（任务目标）、当前阶段、等待事项和当前执行成员的概括状态。
2. **成员**：当前 Task 实际启动的 Child Agent Session 及其状态；选择成员进入对应子会话。
3. **文件**：当前 Project Directory 的文件与文件夹定位入口；点击文件在工作区打开文件标签。
4. **任务 / 文件变更**：只列当前 Task 关联且可证明发生变化的文件、Diff、来源 Run 和变更覆盖事实；点击文件在工作区打开变更阅读标签。
5. **Git**：项目提交历史入口，打开 Project 级只读 Git 页面。

面板不承载需要持续阅读的内容：文件正文、长 Diff、网页和报告始终以工作区标签或全高 Information Inspector 呈现；打开具体对象详情时 Inspector 取代面板位置，关闭后回到任务对话。507 于 2026-09-06 更新布局要求：任务概览关闭时，正文、空态和输入区在工作区居中；打开后统一向左让位，必要时按可用宽度收窄，关闭后恢复居中。宽窗详情栏并列时在剩余空间居中，窄窗保留覆盖呈现与可读宽度。

**稳定几何规则**（适用于导航区、工作区与信息面板）：在同一布局状态内，选中、悬停与运行状态刷新不得改变既有行的行高、列宽、列位置或滚动位置；当前态只用颜色、描边与图标表达。用户显式打开或关闭任务概览、对象详情属于结构切换，按上述规则调整阅读列；此例外取代此前“任何展开或状态切换零位移”的过宽限制。梗概内部的内容刷新仍不移动阅读列。

## Git 页面与变更阅读

Git 页面是 Project 级、只读的工作区页面，不属于当前 Task 的变更管理器。

- Git 页面显示项目的历史提交列表；选择某条提交后显示提交信息、作者、时间、涉及文件和相对父提交的变更。
- 点击提交涉及的文件，在工作区打开与当前任务变更共用的变更阅读标签。
- 当前任务 / 文件变更管理器回答“这项任务现在改了什么”；Git 页面回答“这个项目过去提交了什么”。历史提交不会自动归因给当前 Task，当前 Task 变更也不伪装为已提交历史。
- `0.0.29` 的 Git 页面只读：不提供提交、暂存、重置、切换分支、回滚或合并动作。

## 用户文案与位置映射

| 产品对象 / 概念 | 用户文案 | 出现位置 | 不得出现的位置 |
|---|---|---|---|
| Navigation Sidebar | 导航区 | 左侧主区域 | “项目区”这种排除直接任务的名称 |
| Recent projection | 最近工作 | 创建动作之后、项目之前 | 第三种工作对象分区、单个大按钮 |
| Task | 任务 | 项目下或「任务」分区 | User Scope 容器 |
| Coordination Session | 任务对话 | 工作区默认内容 | 左侧独立子会话行 |
| Child Agent Session | 子会话 | 展开 Task 后 | 顶层工作对象列表 |
| Workspace Tab | 工作区标签 | 工作区顶部 | 并排压缩阅读的默认布局 |
| Task summary | 任务摘要 | 浮动信息面板首组 | 工作区正文内漂浮卡、常驻右栏 |
| Project files | 文件 | 浮动信息面板 | 常驻右栏、变更管理器列表 |
| Task-related changed files | 任务 / 文件变更 | 浮动信息面板 | 常驻右栏、完整项目文件树 |
| Project commit history | Git 页面 | 工作区标签 / 页面 | 当前任务变更列表 |

## 验证意图

主页面原型应按区域逐一确认：先导航区、再工作区、后信息区。每次只改变一个区域的结构关系，并让 507 直接试玩；方向确认后再同步回写根术语表、界面设计系统和 `0.0.29` PRD。原型与文档都不能声称原生 App 已完成、测试通过或人工验收成立。
