# 会话打不开时的恢复指引（面向用户）

状态：Active（随 `0.0.19` 修复能力与 `0.0.20` 修复卡全文展示生效；本页是支持话术基准，不引用内部代号）

适用症状：在 D Code 里打开某个会话时,界面提示**「会话无效 / 暂时无法打开会话」**,或提示**「会话文件尾部不完整(可能上次 Host 中断)」**并出现「备份并修复后打开」按钮。

## 先记住两件事

1. **你的对话记录是文件,不是数据库。** 每个会话是 `~/.pi/agent/sessions/` 下的一个 `.jsonl` 文本文件,按项目目录分文件夹存放。文件还在,记录就在;文件丢了,任何软件都救不回来。
2. **先备份,再做任何修复动作。** 备份只需要复制文件(见下),一分钟内完成;不备份就动手是唯一可能把小问题变成大问题的做法。

## 第一步:备份(任何时候都先做这步)

1. 打开「访达」,按 `⇧⌘G`,输入 `~/.pi/agent/sessions/` 回车。
2. 找到打不开的那个会话文件(可以按修改时间排序,最近的在最前;文件名是一串字母数字,`.jsonl` 结尾)。
3. 选中它,按 `⌘D` 复制一份。这一步不会改变任何现状,只是多了一个副本。

有 Time Machine 的话,此刻也可以顺手回一次快照点,多一层保险。

## 第二步:按你看到的情况走

### 情况 A:出现「会话文件尾部不完整」修复卡(推荐路径)

这说明是**程序中断时最后一句话写了一半**,前面的记录都是完好的:

1. 修复卡会展示**将被移除的那半条记录的原文**——请先选中复制、保存到你放笔记的地方。这半条通常是崩溃前你正想留下的最后一句,修复后它不再出现在会话里。
2. 确认保存后,点「**备份并修复后打开**」。D Code 会先在原目录留一份完整备份(文件名多了 `.bak-` 前缀),再移除那条写坏的记录,然后打开会话。
3. 如果改主意了,点「取消」——什么都不动。
4. 想找回那条被移除的半句:去 `~/.pi/agent/sessions/` 里找同名的 `.bak-` 文件,用「文本编辑」打开即可(它是纯文本)。

### 情况 B:只提示「会话无效」,没有修复卡

这说明损坏不在文件末尾,D Code **不会假装修复**——这是刻意的:对中部损坏的会话文件做"手术"风险远大于收益。你可以:

1. 核对 `.bak-` 备份或第一步自己复制的副本是否可读。
2. 用 Time Machine 回到更早的版本。
3. 都没有时,该会话文件可能无法恢复;新建会话继续工作,原文件保留作后续人工分析。

### 情况 C:提示「连接失败 / Host 需要重启」

这不是记录损坏,是后台进程退出了。侧栏或主页空态会有「**重新连接 Pi Host**」按钮,点击即可回到刚才的会话;若正在生成的回复被中断,它会以「未知状态」如实标注,可核对后继续。

## 什么时候无解

- 会话文件被删除且无备份、无 Time Machine——记录无法恢复。
- 文件中部损坏且所有备份同样损坏——同上。
- 以上情况之外,「尾部不完整」都可以安全修复(修复前的完整备份 + 可先复制的被修剪原文,双保险)。

## 找人支持时,请提供

- D Code 版本号(设置 › 关于,或菜单栏 D Code › 关于 D Code);
- 界面上出现的**原话**(截图或逐字抄写,包括是否有修复卡);
- `~/.pi/agent/sessions/` 里该会话文件的大小与修改时间(不要发送文件内容——里面可能有你的代码或私密对话;支持侧不需要正文)。

## 支持侧备注(不面向用户朗读)

- 修复动作 = `session.repair`(备份 → 修剪尾部 → 复验 → 原子替换);拒绝修复的形态会给出字段级原因,原文件零改动。
- 幂等与重复执行:同一消息 ID 的防重只在 Host 单次生命周期内成立;Host 重启后重发同一 ID 会再次执行,判定"上次是否已写入"需比对正文与会话记录链(见 [ADR 0027](../决策档案/0027-中断状态可辨认与恢复边界.md) Consequences 的条件句)。
- 用户凭据、API key 与本页无关;任何支持流程都不要索要 `~/.pi/agent` 之外的配置文件内容。
