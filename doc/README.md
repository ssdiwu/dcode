# D Code 文档总览

根目录一等项目文档先回答稳定问题：[`README.md`](../README.md) 是 Project Map 入口，[`AGENTS.md`](../AGENTS.md) 约束 Agent 工作，[`PRODUCT.md`](../PRODUCT.md) 定义产品宪章，[`DESIGN.md`](../DESIGN.md) 定义设计原则，[`GLOSSARY.md`](../GLOSSARY.md) 是术语唯一权威。它们按职责和 Task 需要由 LLM 直接读取，不构成每轮全文注入。

## 从问题进入

| 当前 D Code Harness 如何组成和运行 | [架构与运行](10-架构与运行/README.md) | 不承载未来设想或版本需求 |

首次进入项目时，先读根 [`README.md`](../README.md)，再按当前任务选择上表入口；无需按版本历史逐篇通读。

## 已确认架构与当前实现边界

- [ADR 0037](决策档案/0037-D-Code-原生产品数据权威与-Pi-单向导入边界.md) 已确认 D Code 原生拥有产品数据、模型与能力配置，Pi SDK 退为 Runtime Adapter，Pi JSONL 只单向导入。
- [ADR 0038](决策档案/0038-全局创造模式与-D-Code-自举开发边界.md) 已确认全局创造模式只开发和自进化 D Code 自身。
- [ADR 0039](决策档案/0039-一等项目文档与根目录-GLOSSARY-权威边界.md) 已确认一等项目文档和根 `GLOSSARY.md` 的 Markdown 权威。
- [ADR 0040](决策档案/0040-D-Code-系统提示词与活动工具同源边界.md) 已确认 D Code 完整替换 Pi 通用系统提示词，并从真实活动工具快照生成工具说明。
- 当前 Web 客户端由 `client/` 实现，`host/` 继续拥有产品数据与运行事实；技术路线见 [ADR 0044](决策档案/0044-Web客户端与桌面壳技术栈边界.md)。基本验收、源码状态、迁移遗留与后续版本前置条件统一由 `40-版本实施方案/` 维护。

## 权威关系

- `40-版本实施方案/README.md` 是版本状态、当前承诺和验收文档的唯一索引；具体证据保留在对应 PRD 的 Verification Record（验证记录）中。
- `10-架构与运行/` 只记录源码、测试和运行证据已经支持的当前事实；其中 Host/IPC 与原生设计系统分别拥有各自实现边界，并明确标注与目标架构的迁移差距。
- `20-产品与交互/` 拥有跨版本目标；版本 PRD 只切取其中当前承诺的子集。
- `决策档案/` 拥有难逆转决定的理由与取代关系；其他文档只引用其结论，不复制完整理由。旧 ADR 被取代后继续保留历史，不与新决定并列充当当前权威。
- `参考文件/` 和原型只保存参考与验证边界，不能被用来声称实现或验收完成。

## 目录职责

- `10-架构与运行/`：当前 D Code Harness、Host/IPC 与原生界面设计系统的实现地图。
- `20-产品与交互/`：跨版本持续逼近的确认目标；其中 HTML 原型只提供交互参考。
- `40-版本实施方案/`：已经确认、用于指导当前版本交付和验收的 PRD 与专项规格。
- `参考文件/`：507 明确提供的产品与仓库参考；只记录来源和借鉴边界，不建立第二套需求。
- `决策档案/`：满足难逆转、有真实权衡且脱离上下文会困惑的决定。

尚无历史归档。完成但仍有效的需求或验收基准继续保留在原职责目录；只有被取代、放弃或仅供追溯的材料才进入 `90-归档/`。
