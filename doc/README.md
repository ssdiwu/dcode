# D Code 文档总览

## 从问题进入

| 要回答的问题 | 权威入口 | 不负责 |
|---|---|---|
| 当前版本承诺了什么、处于什么状态、如何验收 | [版本实施方案](40-版本实施方案/README.md) | 不定义跨版本目标或当前实现机制 |
| 当前 D Code Harness 如何组成和运行 | [架构与运行](10-架构与运行/README.md) | 不承载未来设想或版本需求 |
| 产品最终要成为怎样、对象之间如何关联 | [产品与交互](20-产品与交互/README.md) | 不证明已经实现或验收通过 |
| 为什么采用某个难逆转边界 | [决策档案](决策档案/README.md) | 不追踪版本进度 |
| 项目专有概念是什么意思 | [术语表](术语表.md) | 不定义产品行为或验收 |
| 外部产品和仓库提供了什么参考 | [外部产品与仓库参考](参考文件/README.md) | 不覆盖 D Code 的产品、架构或版本权威 |

首次进入项目时，先读根 [`README.md`](../README.md)，再按当前任务选择上表入口；无需按版本历史逐篇通读。

## 权威关系

- `40-版本实施方案/README.md` 是版本状态、当前承诺和验收文档的唯一索引；具体证据保留在对应 PRD 的 Verification Record（验证记录）中。
- `10-架构与运行/` 只记录源码、测试和运行证据已经支持的当前事实；其中 Host/IPC 与原生设计系统分别拥有各自实现边界。
- `20-产品与交互/` 拥有跨版本目标；版本 PRD 只切取其中当前承诺的子集。
- `决策档案/` 拥有难逆转决定的理由与取代关系；其他文档只引用其结论，不复制完整理由。
- `参考文件/` 和原型只保存参考与验证边界，不能被用来声称实现或验收完成。

## 目录职责

- `10-架构与运行/`：当前 D Code Harness、Host/IPC 与原生界面设计系统的实现地图。
- `20-产品与交互/`：跨版本持续逼近的确认目标；其中 HTML 原型只提供交互参考。
- `40-版本实施方案/`：已经确认、用于指导当前版本交付和验收的 PRD 与专项规格。
- `参考文件/`：507 明确提供的产品与仓库参考；只记录来源和借鉴边界，不建立第二套需求。
- `决策档案/`：满足难逆转、有真实权衡且脱离上下文会困惑的决定。

尚无历史归档。完成但仍有效的需求或验收基准继续保留在原职责目录；只有被取代、放弃或仅供追溯的材料才进入 `90-归档/`。
